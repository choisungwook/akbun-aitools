# 평가 렌즈, 인터뷰 질문, 지표 목록

`SKILL.md` 2~4단계에서 고른다. 모든 항목을 다 쓰지 않는다. 이 시스템에 해당하는 것만 고른다.

## 렌즈

보안과 운영·유지보수 부담은 필수다. 나머지는 해당할 때만 댄다.

| 렌즈 | 무너뜨리는 질문 | 흔한 발견 |
|---|---|---|
| 보안(필수) | 외부에서 들어온 요청이 검증 없이 닿는 곳은? 내부에 들어온 뒤 더 얻을 수 있는 권한은? 비밀이 평문으로 놓인 곳은? 한 계정이 털리면 어디까지 가는가? | 인증이 서비스마다 따로, 내부 통신 무인증, 과한 IAM·DB 권한, 비밀이 코드·CI 변수·환경변수에 분산, 관리 포트 외부 노출, 감사 로그 없음 |
| 운영·유지보수 부담(필수) | 배포·롤백·스케일·인증서 갱신·계정 발급 중 사람이 손으로 하는 것은? 새 사람이 이 시스템을 혼자 배포하기까지 며칠? 같은 알람이 매주 오는 곳은? 한 기능을 바꾸려면 몇 군데를 고치는가? | 수작업 배포 단계, 서버 직접 접속 운영, 설정이 환경마다 다르게 손으로 관리, 알람만 있고 조치는 사람, 한 변경에 여러 저장소·서비스 동시 수정 |
| 장애·복구 | 이 노드 하나가 죽으면? 이 리전이 죽으면? 데이터가 지워지면 얼마 전으로 돌아가는가? 복구를 마지막으로 해 본 때는? | 단일 장애점, 백업은 있으나 복구 미검증, 재시도 없는 동기 호출, 타임아웃 미설정 |
| 변경 비용 | 스키마를 바꾸려면? 서비스를 하나 더 붙이려면? 라이브러리 버전을 올리려면? | 공유 DB에 여러 서비스, 계약 없는 내부 API, 배포 순서 의존 |
| 비용 | 트래픽이 0일 때도 내는 돈은? 가장 비싼 구성 요소가 하는 일은? | 상시 과대 인스턴스, 쓰지 않는 환경, 데이터 전송 비용 |
| 확장성 | 트래픽 10배에서 먼저 막히는 곳은? | `akbun-analysis-bottleneck`으로 넘긴다. 이 skill에서는 구조 수준만 다룬다 |

보안 시나리오는 아래 여섯 갈래로 나눠 생각하면 빠뜨리지 않는다. 각 갈래에서 "이 시스템에서 가장 쉬운 길"을 하나만 찾는다.

| 갈래 | 질문 |
|---|---|
| 위장(Spoofing) | 남인 척할 수 있는 곳 |
| 변조(Tampering) | 데이터·요청을 중간에서 바꿀 수 있는 곳 |
| 부인(Repudiation) | 누가 했는지 추적 못 하는 곳 |
| 정보 노출(Information disclosure) | 보면 안 되는 것이 보이는 곳 |
| 서비스 거부(Denial of service) | 값싸게 멈출 수 있는 곳 |
| 권한 상승(Elevation of privilege) | 낮은 권한으로 높은 권한을 얻는 곳 |

## 인터뷰 질문

자료에서 확인된 것은 묻지 않는다. 한 라운드에 5개 이하다.

| 묶음 | 질문 | 답이 채우는 것 |
|---|---|---|
| 지켜야 할 것 | 이 시스템이 한 시간 멈추면 무슨 일이 생기는가 | 가용성 목표 |
| 지켜야 할 것 | 지켜야 하는 규정·계약·감사 항목이 있는가 | 제약 |
| 아픈 곳 | 최근 6개월 장애 중 기억나는 것과 원인 | 장애·복구 발견 후보 |
| 아픈 곳 | 매주 손으로 반복하는 일 | 운영 부담 지표 |
| 아픈 곳 | 배포할 때 가장 긴장되는 곳 | 변경 비용 발견 후보 |
| 보안 | 외부에서 접근 가능한 주소·포트 목록 | 노출면 |
| 보안 | 로그인·권한 확인이 이뤄지는 위치 | 인증·인가 경계 |
| 보안 | 비밀번호·키·토큰을 두는 곳 | 비밀 위치 수 |
| 보안 | 다루는 데이터 중 유출되면 곤란한 것 | 데이터 민감도 |
| 운영 | 배포 절차를 처음부터 끝까지 말해 달라 | 배포 단계 수·수작업 수 |
| 운영 | 롤백은 어떻게 하는가, 마지막으로 해 본 때 | 롤백 방법 |
| 운영 | 새 팀원이 혼자 배포하기까지 걸린 기간 | 운영 부담 |
| 제약 | 바꾸면 안 되는 것과 이유 | 제약 |
| 제약 | 이 개선에 쓸 수 있는 사람·기간·예산 | 이행 순서 크기 |
| 규모 | 지금 RPS·데이터 크기·사용자 수, 1년 뒤 예상 | 확장성 판단 |

## 지표 목록

개선 효과 표의 지표는 여기서 고른다. 세는 방법이 있는 것만 지표다.

| 렌즈 | 지표 | 세는 방법 |
|---|---|---|
| 보안 | 외부 노출 포트·엔드포인트 수 | 보안 그룹·Ingress·LB 규칙 |
| 보안 | 인증 없이 닿을 수 있는 내부 호출 수 | 서비스 간 호출 중 토큰·mTLS 없는 엣지 |
| 보안 | 비밀이 놓인 위치 수 | 코드·설정 파일·CI 변수·환경변수·비밀 관리자 각각 |
| 보안 | 과한 권한 수 | `*` 또는 관리자 권한이 붙은 IAM·DB 역할 |
| 보안 | 한 계정 탈취 시 닿는 구성 요소 수 | 권한 그래프에서 도달 가능한 노드 |
| 보안 | 감사 로그가 없는 쓰기 경로 수 | 쓰기 API 중 로그 없는 것 |
| 운영 부담 | 배포 단계 수 / 그중 수작업 수 | 런북·CI 파이프라인 |
| 운영 부담 | 롤백 소요 시간 | 마지막 롤백 기록 또는 절차 단계 |
| 운영 부담 | 주당 반복 수작업 건수 | 인터뷰·티켓 |
| 운영 부담 | 주당 사람이 조치하는 알람 수 | 알람 기록 |
| 운영 부담 | 한 기능 변경에 고치는 저장소·서비스 수 | 최근 PR |
| 운영 부담 | 환경별로 손으로 다르게 맞추는 설정 수 | 설정 파일 diff |
| 운영 부담 | 새 팀원 첫 단독 배포까지 일수 | 인터뷰 |
| 장애·복구 | 단일 장애점 수 | 아키텍처 그림에서 대체 경로 없는 노드 |
| 장애·복구 | 복구 시간·복구 시점 | 백업 주기·복구 절차 |
| 변경 비용 | 공유 DB를 직접 읽는 서비스 수 | 커넥션 설정 |
| 비용 | 월 비용 / 유휴 시 월 비용 | 청구서·인스턴스 목록 |
