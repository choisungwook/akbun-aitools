# akbun-analysis-adversarial-review

사용자가 구현한 코드와 주장을 옹호하지 말고 의심한다. 반례는 두 층에서 찾는다. 설계가 원래 풀려던 문제를 놓치는 상황(거시)과, 코드가 약속한 입력·출력·실패 처리를 어기는 입력(미시)이다.

반례마다 어긴 요구사항·계약, 깨지는 입력이나 상황, 근거(`file:line`, 재현 입력이나 실행 결과), 깨졌을 때의 영향을 적는다. 넷 중 하나라도 비면 반례가 아니라 `미확인 가설`로 따로 둔다. 반례 개수를 채우지 않고, 지원 범위 밖의 가상 입력·막연한 미래 확장·취향은 들지 않는다. 깨지는 반례가 없으면 확인한 범위와 함께 "반례 없음"으로 끝낸다.
