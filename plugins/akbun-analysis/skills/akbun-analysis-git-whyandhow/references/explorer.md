## why에서 온 제약 (있으면)

{CONSTRAINTS}

Preserve와 Avoid에 해당하는 지점이 코드 어디인지 `file:line`으로 찾아 표시한다.

## 절차

이름으로 추측하지 않는다. Glob으로 파일을 찾고 Grep으로 심볼을 찾고 Read로 구현을 읽는다.

1. 진입점. 무엇이 이 동작을 시작하는가(사용자 행동, API 호출, 스케줄).
2. 흐름. 진입점부터 호출 사슬을 따라가며 각 함수를 읽는다. 어떤 데이터가 흐르고 어떻게 변하는가.
3. 핵심 추상. 중심이 되는 타입·인터페이스·서비스·클래스의 정의를 읽고 무엇을 표현하는지 이해한다.
4. 경계. 다른 서브시스템과 만나는 곳. 들어오는 것과 나가는 것.
5. 비자명한 것. 놀라운 것, 역사적 흔적으로 보이는 것, 처음 온 사람이 오해할 것.

손을 흔들지 않고 전체를 설명할 수 있을 때까지 읽는다. 못 추적한 부분은 "X가 Y로 어떻게 연결되는지 확인하지 못했다"고 쓴다. 지어내지 않는다.
