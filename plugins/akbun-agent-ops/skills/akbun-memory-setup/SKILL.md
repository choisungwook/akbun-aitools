# akbun-memory-setup

기억을 많이 저장하는 것보다 **필요한 순간에 올바른 기억을 꺼내주는 것**이 목표다. 이 skill은 저장소를 늘리는 게 아니라, 현재 상황에 정말 필요한 기억만 우선순위대로 꺼낼 수 있게 디렉터리와 읽기 순서를 설계한다. 최초 1회 설정이다. 세션마다 맥락을 복원하는 일은 `akbun-recall`, 세션에서 배운 것을 skill에 남기는 일은 `akbun-reflect`가 맡는다.

디렉터리 구조는 프로젝트마다 다르다. 이 skill이 정한 구조를 다른 프로젝트에 그대로 복사하지 않고, 매번 그 프로젝트의 반복 맥락에서 도출한다.

## 1. 프로젝트를 훑어 반복 맥락을 찾는다

무엇을 기억해야 하는지는 프로젝트가 말해 준다. 아래를 확인하고 "다음 agent가 매번 다시 알아내야 하는 것"을 목록으로 만든다.

- README, 기존 AGENTS.md·CLAUDE.md, docs/, 빌드·테스트·배포 명령
- 최근 커밋과 PR에서 반복되는 수정 유형과 리뷰 지적
- 설정 파일과 환경 변수, 외부 시스템 연결
- 이미 있는 메모·결정 기록·런북

각 항목에 "얼마나 자주 필요한가"와 "어느 상황에서 필요한가"를 붙인다. 이 두 값이 배치를 정한다.

## 2. 배치 규칙

- **매 세션 쓰는 것은 AGENTS.md에 인라인한다.** 별도 파일은 읽을 때마다 비용이 든다. 빌드·테스트 명령, 금지 사항, 용어 정의처럼 항상 필요한 것은 AGENTS.md 본문에 둔다.
- **상황에서만 쓰는 것은 종류별 디렉터리로 나눈다.** 디렉터리 하나에 종류 하나. 각 디렉터리에는 `README.md` 한 줄로 "언제 읽는가"를 적는다. 예: `decisions/`는 설계를 바꾸기 전에, `runbooks/`는 장애 대응 중에, `incident/`는 조사를 이어갈 때.
- **상태와 규칙을 섞지 않는다.** 규칙(어떻게 일하는가)은 AGENTS.md, 상태(지금 어디까지 왔는가)는 디렉터리 안의 파일. 상태가 AGENTS.md에 들어가면 몇 달 뒤 AGENTS.md가 틀린 문서가 된다.
- **같은 지시를 두 번 쓰게 되면 스크립트나 검사로 바꾼다.** 텍스트 지시는 읽는 agent의 협조에 의존한다. lint, 검증 스크립트, CI 검사로 강제할 수 있는 규칙은 그쪽으로 옮기고 AGENTS.md에는 실행 명령만 남긴다.
- 확실하지 않으면 만들지 않는다. 빈 디렉터리와 빈 템플릿은 다음 agent에게 채워야 할 숙제로 보여 잡음이 된다.

## 3. AGENTS.md를 만든다

이미 있으면 덮어쓰지 않고 아래 절을 추가·병합한다. 담을 것은 세 가지다.

1. **읽기 순서와 조건.** 번호 목록으로 "무엇을, 어떤 조건에서" 읽는지 적는다. 조건이 없는 항목은 항상 읽는 것이다. 예: `1. 이 파일 전체. 2. 코드를 바꾸기 전에 decisions/. 3. 장애 조사 중이면 incident/CURRENT.md.`
2. **인라인 규칙.** 2단계에서 "매 세션 쓰는 것"으로 분류한 내용.
3. **세션 시작과 끝.** 시작 때 `akbun-recall`로 맥락을 복원하고, 끝낼 때 `akbun-reflect`로 배운 것을 skill에 남기라는 한 줄씩. 이 두 skill이 없는 환경이면 이 절은 생략한다.

AGENTS.md에는 조사 상태, 임시 메모, 작업 로그를 넣지 않는다.

## 4. CLAUDE.md

없으면 "AGENTS.md를 읽고 따르라"는 지시만 담아 만든다. 이미 있으면 그 한 줄이 있는지만 확인하고 다른 내용은 건드리지 않는다. 내용을 중복해서 쓰지 않는다.

## 5. 보고

만든 디렉터리와 각각의 "언제 읽는가", AGENTS.md에 인라인한 규칙 목록, 스크립트로 옮기기를 권한 규칙, 만들지 않고 넘긴 후보와 이유를 개조식으로 보고한다.
