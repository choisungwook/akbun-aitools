# github-period-pulse

기간 하나를 받아 **그 기간에 내가 무엇을 끝냈고, 무엇이 진행 중이고, 무엇이 막혔는지**를 회의에서 그대로 읽을 수 있는 브리프로 만든다. `github-daily-pulse`가 "오늘 무슨 결정을 했는지 복습"이라면 이 skill은 "이 기간에 무엇을 만들었는지 보고"다. 단위가 시간이 아니라 결과물이다.

GitHub는 `gh` CLI만 쓴다. MCP 도구는 쓰지 않는다. `gh`가 없거나 로그인이 안 됐으면 멈추고 그 사실만 알린다. JSON에 없는 내용은 만들지 않는다.

## 1. 기간과 범위를 고정한다

- 기간: 사용자가 말한 것을 ISO 날짜 범위로 바꾼다. "이번 주"는 이번 주 월요일 00:00 ~ 지금, "지난주"는 지난 월요일 00:00 ~ 일요일 23:59, "1주"·"7일"은 오늘 포함 최근 7일, "어제"는 어제 00:00 ~ 23:59. 로컬 타임존. 말하지 않으면 최근 7일.
- 대상: 기본은 내가 만든 것(`author` = 내 login). 사용자가 "팀 전체"나 repo 이름을 말하면 그 범위로 넓히거나 좁힌다.
- 고정한 기간과 범위를 한 줄로 되돌려 말하고 진행한다.

## 2. 수집한다

`github-daily-pulse`의 수집 스크립트를 기간만 바꿔 재사용한다.

```bash
python3 <plugin-dir>/skills/github-daily-pulse/scripts/collect_github_activity.py \
  --since <YYYY-MM-DDT00:00:00+09:00> --until <YYYY-MM-DDT23:59:59+09:00> \
  --out /tmp/github-period-pulse.json
```

스크립트는 "기간 안에 갱신된" 항목을 준다. 이 skill은 그중에서 다시 고른다.

| 분류 | 조건 |
|---|---|
| 결과 | `type=pull_request`, `state=merged`, `merged_at`이 기간 안. 또는 `type=issue`, `state=closed`, `closed_at`이 기간 안 |
| 진행 중 | `state=open` 또는 `draft`인 PR. `author`가 나이거나 `comments_since`에 내 댓글이 있는 것 |
| 막힌 것 | 진행 중 항목 중 기간 내 갱신이 댓글만이고 커밋·머지가 없는 것, 또는 댓글에 `blocked`, `대기`, `확인 필요`, `질문`이 있는 것 |
| 다음 기간 | `state=open`인 issue 중 내가 만든 것, 라벨에 `next`·`planned`·`todo`가 있는 것 |

- 기간 안에 갱신만 됐고 끝나지 않은 오래된 PR은 결과가 아니다. 진행 중으로 간다.
- `errors`에 든 repo는 문서 끝에 "못 읽은 repo"로 남긴다. 조용히 빼지 않는다.
- 현재 디렉터리가 git 저장소이고 사용자가 원하면 PR 없이 바로 push한 커밋도 `git log --author=<me> --since --until --oneline`으로 보태고 "직접 커밋"으로 표시한다. 기본은 하지 않는다.

## 3. 결과 한 줄을 뽑는다

결과 항목마다 "사용자(또는 이 코드를 쓰는 동료)에게 무엇이 달라졌나" 한 문장을 만든다. 제목을 복사하지 않는다.

1. PR body의 `# 구현` 첫 줄이 있으면 그것을 쓴다. 이 저장소의 PR 템플릿이 그 자리에 정확히 그 문장을 두게 돼 있다.
2. 없으면 body와 댓글에서 결과를 뽑는다. body가 비어 있으면 제목을 쓰고 `(본문 없음)`을 붙인다.
3. 같은 주제의 PR·issue 여러 개는 한 줄로 합치고 링크를 나열한다. 회의에서는 "PR 5개"가 아니라 "결과 하나"로 말한다.

## 4. 문서

한글 개조식. 헤더 이름을 바꾸거나 절을 추가하지 않는다. 회의에서 위에서부터 읽는 순서다.

```markdown
## 기간
2026-09-13 ~ 2026-09-19 (KST) · repo 12개 검사 · 내 항목 23개

## 결과
1. <사용자에게 달라진 것 한 줄> — owner/repo#12, owner/repo#15 (merged PR)
2. ...

## 진행 중
- [open PR owner/repo#20] <무엇을 하는 중인지, 남은 것>
- [draft PR owner/repo#21] ...

## 막힌 것
- owner/repo#20 · <무엇이 막혔고 누구의 답이 필요한지>

## 다음 기간
- owner/repo#30 (open issue) · <무엇을 할 예정인지>

## 수치
merged PR 7 · closed issue 3 · open PR 2 · 못 읽은 repo 1 (owner/private-repo, 권한)
```

작성 원칙:

- **결과**는 3~7개. 넘으면 주제로 더 묶는다. 순서는 회의에서 먼저 말할 것부터. 사용자에게 보이는 변화, 되돌리기 어려운 변화, 다른 팀이 영향받는 변화가 앞이다.
- **진행 중**은 상태 태그를 앞에 둔다. `[open PR]`, `[draft PR]`, `[리뷰 대기]`, `[CI 실패]`. 태그는 JSON의 `state`와 댓글에서만 정한다.
- **막힌 것**은 없으면 "없음"이라고 쓴다. 절을 지우지 않는다. 회의에서 "막힌 것 없음"도 정보다.
- **다음 기간**은 issue에 근거가 있는 것만. 없으면 "issue에 등록된 계획 없음".
- **수치**는 한 줄. 문서 어디에도 수치 표를 만들지 않는다.
- 다른 사람이 만든 항목을 넣을 때는 링크 옆에 `(by login)`.
- 추측을 사실처럼 쓰지 않는다. 결과 한 줄의 근거가 body에 없으면 `(본문 없음)`으로 표시한다.

## 5. 전달

기본은 대화창에 문서 전체를 보이고 `~/github-period-pulse/<since>_<until>.md`로 저장한다. 사용자가 방식을 말하면 그것만 한다.

- `md 파일`: 경로를 줬으면 그 경로.
- `Gmail`, `Apple Notes`, `Google Docs`: `github-daily-pulse`의 3단계 전달 절차를 그대로 따른다. 제목은 `[github-period-pulse] <since> ~ <until>`.

마지막 줄에 전달 결과를 한 줄로 적는다. 실패 원인은 한 줄로만.

## 6. 응답

대화창에는 4단계 문서 전체, 그 아래 전달 결과 한 줄. 회의 직전에 다시 볼 때 문서만 복사하면 되게 다른 말을 붙이지 않는다.
