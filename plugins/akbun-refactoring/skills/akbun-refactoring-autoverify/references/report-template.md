`SKILL.md` 6절이 정한 순서다. 섹션 순서를 바꾸지 않고, `사람이 판단할 것`은 항목이 없어도 `없음`으로 남긴다.

## 형식

아래 Markdown을 채널에 맞게 그대로 쓴다. `github-pr`은 `## 사람이 판단할 것`부터 PR body 끝에 붙이고, `github-issue`는 전체를 코멘트 하나로 쓴다.

```markdown
채널: stdout(기본값) · 범위: `src/order/`, `docs/order.md` · 변경 단위 12 · 사람 항목 3

## 사람이 판단할 것

### 1. `src/order/service.py:88` 반환 형식을 dict에서 dataclass로 변경
- 왜 사람인가: 동작·인터페이스 변경. 호출부 4곳은 고쳤지만 외부 패키지 사용 여부를 알 수 없음
- 권장: 유지. 되돌리려면 이 단위만 revert
- 확인 방법: `grep -rn "create_order(" --include=*.py` 로 저장소 밖 호출 여부 확인

### 2. `docs/order.md` "재시도 정책" 절의 재시도 횟수 3 → 5
- 왜 사람인가: 문서 의미 변경. 코드(`retry.py:12`)는 5인데 문서가 3이었음. 코드에 맞춤
- 권장: 문서를 코드에 맞춘 현재 상태 유지
- 확인 방법: `retry.py:12` 상수와 대조

### 3. `mypy src/order` 기준선 실패 2건
- 왜 사람인가: 기준선 실패. 변경 전부터 실패, 이 작업에서 고치지 않음
- 권장: 별도 작업으로 분리
- 확인 방법: `mypy src/order` 출력 첫 2줄
```

## 작성 규칙

- 사람 항목은 영향이 큰 순서로 번호를 붙인다. 동작·인터페이스 변경, 삭제, 보안·권한·비밀이 앞에 온다.
- 검증 통과 변경은 개별로 나열하지 않는다. 목록이 필요하면 `git diff --stat`로 대신한다.
- 명령 출력은 핵심 줄만 인용한다. 전체 로그를 붙이지 않는다.
- 첫 줄의 채널 표기는 실제로 전달된 채널이다. GitHub 채널에서 `stdout`으로 내려갔으면 `채널: stdout(github-pr 요청, gh 없음)`처럼 이유를 함께 적는다.
