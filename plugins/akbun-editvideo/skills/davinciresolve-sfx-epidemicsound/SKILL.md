# davinciresolve-sfx-epidemicsound

이 skill은 효과음뿐 아니라 음악이 이야기의 흐름을 만드는 **사운드 디자인의 공통 기준**이다. 촬영된 소리, 공간을 잇는 소리, 강조하는 소리, 음악을 함께 설계한다. 장면의 감정과 전달할 정보가 먼저이며, 소리의 개수나 트랙 수를 채우지 않는다. 풍경·사물·동작을 중심으로 판단하고 얼굴이나 대화가 있다고 가정하지 않는다.

배경음악만 요청한 `davinciresolve-bgm-epidemicsound`도 이 문서의 필요한 절을 읽는다. 하위 문서를 읽어 실행하며 Skill 도구의 자동 호출 여부에 의존하지 않는다.

## 1. 범위와 작업본 확보

1. 요청한 타임라인·구간, 말소리 유무, 핵심 현장음, 원하는 분위기와 유지할 음악을 읽는다. 효과음만 요청하면 BGM 교체까지 넓히지 않는다. 후보 검색·계획만이면 타임라인을 수정하지 않는다.
2. **오디오 편집 전에 현재 선택한 타임라인을 반드시 복제**한다. 전체 여행 workflow의 작업본 B여도 오디오 작업 직전 상태를 보존하는 별도 복제본을 만든다. 이름은 `<원본명>_sound_<YYYYMMDD_HHMMSS>`로 하며 중복이면 suffix를 붙인다. `DuplicateTimeline()` 반환, 서로 다른 고유 ID, 길이·fps·트랙·클립·마커·기존 오디오 처리의 보존을 확인하고 `SetCurrentTimeline()` 후 활성 ID를 재확인한다. 실패하면 원본에서 편집하지 않는다.
3. 원본/작업본 ID와 이름을 작업 로그에 남긴다. 같은 오디오 작업을 중단 후 재개할 때는 로그의 작업본 ID·기준 원본을 검증해 이어간다. 후속 자막·렌더 단계에도 이 작업본을 전달해 옛 B를 출력하지 않게 한다.
4. 오디오 단독 요청에서는 시간순 타임라인 재생성·컷 순서·영상 길이 변경을 하지 않는다. 음악에 맞추기 위한 화면 재편집은 제안으로 남긴다. 복제해도 공유되는 소스 파일·미디어 풀 속성·프로젝트 설정은 건드리지 않고 타임라인의 클립·트랙·버스에 적용한다.

## 2. AI Assistant와 Epidemic Sound 경로

2026.9 Resolve AI Assistant를 기준으로 하되 설치된 버전·노출된 도구를 확인한다. Resolve를 조작하는 AI Assistant와 Epidemic Sound의 검색 Assistant/MCP는 역할이 다르다. 자연어 요청만으로 편집 기능이 모두 제공된다고 가정하지 않는다.

| 경로 | 확인과 실행 |
|---|---|
| Resolve Workflow Integration | `Workspace → Workflow Integrations → Epidemic Sound`에서 로그인·검색·미리듣기·다운로드 또는 타임라인 삽입을 확인한다. 플러그인의 선택 타임라인·트랙을 확인하고 삽입 결과를 다시 읽는다. |
| Epidemic Sound MCP | 연결된 서버의 실제 도구 목록·스키마·인증 상태를 읽는다. 음악/SFX 검색, 미리듣기, 다운로드, 가능한 스템·길이 조정 기능을 사용한다. 이름·반환값·지원 스템을 추측하지 않는다. 다운로드와 Resolve 미디어 풀 import·배치는 별개다. |
| 한 경로 사용 불가 | 사용 가능한 다른 경로로 이어간다. 둘 다 불가하면 기존 보유 음원으로 가능한 작업과 검색 큐시트를 준비하고, 필요한 연결만 안내한다. |
| Resolve 조작 | 연결된 Resolve MCP/API 문서를 확인한다. 21.1 문서에는 타임라인 복제·마커와 클립 `AudioVolume`, `AudioPan`, `AudioPitchSemiTones` 속성이 있다. 개별 속성·단위·범위와 활성 상태를 확인하고 적용 후 다시 읽는다. 페이드·시간별 자동화·EQ·리버브·버스 처리는 실제 지원 API가 없으면 Fairlight UI로 한다. UI도 불가하면 정확한 TC·트랙·값의 미적용 항목을 마커와 로그에 남긴다. |

유료 계정으로 편집을 요청한 범위의 검색·미리듣기·구독에 포함된 다운로드는 진행하며 매 파일마다 재승인을 요구하지 않는다. 추가 결제나 새 권한이 필요할 때만 해당 사항을 확인한다. 자산 ID·곡명·아티스트·출처 URL·사용 구간을 남기고, 계정 화면에서 확인 가능한 사용 범위를 기록한다. 음원 메타데이터만으로 새 라이선스 권한을 단정하지 않는다.

분석용 영상·전사와 실제 편집 음원을 구분한다. 참고 자료는 `Downloads/`의 작업 디렉터리에 두고, 프로젝트가 계속 참조할 음원은 `<출력 폴더>/audio-assets/` 등 유지할 위치에 저장한 뒤 import한다. 사용자가 임시 분석 폴더를 지워도 미디어가 오프라인이 되지 않아야 한다.

공식 연결 정보와 영상별 채택 근거는 [references/sound-design-reference.md](references/sound-design-reference.md)를 읽는다. 광고의 상품·팩·할인·채널 추천은 제작 조건으로 옮기지 않는다. 다른 편집기의 메뉴·프리셋 이름도 Resolve 기능으로 바꾸어 적용한다.

## 3. 소리의 역할과 큐시트

대표 구간의 기존 오디오를 먼저 듣고 이야기 비트·장면·`CHAPTER`·`GFX`를 함께 읽는다. 매 비트에 감정 변화(예: 집중→막힘→깨달음), 주인공 소리, 의도한 여백을 적는다. **음악은 기획 때 일찍 고민하되, 진단할 때 잠시 뮤트해 말·현장음만으로도 장면이 이어지는지 확인**한다. 원본 음악을 삭제하지 않는다.

| 역할 | 판단 기준과 출발점 |
|---|---|
| VOICE / LOCATION | devtalk는 내레이션의 이해, 여행은 그 장면을 설명하는 파도·발걸음·생활음 등이 기준이다. 쓸 만한 녹음은 살리고 과도한 잡음만 복제본에서 처리한다. |
| ROOM TONE / AMBIENCE | 음성 컷의 바닥 소음과 장소의 연속성을 잇는다. 실내·실외, 거리, 시간대에 맞추고 디지털 무음으로 생긴 구멍과 의도한 정적을 구분한다. |
| 동작 SFX / Foley | 타이핑·문·발걸음 등 화면 동작을 보완한다. 원음으로 충분하면 추가하지 않는다. Foley는 동작에 맞춰 직접 녹음하는 방식이며 모든 라이브러리 효과음의 동의어가 아니다. |
| 창작 SFX | whoosh·impact·riser·그래픽 악센트로 변화·기대·해소를 표현한다. 실제 현장에서 녹음된 소리처럼 기록하지 않는다. |
| TONAL / MUSIC | pad·drone·tonal hit·BGM·스템으로 분위기와 에너지를 조절한다. 음악이 전면에 나오는 구간과 말 뒤로 물러나는 구간을 구분한다. |
| 여백 | 설명·회고·장면 전환에서 음악이나 강조음을 빼는 것도 선택이다. 모든 컷·키워드에 소리를 붙이지 않는다. |

큐시트: `cue ID | 작업본 ID | 시작~끝 TC | 장면/비트·앵커 ID | 의도 | 역할 | 자산·source in/out | 처리·전환 | 검토 이유`를 기록한다. 검색은 `동작/재질/공간 + 음색/거리/속도`로 좁힌다. 예: `keyboard soft`, `room tone quiet`, `city distant`, `wood impact short`. 맞는 소리가 없으면 저역의 무게·중역의 재질·고역의 움직임으로 나누어 찾는다.

후보는 대표 구간에 맞춰 미리듣고 충분히 다른 대안이 있을 때 비교한다. 3–5개는 검색 출발점일 뿐 의무 수량이 아니다. 일관성은 같은 팩 사용 여부보다 음색·잔향·밀도와 이야기 역할로 판단한다.

## 4. 트랙과 배치

기존 트랙의 이름·내용·링크·뮤트·게인·버스 라우팅부터 조사하고 역할→실제 인덱스 맵을 만든다. 여행 A1 LOCATION/A2 AMBIENCE, devtalk A1 VOICE/A2 LOCATION, A3 SFX/A4 MUSIC은 새 타임라인의 시작 예시다. 기존 A3에 다른 소리가 있으면 덮어쓰거나 이름을 강제로 바꾸지 않는다.

필요하면 빈 트랙에 `SFX_DETAIL`, `SFX_TRANSITION`, `TONAL`, `MUSIC_A`, `MUSIC_B`, `MUSIC_STEM_<역할>`을 추가한다. 스템·크로스페이드는 겹치는 구간을 별도 트랙에 두어 독립 조정할 수 있게 한다. 삽입은 실제 빈 트랙 인덱스와 절대 timeline frame을 확인하고, 음악·SFX의 채널 수와 라우팅을 보존한다.

- **동작 싱크:** 파일 시작이 아닌 들리는 transient를 실제 동작에 맞춘다. 1프레임 단위로 먼저 맞추고 필요하면 Fairlight의 더 세밀한 오디오 편집으로 조정한다. 거리나 의도된 선행음 때문에 어긋나면 이유를 기록한다.
- **레이어링:** 각 소리의 주파수·attack·body·tail 역할이 달라야 한다. 겹칠수록 좋은 것이 아니므로 솔로/전체/레이어 뮤트 비교로 중복을 덜어낸다. 같은 샘플을 복제한 단순 음량 증가를 새 질감으로 착각하지 않는다.
- **공간:** 패닝은 화면 움직임과 청취 관점에 맞추고 과장하지 않는다. EQ·잔향·레벨로 근거리/원거리와 실내/실외를 표현한다. 모노에서 중요한 소리가 사라지지 않는지 확인한다.
- **연결:** J-cut으로 다음 환경음을 먼저 들려주거나 L-cut으로 이전 여운을 남긴다. 현실적인 공간 전환인지 감정적 연결인지 기록한다. 화면 밖 소리도 공간상 타당하면 가능하되 실제 장소·사건과 다른 창작적 연결은 검토 대상으로 남긴다. 컷마다 같은 길이의 전환을 강제하지 않는다.
- **밀도:** 분당 개수·파일 종류 수·반복 횟수를 고정하지 않는다. 말 가림, 피로, 반복의 의도, 장면의 변화가 판단 기준이다. 동작음은 말 도중에도 가능하되 강조음이 핵심 단어를 덮으면 위치·음색·레벨을 바꾼다.

## 5. 여러 BGM과 음악 효과

음악은 비트별로 목적을 정한다. 한 곡, 여러 곡, 같은 곡의 다른 구간·스템, 무음 중 필요한 조합을 고른다. 전곡 길이를 채우거나 모든 비트마다 곡을 바꿀 의무는 없다. 유지할 곡을 먼저 존중하고 새로운 곡은 선택 이유·사용 구간·전환 방법을 큐시트에 적는다.

| 상황 | 편집 방법 | 확인할 것 |
|---|---|---|
| 곡을 짧게/길게 맞춤 | phrase·마디·강박을 듣고 구조가 대응하는 구간을 잘라 연결한다. 공식 길이 조정 기능이 있으면 후보로 사용하고 결과를 검청한다. | 박 누락·중복, 끊긴 멜로디, 반복 루프의 접합부. 모든 곡을 time-stretch하지 않음 |
| 말할 공간이 필요함 | 드럼·멜로디 스템을 줄이거나 BGM을 phrase 끝에서 빼고 room tone·pad·drone으로 여백을 유지한다. 무음도 가능하다. | 말이 묻히지 않는지, 과도한 긴장 유도가 아닌지 |
| 음악을 멈췄다 재진입 | 끝 음의 reverb tail을 보존하고 필요하면 호환 tonal layer로 이어간다. reverse swell/riser의 도착점을 다음 강박·장면 변화에 맞춘다. | tail이 잘리지 않는지, 중복 attack·너무 큰 재진입이 없는지 |
| 곡 A→곡 B | phrase 끝·감정 변화에서 바꾸고 호환하면 crossfade, 충돌하면 짧은 tail→환경음/여백→새 곡으로 연결한다. | BPM·박자·조성·코드·음색·실제 청감의 적합성. 2초 crossfade를 일괄 적용하지 않음 |
| 기존 곡을 보강 | 필요한 스템·tonal hit·pad를 별도 트랙에 추가한다. 같은 source in/out·정렬로 스템을 맞춘다. | full mix와 동일 스템을 그대로 중복 재생해 이중 증폭하지 않는지 |
| 점진적 고조·마무리 | 레이어·대역·밀도를 점진적으로 늘리거나 덜어내고, 음악적 종지·잔향·정적 중 장면에 맞는 끝을 고른다. | 화면 감정보다 과장되지 않는지, 최종 렌더 범위 안에 여운이 있는지 |

Tonal sound는 음높이가 있는 효과음이다. 곡의 key뿐 아니라 실제 겹치는 구간의 코드·장단조·음정·리듬도 확인한다. 같은 key라고 자동으로 어울리지는 않는다. key 메타데이터나 분석은 후보 판정이며 실제 겹쳐 들어야 한다. 불명확하면 비조성 효과음·환경음·무음 전환을 쓰거나 `AUDIO_REVIEW tonal`로 남긴다. 피치 조정과 AI stem 분리가 필요하면 워블·보컬 잔재·attack 손상을 확인한다. 원래 제공된 스템이 있으면 우선 검토한다. 튜토리얼에 등장한 상용 곡을 가져오는 것은 편집 원리 분석과 별개다. 실제 편집에는 사용자가 제공한 사용 가능한 자산이나 계정 범위 안의 Epidemic Sound 음원을 쓴다.

Reverse·reverb tail은 원본 파일을 덮어쓰지 않고 복제된 오디오 클립/파생 파일로 만든다. Fairlight에서 잔향이 이어질 버스·빈 길이 또는 별도 tail 클립을 확보하고 실제 렌더 프리뷰로 확인한다. 다른 편집기의 freeze/nest나 특정 상용 프리셋을 그대로 전제하지 않는다.

## 6. 믹싱과 검청

페이더 값 차이는 소스의 실제 음량 차이가 아니다. 고정 `A1 대비 -6/-12 dB` 대신 대표 구간에서 주인공 소리를 정하고 클립 게인→EQ/필요한 dynamics→시간별 automation/ducking→버스 순으로 확인한다. 대사 중심이면 작은 볼륨에서도 말이 이해되어야 하고, 말 없는 음악 몽타주는 음악이 앞에 나와도 된다.

- 음악/SFX의 충돌 대역을 필요한 만큼 줄여 말이 자리 잡게 한다. de-esser는 튜토리얼의 한 방법이며 필수가 아니다. Fairlight EQ·사용 가능한 dynamic EQ/sidechain 또는 볼륨 자동화를 선택한다. 덕킹의 진입·복귀를 문장과 호흡에 맞춰 펌핑을 피한다.
- 리버브는 거리·공간과 음악적 여운을 위해 쓴다. 저역 중첩, 지나치게 긴 tail, 역재생의 날카로운 peak는 전체 믹스에서 다시 확인한다. 최종 버스를 낮춰도 앞단에서 이미 발생한 클리핑은 복구되지 않는다.
- 페이드/크로스페이드 길이는 attack·박·잔향에 맞춘다. 동상 신호의 constant-power 전환은 가운데가 커질 수 있으므로 곡선과 gain을 검청한다.
- 대표 구간을 음악 없이, SFX 없이, 전체 믹스로 비교하고 처리 전후의 청취 음량도 맞춘다. 한 레이어의 유무가 장면에 기여하지 않으면 덜어낸다.
- 전체 믹스의 말 가림·갑작스런 점프·클릭·위상 상쇄·의도하지 않은 무음·미디어 누락을 확인한다. 헤드폰·작은 스피커/모노에서 비교하고 듣지 못한 환경은 검증했다고 쓰지 않는다.

## 7. 사용자 검토 마커

[workflow 마커 등록표](../akbun-davinciresolve-workflow/SKILL.md#마커-등록표)의 Sand `AUDIO_REVIEW <cue ID> <사유>` 타임라인 마커를 사용한다. 대표 사운드 선택, 곡 전환·재진입·의도된 무음, 창작적 대체음, 싱크/조성/말 가림이 불확실한 구간, 적용 못 한 효과를 표시한다. 모든 정상 효과음에 마커를 붙여 검토 목록을 채우지는 않는다.

노트에는 `정확한 시작~끝 TC / 주인공 소리와 의도 / 적용 사항 또는 미적용 / 사용자에게 들을 포인트 / 대안 / 상태(needs-review·blocked·approved)`를 적는다. `customData`에는 작업 run ID와 cue ID를 넣어 재실행 때 자기 마커만 식별한다. AI 자체 검청은 사용자 승인과 구분하고 사용자가 확인하지 않은 것을 approved로 바꾸지 않는다.

타임라인의 절대 프레임과 마커 상대 좌표를 혼동하지 않는다. `frameId = 목표 절대 프레임 - GetStartFrame()`을 쓰고 FPS·시작 TC를 기록한다. 같은 프레임에 `CHAPTER`·`GFX` 등이 있으면 기존 마커를 지우지 않고 해당 구간 안 가장 가까운 빈 프레임을 쓴다. 노트에는 원래 목표 TC를 유지한다. 빈 프레임이 없거나 마커 추가에 실패하면 TC를 로그 `확인 필요`에 남기고 누락 사실을 보고한다. 추가 후 `GetMarkers()`로 읽어 확인한다.

## 8. 컷 변경과 인계

컷이 바뀌면 `파일/소스 ID | 이전·새 시작 TC | source in/out | 길이·속도 변화`를 받아 cue ID의 장면·동작 앵커를 다시 찾는다. 링크된 원음이 함께 움직였는지 확인하고, 수동 이동은 이동하지 않은 클립에만 적용한다. 삭제된 앵커의 소리는 제거 후보로 표시한다. 음악처럼 여러 샷을 가로지르는 cue는 샷 이동량을 일괄 적용하지 않고 비트 구간·음악 phrase를 다시 편집한다. retime은 들리는 동작을 다시 맞춘다.

관련 페이드·덕킹 자동화·tail·`AUDIO_REVIEW` 타임라인 마커도 새 위치에서 검청한다. 컷을 따라 마커가 자동 이동했다고 가정하지 않는다. 재편집 범위만 갱신하고 승인한 다른 cue를 중복 삽입하지 않는다.

마지막에 아래를 남긴다.

- 원본·작업본 이름/ID, 실제 역할→트랙 맵, 사용 자산과 source in/out·출처, 변경 큐시트
- 적용한 gain·EQ·ducking·음악 전환과 의도, 계측·검청한 범위, 실패·미적용 항목
- 사용자가 순서대로 들을 `AUDIO_REVIEW` TC 목록과 원본 비교 방법
- 후속 작업에 전달할 작업본 ID와 `검토용 초안 / 검청 완료 / 사용자 검토 대기` 상태. 미적용 작업을 완료로 보고하지 않음

이 skill만 호출한 경우 복제본과 검토 목록까지 전달한다. 렌더를 요청한 경우 `davinciresolve-export-youtube`의 기본 프리셋 출력으로 이어간다.
