# akbun-davinciresolve-explainer-night-gouache

## 목적

얼굴 없는 내레이션 설명 영상을 이 스타일로 만든다. 화면은 장면이 바뀌어도 같은 어두운 배경이고, 그 위에서 그림이 말하는 순서대로 하나씩 튀어나온다. 움직임은 짧고 탄력 있게 끝난 뒤 멈춘다. 후광은 꼭 강조할 대상에만 쓰고, 핵심 순간에는 그 대상으로 0.2초 만에 확대(펀치 인)한다. 화면 글자는 아래 자막, 작은 키워드 태그, 말풍선·생각 구름 안 짧은 글자뿐이다.

결과물은 Resolve에서 고칠 수 있는 타임라인이다.

## 범위

- 사용자가 직접 호출할 때 실행한다.
- 그림은 [akbun-draw-night-gouache](../../../akbun-draw/skills/akbun-draw-night-gouache/SKILL.md)로 만든다. 이 스킬은 Fusion 도형으로 그림을 다시 그리지 않는다. 그림·태그 글자를 고치려면 그 스킬의 SVG를 고쳐 레이어를 다시 렌더한다.
- 장면 클립 구조(Fusion 클립 + Template 매크로, `Timing` 노드, 표현식 애니메이션, 제너레이터 길이 조정, 크로스 디졸브·마커 API)는 [akbun-davinciresolve-explainer](../akbun-davinciresolve-explainer/SKILL.md)의 "Resolve 구현"을 따른다. 이 문서는 그 스킬의 "스타일"과 장면 전환 규칙을 대신한다.
- 녹음 정리는 [akbun-davinciresolve-narration-cleanup](../akbun-davinciresolve-narration-cleanup/SKILL.md)을 부른다.

## 스타일

### 캔버스

- 1920×1080. fps는 대상 프로젝트 값, 기준이 없으면 24fps.
- 배경은 모든 장면이 같은 `background.png`(draw 스킬이 레이어 폴더에 만든 어두운 비네트+입자)다. 장면 사이에 배경이 바뀌지 않아야 장면이 바뀌어도 한 화면처럼 이어진다. 데이터 장면만 종이 배경이다. 사용자가 단색 배경을 정하면(예: dark-diagram의 `#202020`) 데이터 장면을 뺀 모든 장면 SVG에 `data-bg="flat:#202020"`을 주고 다시 렌더한다(데이터 장면은 종이 배경 그대로).
- 격자·도트 같은 무늬 배경을 깔지 않는다.

### 자막

- 자막 트랙(이름 `자막`)에 문장 하나 = 자막 하나로 넣는다. 화면에 굽거나 Text+로 그리지 않는다.
- 글꼴·위치는 API로 바꿀 수 없다. 기본값은 Inspector → Track 탭의 Font `Pretendard`, Face `Medium`, Color 흰색, 배경·외곽선 끄기, Size `42`, Position Y `130`이고(데이터 장면이 있으면 Drop Shadow 불투명도 60%), 글자 기준선이 y 950 근처(아래에서 약 12%)에 오는지 뷰어로 확인한다. 값을 넣는 방법은 둘이다.
  1. 같은 값이 이미 설정된 타임라인을 `DuplicateTimeline`으로 복제한다. 트랙 스타일은 복제본에 남고, 자막·영상 클립을 지우고 다시 채워도 남는다.
  2. 화면 조작이 허용되면 Edit 페이지에서 자막 클립 선택 → Track 탭 → 값 더블클릭 → cmd+a → 값 입력 → return → 다른 곳 클릭 → 값을 확대 캡처로 확인한다. 사용자가 키보드를 쓰는 중이면 입력이 무시될 수 있으니 확인이 안 되면 1번으로 돌아간다. 둘 다 못 하면 사용자에게 값을 넘긴다.
- 한 자막은 한 줄 공백 포함 24자 이하, 화면에 1.2초 이상 남는다. 함수 이름처럼 나눌 수 없는 토큰 때문에 넘으면 그대로 두고 완료 보고에 목록으로 적는다.

### 키워드 태그

- draw 스킬이 만든 `tag` 레이어 PNG를 쓴다. 등장 방식은 팝이다. 사용자가 태그 왼쪽 위 노란 점을 빼 달라고 하면SVG 루트에 `data-tag-dot="off"`를 준다.
- 태그는 그 용어를 처음 말할 때 한 번만 나온다.

### 모션

움직임은 아래 표의 6가지뿐이다. 끝나면 장면이 끝날 때까지 정지한다. 장면 전체가 천천히 확대·이동하는 효과는 쓰지 않는다.

| 이름 | 쓰는 대상 | 움직임 |
|---|---|---|
| 팝 | 사물·인물(막대 인물 포함)·말풍선·생각 구름·태그·✕ | 대상 중심을 기준으로 0.3초 동안 크기 0.6 → 약 1.04 → 1.0(넘쳤다 돌아옴). 처음 0.12초에 불투명 |
| 자라기 | 화살표·연결선 | 0.25초 동안 크기 0.85 → 1.0(넘침 없음), 0.2초 페이드 |
| 밀려 들어오기 | 장면 처음에 등장하는 양쪽 대상, 이동하는 대상 | 화면 밖(가까운 가장자리)에서 제자리로 0.6초, 끝으로 갈수록 느려짐(3차). 처음 0.15초 페이드 |
| 후광 맥박 | `*-halo` 레이어 | 0.3초 페이드 뒤 불투명도 0.5~1.0을 1.2초 주기로 오감 |
| 펀치 인 | 장면의 핵심 순간 한 번 | 강조 대상 중심을 기준으로 0.2초 동안 화면 전체 1.0 → 1.4~1.8배. 그 뒤 장면 끝까지 유지 |
| 사라지기 | 다음 설명에 필요 없는 대상 | 0.2초 페이드 아웃. 장면 중간에만 쓴다 |

- 등장 순서와 시점은 내레이션이 그 대상을 말하는 순서·위치다. 동시에 시작하는 요소는 둘 이하(대상과 그 후광, 양쪽에서 밀려 들어오는 두 대상)이고, 다음 요소는 앞 요소 시작 0.3초 이후에 시작한다.
- 후광은 기본으로 쓰지 않는다. 화면의 여러 대상 중 하나를 짚어야 하거나 경고·결론이 처음 나올 때만 그 대상에 하나 두고, 대상과 같은 시점에 시작한다. 팝과 자막만으로 무엇을 말하는지 보이면 넣지 않는다. 사용자가 후광을 끄면 SVG에 `url(#glow)`·`url(#halo-*)`를 쓰지 않고 강조는 펀치 인과 색 대비만 쓴다.
- 펀치 인은 장면당 한 번까지, 마지막 등장 뒤 장면 끝 쪽에서 한다. 펀치 인 뒤 1.0초 이상 머문 다음 확대 없는 화면으로 시작하는 다음 장면으로 하드 컷하면 "줌인 → 줌아웃"처럼 보인다. 이 구성을 기본으로 쓴다.
- 장면 전환은 하드 컷이다. 같은 소재를 이어 설명하는 장면은 앞 장면 마지막 화면의 레이어를 새 장면 0초에 이미 보이게(등장 시점 `-1`) 두고 새 레이어만 등장시킨다.
- 다른 explainer 스타일(예: dark-diagram의 7프레임 디졸브)과 섞어 달라는 요청이면 장면마다 스타일 하나만 쓰고, 전환은 하드 컷, 배경은 한 색으로 통일한다.
- 장면 중간에 상태가 바뀌는 대상(예: 사용 중 → 해제됨)은 draw 스킬에서 같은 자리의 `*-live`·`*-freed` 두 레이어로 받는다. 바뀌는 시점에 `*-live`는 사라지기, `*-freed`는 같은 시점에 0.2초 페이드 인해 교차한다. 대상이 그냥 없어지면 레이어 하나에 사라지기만 쓴다.

### 데이터 장면

- 종이 배경 레이어 위에 `axes`(0.3초 페이드) → `points`(왼쪽에서 오른쪽으로 1.5초 동안 드러남) → `trend`(1.0초 동안 드러남) → `band`(0.3초 페이드) → `labels`(팝) 순서. 드러남은 레이어에 RectangleMask를 걸고 마스크 폭을 표현식으로 0 → 1로 늘린다.
- 펀치 인 대상은 `band`(1.4배)다.

## Fusion 구성

장면 클립 하나의 노드 구성이다. 노드 이름은 기본 Explainer 규칙(한글 종류 접두사, 밑줄)을 따른다.

| 노드 | 이름 | 연결 |
|---|---|---|
| Loader | `배경` | `background.png` → MultiMerge Background |
| Loader | `그림_<레이어>` | 레이어 PNG(화면 전체 크기) |
| Transform | `등장_<레이어>` | Loader → MultiMerge `Layer{n}.Foreground`. Pivot = `layers.json`의 `pivot` |
| MultiMerge | `레이어_합성` | 레이어 순서 = `layers.json` 순서(아래부터) |
| Transform | `레이어_목록` | MultiMerge → MediaOut. 펀치 인을 맡는다 |
| Background | `Timing` | 화면에 연결하지 않는다. `At{n}`(등장 시점 초), `PunchAt`, `PunchZoom`, `On{n}` 컨트롤을 둔다 |

- 레이어 PNG가 화면 전체 크기라서 Loader·Transform에 위치를 넣지 않는다. 크기 변화의 중심만 Pivot으로 준다.
- 도형·점선·그라데이션·반투명 면은 Fusion 노드로 그리지 않고 draw 스킬 레이어 PNG로 받는다. Fusion은 움직임만 맡는다. 기본 Explainer의 sRectangle·sDuplicate 화살표 방식 대신 이 규칙을 쓴다. 노드로 그리면 노드 수가 폭발하고, Background의 `TopLeftAlpha`만 낮춰서는 RectangleMask를 씌운 면이 불투명으로 나온다(Resolve 21.1.1 실측).
- comp 텍스트의 Loader는 `Clip = Input { Value = "..." }`로 쓰면 Media Offline이 된다. Resolve가 내보낸 형식대로 쓴다.

```lua
Loader { Clips = { Clip { ID = "Clip1", Filename = "<png 경로>", FormatID = "PNGFormat", StartFrame = -1, LengthSetManually = true, TrimIn = 0, TrimOut = 0, ExtendFirst = 0, ExtendLast = <프레임수>, Loop = 0, AspectMode = 0, Depth = 0, TimeCode = 0, GlobalStart = 0, GlobalEnd = <프레임수-1> } }, Inputs = { ["Clip1.PNGFormat.PostMultiply"] = Input { Value = 1, } } }
```

- 점선 화살표가 그려지는 모션은 그 Loader의 EffectMask에 RectangleMask를 걸고 Width·Center를 표현식으로 0 → 1로 키운다. 등장 시점과 사라지는 시점은 `Timing`의 다른 컨트롤(`At{n}`, `Until{n}`)로 둔다.
- Text+는 왼쪽 정렬이어도 Center가 글자 상자 가운데 기준이다. 왼쪽을 맞추려면 글자 폭을 추정해 Center를 옮긴다. 폭(Size = px/1920 기준 실측): 한글 ≈ 0.95 × 크기, 영문 ≈ 0.58 × 크기, Menlo 1자 ≈ 0.4104 × 크기.

표현식은 아래 식을 그대로 쓴다. `A` = `(time - (comp.RenderStart + Timing.At{n} * fps))`, `q(d)` = `min(1, max(0, A / (d * fps)))`, `fps`는 숫자로 넣는다.

| 모션 | 입력 | 식 |
|---|---|---|
| 팝 | `등장_*.Size` | `0.6 + 0.4 * (1 + 2.70158*(q-1)^3 + 1.70158*(q-1)^2)`, q = `q(0.3)` |
| 팝 | `Layer{n}.Blend` | `Timing.On{n} * q(0.12)` |
| 자라기 | `등장_*.Size` / `Blend` | `0.85 + 0.15*(1-(1-q)^2)`, q = `q(0.25)` / `q(0.2)` |
| 밀려 들어오기 | `등장_*.Center` / `Blend` | `Point(0.5 + D*(1-q)^3, 0.5)`, q = `q(0.6)` / `q(0.15)`. 왼쪽에서 오면 `D = -(bbox 오른쪽 x / 1920 + 0.02)`, 오른쪽에서 오면 `D = (1920 - bbox 왼쪽 x) / 1920 + 0.02` |
| 후광 맥박 | `Layer{n}.Blend` | `q(0.3) * (0.75 + 0.25*cos(2*3.14159*A/(1.2*fps)))` |
| 펀치 인 | `레이어_목록.Size` | `1 + (Timing.PunchZoom-1) * (1-(1-p)^3)`, p = 펀치 인 시점 기준 `q(0.2)`. Pivot = 아래 "펀치 인 배율"의 묶음 중심 |
| 사라지기 | `Layer{n}.Blend` | 등장 식 × `(1 - q(0.2))`, q는 사라지는 시점 기준 |

펀치 인 배율은 확대 뒤에도 강조 대상과 그 태그·후광이 화면 안에 남는 값으로 정한다.

- 묶음 = 강조 대상·태그·후광 레이어 bbox를 합친 사각형 `(x0, y0, x1, y1)`(px). 묶음 중심 `(cx, cy)`를 Pivot으로 쓴다(Fusion 좌표 `cx/1920`, `1 - cy/1080`).
- 최대 배율 = `min(cx/(cx-x0+40), (1920-cx)/(x1-cx+40), cy/(cy-y0+40), (1080-cy)/(y1-cy+40), (860-cy)/(y1-cy))`. 마지막 항은 확대한 묶음 아래가 자막 자리(y 860)를 덮지 않게 한다(`cy`가 860 이상이면 펀치 인하지 않는다).
- `PunchZoom = min(1.8, 최대 배율)`. 1.3보다 작으면 펀치 인을 하지 않는다.

- 표의 `^`는 읽기 쉽게 쓴 것이다. Fusion 식에는 곱셈으로 풀어 쓴다(`(q-1)*(q-1)*(q-1)`). 이 형태로 Resolve 21에서 값이 맞게 나오는 것을 확인했다(팝 최대 1.038, 펀치 인 0.2초에 목표 배율).
- 시점·확대 배율 숫자는 `Timing` 컨트롤로만 바꾼다. 키프레임을 쓰지 않는다.

## 작업 흐름

1. 대본을 장면 표로 나눈다. 장면마다 자막 문장(1~3개), 레이어 목록, 레이어별 모션과 등장 시점, 후광·펀치 인 여부, 길이를 적는다. 장면 길이와 등장 시점은 기본 Explainer의 "내레이션 규칙" 식을 쓴다. 대본과 장면 표를 사용자에게 먼저 보여 주고 확인받는다.
2. 장면 표를 draw 스킬의 장면 표로 넘겨 장면마다 `--layers`로 레이어를 만든다. 후광 없는 장면은 강조를 "없음"으로 넘긴다. 같은 소재를 이어 가는 장면은 앞 장면 SVG를 복사해 레이어를 더한다.
3. Resolve 준비: 기본 Explainer의 타임라인 이름 규칙대로 새 버전 타임라인을 만든다. 트랙은 V1 장면, 자막 트랙 `자막`, A1 내레이션, A2 BGM, A3 효과음. 다른 타임라인의 한 구간을 그대로 쓰려면 그 타임라인 미디어 풀 항목으로 `AppendToTimeline([{"mediaPoolItem": 타임라인항목, "startFrame": s, "endFrame": e, "mediaType": 1}])`를 쓴다(영상만 들어오고 음성은 안 온다). 그 구간의 배경색·그림은 바뀌지 않으므로 색이나 그림을 바꿔야 하면 같은 구성을 새로 만든다.
4. 자막 srt(시각은 타임라인 시작 기준)를 미디어 풀에 가져와 빈 타임라인에 **먼저** `AppendToTimeline`으로 넣고 자막 트랙을 잠근다. 클립이 있는 타임라인에 srt를 넣으면 지정 위치와 상관없이 마지막 클립 뒤에 붙는다. 기존 타임라인 복제본을 쓸 때는 자막·영상 클립을 모두 `DeleteClips`로 지운 뒤 srt부터 넣는다.
5. 기본 Explainer의 "클립 길이 맞추기"로 제너레이터 길이를 장면 길이로 바꾼 뒤, 플레이헤드를 장면 시작 타임코드에 두고 `InsertFusionCompositionIntoTimeline()`으로 넣는다. 클립은 플레이헤드 위치에 들어가고 플레이헤드는 클립 끝으로 옮겨지므로 장면을 차례로 넣으면 이어 붙는다. 자막 트랙이 잠겨 있어야 자막이 밀리지 않는다(풀린 채 넣으면 자막 클립이 뒤로 밀린다). 플레이헤드가 자막 끝에 있으면 자막 뒤에 들어가니 매번 시작 위치를 확인한다. 끝나면 환경설정 제너레이터 길이가 원래 값인지 현재 설정을 새 프리셋으로 저장·내보내 확인한다.
6. 장면마다 "Fusion 구성"대로 노드를 만들고 표현식을 건다. 기본 Explainer의 Template 매크로로 감싸 Inspector에 그룹별 "보이기"·"등장 시점(초)"와 장면의 "펀치 인 시점"·"펀치 인 배율"을 공개한다.
7. 장면을 모두 넣은 뒤에만 자막 트랙 잠금을 풀고 `GetIsTrackLocked("subtitle", 1)`이 False인지 확인한다. 잠긴 채 넘기면 사용자가 자막을 못 고친다. `SetTrackLock`은 이미 풀린 트랙에 False를 돌려주므로 반환값으로 판단하지 않는다.
8. "자막" 절의 두 방법 중 하나로 Inspector 값을 적용한다.
9. 장면 시작 마커(대본 메모)를 단다. 장면 사이 디졸브는 넣지 않는다.
10. 검수한다. 스틸로 안 보이는 값(팝 넘침, 후광 맥박, 펀치 인 배율)은 Fusion 노드의 `GetInput(입력, 프레임)`으로 몇 프레임을 읽어 표 값과 대조한다.

## 검수

장면마다 등장 직후·펀치 인 직전·마지막 프레임을 `ExportCurrentFrameAsStill`로 뽑아 한 장으로 붙여 한 번만 본다(자막 트랙은 스틸에 나오지 않으므로 자막은 뷰어 화면으로 따로 본다). 아래 채점표로 장면마다 채점한다. 항목마다 0·5·10점, 80점 미만 장면은 고친다.

| # | 항목 | 10점 기준 |
|---|---|---|
| 1 | 배경 | 모든 장면이 같은 어두운 비네트(또는 사용자가 정한 단색) 배경, 무늬 없음 |
| 2 | 그림 | draw 스킬 레이어가 원본 그대로(번짐·잘림·크기 어긋남 없음) |
| 3 | 등장 순서 | 내레이션 순서대로 하나씩, 동시 시작 2개 이하 |
| 4 | 팝 | 사물이 중심에서 넘쳤다 돌아오며 등장(위치가 튀지 않음) |
| 5 | 화살표 | 자라기로 등장, 대상보다 늦게 |
| 6 | 후광 | 강조가 필요한 장면에만 하나, 대상과 같이 시작하고 맥박이 보임 |
| 7 | 펀치 인 | 0~1회, 강조 대상 중심으로 확대, 대상이 화면 밖으로 잘리지 않음 |
| 8 | 정지 | 등장이 끝난 뒤 화면이 멈춤(계속 흐르는 확대·이동 없음) |
| 9 | 자막·태그 | 자막 흰색 Pretendard 한 줄, 아래 약 12% 위치, 태그는 용어 첫 등장 때 한 번, 말풍선 글자는 풍선마다 하나(10자 이하) |
| 10 | 전환 | 하드 컷, 이어지는 장면은 앞 화면이 그대로 이어짐 |

- 클립·자막·마커 개수와 끝 프레임을 장면 표와 대조한다.
- Edit 페이지 Inspector에서 등장 시점 하나를 바꿔 실제로 움직임이 옮겨지는지 확인하고 되돌린다.
- 프로젝트를 저장한다.

## 완료 보고

타임라인 이름·fps·길이, 장면 시작 프레임 표, 장면 표(레이어 수·펀치 인), 장면별 채점 점수, 레이어 폴더 경로, 자막 Inspector 적용 방법, 자막 트랙 잠금 해제 확인, 24자 넘는 자막 목록, 환경설정 복원 확인 결과를 적는다. "확인한 것(스틸로 본 장면 범위)"과 "확인하지 못한 것(재생, 청취)"은 따로 적는다.

## 하지 말 것

- Fusion 도형으로 그림을 다시 그리거나, 레이어를 합친 MP4를 올리는 것.
- 장면 전체에 계속 흐르는 확대·이동, 디졸브 전환.
- 강조가 필요 없는 장면의 후광, 한 장면에 후광 둘 이상, 펀치 인 두 번 이상.
- 키프레임 애니메이션. 시점은 `Timing` 컨트롤로 고친다.
- 다른 작업이 열어 둔 Resolve 프로젝트를 확인 없이 바꾸는 것.
