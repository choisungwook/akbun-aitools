# akbun-vlog-shootplan

확정된 이야기 기획을 실제 촬영 순서와 카메라·음성·화면 준비로 바꾸는 skill이다. 이야기 중심이나 경험의 사실관계가 아직 정해지지 않았다면 먼저 `akbun-vlog-prepared-devtalk`에서 인터뷰한다. 이미 준비 문서가 있으면 그 요약·비트·공개 범위를 그대로 받아 적고 같은 질문을 반복하지 않는다. 결과물은 촬영 계획서 하나이고, 편집은 촬영 뒤 `davinciresolve-story-devtalk`이 맡는다. 계획서의 비트 시트는 `davinciresolve-beats-devtalk` 2절(스토리 비트 제안)의 초안이 된다.

전제 둘이다. 화자는 얼굴을 드러내지 않는다. 촬영은 대부분 집 안(책상·작업 공간)이다. 장비는 종류로만 부른다(카메라, 보조 카메라, 마이크, 화면 녹화). 제품명은 계획서에 쓰지 않는다.

목표는 스토리의 핵심 순간을 빠뜨리지 않고 촬영하고, 불필요한 장면은 찍지 않게 돕는 계획서다. 촬영 가능한 장소·장비를 우선하며 장비 구매를 요구하지 않는다. 답이 없는 항목은 `미정`으로 둔다.

## 스타일 선택

질문표 4번 답을 `davinciresolve-story-devtalk`의 스타일 선택 표에 넣어 style skill을 정하고 계획서에 이유를 적는다. 구조 표(비트·길이·화면)의 원본은 그 style skill의 `SKILL.md`이며 경로는 이 파일과 같은 `skills/` 아래다.

## 질문표

| # | 질문 | 계획서에서 쓰는 곳 |
|---|---|---|
| 1 | 주제를 한 문장으로? (예: "컨테이너가 VM보다 빨리 뜨는 이유") | 훅 문장, 제목 |
| 2 | 시청자가 이 영상을 보고 얻을 맥락이나 생각 한 가지는? | 훅·결론 |
| 3 | 제목·주장을 한 문장으로 한다면? | 훅·결론 초안 |
| 4 | 이 주제는 원리 설명 / 만드는 과정·일상 기록 / 회고·개인 생각 중 무엇에 가까운가? | 스타일 선택 |
| 5 | 목표 길이? 기본 5–7분, 최대 10분 미만 | 비트 길이 배분(한국어 말하기 기준 분당 약 250–300자 후 실제 낭독 시간으로 조정) |
| 6 | 실제 근거로 보여줄 자료(문서·코드·수치·화면)가 있나? 그래픽이 설명에 꼭 필요한가? | essay 자료·tool-neutral 그래픽 아이디어 |
| 7 | 카메라가 몇 대인가, 마이크가 있나, 화면 녹화가 가능한가? | 장비 배정 |
| 8 | 말소리는 찍으면서 녹음하나(손·화면을 찍으며 말함), 따로 내레이션으로 녹음하나? | 음성 방식 |

## 장비 배정

역할로 배정한다. 카메라가 1대면 카메라 열만 쓰고 보조 카메라 열의 장면은 같은 카메라로 시간을 나눠 찍는다.

| 장비 | 역할 | 설정 | 쓰는 비트 |
|---|---|---|---|
| 마이크 | 음성. 외장 마이크가 있으면 카메라·녹음기에 직결, 없으면 카메라에 가장 가까운 자리에서 말한다 | 48 kHz, 입에서 15~20 cm, 피크 -12 dB, 방 안 소음(냉장고·에어컨) 끄기 | 모든 음성 |
| 카메라 | 화면 클립 기본. 손·키보드·모니터·책상·물건. 삼각대 고정 우선 | 현재 카메라의 해상도와 타임라인 fps에 맞추고 HDR은 납품 경로에 맞춤. 얼굴·반사면 확인 | 이야기 비트에 필요한 화면만 촬영 |
| 보조 카메라(있으면) | 중요한 순간의 다른 크기/각도, 타임랩스 | 주 카메라와 같은 fps·화이트밸런스 기준을 우선 | project 변화·핵심 인서트 |
| 화면 녹화 | 코드·터미널·문서·브라우저 | 모니터 해상도 그대로, 커서 크게, 편집기 글꼴 16pt 이상, 알림 끔 | essay 자료 화면, project 화면 보여주기 |

두 카메라를 같은 장면에 쓸 때는 촬영 시작 전에 두 카메라 앞에서 손뼉을 한 번 친다. 편집 skill이 카메라 시계 오프셋을 맞추는 근거가 된다.

카메라 이동에는 장면의 이유가 있을 때만 시작점·끝점·방향을 적는다. 고정 카메라로 의미가 전달되면 이동을 추가하지 않는다. 조명은 창빛·실내 조명·가지고 있는 반사 도구처럼 현재 조건으로 계획하고, 필요하면 분위기 참고 이미지를 준비한다.

## 얼굴이 나오지 않는 프레이밍

| 프레이밍 | 방법 |
|---|---|
| 탑다운 | 카메라를 책상 위에서 아래로. 손·키보드·노트·마우스 |
| 오버 숄더 | 뒤에서 어깨 너머로 모니터. 머리는 프레임 밖 또는 뒷머리만 |
| 가슴 아래 | 정면이지만 프레임 상단을 가슴 높이에서 끊는다 |
| 물건·공간 | 모니터 빛, 커피, 책, 케이블, 빈 의자, 창가 |
| 측면 손 | 책상 옆에서 손·키보드·노트를 향해. 프레임 상단은 팔꿈치 |

촬영 뒤 클립을 한 번 재생해 얼굴이 한 프레임이라도 들어간 클립은 파일명 끝에 `_face`를 붙인다. 편집 skill은 그 클립을 소리로만 쓴다.

## 이야기와 스타일별 말하기 가이드

준비 문서가 있으면 `목표 → 실제 사건/장애 → 선택 → 결과/변화` 흐름을 유지한다. 하루나 한 주의 모든 할 일을 순서대로 나열하지 않고, 각 비트에 해당하는 핵심 순간을 촬영한다. 시청자가 화자를 모르는 상태에서 필요한 배경은 말하기 계획에 포함한다.

### essay

- 대본을 비트 시트 순서로 쓴다. 비트마다 첫 문장이 그 비트의 메시지다.
- 문장 사이 1초 쉰다. 편집에서 침묵을 자르는 지점이 된다.
- 핵심 문장은 짧고 말하기 쉽게 쓴다. 테이크를 더 녹음하도록 강요하지 않으며, 훅에서 재사용할 표현은 실제 발화 중 자연스러운 구간을 편집에서 고른다.
- 항목을 말할 때 "첫째, 둘째"를 소리로 말한다. 번호 제목이 붙는 자리다.
- 원리·트레이드오프를 말하는 문장은 "A가 B로 가면"처럼 관계를 알아듣기 쉽게 말한다. 그래픽이 필요하면 이 단계에는 전달할 관계와 정보만 적고, 제작 도구·형식은 후반에 정한다.
- 자료를 보여줄 문장은 "이 문서에서", "이 코드에서"처럼 무엇을 보여줄지 말한다.
- 한 테이크는 한 비트다. 틀리면 그 문장만 다시 말하고 계속한다. 편집이 마지막 테이크를 고른다.

### project

- 시작 전 음성: 무엇을 왜 하는지와 이번 편에서 확인할 목표 하나를 말한다. 복수 목표가 자연스러운 경우에만 목록으로 쓴다.
- 실제로 변화가 생긴 지점에서 진행을 기록한다. 보통 장애나 판단의 순간과 결과가 유용하지만, 변화가 없으면 보고를 만들지 않는다. 순서는 경험에 따라 "시작 → 막힘/선택 → 결과"로 조정한다.
- 화면을 보여줄 때는 무엇이 달라졌는지 말하면서 화면을 녹화한다. 전후 비교가 이야기에 필요하면 시작 상태를 짧게 기록한다.
- 작업 전체를 녹화하지 않는다. 작업의 전·후 차이나 의미 있는 시간 경과가 보일 때만 고정 타임랩스를 계획하고, 현재 카메라를 오래 켜 두지 않아도 찍을 수 있는 간격과 길이로 정한다.
- 마무리는 배운 것 한 줄 + 시청자에게 묻는 질문 하나.

### reflection

- 생각을 비트 시트 순서(상황 → 계기 → 생각 → 반대편/흔들림 → 결론)로 조용한 곳에서 짧은 단위로 내레이션 녹음한다. 완성 분량은 5–7분을 기준으로 한다.
- 인상적인 문장을 콜드 오픈에 재사용할 수 있지만 같은 문장을 다시 녹음하도록 강요하지 않는다.
- 자막이 모든 대사에 붙으므로 문장을 짧게 끊어 말한다(한 문장 5~7어절).
- B-roll은 말과 같은 대상을 그대로 보여줄 필요는 없지만, 비트의 맥락·행동·감정을 보태야 한다. 장식용 화면을 최소 개수에 맞춰 반복 촬영하지 않는다.

## 화면 커버리지 시작점

종류와 수량을 기계적으로 채우지 않는다. 각 장면이 스토리에 보태는 정보가 있는지 먼저 본다.

| 스타일 | 시작점 |
|---|---|
| essay | 각 근거 비트에 자료·화면 또는 그래픽 아이디어 1개. 필요한 경우에만 B-roll 추가 |
| project | 시작·결과가 달라질 때 두 화면, 변화가 보이는 과정 화면 |
| reflection | 핵심 사건·생각의 변화를 보여줄 화면 1–2개/비트 |

이 수량은 촬영 의무가 아니라 시작점이다. 이미 같은 의미를 전달하는 장면이 있으면 반복 촬영하지 않는다. 주요 순간은 와이드·행동·디테일 등 서로 다른 정보를 주는 coverage를 준비하되, 시간이 부족하면 이야기 이해에 꼭 필요한 샷을 우선한다.

## 촬영 계획서 형식

사용자가 지정한 폴더, 지정이 없으면 현재 폴더에 `shoot-plan_<YYYYMMDD>.md`로 남긴다. 준비 문서가 있으면 확정 비트·공개 범위·길이를 우선한다. 없으면 고른 style skill의 구조 표를 초안으로 쓰고, 말할 핵심·샷·장비·촬영 순서를 이 skill이 채운다.

```markdown
# 촬영 계획 <주제 한 문장>

## 스타일과 길이
essay(이유), 목표 6분, 대본 약 1,800자

## 훅·결론 문장
- 훅:
- 결론:

## 비트 시트
| # | 비트 | 말할 메시지 | 장비 | 화면(B-roll·화면 녹화·카드) | 길이 |
|---|---|---|---|---|---|

## 촬영 순서
| 순서 | 장소·시간 | 장비 | 프레이밍 | 찍는 것 | 확인 |
|---|---|---|---|---|---|

## 말하기 체크
- 문장 사이 1초
- 주장 문장 2번
- 번호는 소리로
- 얼굴이 들어간 클립은 `_face`
```

## 하지 않는 것

- 영상 클립 편집, 타임라인 생성. 촬영 뒤에는 `davinciresolve-story-devtalk`을 부른다
- 답이 없는 질문을 추측으로 채우기. `미정`으로 둔다
- 장비 제품명, 특정 종류의 B-roll, 외출·장소 이동 장면 요구
- 준비 문서에서 확정한 사실이나 공개 범위 변경
