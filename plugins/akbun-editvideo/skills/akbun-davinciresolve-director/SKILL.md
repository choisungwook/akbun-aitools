# akbun-davinciresolve-director

화면이 언제 바뀌고, 무엇이 움직이고, 그때 어떤 소리가 나는지를 한곳에서 정하는 skill이다. 오버레이·효과음·음악을 각각 잘 만들어도 서로 박자가 어긋나면 몰입이 깨진다. 감독은 그 박자를 정하고 확인한다. 직접 배치하지 않고 연출표를 만들어 실행 skill에 넘기며, 실행 뒤에 다시 본다.

`akbun-davinciresolve-workflow`의 기본 원칙과 마커 등록표를 따른다. 실행 skill은 모두 직접 호출 전용이므로 Skill 도구로 부르지 않고 해당 `SKILL.md`를 읽어 수행한다.

## 입력

- 편집 스타일: [explainer](../akbun-davinciresolve-style-explainer/SKILL.md) 또는 [product](../akbun-davinciresolve-style-product/SKILL.md). 없으면 주제로 고르고 이유를 적는다. 원리 설명 중심이면 기존 [essay](../davinciresolve-style-essay/SKILL.md)도 가능하다
- 대본(비트·문장) 또는 전사가 있는 작업 타임라인
- 쓸 수 있는 재료 목록: 촬영 클립(각도별), 화면 녹화, 사진, 결과물

## 연출 원칙

참고 영상 분석(각 스타일의 `references/analysis.md`)에서 나온 원칙이다. 스타일 skill의 수치가 이 원칙보다 구체적이면 스타일 값을 쓴다.

| 원칙 | 기준 |
|---|---|
| 한 순간에 움직임 하나 | 카드 등장과 본편 스냅 확대는 같은 방향의 한 동작으로 본다. 서로 다른 방향의 움직임 두 개를 동시에 두지 않는다 |
| 움직임에는 이유 | 본편은 고정이 기본. 확대는 새 정보가 들어오거나 강조할 때만 |
| 곡선 | 등장 ease-out, 퇴장 ease-in, 이어지는 이동 ease-in-out. 선형은 글자 타이핑뿐 |
| 길이 | 카드 페이드 5~6프레임, pop 6~8프레임, 스냅 확대 6프레임, 화면 녹화 확대 1.25초, 빠른 이동 5~6프레임, 히어로 push 약 5초 |
| 컷 뒤 등장 | 카드·글자는 컷 1~2프레임 뒤에 시작한다. 컷과 같은 프레임에 두 변화가 겹치면 눈이 따라가지 못한다 |
| 소리는 의미 있는 변화에만 | 챕터 경계, 결과 공개, 단계 완료, 제품 첫 등장. 컷마다 넣지 않는다. 설명형 분당 2~4개, 제품형 3~5개 |
| 소리 위치 | 들리는 어택이 화면 변화 0~4프레임 뒤. 파일 시작이 아니라 어택으로 맞춘다 |
| 음악이 물러날 곳 | 핵심 주장·주의·요약·따라 하는 단계에서 저역·드럼을 빼고, 시연·몽타주에서 되돌린다. 챕터 경계는 약 3초 전에 비우고 컷에서 다시 연다 |
| 변화 없는 구간 | 본편만 16초, 화면 녹화는 타이핑·스크롤이 없으면 8초를 넘기지 않는다 |
| 이야기의 박자 | 결과를 먼저 보여 주고, 단계마다 작은 결과를 주고, 끝에서 큰 결과를 준다. 도입의 한 컷으로 끝나는 수미상관을 고려한다 |

## 1. 연출표 만들기

대본 또는 타임라인의 비트를 읽고 아래 표를 만든다. 한 행이 한 연출 cue다. cue ID는 `D<비트 번호>-<순번>`.

```markdown
| cue | 비트 | 시작(대본 문장 또는 TC) | 길이 | 본편 샷(각도) | 본편 움직임 | 오버레이(종류·x·y·폭·등장) | 글자(종류·문구 출처) | 효과음(역할·어택 위치) | 음악 상태 | 전환 | 이유 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| D1-1 | 1 결과 먼저 | 첫 문장 | 6초 | 결과 몽타주 | 없음 | 없음 | 키워드: 대본 1문장 | 없음 | 전면 | 컷 | 약속을 화면으로 먼저 |
| D2-3 | 2 목차 | "세 가지" | 3초 | 측면 클로즈업 | 없음 | 없음 | 목록 3줄, 말할 때마다 | 없음 | 저역 줄임 | 컷 | 볼 순서를 알려 줌 |
```

- 글자 문구는 대본·전사에서만 가져온다. 대본에 없는 수치·결과를 만들지 않는다.
- 재료가 없는 cue는 `재료 필요: <무엇을 어떤 각도로>`로 남기고, 촬영 목록으로 따로 모은다.
- 연출표는 `<출력 폴더>/direction_<YYYYMMDD_HHMM>.md`에 쓴다. 사용자가 확인하기 전에는 타임라인을 바꾸지 않는다. 이 skill에서 사용자 확인을 받는 필수 지점은 여기 하나다.

## 2. 실행 넘기기

승인한 연출표를 실행 skill에 넘긴다. 각 skill의 규칙이 이 표보다 우선하며, 바꾼 값은 연출표의 `이유`에 적는다.

| 열 | 실행 skill |
|---|---|
| 오버레이, 글자, 본편 push | [akbun-davinciresolve-overlay](../akbun-davinciresolve-overlay/SKILL.md) |
| 전체 화면 그래픽 | 선택한 그래픽 도구. HyperFrames면 [davinciresolve-gfx-hyperframes](../davinciresolve-gfx-hyperframes/SKILL.md) |
| 효과음, 음악 상태 | [davinciresolve-sfx-epidemicsound](../davinciresolve-sfx-epidemicsound/SKILL.md). 연출표의 cue ID를 사운드 큐시트의 장면 앵커로 쓴다 |
| 컷 | 스타일에 맞는 컷 skill, 또는 [보이스오버 workflow](../akbun-davinciresolve-workflow-voiceover/SKILL.md)의 조립 단계 |

순서는 컷 → 오버레이·글자 → 그래픽 → 사운드다. 사운드는 화면이 정해진 뒤에 맞춘다.

## 3. 점검

실행이 끝나면 타임라인을 점검한다. 스크립트는 타임라인을 바꾸지 않는다.

```bash
python3 scripts/director.py audit --timeline "<작업 타임라인>" --window-frames 3 --still-seconds 8 --out-dir "<출력 폴더>"
```

| 출력 | 읽는 법 |
|---|---|
| 화면 변화와 효과음 | V1 컷, 본편 밖 모든 비디오 트랙의 클립 시작(`GFX`·`SUBTITLE`·`HOOK_TEXT`는 그 이름, 나머지는 `오버레이`로 표시), push 클립마다 가장 가까운 효과음(이름이 `SFX`로 시작하는 오디오 트랙 클립의 시작)과 오프셋 |
| 짝 없는 효과음 | 화면 변화 없이 나는 소리. 의도(음악 강조, 공간음)가 아니면 옮기거나 뺀다 |
| 변화 없이 N초를 넘는 구간 | 연출표와 대조해 의도된 여백인지 본다. push 구간은 움직임으로 친다 |
| 분당 밀도 | 스타일 skill의 효과음 수와 비교한다 |

- 효과음 위치는 클립 시작이다. 파일 앞 여백 때문에 실제 어택은 늦을 수 있으니, 오프셋이 작아도 표시한 곳은 들어 본다.
- 문제로 본 곳마다 Lavender `DIRECT <cue ID> <사유>` 타임라인 마커를 찍는다. 노트에 `목표 TC / 무엇이 어긋났나 / 제안 / 상태(needs-review·approved)`를 적는다. 마커 좌표·충돌 처리는 [사운드 공통 skill 7절](../davinciresolve-sfx-epidemicsound/SKILL.md#7-사용자-검토-마커)과 같다.
- 스크립트가 보지 못하는 것(움직임 방향이 서로 부딪히는지, 곡선이 튀는지, 글자가 제품을 가리는지)은 해당 구간 렌더 프리뷰를 보고 판단한다. 보지 않은 것은 확인했다고 쓰지 않는다.

## 작업 로그

`edit-log_<YYYYMMDD_HHMM>.md`의 `연출` 절에 아래를 남긴다.

- 연출표 파일 경로와 승인 여부, 스타일과 고른 이유
- 실행 skill별로 넘긴 cue 수와 미적용 cue
- 점검 표 요약(변화 수, 효과음 수와 분당 밀도, 짝 없는 변화·효과음 수, 긴 정지 구간), `DIRECT` 마커 목록

## 하지 않는 것

- 연출표 승인 전 타임라인 수정
- 대본·전사에 없는 문구, 확인하지 않은 수치를 연출표에 넣는 것
- 효과음 수·움직임 수를 채우려고 cue를 만드는 것
- 점검 스크립트 결과만으로 "자연스럽다"고 판정하는 것
