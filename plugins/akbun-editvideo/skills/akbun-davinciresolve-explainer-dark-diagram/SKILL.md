# akbun-davinciresolve-explainer-dark-diagram

## 목적

화자의 얼굴 없이 목소리와 다이어그램만으로 기술 개념을 설명하는 영상의 스타일이다. 화면은 어두운 단색 배경에 색으로 역할을 나눈 글자와 화살표를 기본으로 하고, 구분이 필요한 대상만 둥근 박스로 그린다. 여기에 선으로 그린 아이콘, 연결 막대(터널), 움직이는 점(패킷)을 더한다. 요소는 살짝 커지며 튀어나오고, 장면 전체가 천천히 확대된다.

결과물은 Resolve에서 수정 가능한 타임라인이다. 장면 클립 구조(Fusion 타이틀 + Template 매크로, Timing 노드, 표현식 애니메이션, 제너레이터 길이 조정)는 [akbun-davinciresolve-explainer](../akbun-davinciresolve-explainer/SKILL.md)의 "Resolve 구현"을 그대로 따른다. 이 문서는 그 스킬의 "스타일"·"내레이션 규칙"을 대신하고, 녹음에 맞추는 흐름과 렌더·업로드를 더한다.

## 범위

- 사용자가 직접 호출할 때 실행한다. 새 설명 영상을 만들거나, 이 스타일로 만든 타임라인을 녹음에 맞출 때 쓴다.
- 촬영본 편집, 실사 B-roll 중심 영상은 범위 밖이다.
- 녹음 정리(숨소리·쉼)는 [akbun-davinciresolve-narration-cleanup](../akbun-davinciresolve-narration-cleanup/SKILL.md)을 부른다.

## 스타일

### 캔버스와 색

1920×1080, 24fps 기본. 배경 `#202020` 단색.

| 이름 | 값 | 쓰임 |
|---|---|---|
| WHITE | `#FFFFFF` | 기본 글자, 중립 요소 |
| GREY | `#9A9A9A` | 부제목, 보조 글자 |
| DIM | `#5A5A5A` | 비활성·제외된 요소 |
| YELLOW | `#F2C94C` | 우리 쪽, 주인공 요소 |
| ORANGE | `#F2994A` | 상대 쪽, 장면 결론 한 줄 |
| GREEN | `#27AE60` | 허용, 정상, 확인 표시 |
| BLUE | `#56CCF2` | 연결·터널·경로, 처리 단계 글자 |
| RED | `#EB5757` | 문제, 차단, 끊김 |

박스 채움색은 테두리색을 배경에 섞은 색이다. 섞는 비율은 색 있는 요소 18%, WHITE·GREY·DIM 10%다(`fill = bg × (1-k) + color × k`). 한 장면의 강조색은 두 가지 이내로 쓴다. 글자 흐름의 역할 색("도형과 글자")은 역할 구분이라 이 개수에 넣지 않는다.

### 글자

- Gmarket Sans. 라벨·제목은 Bold, 부제목·설명은 Medium. 화면 글자는 최소 22px.
- 크기: 챕터 이름 36px, 부제목 28px, 결론 한 줄 32px, 큰 질문 64~72px(줄간격 1.25), 박스 라벨·흐름 글자 24~34px, 보조 줄 22px.
- 화면 글자는 대본을 반복하지 않는다. 명사구나 짧은 판정("주기적으로 끊긴다")만 쓴다.

### 고정 위치

- 왼쪽 위 챕터 이름 `N. 챕터명`: 왼쪽 위 기준 (110, 76), 36px Bold WHITE.
- 그 아래 장면 부제목 한 줄: (110, 130), 28px GREY.
- 결론이 있는 장면은 그 아래 (110, 180)에 32px Bold ORANGE 한 줄. 상자로 감싸지 않는다.
- 다이어그램 영역은 y 280~860. 화면 아래 880 이후는 자막 자리로 비워 둔다. 결론·정의 문장을 아래쪽 상자에 넣지 않는다.
- 이웃한 요소 사이는 최소 80px 띄운다. 아이콘 옆 라벨 상자가 아이콘 경계와 겹치지 않게 한다.

### 장면 종류

| 종류 | 화면 | 쓰는 곳 |
|---|---|---|
| 인트로 | 챕터 표시 없음, 문제를 바로 보여 주는 다이어그램 + 빨간 큰 글자 한 줄(y 180) | 처음 3~4장면, 합계 45초 이하 |
| 다이어그램 | 챕터 이름·부제목 + 다이어그램 | 본문 |
| 결론 | 다이어그램 + 주황 결론 한 줄. 결론을 내레이션으로 말한다 | 챕터 마지막 장면, 또는 앞 장면 끝에 결론 줄만 붙인다 |
| 질문 | 가운데 큰 글자만. 챕터 이름·부제목 없음 | 챕터 사이 전환 |
| 체크리스트 | 번호 카드 3~4장(360×420, 번호 배지 52px, 아이콘 + 키워드 + 설명 두 줄) | 마지막 장면. 이 뒤에 글자만 있는 마무리 장면을 두지 않는다 |

### 도형과 글자

- 기본은 글자와 화살표로 그린다. 처리 순서, 프로그램·map 이름, 개념 단계처럼 흐름만 보여 주면 되는 것은 상자로 감싸지 않는다.
- 도형(박스·영역)은 화면 안에 실제로 있는 대상(Pod, node, agent 등)을 서로 구분하거나 포함 관계를 보여야 할 때 쓴다. cluster 안에 namespace, 그 안에 Pod가 들어가는 구조는 영역과 박스로 그린다.
- 색이 바뀌어야 하는 대상(정상 → 문제)도 도형으로 둔다. 색 전환이 테두리·채움으로 일어나기 때문이다.
- 글자로 그릴 때는 글자 색으로 역할을 나눈다. 처리 단계(프로그램·map)는 BLUE, 주인공(Pod 등)은 YELLOW 또는 WHITE, 판정·허용 결과는 GREEN, 문제는 RED.
- 같은 흐름을 상자로 그리면 화면이 무겁고 글자가 덜 읽힌다. 글자로 그린 쪽이 가볍고 읽기 쉽다.

### 다이어그램 요소

- 박스: "도형과 글자"에서 도형이 필요한 대상에만 쓴다. 모서리 반지름 10px, 2px 색 테두리 + 채움색, 가운데 라벨. 보조 줄은 라벨 아래 22px GREY.
- 영역(대역·네트워크): 2px 점선(대시 12, 간격 8), 라벨은 위쪽 40px에 26px Bold, 영역 색.
- 선 아이콘: 도형으로 그린다(선 두께 3~4px, 채움은 22% 섞은 색). server(칸 두 개 + 점 + 줄), db(위아래 타원 + 몸통), building(창 6개 + 문), cloud(원 세 개 + 밑판, 채움만), lock, key, eye, wall(벽돌 3줄), user, device(둥근 상자 + 불빛 점 3개). 방패 모양은 깔때기로 보여서 쓰지 않고 wall을 쓴다.
- 터널: 높이 16px의 둥근 막대가 0.6초 동안 왼쪽에서 오른쪽으로 자란다. 끊김은 색을 RED로 바꾸고 가운데에 ✕ 표시.
- 패킷: 지름 16px 점이 경로를 따라 1.4초 주기로 반복 이동한다. 끊기는 순간 사라진다.
- 표시: 확인은 GREEN 획 두 개, 문제는 RED ✕ 획 두 개(45°).
- 화살표: 3px 실선. 문제 경로는 RED 점선.
- 범위 상자: 채움 없는 테두리만. 채움을 넣으면 안쪽 칸의 글자를 가린다.

### 모션

- 확대 등장: 요소 중심을 기준으로 0.32초 동안 크기 `0.86 + 0.14·q + 0.09·sin(π·q)`(q = 0→1), 0.2초 페이드. 위치 이동은 없다.
- 장면 전체 확대: 클립 길이 동안 1.0 → 1.035배로 천천히 커진다.
- 색 전환: 테두리·채움이 정해진 시각에 다른 색으로 바뀐다(정상 → 문제).
- 장면 전환: 크로스 디졸브 7프레임(24fps 기준 약 0.3초).

### Fusion 노드 구성의 차이

기본 Explainer와 다른 점만 적는다.

- 요소를 합치는 MultiMerge 이름은 `레이어_합성`이다. 그 뒤에 장면 확대용 Transform을 두고 이름을 `레이어_목록`으로 한다. 매크로 출력과 MediaOut은 `레이어_목록`을 가리킨다.
- 확대 등장은 레이어마다 `Layer{n}.Size`와 `Layer{n}.Center` 표현식으로 만든다. 크기가 바뀌어도 요소 중심이 제자리에 있도록 Center를 `Timing.Pos{k} + (pivot - 0.5) × (1 - s)`로 보정한다.
- 장면 확대는 Transform Size = `1 + 0.035 × (time - comp.RenderStart) / (comp.RenderEnd - comp.RenderStart)`.

## 대본과 장면 길이

- 영상 약속(제목이 말하는 위험·질문)을 첫 문장에 바로 말한다. 인사·목차로 시작하지 않는다.
- 구성: 인트로 → 챕터 4~6개(각각 질문 또는 정의로 열고 결론으로 닫음) → 체크리스트로 끝낸다. 마지막 한 문장은 체크리스트 장면 안에서 말한다. 말 없는 결론 카드와 글자만 있는 마무리 장면은 시청자에게 정보가 없어 빼게 된다. 6~8분.
- 읽는 속도는 초당 5.0음절로 잡고 15% 여유를 더한다. `장면 길이(초) = 0.5 + 음절 수 / 5.0 × 1.15 + 1.0`. 장면 길이는 읽기 예상 시간의 1.2배 이상이어야 한다.
- 등장 시점은 그 요소를 말하는 문구의 위치로 정한다. `0.5 + 앞쪽 음절 수 / 5.0`.
- 대본과 화면 글자는 자연화 규칙(akbun-writing의 akbun-writing-naturalize)을 적용해 덮어쓴다. 개수·순서는 아라비아 숫자로 쓴다.
- 회사명, 고객·협력 관계, 특정 산업, 실제 장애 사례, 규제 이야기는 대본·화면·파일명에 쓰지 않는다. 기술적으로만 표현한다.

## 녹음 전 타임라인

1. 대본을 md(장면 표)와 srt로 만든다. srt 한 줄 = 장면 하나, 시작은 장면 시작 + 0.5초.
2. 새 타임라인에 srt를 **먼저** 넣는다. `AppendToTimeline`으로 srt를 넣으면 지정한 위치를 무시하고 타임라인 끝에 붙기 때문이다. 자막 트랙 이름은 `대본`.
3. 자막 트랙을 잠그고 장면을 끝에 하나씩 붙인다. 다른 트랙을 잠근 상태의 리플 삭제는 잠긴 트랙의 클립을 지우므로 쓰지 않는다.
4. 디졸브, 장면 시작 마커(대본 메모), 오디오 트랙(A1 내레이션, A2 BGM, A3 효과음, A4 BGM 2)을 준비한다. 장면 메모 마커는 파랑이 아닌 색, 챕터 마커는 파랑으로 나눈다. 업로드의 Chapters from Markers는 색 하나(기본 파랑)로 걸러 내므로, 같은 색이면 메모 마커가 챕터로 올라가거나 챕터를 만들려고 메모를 지워야 한다.
5. 자막 트랙 글꼴·위치는 API로 바꿀 수 없다. Edit 페이지에서 자막 클립 선택 → Inspector → Track 탭에서 Font `Gmarket Sans`, Face `Medium`, Size `28`, Transform Position Y `110`으로 바꾼다. 기본값(Size 58, Y 216)은 글자가 크고 아래쪽 다이어그램 요소와 겹친다. 타임라인을 새로 만들 때마다 다시 하고, 입력 뒤에는 "검수"의 개수 대조를 한다.

사용자는 이 타임라인의 A1에 자막을 보며 녹음한다. 대본과 다르게 말해도 된다.

## 녹음에 맞추기

1. 녹음이 있는 타임라인을 `… 녹음 원본`으로 이름을 바꿔 보존한다.
2. A1 테이크의 경로·사용 구간·위치를 읽는다.
3. 음성 인식: 자막 트랙이 이미 있는 타임라인에서는 `CreateSubtitlesFromAudio()`가 실패한다. 테이크만 같은 위치에 놓은 임시 타임라인을 만들어 기본 설정으로 실행하고, 자막 항목의 `GetName()`과 시작·끝을 읽은 뒤 임시 타임라인을 지운다. 설정 dict를 넘기면 실패할 수 있다.
4. 테이크를 **내용으로** 장면에 배정한다. 시간 위치로 배정하지 않는다. 사용자가 장면 순서를 건너뛰거나 한 테이크에 여러 장면을 말할 수 있다. 녹음에서 말하지 않은 장면은 목록으로 보고하고 빼는 쪽을 기본으로 제안한다. 남기기로 하면 3초로 둔다.
5. 민감 문장 점검: 인식 결과에서 실제 회사 사례, 장애 경험, 특정 조직을 가리키는 문장을 찾는다. 해당 문장 구간은 기본으로 빼고, 무엇을 뺐는지와 되살리는 방법을 보고한다.
6. 장면별 음성을 [akbun-davinciresolve-narration-cleanup](../akbun-davinciresolve-narration-cleanup/SKILL.md)으로 만든다. 장면 길이 = `ceil((0.25 + 말 길이 + 0.35) × fps)`, 질문 장면은 뒤 0.8초.
7. 등장 시점을 실제 목소리에 맞춘다.
   - 기본: 대본 단서의 음절 비율을 실제 말 길이에 옮긴다. `0.25 + 말 길이 × 앞쪽 음절 수 / 전체 음절 수`.
   - 실제로 다르게 말한 장면은 "대본 단서 → 실제 말한 구절" 표를 만들고, 인식 자막에서 그 구절이 나온 시각을 쓴다(구절 위치 비율로 자막 안에서 보간).
   - 화면과 말이 크게 어긋나는 긴 장면(20초 이상)을 중간 프레임 스틸로 확인한다.
8. 자막: 녹음한 장면은 인식 문장을 정리 결과의 시각 대응표로 옮겨 넣고, 녹음 안 한 장면은 대본 줄을 넣는다. 인식 오류는 명백한 기술 용어만 고친다. 추측해서 고친 문장은 목록으로 보고한다. 두 테이크에 걸친 자막은 테이크 끝에서 나누되, 문장 끝(다·요·.·?) 근처에서 자른다.
9. 새 타임라인을 다시 만든다: 자막 → 장면 → 디졸브 → BGM → 효과음 → 장면 음성(장면 시작 + 0.25초) → 챕터 마커 → 자막 글꼴. 장면 음성이 장면 끝을 넘지 않는지 확인한다. 챕터 마커는 장면 빌드가 장면 마커를 다시 넣으므로 매번 마지막에 단다. 첫 챕터는 0:00, 3개 이상, 각각 10초 이상이어야 챕터로 인식되며, 이 조건은 마커를 달기 전에 스크립트로 검사한다. 마커 이름이 챕터 제목이고, 질문 장면으로 여는 챕터는 질문 장면에서 시작한다.
10. 장면은 목록 위치가 아니라 장면 고유 번호로 가리킨다. 장면을 빼면 제외 목록에 번호를 넣고, 음악 전환점·챕터·대본 문서 같은 파생 결과도 번호로 찾는다. 위치로 찾으면 장면 하나를 뺀 뒤 전부 한 칸씩 어긋난다. 사용자가 "N번째 클립"이라고 하면 타임라인 위치이므로 시각과 클립 이름으로 어느 장면인지 확인한 뒤 뺀다.

## 배경 음악과 효과음

- 곡 선택은 별도 BGM skill이나 사용자 지정 음원을 쓴다. 사용 권한이 업로드할 채널에 맞는지 사용자에게 확인을 받는다.
- 음악 파일을 -40 LUFS로 만든 뒤 클립 볼륨 -6dB로 깐다. 목소리(-16 LUFS)를 가리지 않는 수준이다. 녹음 후 사용자가 음량을 다시 정한다.
- 큰 챕터 전환점에서 두 곡을 서로 다른 트랙에 두고 3초 겹친다. 곡이 필요한 길이보다 짧으면 같은 곡을 4초 크로스페이드로 이어 붙인다.
- 장면 길이가 바뀔 때마다 음악을 새 길이로 다시 자른다.
- 효과음은 장면 길이가 확정된 뒤(녹음 반영 뒤) 넣는다. 질문 장면에 들어갈 때 whoosh(가장 큰 지점을 질문 글자 등장에 맞춤), 주황 결론 줄이 나올 때 짧은 stinger를 둔다. 목소리보다 작게(클립 -10dB 안팎) 깐다.
- 라이선스 문제로 음원을 합성이나 다른 음원으로 바꾸자는 요청이면, 바꾸기 전에 음질이 떨어질 수 있다는 점과 다른 선택지(라이선스 결제, 등록 채널로 업로드)를 함께 알린다. 바꿀 때는 짧은 구간을 먼저 들어 보게 하고, 원래 음원 파일은 미디어 풀에서 지우지 않는다(지우면 보존용 타임라인의 음악도 사라진다). 템포·조성·주파수 측정이 맞아도 음질이 같다는 뜻은 아니다.

## 렌더와 업로드

1. 첫 렌더 전에 한 번에 확인한다: 자막을 화면에 구울지(burn-in) 자막 파일로 올릴지, 업로드 채널(음원 라이선스가 등록된 채널인지), 카테고리, 공개 범위. 업로드 뒤에 자막 방식을 바꾸면 다시 렌더·업로드해야 하고 같은 제목의 영상이 둘 생긴다.
2. 업로드는 YouTube 렌더 프리셋으로 만든 렌더 job으로 한다. Custom Export 프리셋은 파일만 만든다. 반대로 업로드 스위치가 켜진 프리셋은 다음 렌더 설정에 그대로 이어지므로, 파일만 필요한 렌더는 `H.264 Master` 같은 비업로드 프리셋을 먼저 불러온다.
3. 제목·설명·Chapters from Markers는 API로 못 넣는다. Deliver 화면에서 한 번 채운 뒤 `SaveAsNewRenderPreset`으로 저장해 두면, 이후 `LoadRenderPreset` → `AddRenderJob` → `StartRendering`이 화면 조작 없이 된다(화면이 잠겨 있어도 된다). 카테고리와 공개 범위는 프리셋에 저장되지 않는다.
4. 화면 전용 칸(카테고리 드롭다운 같은 것)은 백그라운드 조작으로 한 번 시도해 안 되면 사용자에게 넘긴다. 더 위험한 입력 방법(포커스된 칸에 바로 입력, 전체 화면 제어 요청 반복)으로 올라가지 않는다. 포커스된 칸 입력은 엉뚱한 칸을 덮어쓴다.
5. 자막 burn-in은 `ExportSubtitle: True`, `SubtitleFormat: "BurnIn"`이다. 자막 트랙의 Inspector 글꼴·위치가 그대로 구워진다. 업로드 렌더 전에 비업로드 프리셋과 `MarkIn`/`MarkOut`으로 5초만 렌더해 프레임을 뽑아 확인한다.
6. `SetRenderSettings`는 거부되는 키가 하나라도 있으면 전체가 False를 돌려준다. False가 나오면 키를 하나씩 넣어 거부된 키를 찾는다.
7. 업로드가 끝난 job은 `GetRenderJobStatus`가 값을 주지 않는다. Resolve 로그(`davinci_resolve.log`)의 `WebUploader : Upload job finished with status:2`로 업로드 완료를 확인한다. 화면에서 직접 보지 못했으면 그렇게 보고한다.
8. 자막을 구운 영상에는 같은 언어 자막 파일을 또 올리지 않는다(두 번 보인다). 다른 언어 자막은 문장 중간에서 나뉜 큐를 문장 단위로 묶은 뒤 번역하고, 묶은 큐의 첫 시작·마지막 끝 시각을 쓴다. 조각마다 번역하면 어순이 깨진다.

## 검수

- 장면 몇 개의 중간·끝 프레임을 `ExportCurrentFrameAsStill`로 뽑아 이어 본다(자막 트랙은 스틸에 나오지 않는다. 자막 위치·크기는 뷰어 화면으로 확인).
- 확인 항목: 왼쪽 위 3줄 위치, 흐름만 보여 주는 글자를 상자로 감싸지 않았는지, 아래쪽 자막 자리 침범, 요소 간격 80px, 질문 장면의 글자만 표시, 확대 등장·장면 확대 동작, 등장 시점과 말의 일치.
- 화면 조작(Inspector 입력 등)을 한 뒤와 렌더 직전에는 클립·오디오·자막·마커의 개수와 끝 프레임을 계획과 대조한다. 개수부터 비교한다(목록을 zip으로 비교하면 끝 클립이 빠진 것을 놓친다). 화면 조작 중 키 입력이 타임라인으로 새면 클립이 소리 없이 잘린다.
- 계획과 다른 점을 찾으면 계획대로 되돌리기 전에 사용자에게 보고하고 확인받는다. 사용자가 Resolve에서 직접 고친 것일 수 있다.
- 프로젝트를 저장한다. 녹음 원본 타임라인이 그대로 있는지 확인한다.

## 완료 보고

타임라인 이름과 길이, 녹음을 반영한 장면 범위, 빼거나 남긴 내레이션 없는 장면, 뺀 민감 문장, 추측으로 고친 자막, 지운 숨소리 개수, 대본·srt 경로, 렌더 파일과 업로드 결과(확인한 방법 포함), 사용자가 직접 해야 할 설정(카테고리 등)을 보고한다. 직접 듣거나 보지 않고 스펙트로그램·스틸·로그로만 확인한 것은 그렇게 적는다.

## 하지 말 것

- 녹음을 시간 위치로 장면에 배정하는 것
- 녹음 원본 타임라인이나 원본 녹음 파일, 원래 음원 파일을 지우거나 덮어쓰는 것
- 민감 문장을 사용자 확인 없이 다시 넣는 것
- 사용자가 고친 타임라인을 계획과 다르다는 이유로 확인 없이 되돌리는 것
- 첫 렌더 전에 자막 방식·업로드 채널을 정하지 않고 업로드하는 것
