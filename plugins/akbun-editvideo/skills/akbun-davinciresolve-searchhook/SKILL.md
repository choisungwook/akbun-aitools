# akbun-davinciresolve-searchhook

완성된 여행 브이로그에서 시청자를 붙잡을 도입부를 찾는다. 후보를 먼저 제안하고, 사용자가 고른 것만 새 타임라인으로 만든다. 훅은 영상과 화면 텍스트로만 만들고 내레이션은 쓰지 않는다.

`akbun-davinciresolve-workflow`의 기본 원칙(원본 불변, 클립은 파일명 + 시작 타임코드, dry-run → 사용자 확인 → 적용, 작업 로그)과 마커 등록표를 따른다. 이 skill은 workflow 밖의 단독 skill이고 workflow가 끝난 뒤에 쓴다. 훅을 판단하는 근거는 [`references/hook-principles.md`](references/hook-principles.md)에 있고, 실행 수단은 [`scripts/searchhook.py`](scripts/searchhook.py) 하나다.

## 용어

- 완성 타임라인 B: workflow로 컷·색보정·모자이크·자막까지 끝낸 작업 타임라인. 훅 재료를 여기서만 찾는다. 이 skill은 B를 수정하지 않는다
- 훅 타임라인 H: B를 복제한 타임라인. 복제본의 클립·그레이드·자막·오디오는 그대로 두고 맨 앞에 훅 구간만 넣는다. 이름은 `<B 이름>_hook_<YYYYMMDD_HHMM>`. 본편이 실제 클립이라 H에서 계속 편집할 수 있다
- 훅 소스 S: B를 한 번 더 복제해 BGM 트랙을 끈 스냅숏. 이름은 `<H 이름>_src`. 훅 구간은 S의 일부를 중첩 클립으로 가져온 것이라 색·안정화·모자이크·자막·현장음이 본편과 같고, 나중에 B를 고쳐도 훅이 바뀌지 않는다. S를 지우면 훅 구간이 오프라인이 되므로 지우지 않는다
- BGM 트랙: 배경음악만 있는 오디오 트랙. H를 만들 때 잠가서 제자리에 둔다
- 약속: 제목과 썸네일이 시청자에게 "이런 영상을 보게 된다"고 알리는 내용. 훅은 약속에서 출발한다
- 콜드 오픈: H의 첫 5~7초. 약속을 화면과 글자로 확인해 주는 1~3컷
- 인트로: 콜드 오픈 뒤 20~30초. 최소 맥락, 궁금증, 이 영상만의 것, 예고를 담는다
- 훅: 콜드 오픈 + 인트로. 전체 45초 이내
- 궁금증 고리: 시청자가 아는 것과 알고 싶은 것 사이의 틈. 본편을 봐야 닫힌다
- 예고: 끝이나 중간에 무엇이 있는지 미리 알리는 컷·문구
- `HOOK` 마커: H의 훅 구간마다 찍는 Mint 타임라인 마커. 노트에 B의 원래 타임코드가 있다
- `HOOK_BGM` 마커: 음악 길이 보정이 필요한 BGM 클립의 끝에 찍는 Mint 타임라인 마커. 노트에 할 일이 있다
- `HOOK_TEXT` 트랙: 화면 텍스트만 놓는 H의 비디오 트랙. 하나만 쓴다. 이름이 `HOOK_TEXT`인 트랙이 있으면 그것을 쓰고(workflow 3단계가 만들어 둔 것 포함), 없으면 `text`가 맨 위에 하나 만든다
- 화면 텍스트 클립: `HOOK_TEXT` 트랙에 놓인 일반 Text+ 클립. 화면 텍스트 하나가 클립 하나다. 컴파운드 클립이나 별도 타임라인으로 감싸지 않는다
- `HOOK_TEXT_TEMPLATE`: 미디어 풀의 `HOOK_TEXT_TEMPLATE` bin에 두는 같은 이름의 종류(Type) `Fusion Title` 항목. 화면 텍스트를 다 놓은 뒤에도 지우지 않고 남겨 둔다. `text`가 이 항목을 `HOOK_TEXT` 트랙에 놓아 화면 텍스트 클립을 만든다. 놓인 클립은 이 항목과 이어져 있지 않아 하나를 고쳐도 다른 클립과 이 항목은 바뀌지 않는다
- `HOOK` 오디오 트랙: 훅 구간의 소리만 놓는 H의 새 오디오 트랙. workflow 3단계가 만들어 둔 `HOOK` 트랙이 있으면 그것을 쓰고, 없으면 `build`가 맨 아래에 만들어 이름을 `HOOK`으로 붙인다. 본편의 오디오 트랙에는 훅의 소리를 섞지 않는다

## 시작 전에 확인할 것

| 항목 | 없을 때 |
|---|---|
| 완성 타임라인 B의 이름 | 멈추고 묻는다. 현재 열린 타임라인을 B로 짐작하지 않는다 |
| 제목과 썸네일(또는 그 후보) | 후보마다 어울리는 제목 한 줄과 썸네일로 쓸 프레임의 타임코드를 함께 제안한다. 약속 없이 훅만 확정하지 않는다 |
| 누가 보는 영상인지 한 줄 | 묻는다. 예: "주말에 서울에서 걸을 곳을 찾는 사람" |
| BGM 트랙 번호 | `build --dry-run`의 오디오 트랙 표(이름·클립 수)를 보여주고 어느 트랙이 배경음악인지 묻는다. 트랙 이름만으로 짐작하지 않는다. BGM이 아직 없으면 `--bgm-track` 없이 만든다 |
| 출력 폴더 | workflow의 출력 폴더를 쓴다 |
| Gmarket Sans 설치 | `fc-list \| grep -i gmarket`으로 확인하고 없으면 멈춘다. 다른 글꼴로 바꾸지 않는다 |
| 미디어 풀의 `HOOK_TEXT_TEMPLATE` | 없으면 `text`가 멈춘다. `Text+ 템플릿 준비` 절을 프로젝트마다 한 번 한다 |

## 소리가 이어지는 방식

훅을 앞에 넣으면 본편이 훅 길이만큼 뒤로 밀린다. 이때 트랙마다 다르게 움직인다.

| 트랙 | 움직임 | 결과 |
|---|---|---|
| 영상, 자막, 현장음·효과음 | 훅 길이만큼 함께 뒤로 밀린다 | 화면과 소리의 싱크가 그대로다 |
| BGM(`--bgm-track`) | 잠겨 있어 제자리에 남는다 | 음악이 H의 첫 프레임부터 끊기지 않고 이어진다 |
| 훅 구간 | S에서 가져온 영상은 V1에, 현장음·효과음은 `HOOK` 오디오 트랙에 놓인다 | 훅의 소리만 따로 음량을 고치거나 끌 수 있다. S의 BGM 트랙이 꺼져 있어 음악이 두 번 겹치지 않는다 |
| 타임라인 마커 | 훅 길이만큼 함께 밀린다 | `CHAPTER`가 장면을 따라간다 |

BGM이 제자리에 남으면 음악이 본편보다 훅 길이만큼 앞선다. 장면에 맞춰 일부러 자른 음악 경계와 음악의 끝이 그만큼 어긋나므로 마지막에 길이를 보정한다. `build`가 `BGM 길이 보정` 표와 `HOOK_BGM` 마커로 어느 클립을 몇 프레임 고칠지 알린다.

- 보정 방법: BGM 트랙만 자동 선택한 상태에서 첫 BGM 클립의 끝을 훅 길이만큼 ripple 트림으로 늘린다. 뒤의 BGM 클립이 같은 길이만큼 밀려 본편의 장면과 다시 맞는다.
- 첫 클립의 소스에 남은 길이가 모자라면 표에 "끝을 늘릴 소스가 N프레임뿐"으로 나온다. 훅 전용 음악을 앞에 두거나 다른 곡으로 채운다.
- 스크립팅 API에는 트림 함수가 없다. 화면 조작으로 하거나 `davinciresolve-sfx-epidemicsound`에 넘기고, 둘 다 안 되면 표를 그대로 사용자에게 전한다.
- 음악의 페이드·덕킹 위치는 늘린 뒤 다시 듣고 확인한다.

## 실행 순서

| 순서 | 작업 | 완료 조건 |
|---|---|---|
| 1 | 실행 환경 확인(workflow의 실행 환경 확인 절) | API 연결, B가 존재 |
| 2 | `inventory`로 B의 클립 목록과 스틸을 뽑는다 | 클립 전부가 표에 있고 클립마다 스틸 1장 이상 |
| 3 | 스틸을 전부 보고 장면을 채점한다 | 채점표 작성. 상위 장면은 `--step 2`로 다시 뽑아 컷 지점을 프레임 단위로 정함 |
| 4 | 훅 후보 3~5개를 서로 다른 유형으로 구성해 표로 제안한다 | 사용자가 후보 하나를 고르거나 수정안을 줌 |
| 5 | `build --dry-run`으로 계획 표와 오디오 트랙 표를 보여주고 BGM 트랙을 확인받은 뒤 `build` | 검증 표 여섯 줄이 모두 일치·그대로·전부 등록이고 `확인 필요`가 없음 |
| 6 | `HOOK_TEXT_TEMPLATE`이 없으면 `Text+ 템플릿 준비`를 한다. `text`로 화면 텍스트를 하나씩 놓는다. 첫 텍스트를 스틸로 확인한 뒤 나머지를 놓는다 | 텍스트마다 `적용`, 기존 클립·마커·타임라인 길이 `그대로`, 새 컴파운드 클립·타임라인 `없음` |
| 7 | `BGM 길이 보정` 표대로 음악 길이를 보정한다 | 표의 클립마다 보정했거나, 못 했으면 `확인 필요`로 보고 |
| 8 | 검증 절의 항목을 확인한다 | 전부 통과 또는 `확인 필요`로 보고 |
| 9 | 작업 로그에 `훅` 절을 추가하고 인계한다 | 로그에 후보 표·선택 이유·스크립트 출력이 있음 |

4단계에서 사용자가 고르기 전에는 타임라인을 만들지 않는다. 후보가 마음에 들지 않으면 3단계로 돌아간다.

## 훅의 구조

| 구간 | 길이 | 하는 일 | 화면 | 화면 텍스트 |
|---|---|---|---|---|
| 콜드 오픈 | 5~7초, 1~3컷 | 약속 확인. 썸네일의 대상을 보여준다 | B에서 가장 강한 장면. 첫 컷이 썸네일과 같은 대상 | 제목의 대상을 담은 한 줄. 첫 1~2초 안에 뜬다 |
| 맥락 | 3~6초 | 어디·언제. 관심을 갖는 데 필요한 최소한 | 장소를 알 수 있는 와이드 | 장소·시간 한 줄 |
| 궁금증 | 8~12초, 3~5컷 | 고리를 하나 이상 연다 | 대비되는 두 장면, 끝나기 직전에 자른 동작, 가려진 목적지 | 질문 또는 대비 한 줄. 답은 쓰지 않는다 |
| 이 영상만의 것 | 5~8초 | 증거·노력·개성 중 있는 것 | 본편의 화면 종류를 고루(와이드·디테일·움직임) | 없어도 된다 |
| 예고 | 3~5초 | 끝에 무엇이 있는지 | 마지막 장면의 일부 또는 직전 | "세 곳", "해 질 때까지" 같은 틀 |

- 순서는 콜드 오픈이 맨 앞이고 나머지는 바꿀 수 있다. 세 가지(맥락·궁금증·이 영상만의 것)는 빠지지 않는다.
- 컷 길이는 1.5~4초에서 시작해 장면의 호흡에 맞춘다. 조용한 영상이므로 1초 미만 컷을 늘어놓지 않는다.
- 인트로의 마지막 컷은 본편 첫 컷과 움직임·방향이 이어지는 것으로 고른다. "시작" 같은 멈춤 문구를 넣지 않는다.
- 훅에 쓴 장면은 본편에도 그대로 남는다. 본편에서 지우지 않는다.

## 장면 채점

스틸을 보고 클립(또는 클립 안의 구간)마다 0~2점을 준다. 합계 12점이다.

| 기준 | 0점 | 2점 |
|---|---|---|
| 약속 일치 | 제목·썸네일의 대상이 없음 | 대상이 화면의 중심 |
| 소리 없이 이해 | 무엇인지 알 수 없음 | 스틸 한 장으로 장소·상황을 앎 |
| 한 초점 | 복잡하고 시선이 흩어짐 | 대상 하나가 분명하고 글자 놓을 빈 곳이 있음 |
| 움직임·변화 | 정지에 가까움 | 카메라나 대상이 뚜렷이 움직이거나 빛이 바뀜 |
| 궁금증 | 다음이 궁금하지 않음 | 다른 장면과 대비되거나, 끝나기 직전에 자를 수 있거나, 의외임 |
| 본편 대표성 | 본편과 동떨어짐 | 본편에서 가장 좋은 화면 종류에 속함 |

- 같은 점수면 밝은 장면을 앞에 둔다.
- 움직임은 스틸 한 장으로 알 수 없다. `--step 2`로 뽑은 연속 스틸을 비교해 판단하고, 판단할 수 없으면 1점을 주고 `확인 필요`로 적는다.
- 얼굴이 식별되는 장면은 `PRIVACY_MOSAIC` 마커가 있는 것만 쓴다. 없으면 후보에서 뺀다.
- 채점은 후보를 고르는 근거이지 조회수·유지율의 예측이 아니다.

## 후보 유형

후보 3~5개는 서로 다른 유형으로 만든다. 같은 장면을 순서만 바꾼 것은 다른 후보로 치지 않는다.

| 유형 | 콜드 오픈 | 궁금증을 여는 방법 | 맞는 영상 |
|---|---|---|---|
| 결과 먼저 | 여행의 절정 장면 | 여기까지 어떻게 왔는지 | 절정 장면이 분명한 영상 |
| 대비 | 평범한 출발 → 절정 | 두 장면의 거리(낮과 밤, 도심과 섬) | 분위기가 크게 바뀌는 영상 |
| 중단 | 끝나기 직전에 자른 동작 | 그다음 장면 | 문·모퉁이·도착처럼 넘어가는 순간이 있는 영상 |
| 목록 | 본편 장소 세 곳을 한 컷씩 | 마지막 곳은 끝에 | `CHAPTER` 마커가 3개 이상인 영상 |
| 이유 | 떠난 이유가 보이는 장면 | 그래서 무엇을 찾았는지 | 사용자가 여행의 이유를 알려 준 영상 |

재료가 없는 유형은 만들지 않는다. 궁금증을 만들 장면이 하나도 없으면 후보를 억지로 채우지 않고 "콜드 오픈만 권함"으로 제안한다.

## 화면 텍스트

글꼴·그림자·안전 영역·페이드는 `davinciresolve-subtitle-travelnote`를 따른다. 아래는 훅에만 적용하는 규칙이다.

| 항목 | 값 |
|---|---|
| 글꼴 | Gmarket Sans. 콜드 오픈 한 줄은 Bold, 나머지는 Medium |
| Text+ Size | 콜드 오픈 0.16, 나머지 0.12 |
| 한 줄 글자 수 | 콜드 오픈 12자 이내, 나머지 18자 이내. 최대 2줄 |
| 표시 시간 | 글자 수 × 0.15초와 2초 중 큰 값, 최대 6초 |
| 한 화면의 텍스트 | 1개. 같은 구간에 두 개를 겹치지 않는다. `HOOK_TEXT` 트랙의 기존 클립과 겹치면 `text`가 놓지 않고 충돌한 구간을 알린다 |
| 위치 | 스틸에서 대상을 가리지 않는 빈 곳. 기본 `--x 0.5 --y 0.5`, 하단은 `--y 0.2` |
| 컷 경계 | 컷 시작 0.3초 뒤에 뜨고 컷 끝 0.3초 전에 사라진다. 콜드 오픈 첫 줄만 첫 프레임부터 1초 안에 뜬다 |

문구는 아래 순서로 검사한다.

1. 사실인가. 장소·시간·거리는 메타데이터나 사용자가 준 정보에 있는 것만 쓴다. 본편에 없는 것을 약속하지 않는다.
2. 주제가 첫 줄에 있는가. "대단하다", "믿기지 않는다"처럼 대상이 없는 말로 시작하지 않는다.
3. 쉬운 말인가. 초등학교 5~6학년이 바로 읽는 낱말, 능동문.
4. 한 가지로만 읽히는가. 문구만 따로 읽어 다른 뜻으로 읽히면 고친다.
5. 보는 사람 기준인가. 만든 사람이 한 일보다 보는 사람이 얻는 것을 쓴다.
6. 답을 주지 않았는가. 궁금증 문구는 질문이나 대비까지만 쓴다.
7. 문장 부호는 쉼표와 물음표만 쓴다. 느낌표·말줄임표·이모지를 쓰지 않는다.

## 후보 표

4단계에서 아래 형식으로 제안한다. 타임코드는 B의 타임라인 타임코드이고 끝 프레임은 포함하지 않는다.

```markdown
### 후보 1: 결과 먼저 (훅 31.5초)

약속: <제목 한 줄> / 썸네일 프레임 <B의 TC>

| 순서 | 구간 | 파일명 | B의 IN | B의 OUT | 길이(초) | 화면 | 화면 텍스트 | 점수 |
|---|---|---|---|---|---|---|---|---|
| 1 | 콜드 오픈 | IVDB4951.MOV | 01:12:40:00 | 01:12:43:12 | 3.5 | 해 지는 강 와이드 | 한강, 해 질 때까지 | 11 |
| 2 | 콜드 오픈 | VID_20260926_180154_052.mp4 | 01:03:10:00 | 01:03:12:12 | 2.5 | 다리 위 걷는 발 | - | 9 |

- 여는 고리: <무엇이 궁금해지는가>
- 닫히는 곳: 본편 <B의 TC>
- 이 영상만의 것: <증거·노력·개성 중 무엇을 어느 컷이 보여주는가>
- 약한 점: <이 후보의 단점 한 줄>
```

후보 표 끝에 추천 후보 하나와 이유를 적는다. 모든 후보에 "닫히는 곳"이 있어야 한다. 본편에서 닫히지 않는 고리는 열지 않는다.

## 명령

스크립트가 맞게 도는지 Resolve 없이 확인하는 명령이다.

```bash
python3 scripts/searchhook.py selftest
```

B의 클립 목록과 클립 중간 스틸을 뽑는 명령이다. 스틸은 `<출력 폴더>/hook-stills/<타임코드>.jpg`에 그레이드가 적용된 화면으로 저장된다.

```bash
python3 scripts/searchhook.py inventory --timeline "<B>" --out "<출력 폴더>"
```

클립 안을 2초 간격으로 뽑는 명령이다. 상위 장면의 컷 지점과 움직임을 볼 때 쓴다.

```bash
python3 scripts/searchhook.py inventory --timeline "<B>" --out "<출력 폴더>" --step 2
```

승인된 후보의 계획 표만 보는 명령이다. `--seg`는 재생 순서대로 반복한다.

```bash
python3 scripts/searchhook.py build --timeline "<B>" --seg "01:12:40:00-01:12:43:12=절정" --seg "01:03:10:00-01:03:12:12=걷기" --out "<출력 폴더>" --dry-run
```

훅 타임라인 H와 훅 소스 S를 만드는 명령이다. `--bgm-track`은 BGM 오디오 트랙 번호이고 여러 개면 반복한다. 같은 이름이 있으면 만들지 않고 멈춘다. 훅이 45초를 넘으면 멈춘다.

```bash
python3 scripts/searchhook.py build --timeline "<B>" --seg "01:12:40:00-01:12:43:12=절정" --seg "01:03:10:00-01:03:12:12=걷기" --bgm-track 4 --out "<출력 폴더>"
```

H의 `HOOK_TEXT` 트랙에 화면 텍스트 클립 하나를 놓는 명령이다. `--at`은 H의 타임코드이고 `--seconds`가 클립 길이다. 줄바꿈은 `\n`으로 쓴다. 기존 클립과 겹치면 놓지 않고 멈춘다.

```bash
python3 scripts/searchhook.py text --timeline "<H>" --at 01:00:00:06 --seconds 3 --text "한강, 해 질 때까지" --size 0.16 --style Bold --out "<출력 폴더>"
```

## 스크립트가 하는 일과 한계

Resolve 21.1.0.17에서 실측한 동작이다.

| 동작 | 내용 |
|---|---|
| 복제 | H와 S는 `DuplicateTimeline`으로 만든다. 해상도·프레임레이트·색관리 설정, 클립, 그레이드, 자막, 오디오가 B와 같다 |
| 앞 공간 만들기 | API에는 클립 이동·삽입 함수가 없다. 대신 `InsertFusionTitleIntoTimeline`이 V1 재생헤드에 끼워 넣으며 잠기지 않은 모든 트랙과 타임라인 마커를 미는 것을 쓴다. 맨 앞에 타이틀을 훅 길이 이상이 될 때까지 넣고, 타이틀을 지워 빈 공간으로 만든다 |
| 공간 맞추기 | 타이틀 길이가 고정이라 공간이 훅보다 길 수 있다. 남는 부분에 채움 클립을 놓고 ripple 삭제해 정확히 훅 길이로 맞춘다 |
| BGM 잠금 | `--bgm-track` 트랙을 `SetTrackLock`으로 잠근 뒤 밀고, 끝나면 푼다. 잠긴 트랙의 클립은 제자리에 남는다. 사용자가 미리 잠가 둔 트랙도 밀리지 않으며 풀지 않는다 |
| 중첩 구간 | S의 미디어 풀 항목을 `AppendToTimeline`에 `startFrame`·`endFrame`으로 넘긴다. 프레임은 첫 프레임이 0이고 `endFrame`은 포함하지 않는다. 스틸 비교로 첫·끝 프레임이 원본과 같음을 확인했다 |
| 꺼진 트랙 | S에서 `SetTrackEnable`로 끈 오디오 트랙은 중첩 클립의 소리에 들어가지 않는다. 렌더한 소리의 주파수로 확인했다 |
| 핸들 | 클립을 지울 때는 직전에 트랙에서 다시 읽은 핸들을 쓴다. 다른 삽입 뒤에 남은 옛 핸들로 지우면 Resolve가 종료됐다 |
| 하나씩 붙이기 | 같은 항목을 한 호출에 여러 개 넘기면 첫 개만 들어간다. 그래서 구간마다 따로 호출한다 |
| 마커 | 타임라인 마커는 ripple로 함께 밀린다. 훅이 10초 이상이면 0프레임에 `CHAPTER 인트로`를 더하고, 짧으면 첫 `CHAPTER`를 0프레임으로 옮긴다. 훅 구간마다 `HOOK` 마커를 찍고 0프레임이 차 있으면 다음 빈 프레임에 찍는다 |
| 훅 오디오 트랙 | 이름이 `HOOK`인 오디오 트랙을 찾는다. 없으면 `AddTrack`으로 stereo 오디오 트랙을 더하고 `SetTrackName`으로 `HOOK`이라 이름 붙인다. 이 트랙이 잠겨 있거나 BGM으로 지정되면 멈춘다. 훅 구간마다 영상(`mediaType` 1)은 V1에, 소리(`mediaType` 2)는 이 트랙에 같은 위치로 따로 붙인다. 렌더한 소리의 주파수로 훅 구간에서 이 트랙의 소리가 나는 것을 확인했다 |
| V1 | V1이 잠겨 있으면 멈춘다 |
| 실패했을 때 | 중간에 멈추면 H와 S가 만들다 만 상태로 남고 BGM 트랙이 잠겨 있을 수 있다. 스크립트는 타임라인을 지우지 않는다. 사용자 확인을 받고 지운 뒤 다시 실행한다 |
| 화면 텍스트 | 미디어 풀의 `HOOK_TEXT_TEMPLATE`을 `AppendToTimeline`에 `trackIndex`(`HOOK_TEXT`)·`recordFrame`(시작)·`endFrame`(길이)으로 넘겨 일반 Text+ 클립 하나를 놓고, 그 클립의 Text+ 툴에 문구·글꼴·스타일·Size·Center를 넣는다. 자세한 실측은 `화면 텍스트를 놓는 방법` 절에 있다 |
| 텍스트 수정 | `HOOK_TEXT` 트랙에서 Text+ 클립을 선택하고 Inspector의 Video > Title > Text 칸에서 문구를 바로 고친다. 글꼴·크기·위치도 같은 곳에서 고친다 |
| 클립 마커 | 본편의 클립 마커(`PRIVACY_MOSAIC` 등)는 H에 그대로 있다. 훅 구간은 중첩 클립이라 그 안의 클립 마커가 보이지 않으므로 S에서 확인한다 |
| 타임코드 | non-drop-frame만 지원한다. drop-frame 타임라인이면 멈춘다 |
| 페이드 | 텍스트 등장·퇴장 페이드는 스크립트가 넣지 않는다. 필요하면 Resolve에서 넣는다 |

## 화면 텍스트를 놓는 방법

Resolve 21.1.0.17에서 확인한 것이다. 확인한 API 한계와 그래서 화면(UI)에서 하는 일을 나눠 적는다.

### API로 하는 것

| 확인한 동작 | 결과 |
|---|---|
| Fusion Title 미디어 풀 항목을 `AppendToTimeline`에 `trackIndex`·`recordFrame`·`startFrame` 0·`endFrame`·`mediaType` 1로 넘김 | 그 트랙의 그 위치에 일반 Text+ 클립 하나가 놓인다. 다른 트랙의 클립, 타임라인 마커, 타임라인 끝 프레임은 바뀌지 않는다. 모든 트랙의 잠금을 푼 상태에서도 같다 |
| `endFrame`을 항목 길이(72프레임)보다 크게 줌 | 96·120·144프레임 모두 클립 하나로 놓였다. 이어 붙이지 않는다 |
| 놓인 클립의 종류 | `GetFusionCompCount()`가 1이고 Text+ 툴이 있으며 `GetMediaPoolItem()`이 없다. 컴파운드 클립이 아니고, 미디어 풀 항목 수와 타임라인 수가 늘지 않는다 |
| 클립마다 따로 수정 | 한 클립의 문구를 API나 Inspector로 고쳐도 다른 클립과 `HOOK_TEXT_TEMPLATE`은 그대로다 |
| 이미 클립이 있는 구간에 넘김 | 놓이지 않고 기존 클립이 그대로 남는다. `text`는 넘기기 전에 겹침을 검사해 충돌한 구간을 알리고 멈춘다 |
| 잠긴 트랙에 넘김 | 놓이지 않는다. `text`는 `HOOK_TEXT` 트랙이 잠겨 있으면 멈춘다 |

### API로 못 하는 것

| 한계 | 확인한 내용 |
|---|---|
| 트랙과 위치를 정해 Text+를 새로 만들기 | 공식 API에 그런 함수가 없다. `InsertFusionTitleIntoTimeline`은 인자가 타이틀 이름뿐이다 |
| `InsertFusionTitleIntoTimeline`로 `HOOK_TEXT`에 놓기 | 재생헤드에 끼워 넣는 편집이다. 다른 트랙을 모두 잠그면 `HOOK_TEXT`에 들어가지만 그 뒤의 타임라인 마커와 같은 트랙의 뒤 클립이 밀리고, 길이가 72프레임으로 고정된다. 그래서 화면 텍스트에는 쓰지 않는다. Resolve 화면에서 빈 상위 트랙에 Text+를 끌어 놓는 동작과 다르다 |
| Fusion Title 미디어 풀 항목 만들기 | API에 없다. 놓인 Text+의 `GetMediaPoolItem()`은 비어 있고, 타임라인 클립을 미디어 풀로 옮기는 함수도 없다. 아래 `Text+ 템플릿 준비`를 화면에서 한다 |
| 클립 길이·위치 바꾸기 | 트림·이동 함수가 없다. 놓은 뒤 길이나 위치를 바꾸려면 Resolve에서 클립 끝을 끌거나 옮긴다. 스크립트로 다시 하려면 그 클립을 사용자 확인 뒤 지우고 `text`를 다시 실행한다 |

### Text+ 템플릿 준비

프로젝트에 `HOOK_TEXT_TEMPLATE`이 없을 때 Resolve 화면에서 한 번 한다. 화면을 조작할 수 있으면 agent가 하고, 없으면 사용자에게 아래 순서를 전한다. 연습용으로 복제한 타임라인이나 H의 `HOOK_TEXT` 트랙 빈 곳에서 한다. B에서는 하지 않는다.

1. Edit 페이지에서 Effects > Titles > Text+를 `HOOK_TEXT` 트랙의 빈 곳에 끌어 놓는다. 문구와 글꼴은 고치지 않는다.
2. 미디어 풀의 Master 아래에 `HOOK_TEXT_TEMPLATE` bin을 만들고 연다. Smart Bin에는 넣을 수 없다.
3. 타임라인의 그 Text+ 클립을 그 bin으로 끌어 놓는다. bin에 `Text+` 항목이 생긴다.
4. 미디어 풀의 그 항목 이름을 `HOOK_TEXT_TEMPLATE`으로 바꾼다.
5. 1에서 놓은 타임라인의 Text+ 클립을 지운다.

- 확인한 것은 3번(타임라인의 Text+ 클립을 미디어 풀로 끌어 놓으면 `Fusion Title` 항목이 생김)과 그 항목을 API로 놓는 것이다. 2번의 bin 만들기와 항목 옮기기는 API `AddSubFolder`·`MoveClips`로, 4번은 API `SetName`으로도 된다. `text`는 미디어 풀 전체에서 이름과 종류로 항목을 찾으므로 항목이 다른 bin에 있어도 쓴다. 1번과 5번은 Resolve의 일반 편집 동작이고 따로 확인하지 않았다.
- Effects 목록의 Text+를 미디어 풀로 바로 끌어 놓는 것은 한 번 시도했고 항목이 생기지 않았다. 되는 방법으로 확인한 것은 타임라인의 클립을 끌어 놓는 것이다.
- bin을 `.drb`로 내보내 다른 프로젝트에서 가져오는 API(`Folder.Export`, `ImportFolderFromFile`)가 있다. 내보낸 파일에 프로젝트 이름과 시스템 ID가 들어가므로 skill에 넣어 배포하지 않는다. 다른 프로젝트로 가져오는 것은 확인하지 않았다.

API로 놓을 수 없고 화면 조작으로도 템플릿을 만들 수 없으면 멈추고 사용자에게 알린다. 컴파운드 클립으로 감싸는 예전 방식으로 바꿔 놓지 않는다.

| 첫 프레임 | H의 첫 프레임 스틸 | 검은 화면·로고·빈 화면이 아니고 썸네일의 대상이 보인다 |
| 주제가 늦지 않음 | 첫 화면 텍스트의 시작 | H 시작 1초 이내 |
| 길이 | `build` 출력 | 콜드 오픈 5~7초, 훅 전체 45초 이내 |
| 고리가 닫힘 | 후보 표의 "닫히는 곳" | 연 고리마다 본편 타임코드가 있다 |
| 텍스트 | `text`가 낸 스틸 | 글자 전체가 안전 영역(화면 폭 90%) 안, 대상을 가리지 않음, 한글이 네모로 깨지지 않음 |
| 텍스트 클립 | `text`가 낸 표, H의 `HOOK_TEXT` 트랙 | 화면 텍스트마다 요청한 시작·길이의 Text+ 클립 하나. 기존 클립·마커·타임라인 길이 `그대로`, 새 컴파운드 클립·타임라인 `없음`. 클립을 선택하면 Inspector에 Text+의 문구 칸이 보임 |
| 본편 보존 | `build` 검증 표 | 트랙별 클립 위치·길이 일치, 마커가 훅 길이만큼 밀림, B의 클립·마커 위치 그대로, 훅 오디오 트랙 이름이 `HOOK` |
| 음악 | H를 처음부터 훅 끝 너머까지 듣는다. `HOOK_BGM` 마커 위치를 듣는다 | 훅에서 음악이 두 번 겹치지 않고 끊기지 않음. 보정한 음악 경계가 장면과 맞고 음악이 영상 끝보다 먼저 끝나지 않음 |
| 챕터 | H의 마커 | 첫 `CHAPTER`가 0프레임, 간격 10초 이상 |
| 넘어가는 컷 | 인트로 마지막 컷과 본편 첫 컷의 끝·처음 스틸 | 밝기·방향이 크게 튀지 않음. 튀면 `확인 필요` |

H를 재생해 볼 수 없는 환경이면 움직임·소리에 관한 판단은 `확인 필요`로 남긴다.

## 작업 로그와 인계

작업 로그 `검증` 절 앞에 `## 훅` 절을 만들고 아래를 넣는다.

- 약속(제목·썸네일), 시청 대상
- 제안한 후보 표 전부와 사용자가 고른 후보, 고른 이유
- `searchhook_*.md`, `searchhook-text_*.md` 출력
- 검증 표

H를 만든 뒤의 작업은 아래 skill에 넘긴다.

| 작업 | skill | 넘기는 것 |
|---|---|---|
| BGM 길이 보정, 훅 구간 소리 연결, 훅 전용 음악 | `davinciresolve-sfx-epidemicsound` | H 이름, `HOOK` 오디오 트랙 번호, `BGM 길이 보정` 표, `HOOK`·`HOOK_BGM` 마커 |
| 렌더 | `davinciresolve-audio-delivery` | H 이름. B가 아니라 H를 렌더한다 |
| 세로 Shorts | `davinciresolve-youtube-shorts` | 별도 작업. 이 skill의 훅을 재사용하지 않는다 |

H와 S는 B의 복제본이라 만든 뒤에 B를 고쳐도 바뀌지 않는다. B의 바뀐 컷을 훅 타임라인에 반영하려면 새 이름으로 `build`와 `text`를 다시 실행한다. 옛 H와 S는 사용자 확인을 받고 지운다.

## 하지 않는 것

- 사용자가 후보를 고르기 전에 타임라인 생성
- 완성 타임라인 B, 타임라인 A, 미디어 파일 수정. 훅은 항상 B의 복제본에 만든다
- 훅에 쓴 장면을 본편에서 잘라 옮기기. 훅 구간은 복사본이고 본편은 그대로 둔다
- 어느 트랙이 BGM인지 사용자에게 묻지 않고 잠그기
- 본편에 없는 장면·사실을 약속하는 문구
- `HOOK_TEXT_TEMPLATE` bin과 항목 삭제. 놓인 화면 텍스트는 남지만 다음 `text`가 멈춘다
- 내레이션 대본 작성, 음성 합성
- 조회수·유지율·클릭률 수치 약속
- Gmarket Sans가 없을 때 다른 글꼴로 대체
- 마커 등록표 밖의 색·이름 사용
- 화면 텍스트를 컴파운드 클립이나 별도 타임라인으로 감싸기, 텍스트 하나를 여러 클립으로 이어 붙이기
- `HOOK_TEXT` 트랙의 기존 클립을 덮어쓰거나 지우기, 예전에 컴파운드 클립으로 놓인 텍스트를 Text+로 바꾸기(사용자가 요청할 때만)
- H·S 삭제, 렌더, YouTube 업로드(각각 사용자 확인 또는 해당 skill의 일)
