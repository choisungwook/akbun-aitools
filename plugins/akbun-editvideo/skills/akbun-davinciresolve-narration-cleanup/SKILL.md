# akbun-davinciresolve-narration-cleanup

## 목적

목소리 녹음은 내용 전달이 목적이므로, 말소리는 그대로 두고 숨소리와 빈 시간만 덜어 낸다. 결과는 장면마다 하나씩 정리된 음성 파일(`sNN.wav`)과, 지운 구간을 적은 보고서다. 원본 녹음 파일과 녹음이 놓인 타임라인은 수정하지 않는다.

## 입력과 산출물

| 입력 | 설명 |
|---|---|
| 녹음 테이크 | Resolve A1 클립의 원본 파일 경로, 클립이 쓰는 원본 구간(LeftOffset, Duration), 타임라인 위치 |
| 장면 배정 | 장면마다 어떤 테이크의 어느 구간을 쓸지. 테이크 하나를 여러 장면으로 나누거나 여러 테이크를 한 장면에 이을 수 있다 |
| 사용자가 짚은 숨소리 | 선택. 타임라인 시각(`MM:SS:FF`, 시 생략)이나 구간 |

산출물:

1. 장면별 음성 wav(24bit, 48kHz, 모노, -16 LUFS)
2. 보고서 JSON: 지운 숨소리 목록(구간, 판정 규칙), 남긴 조각의 원본→결과 시각 대응표(`pieces`)
3. 사용자 보고: 장면별 원래 길이 → 정리 후 길이, 숨소리 개수와 위치, 지우지 않고 남긴 의심 구간. 개수는 장면별 보고서 JSON의 `breaths`를 합산한 값으로 말한다. 실행 로그를 눈으로 더하거나 앞 보고에 더하면 틀린다.

## 숨소리 판정: 주파수 프로필

분석 단위는 10ms 프레임이다. 각 대역의 5번째 백분위수(방의 잡음 바닥)를 0dB로 두고 그 위로 몇 dB인지 본다. 녹음 음량이 달라도 같은 기준이 맞는다.

| 대역 | 숨소리 | 말소리(모음) | ㅅ·ㅊ 마찰음 |
|---|---|---|---|
| 70~300Hz (목소리 배음) | 낮음, 1~6kHz보다 4dB 이상 아래 | 바닥 위 40~55dB | 낮거나 중간 |
| 1~6kHz | 바닥 위 14~42dB | 바닥 위 40dB 이상 | 높음 |
| 8~20kHz | 1~6kHz보다 10dB 이상 아래 | 중간 | 1~6kHz와 비슷하거나 더 높음 |
| 길이 | 0.12~0.8초 | | 0.05~0.15초 |

규칙은 두 가지다. 하나라도 맞으면 숨소리로 본다.

- **말 사이 숨소리**: 위 표의 숨소리 열을 모두 만족하고, 앞뒤 30ms 안에 유성음(70~300Hz가 바닥 위 38dB 초과)이 없다. ㅎ+모음은 소음 바로 뒤에 유성음이 붙으므로 이 조건에서 걸러진다.
- **쉼 속 작은 숨소리**: 1~6kHz만 바닥 위 8~30dB, 70~600Hz는 바닥 수준, 0.1~0.8초, 앞뒤 40ms 안에 말소리가 없다.

숨소리에 붙은 0.15초 미만의 짧은 소리 조각은, 반대쪽이 조용하면 숨의 시작·끝으로 보고 함께 지운다. 남겨 두면 쉼이 둘로 쪼개져 쉼 줄이기가 동작하지 않는다.

판정이 애매하면 지우지 않는다. 예: 유성음과 30ms 안에 붙은 소음, 8kHz 이상이 강한 짧은 소음(입술·혀 소리일 수도, 자음일 수도 있음).

## 사용자가 짚은 숨소리 반영

1. 사용자 시각 `MM:SS:FF`를 프레임으로 바꾸고, 그 프레임이 속한 장면과 장면 음성 안의 초로 바꾼다(장면 시작 + 앞 여백을 뺀다).
2. 그 구간을 `profile`로 재서 위 표와 비교한다. 같은 패턴이면 규칙이 맞는 것이고, 다르면 임계값(`--mid-min`, `--mid-max`, `--voiced-db`)을 그 숫자에 맞춰 조정한다.
3. 지점 하나만 받았는데 그 위치가 유성음 위라면 자르지 않는다. 앞뒤 0.5초 안의 단어 사이에서 숨 패턴을 찾아 그쪽을 지우고, 무엇을 지웠는지 보고한다.
4. 사용자가 귀로 확정한 구간은 규칙과 상관없이 `--mark`로 지운다. 단, 끝이 다음 단어의 첫 소리에 걸리면 그 직전에서 멈춘다.
5. 규칙을 녹음 전체에 다시 적용한다. 사용자가 짚은 곳만 고치지 않는다.

## 쉼 줄이기와 숨고르기

- 말소리 사이 쉼이 0.3초보다 길면 앞 단어 뒤 0.12초, 다음 단어 앞 0.15초만 남긴다(총 0.27초). 0.3초 이하의 쉼은 말의 리듬이므로 그대로 둔다.
- 테이크 앞은 첫 단어 0.06초 전, 끝은 마지막 단어 0.15초 뒤에서 자른다.
- 남긴 쉼 안의 숨소리는 -30dB로 줄인다. 이어 붙이는 곳마다 10ms 크로스페이드를 넣는다.
- 장면 길이는 `앞 여백 0.25초 + 말 + 뒤 여백 0.35초`다. 그래서 장면이 넘어갈 때 말과 말 사이에 약 0.6초의 숨고르기가 생긴다. 질문 장면은 뒤 여백 0.8초. 내레이션이 없는 장면은 3초.

## 실행

Python은 `uv run --python 3.12`로 실행한다. ffmpeg가 필요하다.

사용자가 짚은 구간의 주파수 프로필을 확인한다(초는 파일 기준).

```bash
uv run --python 3.12 scripts/narration_cleanup.py profile take.wav --range 18.68-18.89 --range 21.72-21.96
```

장면 하나를 정리한다. 세그먼트는 `경로@시작:끝`(초)이고 적은 순서대로 이어 붙인다. `--mark`는 이어 붙인 음성 기준 초다.

```bash
uv run --python 3.12 scripts/narration_cleanup.py clean \
  --segment take_a.wav@1.00:12.30 --segment take_b.wav@1.00:5.70 \
  --mark 4.57-4.66 --report s06.json -o s06.wav
```

여러 장면의 음량을 똑같이 맞춰야 하면 `--no-master`로 정리만 한 뒤, 모든 장면의 중앙 LUFS로 공통 게인을 정해 같은 마스터 체인(highpass 70Hz → 컴프레서 3:1 → 공통 게인 → 리미터 -2dBFS)을 건다.

## Resolve 작업 흐름

1. 녹음이 놓인 타임라인을 복제하거나 이름을 바꿔 `… 녹음 원본`으로 보존한다. 이후 작업은 새 타임라인에서 한다.
2. A1 클립에서 원본 경로·`GetLeftOffset()`·`GetDuration()`·타임라인 시작을 읽어 JSON으로 저장한다. 녹음 세션이 나뉘어 타임라인 좌표가 겹치면 뒤 세션 프레임에 큰 상수(예: +100000)를 더해 구분한다.
3. 장면 배정을 정한다. 나누는 지점은 두 문장 사이의 쉼 안에서 10ms 에너지가 가장 낮은 곳으로 잡는다.
4. 장면마다 `clean`을 실행한다.
5. 결과 wav를 미디어 풀의 별도 폴더에 가져와 A1의 `장면 시작 + 앞 여백` 프레임에 놓는다(`AppendToTimeline`에 `recordFrame`, `trackIndex`, `mediaType: 2`). 가져온 wav의 `GetClipProperty("Frames")`는 빈 문자열일 수 있으니 `Duration` 타임코드를 프레임으로 바꿔 `endFrame`에 쓴다. 빈 값을 쓰면 길이 0으로 들어간다. 음성이 장면 끝을 넘지 않는지 확인한다.
6. 자막이 있으면 `pieces` 대응표로 시각을 옮긴다. 잘린 구간에 걸친 시각은 가장 가까운 남은 조각으로 붙인다.

## 검증

- 지운 숨소리마다 앞뒤 0.6초를 붙여 스펙트로그램을 만들고(`ffmpeg -lavfi showspectrumpic`) 한 장으로 이어 본다. 지운 구간에 배음(아래쪽 가로 줄무늬)이 보이면 말소리를 지운 것이므로 되돌린다.
- 사용자가 짚은 구간은 결과 파일에서 같은 자리의 스펙트로그램으로 소음이 사라졌는지 확인한다.
- 숫자 판정과 스펙트로그램은 귀로 듣는 것을 대신하지 못한다. 직접 들어 보지 않았으면 그렇게 보고한다.

## 하지 말 것

- 원본 녹음 파일이나 녹음 원본 타임라인을 덮어쓰는 것
- 애매한 구간을 지우는 것. 의심 구간은 위치를 보고하고 남긴다.
- 사용자가 짚은 곳만 고치고 같은 패턴의 다른 숨소리를 그대로 두는 것
- 0.3초 이하의 쉼까지 줄여 말을 몰아붙이는 것
