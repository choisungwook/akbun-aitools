# akbun-edit-quote-cards-lilac

## 언제 쓰나

레이아웃은 고정하지 않는다. 상황에 맞는 부품을 고르고, 부품의 모양·색·글꼴·모션만 아래 "스타일"대로 지킨다.

| 상황 | 화면에 나오는 것 |
|---|---|
| "요즘 이런 말이 나온다"처럼 여러 반응을 모아 보여 준다 | 출처가 다른 카드 2~4장이 차례로 겹쳐 쌓임. 마지막 카드의 핵심 구절에 형광펜 |
| 글 한 편의 핵심 문장을 짚는다 | 카드 한 장. 읽는 구절을 한 줄씩 형광펜으로 칠함 |
| 댓글·이슈·리뷰에서 반복되는 말을 보여 준다 | 같은 사이트 카드 2~3장. 카드마다 같은 뜻의 구절에 형광펜 |
| 주장과 반박을 나란히 둔다 | 카드 두 장을 좌우로 약간 겹쳐 놓고, 말하는 쪽 카드로 카메라가 흐름 |

- **경계**: 본편(촬영본·화면 녹화)이 계속 보이는 위에 발췌 패널을 띄우고 밑줄·원·효과음을 붙이는 것은 [akbun-davinciresolve-article-overlay](../akbun-davinciresolve-article-overlay/SKILL.md)다. 이 스킬은 본편을 가리고 캔버스 위에 카드만 보이는 전체 화면 장면이다. 웹 페이지 하나를 둘러보며 요소를 짚는 것은 [akbun-edit-page-tour-lilac](../akbun-edit-page-tour-lilac/SKILL.md)다.
- 카드는 실제 출처 화면의 스크린샷만 쓴다. 게시물·작성자·날짜·문구·숫자를 지어내거나 고쳐 그리지 않는다. 출처가 없으면 만들지 않고 사용자에게 받는다. 얼굴 화면(PIP)·인물 촬영은 넣지 않는다.
- 다른 사람의 프로필 사진·이름이 보이는 화면은 사용자가 공개 사용을 정했는지 확인하고, 아니면 Crop으로 프로필 영역을 빼거나 사용자에게 가림 여부를 묻는다.

## 녹음 전후 시각 맞추기

작업 흐름은 대본 → 영상 → 녹음 → 영상 수정이다. 카드 등장·형광펜·카메라 키·클립 길이는 모두 대본의 "신호 단어"에 묶는다. plan의 시간은 클립 시작 기준 초이고, 클립의 0초는 그 장면 첫 문장의 시작이다.

- **녹음 전**: 대본을 초당 6.5음절로 읽는다고 보고 시각을 잡는다. 한글 한 글자 = 1음절, 영어 단어 = 모음 글자 묶음 수(a·e·i·o·u, 단어 끝이 아닌 y 포함, 붙어 있는 모음은 한 묶음, 최소 1, camelCase·snake_case는 단어로 나눠 센다), 숫자·기호 = 한국어로 읽는 소리 수. 띄어쓰기는 시간을 더하지 않고, 쉼표는 0.2초, 문장 끝은 0.4초를 더한다. 요소는 신호 단어 시작 0.1초 전에 시작한다(0보다 작으면 0). 클립 길이는 그 장면 마지막 음절이 끝나는 시각 + 0.4초다(문장 끝 쉼 0.4초를 한 번만 더한다).
- **녹음 후**: 단어 시각(Resolve 전사, SRT, Whisper 단어 타임스탬프 중 있는 것)에서 신호 단어의 시작 시각을 찾아 plan의 `at`·`duration`·`fade`·`start`·`camera[].at`를 고치고 `retime`으로 다시 맞춘다. 길이는 그대로 두고 시작 시각만 옮긴다.
- 형광펜은 인용 구절을 소리 내어 읽기 시작하는 단어가 신호 단어다. 읽는 길이가 쓸기 길이보다 길면 쓸기를 0.6초로 두고 구절이 끝날 때까지 정지해 둔다.
- SRT처럼 문장 단위 시각만 있으면 문장 시작~끝을 음절 수 비율로 나눠 단어 시각을 추정하고 장면 표에 "추정"으로 표시한다. 신호 단어를 못 찾으면 시각을 추측하지 말고 목록으로 보고한다.
- **우선순위**: 신호 단어 시각 > 아래 모션 표의 길이 > 그 밖의 간격 규칙.
- 장면 표에는 요소마다 신호 단어, 녹음 전 시각, 녹음 후 시각 열을 둔다. 녹음 전이면 녹음 후 열은 "녹음 후 갱신"으로 둔다.

## 스타일

1920×1080 기준이다.

### 색과 글꼴

| 이름 | 값 | 쓰임 |
|---|---|---|
| CANVAS | `#EAEAEA` | 배경(`canvas_color`) |
| 창 틀 | `frame` 명령. 스크린샷이 밝으면 light, 어두우면 dark | 신호등 점, 제목줄에 출처 주소 |
| MARK | `#C9BCFF` | 밝은 카드의 형광펜(`highlight`, Multiply) |
| MARK_DARK | `#9C8CFF`, `alpha` 0.45 | 어두운 카드의 형광펜(`fill`, `sweep: true`) |

- 강조색은 연보라뿐이다. 카드마다 다른 색을 쓰지 않는다.
- 창 제목줄 글자는 Pretendard(없으면 Noto Sans KR)다. 설치돼 있지 않으면 받기 전에 사용자에게 묻는다(공식 배포처).

### 쌓기

| 항목 | 규칙 |
|---|---|
| 카드 수 | 한 화면 2~4장 |
| 카드 폭 | 820~1250px. 스크린샷의 글자 높이가 화면에서 18px 이상이 되게 |
| 겹침 | 다음 카드는 앞 카드의 오른쪽 아래로 x +80~+160px, y +90~+170px 옮긴다. 앞 카드 면적의 25~60%를 덮는다. 나중 카드가 위 |
| 묶음 위치 | 카드 묶음 경계 상자 중심이 가로·세로 모두 화면 가운데 60%(x 384~1536, y 216~864) 안 |
| 형광펜 | 줄마다 사각형 하나, 글자 줄을 위아래 3~5px 넉넉히 덮음. 한 화면 형광펜 줄은 3개까지 |

- 첫 카드가 가장 왼쪽 위다. 좌우 대비 장면만 두 카드를 같은 높이에 좌우로 둔다(가운데서 100~200px 겹침).
- 형광펜은 마지막으로 나온 카드(맨 위 카드)에만 칠한다. 앞 카드 구절을 짚으려면 카메라를 그 카드로 옮긴다.

### 모션

| 움직임 | 방식 | 길이 |
|---|---|---|
| 카드 등장 | `CARD_*_LAYOUT` Blend 페이드 | 0.25초 |
| 형광펜 | 왼쪽→오른쪽 쓸기, 여러 줄이면 위 줄부터 차례로(앞 줄 끝에 다음 줄 시작) | 줄당 0.4~0.6초 |

- **느린 흐름(항상)**: 장면 전체에 linear 카메라 키를 둔다. zoom을 장면 전체에서 0.04~0.08 키우고, 맨 위 카드 쪽으로 30~120px 옮긴다. 카메라가 멈춘 구간을 두지 않는다.
- **핵심 순간 확대**: 선택이며 장면당 한 번. 형광펜 줄을 향해 0.6~0.9초 ease-in-out으로 zoom을 그 시점 흐름 값보다 0.15~0.35 더 올리고, 뒤로도 linear 흐름을 이어 간다. 확대 중 보이는 영역에 형광펜 줄 전체가 들어간다.
- 카드 사이 등장 간격은 신호 단어가 정한다. 장면 전환은 하드 컷이다.
- **캔버스 밖 금지**: 카메라 키마다 보이는 영역(x ± 960/zoom, y ± 540/zoom)이 캔버스(0~1920, 0~1080) 안에 있어야 한다. 대상이 가장자리에 가까우면 가운데를 안쪽으로 옮긴다(x는 960/zoom ~ 1920 − 960/zoom, y는 540/zoom ~ 1080 − 540/zoom).

## 작업 흐름

`<page-tour>`는 [akbun-edit-page-tour-lilac](../akbun-edit-page-tour-lilac/SKILL.md) 디렉터리다. 스크립트·plan 형식·노드 구성·21.1.1 실측·검증·스크린샷 찍기는 [fusion-cards.md](../akbun-edit-page-tour-lilac/references/fusion-cards.md)를 먼저 읽고 따른다.

1. **장면 표**: 장면마다 "언제 쓰나"의 행, 카드 순서(출처 URL·찍은 날짜), 형광펜 구절과 신호 단어·시각을 적는다.
2. **스크린샷**: 출처 화면을 2배로 찍거나 사용자에게 받는다. 카드 하나에 필요한 부분만 `crop`으로 고른다.
3. **자산**: 카드마다 `frame` 명령으로 틀을 만든다(카드 크기·위치는 위 쌓기 규칙). 캔버스 영상은 타임라인 fps로 만든다.
4. **plan.json**: 카드는 등장 순서대로 `cards`에 적는다(뒤 카드가 위에 그려진다). 형광펜 좌표는 `where`로 계산한다.
5. **빌드·검증·녹음 후**: page-tour와 같은 `build` → `grab` → `retime` 순서다. 트랙 이름은 `QUOTE_CARDS`다.

예시 plan과 Resolve에서 만든 결과 시트는 [references/example/](references/example/)에 있다. 스타일 확인용이며 좌표·문구를 그대로 쓰지 않는다.

카드 셋을 오른쪽 아래로 겹쳐 쌓는 틀을 만드는 명령이다.

```bash
uv run --python 3.12 <page-tour>/scripts/resolve_cards.py frame --rect 300,150,1000,560 --theme light --title example.com/post/1 --out edit-assets/quote01_frame.png
uv run --python 3.12 <page-tour>/scripts/resolve_cards.py frame --rect 420,280,1000,560 --theme light --title example.com/post/2 --out edit-assets/quote02_frame.png
uv run --python 3.12 <page-tour>/scripts/resolve_cards.py frame --rect 540,410,1000,560 --theme dark --title example.com/post/3 --out edit-assets/quote03_frame.png
```

## 사용자가 고치는 법

Edit 페이지에서 `QUOTE_CARDS` 트랙의 클립을 고르고 Fusion 페이지로 간다.

| 고치려는 것 | 노드 → Inspector |
|---|---|
| 카드 하나의 위치·크기 | `CARD_02_LAYOUT` → Center, Size |
| 카드 안 스크린샷이 보이는 부분 | `SHOT_02_CROP` → X/Y Offset, X/Y Size |
| 형광펜 위치·길이·높이 | `MARK_01_SHAPE` → Center X/Y, Width, Height |
| 형광펜 색 | `MARK_01_COLOR` → Color |
| 형광펜 하나 숨기기 | `MARK_01` → Blend 0 |
| 카메라 흐름 | `CAMERA` → Size·Center 키프레임 |

캔버스 클립 모드에서는 Edit 페이지 Inspector에 이 값들이 나오지 않는다(21.1.1 실측).

**Edit Inspector에서 고치고 싶을 때(title 모드)**: plan에 `"mode": "title"`을 넣고 `build`하면 장면이 장면 전용 타임라인(`title_timeline`) 끝에 Fusion 타이틀로 붙는다. 그 클립을 고르고 Inspector → Video → Title 탭에서 `Mark 01 Color`·`Mark 01 Position`·`Mark 01 Width/Height`·`Card 01 Position/Size`·`Callout 01 Text/Position`을 바로 바꾼다. 대가는 장면이 본편 위 트랙이 아니라 별도 타임라인에 있어 사용자가 본편으로 복사해 붙여야 하고, `retime`이 안 돼 녹음 후에는 클립을 지우고 다시 `build`한다는 점이다(Inspector에서 고친 값은 plan 값으로 돌아간다). 자세한 절차는 [fusion-cards.md의 Edit Inspector 모드](../akbun-edit-page-tour-lilac/references/fusion-cards.md#edit-inspector-모드-title)다.

완료 보고에 어느 모드로 만들었는지와 해당 표(또는 Inspector 컨트롤 목록)를 적는다.

## 검수

- `build` 출력의 `frames` = 장면 길이 × fps이고, 다른 트랙 클립·마커 대조를 통과했다.
- `grab`: 0프레임은 캔버스만, 카드 등장 시각마다 카드 수가 하나씩 늘고, 형광펜 쓸기 중간 프레임에서 형광펜이 왼쪽 절반만 칠해져 있다.
- 쌓기 규칙(이동 거리, 덮는 비율 25~60%, 묶음 중심 60% 안)을 plan 좌표로 계산해 맞다.
- 카메라 키 첫 `at` 0, 마지막 `at` = 장면 길이, 멈춘 구간 없음.
- 카드 글자 높이가 화면에서 18px 이상이다(스크린샷 글자 높이 × 배율).
- 출처 화면이 사용자가 준 것과 같고, 문구를 고친 곳이 없다.

## 완료 보고

작업 타임라인·트랙·클립 시작 타임코드·길이, 카드별 출처 URL과 찍은 날짜, plan·자산 경로, 장면 표, `grab` 결과, "사용자가 고치는 법" 표를 적는다. 확인하지 않은 항목은 "확인하지 않음"으로 적는다.

## 하지 말 것

- 출처 화면의 글자를 고치거나 지어낸 게시물을 만들지 않는다.
- 카드에 밑줄·원·효과음을 붙이지 않는다(본편 위 발췌는 article-overlay의 범위).
- 원본 타임라인과 본편 트랙을 고치지 않는다. 표현식에 `comp.RenderStart`를 쓰지 않는다.
