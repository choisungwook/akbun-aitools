# akbun-draw-storybook-crayon

## 언제 쓰나

레이아웃은 고정하지 않는다. 상황에 맞는 부품을 고르고, 부품의 모양·색·글꼴·모션만 아래 "스타일"대로 지킨다.

| 상황 | 화면에 나오는 것 |
|---|---|
| 구성 요소의 역할을 사람·도구에 빗댄다 | 캐릭터 1~2명 + 각자의 도구. 지면 띠와 먼 실루엣 |
| 한 요소가 다른 요소에게 무언가를 건넨다 | 두 캐릭터(또는 캐릭터와 도구) 사이를 잇는 끈·관·화살표가 그려짐 |
| 속을 들여다본다 | 대상 위에 확대 원. 원 안에 대상의 속(작은 기호·글자·부품)을 크게 |
| 위험·주의할 점 | 비유 장치가 불안정해지는 포즈 + 빨간 점선 주석 |
| 단계가 쌓이거나 이어진다 | 비유 장치(아래 표) 하나가 포즈마다 한 단계씩 자란다 |

- 비유 장치는 장면마다 아래 표에서 하나를 고른다. 같은 영상에서 같은 장치를 세 장면 넘게 연달아 쓰지 않는다.

| 비유 장치 | 보여 주는 것 |
|---|---|
| 쌓기 (상자·돌·책) | 앞 단계 위에 다음 단계가 올라감. 아래가 약하면 위가 기욺 |
| 잇기 (관·다리·끈) | 두 쪽이 연결됨. 끊긴 곳이 문제 |
| 거르기 (체·그물·문) | 많은 것 중 일부만 통과 |
| 잠그기 (상자·자물쇠·열쇠) | 열 수 있는 것과 없는 것 |
| 길찾기 (표지판·지도·발자국) | 갈림길과 선택 |
| 저울 | 두 쪽의 무게 비교 |

## 녹음 전후 시각 맞추기

작업 흐름은 대본 → 영상 → 녹음 → 영상 수정이다. 시간 속성·카메라 키·장면 길이는 모두 대본의 "신호 단어"에 묶는다. 시각은 장면 시작 기준 초이고, 장면의 0초는 그 장면 첫 문장의 시작이다.

- **녹음 전**: 대본을 초당 6.5음절로 읽는다고 보고 시각을 잡는다. 한글 한 글자 = 1음절, 영어 단어 = 모음 글자 묶음 수(a·e·i·o·u, 단어 끝이 아닌 y 포함, 붙어 있는 모음은 한 묶음, 최소 1, camelCase·snake_case는 단어로 나눠 센다), 숫자·기호 = 한국어로 읽는 소리 수(`4초` → 사초, 2음절). 띄어쓰기는 시간을 더하지 않고, 쉼표는 0.2초, 문장 끝은 0.4초를 더한다.
- 요소는 신호 단어 시작 0.1초 전에 시작한다. 0보다 작으면 0이다. 내림할 때는 계산 오차 때문에 0.000001을 더한 뒤 내린다(4.30이 4.29가 되지 않게). 시각은 소수 둘째 자리에서 내림한다.
- 장면 길이는 녹음 전에는 그 장면 마지막 음절이 끝나는 시각 + 0.4초(문장 끝 쉼 0.4초를 한 번만 더한다), 녹음 후에는 다음 장면 첫 문장 시작까지다. 프레임 단위로 반올림한다. 느린 흐름 카메라 키의 마지막 `at`은 장면 길이와 같게 옮긴다.
- **녹음 후**: 단어 시각(Resolve 전사, SRT, Whisper 단어 타임스탬프 중 있는 것)에서 신호 단어의 시작 시각을 찾아 등장 시점과 카메라 키를 다시 맞추고 다시 렌더한다. 빌드 길이는 그대로 두고 시작 시각만 옮긴다.
- SRT처럼 문장 단위 시각만 있으면 문장 시작~끝을 음절 수 비율로 나눠 단어 시각을 추정하고 장면 표에 "추정"으로 표시한다. 신호 단어를 못 찾으면 시각을 추측하지 말고 목록으로 보고한다.
- **우선순위**: 신호 단어 시각 > 모션 표의 길이 > 그 밖의 간격 규칙(동시 빌드 수, "마지막 빌드는 장면 끝 1.0초 전"). 마지막 단어에 묶인 요소 때문에 끝 여유가 1.0초보다 줄면 0.5초까지는 그대로 둔다. 신호 단어에 맞추면 다른 규칙이 깨질 때는 빌드 길이를 모션 표의 최소값까지 줄이고, 그래도 안 되면 그 요소를 가장 가까운 다른 신호 단어(앞이든 뒤든)로 옮기고 장면 표에 이유를 적는다. 시간 규칙 때문에 대본·글자를 바꾸지 않는다.
- 장면 표에는 요소마다 신호 단어, 녹음 전 시각, 녹음 후 시각 열을 둔다. 녹음 전이면 녹음 후 열은 "녹음 후 갱신"으로 둔다.

## 스타일

1920×1080 기준이다. 다른 해상도는 세로 비율로 늘이거나 줄인다.

### 색

| 이름 | 값 | 쓰임 |
|---|---|---|
| PAPER | `#EEE6CE` | 배경(하늘). spec `background` + `"grain": 0.04` |
| OUTLINE | `#2F2619` | 모든 외곽선 3px, 세부 2px |
| GROUND | `#C99F6C` | 지면 띠 |
| GROUND_DARK | `#A7804F` | 지면 빗금·자갈 점 |
| FAR | `#DDD3B9` | 먼 실루엣(외곽선 없음) |
| FAR_DETAIL | `#D2C7AB` | 먼 실루엣 안 창문 같은 작은 사각형 |
| CLOUD | `#F4EEDC` | 구름 채움(OUTLINE 2px) |
| RED | `#D2453A` | 빨간 점선 주석과 그 글자 |

물체 색은 아래에서 IVORY 말고 한 장면에 4색까지 고른다. IVORY는 흰 바탕색이라 세지 않고 필요한 만큼 쓴다. 빗금은 각 색의 "빗금" 값이다.

| 이름 | 채움 | 빗금 |
|---|---|---|
| NAVY | `#34406E` | `#1F2747` |
| SKY | `#8DB6D6` | `#5E86A6` |
| MUSTARD | `#E8B94A` | `#B48A2A` |
| CORAL | `#D9735B` | `#A44F3B` |
| LEAF | `#7EA06A` | `#57754A` |
| IVORY | `#F7F2E4` | `#C9BFA4` |

- **세는 법**: 물체 색 표에서 IVORY 말고 채움으로 쓴 색 수를 센다. 위 표의 색(PAPER·OUTLINE·GROUND·GROUND_DARK·FAR·FAR_DETAIL·CLOUD·RED)은 세지 않는다.
- 눈 흰자, 사람 피부, 이름표 바탕, 확대 원 안쪽은 IVORY다. 눈동자는 OUTLINE이다.
- 설계 크기(흔들림 전)의 짧은 변이 30px보다 작은 면(눈 흰자, 작은 램프, 손잡이 선)에는 빗금을 넣지 않는다. 이름표·확대 원 안쪽·눈 흰자의 IVORY에도 넣지 않는다.

### 그림체

- **평면 색 + 색연필 빗금**: 물체 색 표의 색 면마다 같은 계열 빗금 색으로 1.5px 평행선(기본 45°, 가로로 긴 면은 30°, 선 사이 수직 거리 6~9px, `opacity="0.45"`)을 그 면의 `clipPath` 안에 덮는다. 그늘 쪽(면의 오른쪽 또는 아래 35~45%)은 간격을 4~5px로 좁혀 한 번 더 덮는다. 구름·실루엣·지면에는 이 빗금을 쓰지 않는다.
- 그리는 순서는 물체마다(뒤 물체부터) 채움 → 빗금 → 외곽선 → 눈·세부다.
- **흔들린 외곽선**: 큰 물체 외곽선은 `<rect>`·`<circle>` 대신 `Q`·`C` 곡선 `<path>`로 그리고 반듯한 형태에서 2~4px 어긋나게 한다. 한 번 그린 뒤 고정한다(프레임마다 바꾸지 않는다).
- 그라데이션·흐림·`filter`·사진은 쓰지 않는다.

### 배경

- **지면 띠**: 지평선을 y 790~830 사이에 두고 그 아래 화면 끝까지 GROUND로 채운다. 지평선은 OUTLINE 2.5px 살짝 물결진 선. 지면 안에 GROUND_DARK 짧은 가로 획 10~20개와 자갈 점(반지름 3~6) 10~20개(지면 질감이며 clipPath 없이 지면 띠 안에만 둔다).
- 구름·실루엣·지면은 카메라가 옮겨도 끝이 보이지 않게 x −200~2120까지 그린다.
- **먼 실루엣**: 지평선 뒤 높이 60~220px의 FAR 도형(건물 덩어리·언덕·나무 줄 중 하나를 장면 표에 적는다). 외곽선 없음, 창문 같은 세부는 PAPER보다 살짝 어두운 `#D2C7AB` 작은 사각형만.
- 구름은 0~3개, 화면 위 25% 안.

### 캐릭터와 도구

캐릭터는 영상마다 새로 정한다. 아래 표에서 열마다 한 칸씩 골라 장면 표에 적고, 같은 영상의 두 캐릭터는 네 열 중 두 열 이상을 다르게 고른다.

| 몸 | 머리 | 눈 | 색(물체 색 표) |
|---|---|---|---|
| 둥근 상자 + 짧은 다리 | 몸과 하나(머리 없음) | 점 둘 | NAVY |
| 세로 캡슐 | 원 | 흰 원 안 점 | SKY |
| 원뿔(아래가 넓음) | 둥근 삼각형 | 반달(∩) | MUSTARD |
| 낮은 원통 + 바퀴 둘 | 가로 타원 | 가로 짧은 선 | CORAL |
| 사람(둥근 머리 + 사다리꼴 옷) | 사람 머리 + 짧은 머리카락 곡선 | 점 둘 | LEAF |

- 캐릭터 키는 화면 높이의 30~45%. 팔은 OUTLINE 3px 굽은 선 둘(관절 없음), 도구를 쥔 팔 끝은 도구 외곽선에 닿는다.
- 같은 역할의 대상이 여럿이면(서버 세 대 등) 같은 모양을 반복하고 캐릭터 1명으로 센다. 이 반복 캐릭터의 키는 화면 높이의 20~35%다.
- 도구는 캐릭터마다 하나이고, 그 캐릭터 몸 색과 다른 물체 색을 쓴다. 비유에 맞는 일상 도구(돋보기·삽·저울·전등·체·열쇠·상자)를 단순 도형 3~6개로 그리고 물체 색 하나를 쓴다. 도구에 짧은 이름표(IVORY 사각형 + OUTLINE + 글자, 도형 수에 넣지 않음)를 붙일 수 있다.
- 끈·관·화살표는 OUTLINE 3px(관은 물체 색 면 + 외곽선)다.
- 실제 제품·로고·마스코트·알려진 캐릭터와 닮게 그리지 않는다. 화면 얼굴을 한 로봇, 안전모를 쓴 작업자는 쓰지 않는다.

### 확대 원과 주석

- **확대 원**: 반지름 150~230px. OUTLINE 10px 테두리 + IVORY 채움, 원 `clipPath` 안에 대상의 속을 원 밖에 그린 그 대상 크기의 1.8~3배로 그린다. 손잡이(OUTLINE 14px 짧은 선)는 선택. `data-fade` 0.3초로 나타난다. 확대 원은 도구가 아니다.
- **빨간 점선 주석**: RED 3px, `stroke-dasharray="10 7"`, 대상 둘레의 둥근 사각형·타원 또는 굽은 화살표. 옆에 RED 손글씨 라벨 하나(28~40px). 한 화면 2개까지.
- **손글씨 라벨**: 빨간 주석이 아닌 라벨은 OUTLINE 32~40px.
- **손글씨**: `font-family`는 `'Gaegu', 'Nanum Pen', 'Nanum Pen Script', sans-serif`. 이름표·코드 글자는 `'D2Coding', monospace` 20~26px. 렌더 전에 `uv run --python 3.12 <doodle>/scripts/render_doodle.py --fonts "Gaegu,D2Coding"`가 `ok`인지 보고, `missing`이면 렌더하지 말고 설치할지 사용자에게 묻는다(공식 배포처).

### 화면 배치

- 주인공 묶음(지금 말하는 캐릭터 + 도구 + 비유 장치의 몸체, 화면 끝까지 뻗는 끈·화살표 제외)의 경계 상자 중심은 카메라 키 시점마다 화면 좌표로 가로·세로 모두 화면 가운데 60% 안(x 384~1536, y 216~864)에 둔다.
- 캐릭터와 비유 장치는 지평선 위에 선다(발·바닥이 지평선 아래 0~40px). 떠 있는 것은 구름·확대 원·주석뿐이다.

### 모션

| 움직임 | 방식 | 길이 |
|---|---|---|
| 캐릭터·도구 등장 (기본) | `data-show` | 즉시 |
| 끈·관·화살표·점선 주석 | `data-draw`(점선 모양 유지). 화살촉은 선이 끝나는 시각에 `data-show` | 선 길이 ÷ 700초, 최소 0.3초 |
| 확대 원 | `data-fade` | 0.3초 |
| 라벨 글자 | `data-write` | 글자 수(공백 포함) ÷ 8초 |
| 캐릭터 동작·표정, 비유 장치가 자람·기욺 | 포즈 교체(포즈 사이 1~2곳만 다름) | 포즈당 0.4초 이상 |
| 사라짐 | 그 요소가 없는 포즈로 교체 | 즉시 |

- `drawings_per_second`: fps 24·48·60이면 12, fps 30이면 15.
- 빌드·간격 규칙은 이 절이 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md)보다 우선한다(motion-doodle의 0.3초 쉼과 "초당 12장 고정"은 쓰지 않는다). 카메라 이동은 빌드가 아니라 마감 뒤에도 이어져도 된다. 시작 시각은 소수 둘째 자리에서 내림, 끝 시각은 올림한다.
- **빌드**는 시간이 걸리는 등장(`data-draw`, `data-write`, `data-fade`)이다. `data-show`와 포즈 교체는 빌드가 아니다. 동시에 진행 중인 빌드는 둘까지다. 마지막 빌드는 장면 끝 1.0초 전까지 끝낸다. 그 뒤로는 빌드·포즈 교체가 없다(카메라 흐름은 이어진다).
- **느린 흐름(항상)**: 모든 장면에 카메라 키를 두고 zoom은 1.05 이상으로 둔다. 장면 전체에서 `"ease": "linear"`로 x를 40~120px 옮기거나 zoom을 0.02~0.05 바꾼다. 카메라가 멈춘 구간을 두지 않는다.
- **장면 안 이동**: 주인공을 바꿀 때 0.8~1.2초 ease-in-out으로 옮긴다. 이동 중 zoom은 1.05~1.6 사이. viewBox는 1920×1080 그대로 두고 카메라로만 옮긴다.
- **핵심 순간 확대**: 선택이며 장면당 한 번까지, zoom 최대 1.8, 0.8~1.0초 ease-in-out. 확대 뒤에도 linear 흐름을 장면 끝까지 이어 간다.
- **화면 밖 금지**: 카메라 키마다 보이는 영역(x ± 960/zoom, y ± 540/zoom)이 x −200~2120, y 0~1080 안에 있어야 한다.
- 장면 전환은 하드 컷이다. 장면 하나는 25초 이하.
- 렌더는 카메라가 계속 움직여 매 프레임 다시 그리므로 영상 1초에 10~20초 걸린다(14초 영상 3분 11초~3분 47초 실측). 렌더는 백그라운드로 실행하고 끝날 때 결과를 확인한다.

## 작업 흐름

`<doodle>`은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md) 디렉터리다.

1. **장면 표**: 장면마다 id, "언제 쓰나"에서 고른 행(여럿이면 모두), 비유 장치, 캐릭터 칸, 쓸 물체 색(4색 이하), 먼 실루엣 종류, 요소별 신호 단어와 시각을 적는다. 출력 폴더는 사용자가 정한 곳, 없으면 `storybook-output/<작업명>/`.
2. **SVG 포즈**: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1920 1080">`로 시작하고 `width`·`height`·배경 사각형·`filter`·`<image>`를 넣지 않는다. 그리는 순서는 구름 → 먼 실루엣 → 지면 → 물체마다(뒤 물체부터) 채움·빗금(clipPath)·외곽선 → 확대 원·주석 → 글자. 포즈가 여러 장이면 공통 부분(배경·지면·실루엣)을 한 번만 정의하는 작은 생성 스크립트(출력 폴더)로 만든다. 빗금은 반복문으로 만든다.
3. **spec.json**: 아래 예시처럼 쓴다. `fps`는 놓을 타임라인 fps와 같게 한다.
   예시: [references/example/](references/example/)(메시지 큐를 선반 쌓기로 빗댄 두 장면, `sheet.jpg`는 포즈별 마지막 그림). 스타일 확인용이며 캐릭터·장치·문구를 그대로 쓰지 않는다.

캐릭터가 도구로 대상을 살피는 10초 장면 하나(포즈 셋, 왼쪽에서 오른쪽으로 옮기며 확대)의 spec 예시다.

```json
{
  "size": [1920, 1080], "fps": 24, "drawings_per_second": 12,
  "background": "#EEE6CE", "grain": 0.04,
  "scenes": [
    {"id": "inspect", "duration": 10.0,
     "poses": [{"svg": "inspect_1.svg", "at": 0}, {"svg": "inspect_2.svg", "at": 3.5}, {"svg": "inspect_3.svg", "at": 6.4}],
     "camera": [{"at": 0, "zoom": 1.35, "x": 760, "y": 600}, {"at": 3.0, "x": 820, "ease": "linear"},
                {"at": 4.0, "zoom": 1.25, "x": 1180, "y": 580}, {"at": 10.0, "zoom": 1.22, "x": 1120, "ease": "linear"}]}
  ]
}
```

spec을 MP4로 렌더하고 포즈별 스틸을 남기는 명령이다.

```bash
uv run --python 3.12 <doodle>/scripts/render_doodle.py storybook-output/<작업명>/spec.json storybook-output/<작업명>/out.mp4 --stills storybook-output/<작업명>/stills
```

스틸을 한 장으로 붙이는 명령이다. `tile=열x행`은 스틸 수로 정한다: 1장 `1x1`, 2장 `2x1`, 3장 `3x1`, 4장 `2x2`, 5~6장 `3x2`, 7~8장 `4x2`, 9장 `3x3`, 10~12장 `4x3`, 13~16장 `4x4`.

```bash
ffmpeg -v error -y -pattern_type glob -i 'storybook-output/<작업명>/stills/*.png' -vf "scale=640:-1,tile=3x1:color=0xEEE6CE" -frames:v 1 storybook-output/<작업명>/sheet.jpg
```

### 검수

숫자로 먼저 확인한다.

- 렌더 프레임 수 = 장면 길이 합 × fps.
- 글꼴 검사가 `ok`.
- SVG 채움 색이 위 두 색 표 안이고, 물체 색이 장면당 4색 이하(IVORY 제외)인가.
- 글꼴 검사 출력 JSON의 값이 모두 `"ok"`인가.
- 물체 색 면마다 같은 계열 빗금이 있고 `clipPath`로 면 안에만 있는가(지면 질감 획 말고 빗금 `<path>`·`<line>`이 clip 없이 놓여 있지 않은가).
- 모든 장면에 카메라 키가 있고 첫 키 `at` 0, 마지막 키 `at`이 장면 길이와 같은가. zoom이 1.05~1.8 안이고 키마다 보이는 영역이 x −200~2120, y 0~1080 안인가.
- 카메라 키마다 주인공 묶음 중심을 화면 좌표로 바꿨을 때(화면 x = 960 + (svg x − 카메라 x) × zoom, y도 같은 식) x 384~1536, y 216~864 안인가.
- 동시에 진행 중인 빌드가 둘 이하이고, 마지막 빌드가 장면 끝 1.0초 전에 끝나는가.

시트를 한 번 보고 확인한다.

- 외곽선이 반듯한 도형이 아니라 살짝 흔들린 손그림인가. 빗금이 색연필처럼 보이는가.
- 캐릭터가 고른 칸대로 그려졌고 알려진 캐릭터·마스코트와 닮지 않았는가. 닮았으면 캐릭터 표에서 두 칸 이상 바꾼다.

### 완료 보고

출력 경로, 장면 표(비유 장치·캐릭터 칸·물체 색·신호 단어·녹음 전/후 시각), 렌더 프레임 수, 글꼴 검사, 검수 결과를 적는다. 확인하지 않은 항목은 "확인하지 않음"으로 적는다. Resolve에 놓아 달라고 하면 [motion-doodle의 Resolve 배치](../akbun-draw-motion-doodle/SKILL.md#resolve-배치)를 따른다.

## 하지 말 것

- `filter`(특히 `feTurbulence`)로 종이 결·연필 질감을 만들지 않는다. 종이 결은 spec `grain`, 연필 질감은 빗금이다.
- 외곽선을 프레임마다 흔들지(line boil) 않는다.
- 카메라를 멈춘 채 두지 않는다. 회전·흔들기는 하지 않는다.
