# akbun-draw-folk

## 목적

아무 장면을 folk 소박파 회화 스타일로 담는 영어 이미지 생성 프롬프트를 만든다. 이 skill이 고정하는 것은 물감 질감·윤곽선·모양·색 쓰는 법·빛·분위기이고, 무엇을 그릴지(사물·동물·장소)와 구도는 입력에 맞춰 정한다.

모델은 프롬프트 문장을 직접 쓰지 않는다. spec만 쓰고, 스타일 문장은 스크립트가 라이브러리에서 가져온다. 그래서 몇 장을 만들어도 같은 그림체가 나온다.

## 무엇을 정할 때 어느 파일

| 정할 것 | 파일 | 고르는 법 |
|---|---|---|
| 그림체(질감·윤곽선·모양·색 쓰는 법·빛·분위기) | [references/style.jsonl](references/style.jsonl) | 고르지 않는다. 스크립트가 전부 넣는다. 읽고 장면이 이 규칙(사람 없음, 원근 없음)과 어긋나지 않게만 한다 |
| 색 | [references/palettes.jsonl](references/palettes.jsonl) | 기본 `cobalt`. 장면이 다른 줄의 `use`와 맞을 때만 그 `id`. 다음 순서로 처음 맞는 줄에서 멈춘다. (1) 밤이면 `dusk`. (2) 낮이면 화면 넓이를 가장 많이 차지할 색이 주황·갈색 쪽이면 `terracotta`. (3) 나머지는 `cobalt` |
| spec 형식 예시 | [references/example/](references/example/) | 형식만 본다. 소재를 그대로 쓰지 않는다 |

라이브러리에 없는 팔레트가 필요하면 spec에 지어내지 말고, jsonl에 한 줄을 더하는 변경으로 사용자에게 제안한다.

## 작업 흐름

### 1. 장면 정하기

입력에서 장면 하나를 정한다(여러 장이면 장면마다). 요청이 바쁘거나 지친 상황(밤샘, 마감)이어도 그 상황의 조용한 한 순간을 고른다. 글만 있으면 지어낸 장면임을 결과에 밝힌다. 장면마다 `<id>`(영어 소문자·하이픈 짧은 이름, 예: `bakery-oven`)를 붙인다. 개념(예: 캐시, 로드밸런서)을 그려 달라는 요청이면 그 개념을 일상 장면 하나로 비유한다(예: 캐시는 계산대 옆 작은 선반에 자주 팔리는 병만 올려 둔 가게). 원근이 필요한 가깝다·멀다 비유는 피한다. 고른 비유는 결과 보고에 한 줄로 적는다.

### 2. spec 쓰기

출력 폴더는 사용자가 정한 곳, 없으면 작업 디렉터리 아래 `folk-output/<작업명>/`이고, build 전에 폴더를 먼저 만든다. 사람이 나오는 요청은 사람 대신 그 사람이 남긴 사물(세워 둔 자전거, 뒤로 밀린 의자)을 `subjects`에 둔다. 화면·간판·우편물처럼 글자가 들어갈 자리는 글자 없는 단색 면으로 쓰고(예: `a laptop with a blank screen`), 건물의 쓰임은 간판 대신 사물(우체통, 빵)로 보인다.

| 키 | 값 |
|---|---|
| `palette` | palettes.jsonl의 `id` |
| `canvas` | `16:9`(기본) 또는 `3:4`. 사용자가 세로 그림을 원하거나 높이 쌓인 소재(탑·계단·나무)가 주인공일 때만 `3:4` |
| `scene` | 어떤 순간인지 영어 6~40단어(공백으로 나눈 수, 경계 포함) |
| `setting` | 어디인지 영어 한 구절, 빈칸 불가, 마침표로 끝내지 않음 |
| `subjects` | 화면에서 알아봐야 할 사물·동물 영어 구절 1~5개(경계 포함), 대소문자·앞뒤 공백을 무시하고 중복 없이 |

### 3. 프롬프트 조립

`<skill>`은 이 `SKILL.md`가 있는 디렉터리다. 채점이 100점이 아니면 프롬프트를 쓰지 않고 FAIL 항목을 보여 준다. 고쳐서 다시 돌린다.

spec을 채점하고 프롬프트 파일을 쓰는 명령이다.

```bash
uv run --python 3.12 python -I <skill>/scripts/folk_prompt.py build folk-output/<작업명>/01_<id>.json -o folk-output/<작업명>/01_<id>.txt
```

채점표만 보려면 `build` 대신 `check`를 쓴다. 채점은 위 표의 값 외에 모델이 쓴 글(spec의 문자열만. 스크립트가 붙이는 스타일·DO NOT 문장은 세지 않는다)이 영어(ASCII)인지, 금지 낱말 세 묶음이 없는지 본다. 사람(human·person·people·man·woman·boy·girl·child·kid·face·portrait·hand·silhouette·crowd), 스타일을 깨는 말(photo·photorealistic·realistic·3d·cgi·render·anime·vector·neon·hdr·4k·8k·ultra·glossy·glow·gradient·perspective·cyberpunk), 그림 안 글자(text·letter·lettering·word·title·caption·sign·signboard·label·logo·signature·watermark). 낱말은 대소문자를 가리지 않고 단어 경계로 세며, -s·-es 복수형까지 센다(그 밖의 활용형은 세지 않는다).

스크립트나 jsonl을 고쳤으면 예시 txt를 `build`로 다시 쓰고 자체 검사가 `selftest ok`를 내는지 본다.

```bash
uv run --python 3.12 python -I <skill>/scripts/folk_prompt.py --selftest
```

### 4. 이미지 생성과 확인

사용자가 이미지까지 요청했을 때만, 사용자가 쓰는 이미지 생성 도구와 기본 모델에 `folk-output/<작업명>/01_<id>.txt` 전문을 그대로 넣어 spec의 `canvas` 비율로 만들고 같은 폴더에 `01_<id>.png`로 저장한다. 여러 장은 장마다 따로, 동시에 만들어도 된다.

여러 장이면 결과를 한 장으로 붙여 한 번만 보고 아래를 확인한다. 어긋난 장은 같은 프롬프트로 다시 생성한다.

- 사진·3D·매끈한 디지털 칠이 아니라 붓털·나이프 자국이 남은 두꺼운 물감 질감이 보인다.
- 모든 형태를 짙은 고동색 윤곽선이 감싸고, 기와·돌·잎 같은 반복 부분도 덩이마다 윤곽선으로 갈라져 있다.
- 소실점 원근 없이 납작하고, 매끈한 그러데이션·드리운 그림자·빛 번짐이 없다.
- 사람·얼굴·손이 없고, 그림 안에 읽히는 글자·서명·로고·워터마크가 없다.
- 바닥·탁자 윗면이 기울어 깊이가 생기지 않았다.
- 알려진 화가의 특정 작품이나 알려진 그림책·애니메이션의 장면과 닮지 않았다. 닮았으면 setting·subjects를 바꿔 build부터 다시 한다.

## 결과 보고

장면마다 spec 파일, 프롬프트 파일, 채점 점수, 고른 팔레트와 캔버스, 개념 요청이면 고른 비유를 적는다. 이미지를 만들었으면 경로와 위 확인 결과를, 만들지 않았으면 "이미지 생성하지 않음"을 적는다. 프롬프트는 한 개의 `text` 코드블록으로도 보여 준다.

## 하지 말 것

- 프롬프트 문장을 손으로 고치거나 라이브러리 밖 스타일 문구를 덧붙이는 것. 바꿀 것이 있으면 jsonl을 고친다.
- 사람·얼굴·손을 장면에 넣는 것, 실존 화가의 이름이나 특정 작품을 프롬프트에 쓰는 것.
- 그림 안에 글자(서명·간판·제목)를 넣는 것.
