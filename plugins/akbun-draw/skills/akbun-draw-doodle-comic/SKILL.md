# akbun-draw-doodle-comic

## 목적

짧은 이야기를 2·4·6컷 만화로 만든다. 그림은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md)과 같은 흰 종이 잉크 낙서 그림체이고, 움직이지 않는 정지 그림이다. 독자가 컷을 순서대로 읽도록 모든 컷 왼쪽 위에 번호(1, 2, 3 …)를 단다.

결과물은 출력 형식에 따라 PNG 한 장 또는 컷 수만큼의 PNG다. 같은 이름의 SVG도 함께 나와 Figma에서 글자를 고칠 수 있다.

## 범위

- 사용자가 직접 호출할 때 실행한다.
- 움직이는 장면(영상)은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md)의 범위다.
- 캐릭터와 글자는 매번 새로 디자인한다. 이미 있는 캐릭터·로고·글자 모양을 따라 그리지 않는다. 사용자가 지정한 캐릭터 스펙(예: [akbun-mascot-whale](../akbun-mascot-whale/SKILL.md))만 예외다.

## 스타일

motion-doodle SKILL.md의 아래 절을 그대로 따른다. 이 문서는 만화에만 필요한 규칙을 더한다.

- `### 그림체`, `### 선 굵기`, `### 색`, `### 음영`
- `### 캐릭터 설계 규칙`(선택 표, 표정 표, 팔다리 규칙)
- `### 손글씨`(SIL OFL 글꼴 `'Gaegu', 'Nanum Pen Script', sans-serif`)
- `### 말풍선과 주석`

motion-doodle의 `### 모션`과 시간 속성(`data-show`·`data-draw`·`data-write`)은 쓰지 않는다. 만화는 정지 그림이다.

## 출력 형식

| 형식 | 결과 | 컷 SVG viewBox | 쓰는 곳 |
|---|---|---|---|
| `page` | 모든 컷을 격자로 놓은 PNG 한 장(2컷 2052×636, 4컷 2052×1212, 6컷 2052×1788) | `0 0 1920 1080` | 블로그·문서에 한 장으로 넣을 때 |
| `instagram` | 컷마다 1장, 1080×1350(4:5) | `0 0 1080 1350` | 인스타툰(캐러셀) |
| `youtube` | 컷마다 1장, 1080×1080(1:1) | `0 0 1080 1080` | 유튜브 커뮤니티 게시물 |

- 근거 규격: Instagram은 폭 1080px, 비율 1.91:1~4:5를 원본 그대로 올리고, 한 게시물의 모든 사진은 같은 방향이어야 한다. 유튜브 커뮤니티 게시물 이미지는 1:1 정사각형을 권장하고, 한 게시물에 10장, 장당 16MB까지다. 유튜브는 픽셀 수를 정하지 않아 Instagram과 같은 폭 1080px을 쓴다.
- 형식 고르기: 사용자가 게시처를 말했으면 그 형식을 쓴다(인스타툰 → `instagram`, 유튜브 커뮤니티 → `youtube`, 블로그·한 장 → `page`). 말하지 않았으면 그리기 전에 질문 대화상자(AskUserQuestion 같은 선택지 질문 도구)로 세 형식 중 하나를 묻는다. 컷 그림의 비율이 형식마다 달라 그린 뒤에는 바꾸기 어렵다.
- 1장씩 형식의 파일 이름은 `<이름>_01.png`, `<이름>_02.png` …이다. 올리는 순서가 곧 번호 순서다.

## 컷 수와 컷의 역할

컷 수는 2, 4, 6 중 하나다. 사용자가 정하지 않았으면 이야기의 사건 수로 고른다.

| 컷 수 | 컷 역할(순서대로) | 고르는 기준 |
|---|---|---|
| 2 | 상황 → 반전 | 사건 하나와 뜻밖의 결과 하나 |
| 4 | 상황 → 시도 → 뜻밖의 일 → 마무리(웃음·깨달음) | 기본값 |
| 6 | 상황 → 시도 → 문제 → 다시 시도 → 뜻밖의 일 → 마무리 | 시도가 두 번 필요한 이야기 |

- `page` 형식의 배치: 2컷은 1행 2열, 4컷은 2행 2열, 6컷은 3행 2열이다. 읽는 순서는 왼쪽 → 오른쪽, 위 → 아래다.
- 첫 컷에서 인물과 장소를 보여 준다. 마지막 컷이 이야기의 결말(웃음·깨달음)이다.

## 컷 그리기 규칙

- 컷 SVG 하나 = 컷 하나. viewBox는 출력 형식 표의 값이다. 배경 사각형, 컷 테두리, 번호는 그리지 않는다. 스크립트가 그린다.
- 번호 자리를 비운다. 컷 왼쪽 위 `page`는 200×200, `instagram`·`youtube`는 140×140(컷 좌표) 안에 아무것도 두지 않는다.
- 같은 캐릭터는 모든 컷에서 같은 도형·색·비율이다. 컷 SVG를 손으로 따로 쓰지 말고 작은 생성 스크립트(출력 폴더에 둔다)에 캐릭터를 함수로 한 번만 정의하고, 컷마다 위치·크기·표정·팔만 바꿔 부른다.
- 4·6컷은 적어도 한 컷에서 주인공 크기를 다른 컷의 1.5배 이상으로 바꿔(가까이 보기) 같은 구도가 반복되지 않게 한다.
- 세로 형식(`instagram`)은 위 1/3에 말풍선, 아래 2/3에 인물을 두는 배치를 기본으로 한다.
- 한 컷의 말풍선은 2개 이하, 대사는 한 줄 10자 이하·2줄 이하다. 말풍선 순서도 왼쪽 → 오른쪽, 위 → 아래로 읽히게 둔다.
- 효과음 글자(예: "첨벙!")는 컷당 하나, `font-weight="700"`, 말풍선 없이 쓴다.

글자 크기는 최종 이미지에서 같은 크기로 보이도록 형식마다 다르다(`page`는 컷이 절반으로 줄어든다).

| 글자 | `page` 컷 좌표 | `instagram`·`youtube` 컷 좌표 |
|---|---|---|
| 말풍선 대사 | 80~90px | 44~52px |
| 효과음 | 130~160px | 72~90px |

- 말풍선 폭 = 글자 수 × 글자 크기 × 0.82 + 90, 높이 = 글자 크기 × 1.9. 꼬리 밑동은 아래 변 안쪽(양 끝 50px 제외)에 두고, 꼬리 끝은 말하는 캐릭터 머리에서 40~70px 떨어진 곳을 가리킨다.

## 작업 흐름

### 1. 형식과 컷 수

"출력 형식"과 "컷 수와 컷의 역할"대로 정한다. 형식을 모르면 그리기 전에 묻는다.

### 2. 컷 표

컷마다 번호, 역할, 장면(누가 어디서 무엇을), 대사, 캐릭터 표정·팔, 주인공 크기를 적는다. 캐릭터는 motion-doodle "캐릭터 설계 규칙" 표에서 고른 칸도 적는다.

### 3. 출력 폴더

사용자가 정한 폴더, 없으면 작업 디렉터리 아래 `comic-output/<작업명>/`. 생성 스크립트, 컷 SVG, `comic.json`, 결과물을 모두 여기에 둔다.

### 4. 컷 SVG 그리기

"컷 그리기 규칙"대로 생성 스크립트에서 컷 SVG를 만든다. 예시: [references/example/](references/example/) (스타일 확인용이다. 캐릭터·이야기를 그대로 쓰지 않는다).

### 5. comic.json

컷을 읽는 순서대로 적는다. 경로는 `comic.json` 기준 상대 경로다.

4컷을 인스타툰으로 렌더하는 comic.json 예시다.

```json
{
  "format": "instagram",
  "panels": ["panel_1.svg", "panel_2.svg", "panel_3.svg", "panel_4.svg"],
  "font_dirs": []
}
```

- `format`을 빼면 `page`다.
- 시스템 글꼴(`~/Library/Fonts` 포함)은 항상 읽는다. 그 밖의 글꼴 폴더만 `font_dirs`에 넣는다.
- 렌더 전에 Gaegu·Nanum Pen Script가 `~/Library/Fonts`에 있는지 확인한다. 없으면 sans-serif로 대체되어 손글씨 느낌이 사라지므로, Google Fonts 공식 배포처에서 설치할지 사용자에게 먼저 묻는다.

### 6. 렌더

`<skill>`(이 `SKILL.md`가 있는 디렉터리)의 스크립트로 렌더하는 명령이다.

```bash
uv run --python 3.12 <skill>/scripts/compose_comic.py comic-output/<작업명>/comic.json comic-output/<작업명>/comic
```

스크립트를 고쳤으면 아래 자체 검사가 `selftest ok`를 내는지 먼저 본다.

```bash
uv run --python 3.12 <skill>/scripts/compose_comic.py --selftest
```

### 7. 검수

이미지를 한 장만 열어 본다. `page`는 결과 PNG를, 1장씩 형식은 컷 PNG를 한 장으로 붙여서 본다.

1장씩 형식의 컷 PNG를 가로로 붙이는 명령이다. `tile=Nx1`의 N은 컷 수다.

```bash
ffmpeg -v error -y -pattern_type glob -i 'comic-output/<작업명>/comic_*.png' -vf "scale=360:-1,tile=4x1:color=white" -frames:v 1 comic-output/<작업명>/sheet.jpg
```

검수 항목은 다음과 같다. 어긋나면 컷 SVG를 고치고 다시 렌더한다.

- 결과 파일 수와 크기가 출력 형식 표와 같은가.
- 모든 컷 왼쪽 위 번호가 1부터 순서대로 보이고 그림에 가려지지 않는가.
- 같은 캐릭터가 모든 컷에서 같은 도형·색·비율인가.
- 말풍선 꼬리가 말하는 캐릭터를 가리키고, 말풍선·글자가 컷 밖으로 잘리지 않는가.
- 대사·효과음 글자 크기가 표 안에 있고 컷당 말풍선 2개 이하인가.
- 물건을 쥐거나 가리키는 팔 끝이 물건에 닿는가.
- 마지막 컷이 이야기의 결말인가.
- 캐릭터·글자·장면이 이미 알려진 캐릭터·마스코트·만화 장면과 닮아 보이지 않는가. 닮았으면 motion-doodle "캐릭터 설계 규칙" 표에서 두 칸 이상 바꿔 다시 그린다.

### 8. 완료 보고

출력 형식과 고른 이유, 컷 표(번호·역할·대사), 결과 파일 경로·크기, 검수 결과를 적는다. 검수하지 않은 항목은 "확인하지 않음"으로 적는다.

## 하지 말 것

- 컷 수를 2·4·6 밖으로 늘리거나 줄이지 않는다.
- 컷 SVG에 배경 사각형·컷 테두리·번호를 직접 그리지 않는다.
- 한 게시물(1장씩 형식)에 가로·세로·정사각형 비율을 섞지 않는다.
- 이미 있는 캐릭터·마스코트·로고·손글씨 글자 모양을 따라 그리지 않는다.
