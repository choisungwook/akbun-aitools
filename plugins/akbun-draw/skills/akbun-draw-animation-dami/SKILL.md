# akbun-draw-animation-dami

## 목적

아무 소재·주제를 dami 스타일의 짧은 세로 애니메이션(쇼츠)으로 만든다. 산출물은 배역 캐릭터 시트, 컷별 열쇠 그림(1–4장), 1080×1920 MP4 미리보기와 시트다. 이 skill이 고정하는 것은 그림체·색·빛·인물 그림체·카메라 문법·손글씨 자막과 말투이고, 무엇이 일어나는지(이야기·장소·배역·행동)는 입력에 맞춰 정한다.

모델은 프롬프트 문장을 직접 쓰지 않는다. 이야기 spec만 쓰고, 스타일 문장은 스크립트가 라이브러리에서 가져온다. 그래서 컷이 몇 개든 같은 그림체가 나온다.

## 무엇을 정할 때 어느 파일

| 정할 것 | 파일 | 고르는 법 |
|---|---|---|
| 그림체(모양·질감·인물·깊이·빛·강조색·분위기) | [references/style.jsonl](references/style.jsonl) | 고르지 않는다. 스크립트가 전부 넣는다. 읽고 장면이 이 규칙과 어긋나지 않게만 한다 |
| 색 | [references/palettes.jsonl](references/palettes.jsonl) | 컷마다 `use`가 시간·장소와 맞는 `id` 하나. 둘 이상 맞으면 광원이 장면을 지배하는 쪽. 맞는 것이 없으면 가장 가까운 것을 고르고 결과 보고에 적는다 |
| 카메라 | [references/cameras.jsonl](references/cameras.jsonl) | 컷마다 행동이 가장 잘 읽히는 `id` 하나. 같은 카메라를 연달아 3컷 넘게 쓰지 않는다. `drift`는 렌더 때 천천히 밀어 들어가는 비율이다 |
| 배역 특징 | [references/traits.jsonl](references/traits.jsonl) | 배역마다 특징 7개(성별·나이·키·체격·얼굴형·피부·옷 주색)를 `options`의 키로 고른다 |
| 참고 배역 | [references/characters.jsonl](references/characters.jsonl) | 배역을 짜는 형식 예시 6명. 그대로 쓰지 않는다. 새 배역은 성별·나이·키·체격·얼굴형·피부 중 2개 이상이 모든 참고 배역과 달라야 한다 |
| spec 형식 예시 | [references/example/](references/example/) | 형식만 본다. 소재·배역·자막을 그대로 쓰지 않는다 |

라이브러리에 없는 팔레트·카메라·특징이 필요하면 spec에 지어내지 말고, jsonl에 한 줄을 더하는 변경으로 사용자에게 제안한다.

## 작업 흐름

### 1. 이야기와 자막 정하기

입력에서 이야기를 컷으로 나눈다. 컷 하나는 2.5–4.5초(경계 포함)이고 장면의 뜻 하나만 담는다. 길이가 없으면 10초로 본다. 길이는 0.1초 단위로 반올림한 2.5–48초이고, 4.5초를 넘고 5초 미만이면 5초로 늘린다. 컷 수는 길이 4.5초 이하면 1, 그 밖에는 길이 ÷ 4를 올림이다. 컷 길이는 길이 ÷ 컷 수를 0.1초 단위로 내린 값이고, 모자란 0.1초들은 마지막 컷부터 앞으로 한 컷에 0.1초씩 더한다(예: 10초 → 3컷 3.3·3.3·3.4, 15초 → 4컷 3.7·3.7·3.8·3.8). 48초를 넘으면 이야기를 나눠 여러 편으로 만든다. 글만 있으면 일상적인 순간으로 이야기를 지어내고, 지어낸 것임을 결과에 밝힌다.

자막은 모델이 이 이야기를 위해 새로 쓴 문장만 쓴다. 노래 가사·영화·드라마 대사·책·광고 문구·다른 영상의 자막을 옮기거나 살짝 바꿔 쓰지 않는다. 말투는 장면을 조용히 지켜보는 3인칭 내레이션이다.

- 컷마다 1–2줄, 줄마다 2–16자(공백·문장부호 포함, 경계 포함), 한글·숫자·공백·`, . ! ? … ·`만. 따옴표와 대사(인물의 말)는 쓰지 않는다.
- 인물은 이름 대신 "그", "그녀", "이웃"처럼 부른다.
- 한 문장이 다음 컷으로 이어지면 앞 컷 마지막 줄을 연결어미(-고, -며, -는데, -면, 뒤에 쉼표 가능)나 `…`로 끝낸다. 둘을 함께 써도 된다.
- 마지막 컷 마지막 줄은 `-ㅂ니다`/`-습니다`로 맺는다.

### 2. 배역 짜기

이야기에 나오는 사람마다 배역을 하나 만든다(1–4명). 이야기마다 새로 짜고, 직전 이야기의 배역을 다시 쓰지 않는다. 한 이야기 안에서는 같은 사람이 끝까지 같은 배역이다.

| 키 | 값 |
|---|---|
| `id` | `p-` + 영어 소문자 역할 이름, 하이픈 가능(예: `p-clerk`, `p-night-nurse`) |
| `gender`, `age`, `height`, `build`, `face`, `skin`, `color` | traits.jsonl의 `options` 키. 역할과 이야기에서 자연스러운 값을 고르되, 한 이야기 안의 배역끼리는 실루엣이 구분되게 키·체격 중 하나 이상을 다르게 한다 |
| `hair` | 머리 모양·색과 안경·모자 같은 얼굴 둘레 특징, 영어 2–12단어 |
| `outfit` | 옷차림과 늘 지니는 물건, 영어 3–14단어. 색은 `color`가 정하므로 쓰지 않는다. 붉은색은 쓰지 않는다(붉은색은 `accent` 전용) |

### 3. spec 쓰기

출력 폴더는 사용자가 정한 곳, 없으면 작업 디렉터리 아래 `dami-output/<작업명>/`(작업명은 영어 소문자·하이픈 짧은 이름). 미리 만들고 그 안에 `story.json`을 쓴다. 키는 `{"title": 한국어 제목, "cast": [배역, ...], "shots": [컷, ...]}`이고 컷은 아래 키를 가진다.

| 키 | 값 |
|---|---|
| `id` | 영어 소문자·숫자·하이픈 짧은 이름, 컷끼리 중복 없이 |
| `palette`, `camera` | jsonl의 `id` |
| `scene` | 무슨 일이 일어나는지 영어 6–40단어(공백으로 나눈 단어 수, 경계 포함). 인물은 역할로 부른다(a librarian, the neighbor). 인물마다 무엇을 하는지의 세부는 `action`에 쓴다 |
| `setting` | 어디인지 영어 한 구절. 시간대를 넣으면 팔레트와 맞춘다 |
| `characters` | `[{"id": 배역 id, "action": 영어 3단어 이상}]`, 카메라의 `chars` 범위(경계 포함) 안. 배역의 생김새·옷은 늘 붙으므로 `action`에서 되풀이하지 않는다. `passing-foreground`에서는 목록 첫 인물이 카메라 앞에서 잘리는 인물이 된다. `close-detail`에서도 손의 주인 하나를 넣는다 |
| `props` | 장면의 사물 영어 구절 2–10개, 중복 없이. 여러 컷에 이어지는 사물은 컷마다 같은 구절로 쓴다. `props`·`accent`에 글자가 보이는 사물(간판·라벨·포스터·메뉴·신문)은 쓰지 않는다. 책·공책·화면은 프롬프트가 글자 없이 그리게 하므로 써도 된다 |
| `accent` | 프레임에 하나뿐인 붉은 물체, 영어 1–6단어(예: `a red thermos`). 옷·소품 어느 것이든 되고, 한 켤레·한 쌍은 하나로 센다(`a pair of red gloves`). `scene`·`action`에서는 불러도 되지만 `props`에 다시 쓰지 않는다. 이어지는 사물이 붉은색이면 그 사물이 나오는 모든 컷의 `accent`를 같은 구절로 쓴다 |
| `caption` | 1번에서 쓴 자막 줄 목록 |
| `seconds` | 컷 길이(초), 2.5–4.5 |
| `poses` | 첫 장 다음에 넘길 자세 0–3개, 각 영어 3–40단어(공백으로 나눈 수, 하이픈으로 이은 말은 한 단어). 장 수 = 1 + 자세 수. 걷기·일어서기처럼 몸 전체가 움직이는 컷은 3개(4장), 손·고개·표정만 바뀌는 컷은 1개(2장), 정지한 컷은 0개(1장). 자세마다 그 순간의 모습 전체를 쓴다. 편집 모델은 이 문장만 받으므로 인물을 생김새로 부른다(the tall man in the slate blue coat). `close-detail`이면 손·물건의 변화만 쓴다 |

영어 칸(`scene`·`setting`·`action`·`props`·`accent`·`poses`)에는 배역 id와 참고 배역 이름을 쓰지 않는다. 그림 모델은 id를 모른다.

그림 수는 배역 수 + 컷 수 + 자세 수다. 예시 이야기(배역 2, 3컷, 자세 4·2·4장)는 2 + 3 + 7 = 12장이다.

### 4. 채점과 프롬프트

`<skill>`은 이 `SKILL.md`가 있는 디렉터리다. 채점이 100점이 아니면 프롬프트를 쓰지 않고 FAIL 항목을 보여 준다. 고쳐서 다시 돌린다. 채점은 위 두 표의 수치 외에 컷 수 1–12, 컷 id 중복, 배역이 모두 한 컷 이상 나오는지, 참고 배역과 2개 이상 다른지, 같은 카메라 4컷 연속, 마지막 줄 `니다` 종결, 영어 칸의 ASCII·id·글자 소품, 금지 낱말(outline·line art·3d·photorealistic·realistic·anime·chibi·neon·cel-shaded)을 본다. 자막이 새로 쓴 문장인지, 연결어미 규칙, 3인칭 말투는 채점이 못 보므로 직접 확인한다.

spec을 채점하고 spec 옆에 배역 시트 `cast_<id>.txt`, 컷 첫 장 `NN_<id>.txt`, 자세 `NN_<id>_<k>.txt`(k = 2부터), 생성 순서 `order.txt`를 쓰는 명령이다.

```bash
uv run --python 3.12 --with pillow python -I <skill>/scripts/dami.py prompts dami-output/<작업명>/story.json
```

채점표만 보려면 `prompts` 대신 `check`를 쓴다. 스크립트나 jsonl을 고쳤으면 `--selftest`가 `selftest ok`를 내는지 먼저 본다.

### 5. 그림 생성

사용자가 쓰는 이미지 생성 도구와 기본 모델로 `order.txt`의 세 단계를 차례로 만든다. 단계 안의 그림은 동시에 만든다. 한 줄이 한 장이고, 프롬프트 파일 전문을 바꾸지 않고 넣어 적힌 비율로 만들며, `편집:` 그림을 고치고 `참조:` 그림을 참조 이미지로 붙여 적힌 PNG 이름으로 spec 옆에 저장한다. 이미 있는 PNG는 건너뛴다.

1. 배역 시트·자막: 배역마다 전신 정면 한 장, 컷마다 흰 바탕에 자막을 손글씨로 그린 16:9 한 장(`<컷>_caption.png`). 자막은 폰트로 얹지 않고 이미지 모델이 그린다.
2. 컷 첫 장: 그 컷에 나오는 배역의 시트를 참조 이미지로 붙인다.
3. 자세: 그 컷 첫 장과 배역 시트를 붙여 첫 장을 편집한다. 배경과 카메라는 첫 장 그대로이고 자세만 바뀐다.

세 단계가 끝나면 `order.txt`의 PNG가 모두 있는지 보고, 빠진 그림은 다시 만든다.

### 6. 렌더와 확인

렌더 전에 ffmpeg가 설치돼 있어야 한다. 없으면 스크립트가 멈추고, 설치할지 사용자에게 먼저 묻는다.

그림으로 9:16 영상 `dami.mp4`와 열쇠 그림마다 한 프레임씩 붙인 `sheet.jpg`를 spec 옆에 만드는 명령이다.

```bash
uv run --python 3.12 --with pillow python -I <skill>/scripts/dami.py render dami-output/<작업명>/story.json
```

판형은 스크립트가 고정한다: H.264 MP4(쇼츠 업로드와 편집기 가져오기에 바로 쓰는 형식), 30fps, 흰 바탕 1080×1920, 위에서 216px 아래에 컷 그림 1080×1080, 그 아래 자막 그림을 1080×608(16:9)로 채워 자른 것. 컷 사이는 전환 효과 없는 하드컷이다. 컷 안에서는 카메라 `drift`만큼 천천히 밀어 들어가며, 열쇠 그림을 컷 길이 ÷ 장 수 간격으로 넘기고 넘길 때 3프레임 동안 교차 전환한다.

스크립트는 실제로 쓴 프레임 수가 컷 길이 합 × 30(컷마다 반올림)과 다르면 종료 코드 1로 끝난다. 30fps는 고정이다. 23.976·29.97fps 타임라인에 넣으면 편집기가 변환해 프레임 수가 달라지므로, 편집기 타임라인을 30fps로 만들거나 그림 PNG로 다시 조립한다. `sheet.jpg`와 배역 시트를 한 장으로 붙여 한 번만 보고 아래를 확인한다. 어긋난 그림은 그 PNG를 지우고 그 그림을 다시 만들되 그림마다 2번까지만 하고, 그 그림에서 만든 그림도 함께 지운다(컷 첫 장이면 그 컷의 `_2`–`_4`, 배역 시트면 그 배역이 나오는 컷 그림 전부). 그래도 어긋나면 그 항목을 결과 보고에 적는다. 알려진 영화·만화 캐릭터와 닮았으면 그 배역의 특징을 2개 이상 바꾸고, 그 배역의 시트와 나오는 컷 그림을 지운 뒤 prompts부터 다시 한다.

- 외곽선·잉크 선이 없고 형태가 색 면 경계로만 나뉜다.
- 붉은 물체가 컷마다 하나뿐이고 나머지 색은 차분하다.
- 멀리 있는 것이 안개처럼 옅어진다.
- 같은 배역이 모든 컷에서 시트와 같은 체형·머리·옷 색이다.
- 한 컷의 열쇠 그림끼리 배경·카메라가 같고 자세만 다르다.
- 컷 그림 안에 글자가 없고, 자막 그림의 글씨가 spec `caption`과 한 글자도 다르지 않으며 줄바꿈 위치가 같고 다른 글자가 없다. 틀린 자막 그림은 그 PNG만 지우고 다시 만든다.

## 결과 보고

spec 경로, 채점 점수, 배역마다 고른 특징, 컷마다 고른 팔레트·카메라·인물·장 수·자막, 그림 수, 영상 경로와 형식(H.264 MP4, 1080×1920, 30fps, 프레임 수, 쇼츠 업로드·편집기 가져오기에 바로 쓰려고 고른 형식), 시트 경로, 위 확인 결과를 적는다. 이미지를 만들지 않았으면 "이미지 생성하지 않음"을 적고 프롬프트 파일 목록을 보여 준다.

- 참고 배역이나 기존 작품의 인물·장면·자막을 그대로 쓰는 것.
- 그림 안에 글자(제목·간판·말풍선)를 넣는 것.
