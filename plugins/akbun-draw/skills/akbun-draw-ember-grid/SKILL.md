# akbun-draw-ember-grid

## 언제 쓰나

추상적인 개념(신호, 상태, 값의 변화, 두 경우의 비교)을 숫자·선·사물 몇 개로 차분하게 풀어 주는 장면에 쓴다. 화면 요소가 적고, 한 요소가 다음 설명으로 모양을 바꾸며 이어지는 흐름이 맞는 내용이다. 무엇을 어디에 몇 개 둘지는 설명할 내용이 정한다.

- 카드·칸으로 시스템 상태를 보여 주는 장면은 [akbun-draw-slate-marker](../akbun-draw-slate-marker/SKILL.md), 손채색 비유 장면은 [akbun-draw-night-gouache](../akbun-draw-night-gouache/SKILL.md), 같은 스타일을 Resolve에서 고칠 수 있는 타임라인으로 만드는 일은 [akbun-davinciresolve-explainer-ember-grid](../../../akbun-editvideo/skills/akbun-davinciresolve-explainer-ember-grid/SKILL.md)의 범위다.
- 사람 얼굴·실사 인물을 그리지 않는다. 실제 제품 로고도 그리지 않는다.

## 캔버스

| 용도 | size |
|---|---|
| 일반 영상 (기본) | `[1920, 1080]` |
| 쇼츠·릴스 | `[1080, 1920]` |

아래 px 값은 두 크기에서 그대로 쓴다. 그 밖의 크기는 짧은 변 ÷ 1080을 곱하고 0.5px 단위로 반올림한다.

## 스타일

### 색

| 이름 | 값 | 쓰임 |
|---|---|---|
| EMBER | `#181212` | 캔버스. spec `background`, `"grain": 0.02` |
| GRID | `#221B19` | 바탕 격자선 |
| VIGNETTE | `#060404` | 가장자리 어둡게(바탕 비네트의 끝 색) |
| WHITE | `#FAFAFA` | 숫자·단어·선의 기본 |
| DIMMED | `#6E6866` | 끝난 요소, 선 끝 흐림 |
| LIME | `#88B000` | 좋은 쪽·성공·같음·더해지는 쪽 라벨 |
| COBALT | `#3C78F0` | 나쁜 쪽·실패·다름·상쇄되는 쪽 라벨 |
| GOLD | `#E4C072` | 사물 밝은 면(금속·부품) |
| GOLD_SHADE | `#7E663C` | GOLD 사물의 어두운 면 |
| CREAM | `#F0D2A8` | 사물 밝은 면(플라스틱·종이) |
| CREAM_SHADE | `#A8916E` | CREAM 사물의 어두운 면 |
| PLUM | `#8A2D6E` | 사물 포인트 면 하나 |

- 글자·선은 WHITE가 기본이다. 라벨 색은 LIME·COBALT 둘뿐이고, 라벨 하나만 쓸 때도 표의 뜻을 따른다. 이름표처럼 뜻이 없는 글자는 라벨이 아니라 설명 글자(WHITE)다.
- 사물 색(GOLD·CREAM·PLUM과 그 SHADE)은 사물 그림에만 쓰고 글자·선에 쓰지 않는다.

### 바탕

모든 포즈의 맨 앞에 `<g id="ground">`를 둔다. 투명 MOV로 렌더할 때는 이 묶음만 뺀다.

- 격자: GRID 1px 직선, 간격 48px, 화면 전체. 첫 선은 x = 0, y = 0.
- 비네트: 화면 전체 사각형 하나에 `radialGradient cx="50%" cy="50%" r="75%"`(기본 objectBoundingBox). stop은 0과 0.7에서 VIGNETTE `stop-opacity="0"`, 1에서 `stop-opacity="0.75"`.
- 바탕은 장면이 바뀌어도 똑같다.

### 글꼴

모두 SIL OFL 글꼴인 Pretendard 하나를 쓴다(`'Pretendard', sans-serif`).

| 대상 | 굵기 | 크기·모양 |
|---|---|---|
| 큰 숫자·핵심 단어 | 800 | 160~260px, WHITE. 영어 단어는 원래 대소문자 |
| 작은 숫자·단어(옮겨 가서 다음 설명의 라벨이 된 것) | 800 | 56~80px, WHITE 또는 DIMMED. 옮겨 간 뒤에는 큰 숫자 개수에 세지 않는다 |
| 라벨 | 700 | 24~30px, LIME 또는 COBALT, 영어는 대문자, `letter-spacing="1"` |
| 짧은 설명 글자 | 600 | 18~22px, WHITE 또는 DIMMED |

- 한 화면의 글자는 큰 숫자·단어 1~2개와 라벨·설명 몇 개다. 문장을 화면에 쓰지 않는다.
- 렌더 전에 `uv run --python 3.12 <doodle>/scripts/render_doodle.py --fonts "Pretendard"`가 `ok`인지 본다. `missing`이면 렌더하지 말고 설치를 묻는다(배포처 github.com/orioncactus/pretendard 릴리스).

### 선

- 선은 채움 없는 `<path>`, WHITE 5px, `stroke-linecap="round"` `stroke-linejoin="round"`. 작은 도식 속 선은 3px.
- 긴 선(시작점과 끝점 사이 직선 거리가 화면 긴 변의 40% 이상)은 양 끝 12%가 DIMMED로 흐려진다: `linearGradient gradientUnits="userSpaceOnUse"`(x1·y1·x2·y2 = 선의 시작점·끝점, stop 0%·100% DIMMED, 12%·88% WHITE)를 stroke로 쓴다. 그보다 짧은 선은 단색 WHITE다. 사물을 두르는 선도 5px다.
- 곡선은 부드러운 곡선(`C`·`Q`)으로 쓰고, 꺾인 직선 조각으로 흉내 내지 않는다.
- 선을 여러 개 겹칠 때는 같은 굵기·같은 색으로 겹치고, 겹친 수가 의미를 갖게 한다(예: 많아질수록 화면을 덮음).

### 사물

- 납작한 벡터 그림이다. 외곽선 없이 밝은 면 + 어두운 면(SHADE) 두 단계로만 칠한다. 그라데이션·그림자·광택을 넣지 않는다.
- 사물은 한 화면에 1~2개, 사물의 긴 변이 화면 짧은 변의 15~35%.
- 사물의 작은 세부(핀, 키, 화면 테두리)는 같은 SHADE 색 사각형·원으로 단순하게 그린다.

### 선택 부품

기본으로 쓰지 않는 선택 장치다. 장면이 요청할 때만 영상 전체에서 한 번까지 쓴다.

| 부품 | 모양 |
|---|---|
| 입체 단어 | 핵심 단어 하나를 Pretendard 900으로 쓰고, 같은 글자를 COBALT 짙은 면 `#0848D8`로 오른쪽 아래 6px씩 4번 겹친 뒤 맨 위 면을 `#5088F8`로 둔다 |
| 곡선 위 글자 | 짧은 설명 글자를 `<textPath>`로 곡선을 따라 쓰고, 같은 곡선 아래에 LIME·COBALT 짧은 선 조각을 번갈아 둔다 |

### 모션

매끄러운 움직임이다. spec의 `drawings_per_second`는 `fps`와 같게 한다(예: 30, 30).

| 움직임 | 방식 | 길이 |
|---|---|---|
| 숫자·단어·사물 등장 | `data-fade` | 0.3초 |
| 선 그리기 | `data-draw`. 흐름의 시작 끝에서 시작 | 선 길이(px) ÷ 800초를 0.05초 단위로 올림, 최소 0.4초 |
| 라벨·설명 글자 | `data-fade` | 0.2초 |
| 흐려지기 | 같은 글자·선의 DIMMED 사본을 바로 위에 두고 `data-fade`. 사물은 같은 도형들을 DIMMED 한 색으로 칠한 실루엣 사본 | 0.4초 |
| 바뀌어 이어지기 | `data-move="t0 t1 dx dy s cx cy"`. s < 1이면 작아지며 다음 설명의 라벨 자리로, s = 1이면 크기 그대로 옮겨 간다(사물이 오감) | 0.6초 |
| 늘어나기 | 같은 선·요소의 사본을 차례로 `data-show` | 사본 사이 0.08초 |
| 사라짐 | 그 요소가 없는 포즈로 교체 | 즉시 |

- `data-move`는 요소와 그 흐려지기 사본을 함께 감싼 `<g>`에 건다. cx·cy는 요소의 중심이고, 글자는 cx = 가운데 정렬 x, cy = 기준선 − 0.35 × 글자 크기로 센다. 다음 포즈는 `data-move` 끝 시각에 시작하고, 그 요소를 옮긴 자리·크기로 시간 속성 없이 다시 그린다: x′ = cx + dx + s × (x − cx), y′ = cy + dy + s × (y − cy), 글자 크기′ = s × 글자 크기. 선은 굵기가 같이 줄어드니 s = 1로만 옮긴다.
- 빌드(`data-fade`·`data-draw`·`data-move`)는 동시에 둘까지다. 한 요소에 걸린 페이드와 이동도 각각 한 빌드다. 포즈와 상관없이 장면 시각으로 센다. `data-show`와 포즈 교체는 세지 않는다. 신호 단어에 맞추느라 셋이 겹치면 선 그리기를 최소 0.4초까지 줄이고, 그래도 겹치면 그 요소를 가장 가까운 다른 신호 단어로 옮긴다.
- 마지막 빌드는 장면 끝 1.0초 전에 끝낸다. 대본 마지막 단어에 묶인 요소 때문에 지킬 수 없으면 0.5초 전까지 허용한다. 장면 하나는 25초 이하다.
- 카메라는 쓰지 않는다. 장면 전환은 하드 컷이고, 앞 장면 마지막 요소가 다음 장면에서 이어지면 같은 자리·같은 크기로 처음부터 보이게 둔다.
- 시각은 대본의 신호 단어에 묶는다. 신호 단어는 그 요소의 이름이나 그 변화를 말하는 첫 단어다. 이 skill의 수치가 링크한 다른 skill과 다르면 이 skill을 따른다. 음절 세는 법과 녹음 후 다시 맞추는 법은 [code-window-lilac의 녹음 전후 시각 맞추기](../akbun-draw-code-window-lilac/SKILL.md#녹음-전후-시각-맞추기)를 따른다.

## 작업 흐름

`<doodle>`은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md) 디렉터리다. 출력 폴더는 사용자가 정한 곳, 없으면 `ember-grid-output/<작업명>/`.

1. **장면 표**: 장면마다 id, 길이, 보여 줄 변화, 큰 숫자·단어, 선, 사물, 라벨 색, 요소별 신호 단어와 시각을 적는다.
2. **SVG 포즈**: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H">`로 시작하고 `width`·`height`·`filter`·`<image>`를 넣지 않는다. 맨 앞은 `<g id="ground">`. 포즈가 여러 장이면 공통 부분을 한 번만 정의하는 작은 생성 스크립트(출력 폴더)로 만들어 포즈 사이 좌표를 똑같이 맞춘다. 점선을 그려지게 하려면 `stroke-dasharray`를 그 `<path>`에 직접 둔다.
3. **spec.json**: `"background": "#181212"`, `"grain": 0.02`, `fps`와 `drawings_per_second`는 놓을 타임라인 fps(정수). 23.976·29.97처럼 정수가 아니면 렌더하지 말고 사용자에게 알린다.
4. **렌더**: 기본은 `uv run --python 3.12 <doodle>/scripts/render_doodle.py <출력>/spec.json <출력>/out.mp4 --stills <출력>/stills`. 배경을 따로 작업한다는 신호가 있으면 렌더 전에 [motion-doodle의 출력 형식](../akbun-draw-motion-doodle/SKILL.md#2-출력-형식)대로 "MOV(투명 배경)"와 "MP4(바탕 포함)" 두 선택지로 묻고, MOV를 고르면 `ground` 묶음을 뺀 포즈로 `out.mov`를 렌더한다.
5. **검수**: 아래 숫자 검사를 먼저 하고, 스틸을 한 장으로 붙여 한 번만 본다.

예시: [references/example/](references/example/)는 DB 조회(120ms)와 캐시 조회(8ms)의 속도 차이를 세로 가운데 축 구도의 두 포즈로 설명한 장면이다. 스타일 확인용이며 배치·문구를 그대로 쓰지 않는다.

### 검수

SVG에 색 표 밖의 색이 없는지 보는 명령이다. 선택 부품을 쓰지 않았다면 아무것도 출력하지 않아야 한다.

```bash
grep -ohiE '#[0-9a-f]{6}' <출력>/*.svg | tr a-f A-F | sort -u | grep -vE '^#(181212|221B19|060404|FAFAFA|6E6866|88B000|3C78F0|E4C072|7E663C|F0D2A8|A8916E|8A2D6E)$'
```

- 렌더 프레임 수 = 장면 길이 합 × fps.
- `--fonts "Pretendard"`가 `ok`.
- 포즈마다 큰 숫자·단어 ≤ 2개, 사물 ≤ 2개, 라벨 색은 LIME·COBALT 안.
- 동시 빌드 ≤ 2, 마지막 빌드가 장면 끝 1.0초(예외 0.5초) 전에 끝나는가.
- `data-move`가 끝난 자리·크기와 다음 포즈의 같은 요소 자리·크기가 1px 안에서 같은가.
- 시트에서: 글자가 잘리거나 겹치지 않는가, 사람 얼굴·실제 로고·알려진 캐릭터와 닮은 그림이 없는가, 같은 의미가 장면마다 같은 라벨 색인가.

## 완료 보고

출력 경로, 출력 형식(MP4·MOV)과 고른 이유, 장면 표(신호 단어·녹음 전 시각·녹음 후 시각), 렌더 프레임 수, 글꼴 검사, 색 검사 출력, 검수 결과를 적는다. 확인하지 않은 항목은 "확인하지 않음"으로 적는다. Resolve에 놓아 달라고 하면 [motion-doodle의 Resolve 배치](../akbun-draw-motion-doodle/SKILL.md#resolve-배치)를 따른다.

## 하지 말 것

- 배치는 장면이 설명하는 관계로 고른다: 순서·흐름(방향은 위→아래, 아래→위, 오른쪽→왼쪽, 대각선 모두 된다), 가운데와 둘레(하나가 여럿과 이어짐), 안과 밖(포함·겹침), 나란히 견주기(둘 비교), 하나만 크게(한 값·한 대상). 흐름을 기본으로 왼쪽→오른쪽에 두지 않고, 이어지는 두 장면이 같은 배치였으면 다음 장면은 다른 배치를 고른다.
- 바탕 비네트와 선 끝 흐림 말고는 그라데이션을 쓰지 않는다. 후광(glow)·그림자·3D 기울기도 쓰지 않는다(선택 부품의 입체 단어는 예외).
- 사람 얼굴, 실사 사진, 실제 로고를 넣지 않는다.
