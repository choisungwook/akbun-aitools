# akbun-draw-motion-doodle

## 목적

설명 영상 사이에 끼우는 짧은 손그림 애니메이션 장면(1~25초)을 만든다. 화면은 거의 흰 종이에 검은 잉크 선으로 그린 단순한 캐릭터·소품·손글씨다. 그림은 흔들리지 않는다. 사람이 그린 애니메이션처럼 보이게 하는 것은 두 가지다. 캐릭터는 사이 동작 없이 포즈를 바꿔 끼우고, 설명 요소는 손이 쓰듯 선과 글자가 차례로 나타난다. 둘 다 초당 12장으로 뚝뚝 끊긴다.

결과물은 영상 파일 하나다. 기본은 MP4이고, Resolve에서 쓰더라도 종이 배경을 그대로 쓰면 MP4다.

| 출력 | 형식 | 쓰는 곳 |
|---|---|---|
| `.mp4` (기본) | H.264, 종이 배경 `#FEFEFE` | 낙서 장면이 화면 전체를 채울 때. 어느 편집기·플레이어에서나 열리고 파일이 작다 |
| `.mov` | ProRes 4444, 투명 배경 | 낙서만 다른 영상·배경 위에 겹칠 때. Resolve가 투명을 안정적으로 인식한다. 파일이 크다(10초 1080p 수백 MB) |

MP4(H.264)는 투명을 담지 못한다. 투명이 필요하면 MOV다.

## 범위

- 사용자가 직접 호출할 때 실행한다. 이 스타일의 장면을 새로 만들거나, 만든 장면을 Resolve 타임라인에 놓을 때 쓴다.
- Inspector에서 글자를 고치는 Fusion 타이틀 장면은 [akbun-davinciresolve-explainer](../../../akbun-editvideo/skills/akbun-davinciresolve-explainer/SKILL.md)의 범위다. 이 스킬은 렌더된 클립을 만든다. 글자를 고치려면 SVG를 고쳐 다시 렌더한다.
- 캐릭터와 글자는 아래 "스타일" 규칙으로 매번 새로 디자인한다. 이미 있는 캐릭터·로고·글자 모양을 따라 그리지 않는다.

## 스타일

모든 숫자는 1920×1080 기준이다. 다른 해상도는 세로 길이 비율로 늘이거나 줄인다.

### 그림체

- 흰 종이 위 펜 낙서. 굵은 검정 마커로 한 번에 그은 듯한 선과 평면 채움만 쓴다. 그라데이션, 질감, 그림자 흐림, 테두리 광, 사진, 3D는 쓰지 않는다.
- 선은 자로 그은 직선이 아니다. 긴 직선도 살짝 휘게 그린다(SVG `C`·`Q` 곡선, 끝점을 2~6px 어긋나게). 박스도 네 모서리가 정확한 직각이 아니다.
- 선 끝과 꺾임은 둥글게(`stroke-linecap="round"`, `stroke-linejoin="round"`).
- 형태는 원·둥근 사각형·물방울·막대처럼 단순한 도형 몇 개로 끝낸다. 손가락, 옷 주름, 머리카락 같은 세부는 그리지 않는다.

### 선 굵기

| 대상 | 굵기 |
|---|---|
| 캐릭터·소품 외곽선, 손글씨 획 | 8~10px |
| 안쪽 세부(빗금, 눈금, 아이콘 속 줄) | 4~5px |
| 큰 화살표, 차트 축 | 7~8px. 큰 화살표는 회색, 차트 축은 INK |
| 주석 화살표 | 4~5px, 회색 |
| 말풍선 외곽선 | 6~7px |

### 색

| 이름 | 값 | 쓰임 |
|---|---|---|
| PAPER | `#FEFEFE` | 배경. 렌더 스크립트가 깐다. SVG에 배경 사각형을 그리지 않는다 |
| INK | `#000000` | 모든 외곽선, 손글씨, 눈 |
| WHITE | `#FFFFFF` | 캐릭터·소품 안쪽 채움(종이보다 아주 조금 밝다) |
| SHADE | `#E0E0E0` | 흰 면의 그늘 |
| ARROW | `#B0B0B0` | 화살표, 보조 선, 바닥 그림자 |
| ACCENT | `#E89850` | 강조색 하나. 캐릭터 몸통, 강조할 단어 |
| ACCENT_SHADE | `#E05018` | ACCENT 면의 그늘 |
| ACCENT2 | `#7CD0FC` | 보조 강조색(선택). 색으로 구분해야 하는 두 번째 대상 하나. 그늘 없이 평면으로만 쓴다 |

- 한 영상의 강조색은 ACCENT 하나가 기본이다. 같은 화면의 두 대상을 색으로 구분해야 할 때만 두 번째 대상에 ACCENT2를 쓴다. 강조색을 칠하는 자리는 "캐릭터 설계 규칙" 표에서 고른다. 실제 브랜드 로고를 그리지 않는다.
- 차트에서는 주목할 선이나 막대 하나만 ACCENT, 나머지는 INK다.
- 화면 면적의 85% 이상은 종이색이다. 색은 작은 면적에만 쓴다.

### 음영

- 둥근 면은 한쪽(오른쪽 또는 아래)에 초승달 모양 그늘 한 덩어리를 평면으로 칠한다. 흰 면은 SHADE, 강조색 면은 ACCENT_SHADE.
- 상자처럼 평평한 면이 꺾이는 물체는 옆면 하나를 통째로 SHADE로 칠하고, 그 옆면은 물체 외곽선의 일부로 테두리를 긋는다.
- 그늘은 외곽선 안쪽에 채움만 두고 테두리를 따로 긋지 않는다. 그늘을 먼저 칠하고 외곽선을 맨 위에 다시 그어 경계를 덮는다.
- 그물·바구니·천처럼 면에 무늬가 필요하면 4~5px 빗금(교차 사선)으로 표현한다.
- 서 있는 캐릭터·물건 발밑에는 바닥 그림자를 둔다. ARROW 색 평면 타원, 외곽선 없음, 폭은 발 사이 거리의 1.3~1.6배, 높이는 폭의 1/5. 그림자는 캐릭터보다 먼저(아래에) 그린다. 떠 있거나 책상 위에 놓인 물건은 그림자를 생략한다.

### 캐릭터 설계 규칙

캐릭터는 영상마다 새로 디자인한다. 모델마다 같은 캐릭터로 몰리지 않도록 아래 표에서 캐릭터마다 한 칸씩 골라 장면 표에 적고, 같은 영상의 두 캐릭터는 세 열 중 두 열 이상을 다르게 고른다.

| 머리·몸통 | ACCENT 위치 | 성격 소품 |
|---|---|---|
| 물방울 일체형(머리가 곧 몸통) | 몸통 전체 | 짧은 눈썹 두 개 |
| 세로 타원 일체형 | 모자·두건 | 머리 위 땀방울 하나 |
| 둥근 사각형 머리 + 막대 몸통 | 목도리 | 볼 빗금 |
| 콩(땅콩) 모양 일체형 | 머리 위 더듬이·잎 끝 | 머리 위 물음표·느낌표 |
| 사람이 아닌 대상의 도형(서버 상자, 문서, 원통) | 대상의 한 부분(손잡이, 뚜껑, 띠) | 눈 모양만 바꿈(반쯤 감김, 큰 원) |

- 성격 소품은 표에 있는 것만 쓴다. 안경·모자·옷 같은 소품을 표 밖에서 더하지 않는다.
- 사용자가 기존 캐릭터 스펙(예: [akbun-mascot-whale](../akbun-mascot-whale/SKILL.md))을 지정하면 표 대신 그 스펙의 형태·비율·눈·입을 지키고, 선 굵기·색만 이 스타일 표로 바꾼다. 그 캐릭터에 ACCENT 자리가 없으면 함께 나오는 소품이나 다른 캐릭터에 ACCENT를 둔다.
- 머리(또는 일체형 몸통)는 단순한 도형 하나이고 전체 키의 1/3 이상을 차지한다.
- 눈은 두 개다.

표정은 눈 모양과 선 하나짜리 입으로만 만든다. 입을 검게 채우지 않는다.

| 표정 | 눈 | 입(4~6px 선) |
|---|---|---|
| 기본 | 점 | 없음 |
| 말함 | 점 | 작은 빈 원. 포즈마다 원 크기만 바꾼다 |
| 놀람 | 흰 원 안에 점(지름 2배) | 작은 빈 원 |
| 화남·불만 | 점 + 눈 바로 위 짧은 가로선 | 짧은 직선 |
| 걱정·곤란 | 점 + 머리 옆 땀방울 하나 | 물결선 |
| 기쁨 | 위로 볼록한 짧은 호(∩) | 위로 휜 짧은 호 |

- 팔·지느러미 같은 팔다리는 얼굴(눈·입)을 가리지 않게 몸 외곽선 밖으로 뻗는다.
- 팔다리는 8~10px 선 하나씩. 관절과 손은 그리지 않는다. 물건을 쥐거나 가리키는 팔은 선 끝을 물건 외곽선에 닿게 그린다(떠 있는 팔 금지). 이 접점은 80px 간격 규칙의 예외다.
- 사람이 아닌 대상(도구, 서비스, 파일)은 그 대상을 떠올리게 하는 도형에 눈과 팔다리를 붙여 캐릭터로 만든다. 실제 제품 로고·아이콘 모양을 쓰지 않는다.

### 손글씨

글꼴과 SVG 속성으로 손으로 쓴 느낌을 만든다.

- 글꼴은 저작권 없는 SIL OFL 글꼴만 쓴다. `font-family`는 항상 `'Gaegu', 'Nanum Pen', 'Nanum Pen Script', sans-serif`로 지정한다. 둘 다 Google Fonts에서 무료다. Nanum Pen Script 글꼴 파일의 실제 family 이름은 `Nanum Pen`이라 둘 다 적는다. 유료·상용 글꼴이나 라이선스가 불분명한 글꼴 이름을 넣지 않는다.
- 렌더하는 컴퓨터에 글꼴이 없으면 resvg가 sans-serif로 대체해 손글씨 느낌이 사라진다. 렌더 전에 `uv run --python 3.12 <skill>/scripts/render_doodle.py --fonts "Gaegu"`의 JSON 값이 `"ok"`인지 보고, `"missing"`이면 설치할지 사용자에게 먼저 묻는다. 글꼴 파일을 skill 폴더에 넣지 않는다.
- 글자마다 기울기와 높이를 조금씩 다르게 준다. `<text>`에 `rotate`(글자별 -3~3도)와 `dy`(글자별 -5~5px, 합이 0에 가깝게) 목록을 넣는다. 같은 값을 연속 두 글자에 쓰지 않는다.
- 영문은 평소 쓰는 대소문자 그대로 쓴다. 글자 크기를 단어 안에서 바꾸는 장식은 하지 않는다. 명령어·브랜치 이름 같은 코드 토큰은 원래 대소문자를 지킨다.
- 써지기(`data-write`)를 쓰는 글자는 `tspan` 없이 한 `<text>`에 쓴다.
- 글자는 INK, 강조할 단어만 ACCENT. 글자에 외곽선·그림자·배경 상자를 넣지 않는다.

| 글자 | 크기 |
|---|---|
| 장면 제목 | 150~200px |
| 주석·축 라벨 | 45~70px |
| 말풍선 대사 | 45~55px, 3줄 이하, 왼쪽 정렬 |

개념 카드는 제목 한 줄, 주석 장면은 주석 4개, 차트 장면은 축 라벨 2개 + 주석 3개까지다. 문장은 말풍선 대사에만 쓴다.

### 말풍선과 주석

- 말풍선: WHITE 채움, INK 6~7px, 모서리가 둥근 손그림 사각형(네 변이 살짝 휜다). 꼬리는 말하는 캐릭터 머리 쪽으로 짧게(40~70px) 뾰족하게 뺀다. 글자와 테두리 사이 여백 30px 이상.
- 주석: 짧은 라벨 한 줄 + ARROW 4~5px 굽은 화살표(`Q` 곡선 하나, 끝에 열린 화살촉 두 획 18~24px). 화살표는 라벨 옆에서 출발해 대상 외곽선 20~40px 앞에서 멈춘다.

### 구도

| 장면 종류 | 배치 | 길이 |
|---|---|---|
| 캐릭터 장면 | 캐릭터·소품 묶음을 가로 가운데에 둔다. 묶음 폭은 화면의 55~70%, 세로는 위 7% ~ 아래 88% 안. 바닥선·배경 풍경은 그리지 않고 책상 같은 소품만 둔다 | 1~6초 |
| 크기 대비 장면 | 큰 쪽 키를 작은 쪽의 2배 이상으로 그려 힘·양의 차이를 보여 준다. 배치(좌우·앞뒤·위아래)는 내용에 맞춰 정하고 묶음은 화면 가운데 | 1~6초 |
| 대화 장면 | 두 캐릭터를 좌우에 두고 말하는 쪽 머리 위·옆에 말풍선 하나. 대사가 바뀌면 말풍선과 두 캐릭터 표정을 함께 바꾼 새 포즈 | 빌드 +1.5초 이상 |
| 반응 장면 | 캐릭터의 표정 포즈 하나로 감정을 보여 준다. 기호가 필요하면 성격 소품 칸의 기호 하나를 머리 근처에 둔다. 글자 없음 | 1~2초 |
| 설정 장면 | 장소를 알려야 할 때만. 벽 모서리·책상·문 같은 원근선 3~6개와 캐릭터. 캐릭터는 화면 높이 40~60% | 1~6초 |
| 주석 장면 | 대상 하나와 주석 1~4개. 주석(짧은 라벨 + 회색 굽은 화살표)은 대상 주변 빈 곳에 화면 무게가 한쪽으로 쏠리지 않게 나눠 둔다 | 빌드 +1.5초 이상 |
| 차트 장면 | 손그림 축 두 개(끝에 열린 화살촉)와 축 라벨을 먼저 그리고, 데이터(선·막대)를 하나씩 그린다. 주석은 꼭 필요한 곳에만. 축 영역은 가로 25~85%, 세로 12~88% | 빌드 +1.5초 이상 |
| 개념 카드 | 제목 한 줄과 그 개념을 나타내는 그림 하나(아이콘·소품, 높이 250~400px). 제목과 그림의 배치(위아래·좌우)는 내용에 맞춰 정하고, 둘 사이를 80px 이상 띄운다 | 1~3초 |

- 기본은 배경 없는 빈 종이다. 바닥선·풍경은 설정 장면에서만 그린다.
- 요소 사이는 최소 80px 띄운다(주석 화살표 끝과 그 대상, 쥔 물건과 팔 끝은 예외). 화면 테두리, 액자, 구분선은 그리지 않는다.
- 빈 종이 여백을 남긴다. 화면을 채우려고 요소를 더하지 않는다.

### 모션

종이와 그림은 흔들리지 않는다. 움직임은 포즈 교체와 빌드(등장·그려지기·써지기) 두 가지뿐이다.

- **그림 수**: 초당 12장. 24fps 타임라인이면 그림 한 장이 2프레임, 60fps면 5프레임 유지된다. 그려지기도 매끄럽지 않고 12장/초로 끊긴다. 바뀌는 요소가 없는 동안 화면은 완전히 정지한다.
- **포즈 바꾸기**: 캐릭터 동작은 사이 동작 없이 포즈 그림을 바꿔 끼워 보여 준다. 눈썹·입·팔 각도·고개 기울기 중 1~2개만 다른 포즈를 장면당 2~3장 그린다. 포즈 하나는 최소 0.5초 유지한다.
- **등장(`data-show`)**: 라벨·말풍선·아이콘·기호가 통째로 나타난다.
- **그려지기(`data-draw`)**: 축·데이터 선·화살표가 시작점부터 끝까지 그려진다. 걸리는 시간 = 선 길이(px) ÷ 700, 최소 0.3초. 화살촉은 이 최소값의 예외로 선이 끝난 뒤 0.1초 동안 그린다.
- **써지기(`data-write`)**: 라벨·축 이름이 한 글자씩 써진다. 걸리는 시간 = 글자 수(공백 포함) ÷ 8 초.
- **시각 단위**: 시간 속성은 그림 단위(1/12초)로 적용된다. 그 시각 이후 첫 그림부터 바뀐다. 예를 들어 2.3초는 2.33초 그림부터 보인다. 값은 소수 둘째 자리까지 쓴다.
- **빌드 순서**: 내레이션이 그 요소를 말하는 순서대로 하나씩 한다. 동시에 그려지는 요소는 둘 이하. 다음 요소는 앞 요소가 끝나고 0.3초 이상 쉬고 시작한다. 빌드가 끝나면 장면 끝까지 그대로 둔다.
- **장면 전환**: 하드 컷. 디졸브, 와이프, 줌, 카메라 이동, 이징 애니메이션을 쓰지 않는다.
- **장면 길이**: 구도 표의 "길이" 열을 따른다. "빌드 +1.5초 이상"은 마지막 빌드가 끝난 뒤 1.5초 이상 정지해 있다는 뜻이고, 어떤 장면도 25초를 넘기지 않는다. 길이 값은 표에만 적고 다른 곳에 다시 쓰지 않는다.

## 작업 흐름

Opus·Sonnet·Haiku 모두 같은 순서로 한다. 판단이 필요한 곳은 위 표의 숫자와 칸을 고른다.

### 1. 장면 표

장면마다 `id`, 종류("구도" 표의 캐릭터·크기 대비·대화·반응·설정·주석·차트·개념 카드 중 하나), 길이(초), 포즈별 차이, 글자를 적는다. 캐릭터는 "캐릭터 설계 규칙" 표에서 고른 칸(머리·몸통, ACCENT 위치, 성격 소품)도 적는다. 사용자가 이미 장면을 정했으면 그대로 옮긴다.

### 2. 출력 형식

요청과 대화에서 배경을 따로 작업하는지 판단한다.

- 배경을 따로 작업한다는 신호가 없으면 묻지 않고 `.mp4`로 렌더한다.
- 신호가 있으면 렌더 전에 질문 대화상자(AskUserQuestion 같은 선택지 질문 도구)로 묻는다. 선택지는 "MOV(투명 배경)로 렌더"와 "MP4(종이 배경)로 렌더" 두 개다. 도구가 없으면 같은 두 선택지를 한 줄로 묻고 답을 기다린다.

배경을 따로 작업한다는 신호의 예:

- 촬영본·화면 녹화·다른 그래픽 "위에" 얹는다, 겹친다, 오버레이한다고 말함.
- 배경을 Resolve(또는 다른 편집기)에서 따로 넣거나 바꾼다고 말함.
- 장면에 종이 배경 없이 화살표·글자만 필요하다고 말함.

Resolve에 놓는다는 말만으로는 신호가 아니다. 종이 배경 그대로 트랙에 놓으면 MP4로 충분하다.

### 3. 출력 폴더

사용자가 정한 폴더, 없으면 작업 디렉터리 아래 `doodle-output/<작업명>/`. SVG·`spec.json`·결과물을 모두 여기에 둔다.

### 4. SVG 그리기

포즈마다 SVG 파일 하나를 만든다.

- `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1920 1080">`로 시작한다. `width`·`height`는 넣지 않는다.
- 배경 사각형을 그리지 않는다. 종이 배경은 스크립트가 MP4에만 깔고, MOV는 투명으로 남긴다.
- 그리는 순서: 채움 면 → 그늘 → 외곽선 → 눈·세부 → 글자.
- 빌드가 있는 장면은 요소에 시간 속성(장면 시작 기준 초)을 붙인다. 그려지기는 `<path>`에만, 써지기는 `tspan` 없는 `<text>`에만 붙는다.

| 속성 | 붙는 곳 | 뜻 |
|---|---|---|
| `data-show="t"` | 아무 요소·`<g>` | t초부터 보인다 |
| `data-draw="t0 t1"` | `<path>` | t0~t1초 동안 시작점부터 그려진다 |
| `data-write="t0 t1"` | `<text>` | t0~t1초 동안 한 글자씩 써진다 |

- 렌더러는 `data-fade`(불투명도)·`data-move`(이동·확대축소)도 지원한다. 매끄럽게 움직이는 다른 스타일 skill용이라 이 스타일에서는 쓰지 않는다.

- 같은 장면의 포즈 파일은 바뀌는 부분만 다르고 나머지 좌표는 똑같이 복사한다. 좌표가 조금이라도 다르면 포즈를 바꿀 때 그림 전체가 튄다. 포즈가 여러 장이면 SVG를 손으로 따로 쓰지 말고 작은 생성 스크립트(출력 폴더에 둔다)에서 공통 부분을 한 번만 정의한다.
- 예시: [references/example/](references/example/). 스타일 확인용이다. 캐릭터·글자를 그대로 쓰지 않는다.

### 5. spec.json

장면 순서대로 적는다. 경로는 `spec.json` 기준 상대 경로다.

장면 세 개(캐릭터 4초 + 개념 카드 3초 + 주석 7.5초)를 렌더하는 spec 예시다.

```json
{
  "size": [1920, 1080],
  "fps": 24,
  "drawings_per_second": 12,
  "background": "#FEFEFE",
  "font_dirs": [],
  "scenes": [
    {"id": "character", "duration": 4.0, "poses": [{"svg": "character_a.svg", "at": 0}, {"svg": "character_b.svg", "at": 1.5}]},
    {"id": "title", "duration": 3.0, "poses": [{"svg": "title.svg", "at": 0}]},
    {"id": "callout", "duration": 7.5, "poses": [{"svg": "callout.svg", "at": 0}]}
  ]
}
```

- `fps`는 Resolve에 놓을 타임라인의 fps와 같게 한다. `fps`는 `drawings_per_second`(12)의 배수여야 한다. 23.976·29.97처럼 배수가 아니면 렌더하지 말고 사용자에게 알린다.
- `at`은 그 포즈가 시작되는 초. 첫 포즈는 0.
- 시스템 글꼴(`~/Library/Fonts` 포함)은 항상 읽는다. 그 밖의 글꼴 폴더만 `font_dirs`에 넣는다(절대 경로, `~`, spec 기준 상대 경로 모두 가능).

### 6. 렌더

2단계에서 정한 형식을 출력 확장자로 준다. `.mp4`는 종이 배경, `.mov`는 투명 배경이다.

`<skill>`(이 `SKILL.md`가 있는 디렉터리)의 스크립트로 렌더하는 명령이다.

```bash
uv run --python 3.12 <skill>/scripts/render_doodle.py doodle-output/<작업명>/spec.json doodle-output/<작업명>/out.mp4 --stills doodle-output/<작업명>/stills
```

스크립트를 고쳤으면 아래 자체 검사가 `selftest ok`를 내는지 먼저 본다.

```bash
uv run --python 3.12 <skill>/scripts/render_doodle.py --selftest
```

### 7. 검수

스틸은 포즈마다 1장(`장면번호_id_포즈번호.png`, 그 포즈의 마지막 그림 = 빌드가 끝난 모습)이 나온다. 이미지를 한 장씩 여러 번 읽지 말고 한 장으로 붙여 한 번만 본다.

스틸을 한 장으로 붙이는 명령이다. `tile=열x행`은 스틸 개수 이상이 되게 고른다(예: 7장이면 `4x2`).

```bash
ffmpeg -v error -y -pattern_type glob -i 'doodle-output/<작업명>/stills/*.png' -vf "scale=640:-1,tile=4x2:color=white" -frames:v 1 doodle-output/<작업명>/sheet.jpg
```

검수 항목은 다음과 같다. 어긋나면 SVG를 고치고 다시 렌더한다.

- 렌더 출력의 프레임 수 = 장면 길이 합 × fps.
- 종이색 외 색은 표의 7색과 보조 강조색 하나뿐인가.
- 캐릭터 머리가 키의 1/3 이상이고, 손가락·옷 주름 같은 세부가 없는가.
- 물건을 쥐거나 가리키는 팔 끝이 물건에 닿는가.
- 캐릭터가 "캐릭터 설계 규칙" 표에서 고른 칸대로 그려졌는가.
- 글자 수가 장면 종류별 한도 안이고 크기 표 안에 있는가.
- 빌드가 있는 장면이 빌드 순서 규칙(동시 2개 이하, 0.3초 쉼)과 선 길이 ÷ 700 시간을 지켰는가. 시간 속성 값과 선 길이를 표로 대조한다.
- 요소가 화면 밖으로 잘리거나 80px보다 가깝게 붙지 않았는가.
- 캐릭터·글자·장면이 이미 알려진 캐릭터·마스코트·영상 장면과 닮아 보이지 않는가. 닮았으면 "캐릭터 설계 규칙" 표에서 두 칸 이상 바꿔 다시 그린다.

### 8. Resolve 배치

사용자가 Resolve 타임라인에 놓아 달라고 했을 때만 한다. 렌더한 파일(MP4·MOV 어느 쪽이든)로 아래 "Resolve 배치" 절을 따른다.

### 9. 완료 보고

출력 파일 경로와 형식(MP4·MOV, 고른 이유), 장면 표(id·길이·포즈 수·고른 캐릭터 칸), 렌더 프레임 수, 검수 결과, Resolve에 놓았으면 타임라인 이름·트랙·시작 타임코드를 적는다. 검수하지 않은 항목은 "확인하지 않음"으로 적는다.

## Resolve 배치

DaVinci Resolve MCP의 `run_script`로 한다. MCP가 두 개(`DaVinci_Resolve`, `DaVinci_Resolve_Studio`) 보이면 실행 중인 쪽을 `get_resolve_status`로 확인해 쓴다. Resolve가 꺼져 있으면 `launch_resolve` 전에 사용자에게 묻는다.

- 원본 타임라인을 직접 고치지 않는다. 사용자가 작업용 타임라인을 지정하지 않았으면 현재 타임라인을 복제해 그 복제본에 놓는다.
- 새 비디오 트랙을 하나 만들어 그 트랙에만 놓는다. 기존 트랙의 클립을 덮어쓰지 않는다.
- 타임라인 fps가 spec의 `fps`와 다르면 놓지 말고 spec을 고쳐 다시 렌더한다.

현재 타임라인의 지정 위치(초)에 렌더한 클립을 새 비디오 트랙으로 놓는 스크립트다. `CLIP`과 `AT_SECONDS`만 바꾼다.

```python
CLIP = "/절대/경로/doodle-output/<작업명>/out.mp4"  # 투명으로 렌더했으면 out.mov
AT_SECONDS = 12.0

timeline = project.GetCurrentTimeline()
fps = float(timeline.GetSetting("timelineFrameRate"))
media_pool = project.GetMediaPool()
item = media_pool.ImportMedia([CLIP])[0]
timeline.AddTrack("video")
track = timeline.GetTrackCount("video")
record = timeline.GetStartFrame() + round(AT_SECONDS * fps)
placed = media_pool.AppendToTimeline([{"mediaPoolItem": item, "trackIndex": track, "recordFrame": record}])
result = {"timeline": timeline.GetName(), "fps": fps, "track": track, "start": placed[0].GetStart(), "end": placed[0].GetEnd()}
```

- `result`의 `start`가 `record`와 같은지 확인한다. 다르면 클립을 지우고 원인을 보고한다.
- 놓은 뒤 `timeline.GetItemListInTrack("video", track)`가 클립 1개만 돌려주는지 확인한다.

## 하지 말 것

- 이미 있는 캐릭터·마스코트·로고·손글씨 글자 모양을 따라 그리지 않는다. 사용자가 지정한 캐릭터 스펙만 예외다.
- SVG에 배경 사각형, 그라데이션, `filter`, 이미지(`<image>`)를 넣지 않는다.
- 위치·크기를 프레임 사이에 보간하는 애니메이션, 선을 흔드는 효과(line boil·wiggle)를 만들지 않는다. 움직임은 포즈 교체와 빌드뿐이다.
- 렌더 스크립트를 거치지 않고 ffmpeg로 정지 그림을 이어 붙이지 않는다. 빌드와 그림 수가 빠진다.
