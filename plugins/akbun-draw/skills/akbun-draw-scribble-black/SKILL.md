# akbun-draw-scribble-black

## 언제 쓰나

수식·단계·"누가 무엇을 묻고 무엇을 받는지"를 손으로 적어 가며 설명하는 장면에 쓴다. 설명하는 사람이 보드에 바로 써 내려가는 속도감이 필요할 때 맞다. 무엇을 어디에 몇 개 둘지는 설명할 내용이 정한다.

- 흰 종이에 캐릭터가 연기하는 낙서 장면은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md), 같은 스타일을 Resolve에서 고칠 수 있는 타임라인으로 만드는 일은 [akbun-davinciresolve-explainer-scribble-black](../../../akbun-editvideo/skills/akbun-davinciresolve-explainer-scribble-black/SKILL.md)의 범위다.
- 그리는 손·사람 얼굴·실사 사진을 넣지 않는다. 막대 인물의 머리는 빈 원이다.

## 캔버스

| 용도 | size |
|---|---|
| 일반 영상 (기본) | `[1920, 1080]` |
| 쇼츠·릴스 | `[1080, 1920]` |

아래 px 값은 두 크기에서 그대로 쓴다. 그 밖의 크기는 짧은 변 ÷ 1080을 곱하고 0.5px 단위로 반올림한다.

## 스타일

### 색

| 이름 | 값 | 쓰임 |
|---|---|---|
| BOARD | `#0E0E10` | 보드(검정). spec `background`, `"grain": 0.01`. SVG에 배경 사각형을 그리지 않는다 |
| PEN | `#F2F2EE` | 모든 도형·글씨의 기본 |
| GRAY | `#8A93A6` | 화살표, 보조 글씨, 지나간 단계 |
| SKY | `#6EC6F0` | 입력·변수·묻는 값 |
| ORANGE | `#F8823A` | 결과·바뀐 값·답 |
| YELLOW | `#FFD54A` | 지금 주목할 값 하나 |
| RED | `#FF5A5A` | 문제·틀림·다른 점 |
| FILL | `#24486B` | 작은 상자 사물 안의 채움 하나 |

- 색 글씨는 SKY·ORANGE·YELLOW·RED이고, 한 화면에 3가지까지다. 같은 값은 장면을 넘어가도 같은 색으로 쓴다. YELLOW는 화면에 하나만 둔다.
- FILL은 사물 안 채움에만 쓰고 글씨·선에 쓰지 않는다. 채움 위의 작은 점(PEN 지름 6~10px) 5~12개로 "안에 무언가 들어 있음"을 나타낸다.

### 선

- 모든 선은 채움 없는 `<path>`, PEN 6px(화살표는 GRAY 6px), `stroke-linecap="round"` `stroke-linejoin="round"`.
- 손으로 그은 선이다. 직선도 `Q` 하나로 쓰고 제어점을 선 가운데에서 수직으로 1~3px 비킨다. 원(구름 꼬리 원 제외)은 끝이 시작점에서 4~10px 지나쳐 겹치게 끝낸다. 외곽선에는 닫힌 `Z`를 쓰지 않는다.
- 흔들림은 그리는 순간 한 번 정해지고 움직이지 않는다. 프레임마다 선을 흔들지 않는다.
- 화살표: GRAY 6px 몸통 한 획 + 촉 한 획(열린 두 날개 각 18~24px, 몸통과 30~40°, 한 `<path>`로 날개 → 끝점 → 날개). 빌드는 둘이다. 몸통은 흐르는 방향(꼬리 → 끝점)으로 긋는다. 대상 가장자리에서 16~30px 떨어져 멈춘다.

### 도형

| 도형 | 모양 |
|---|---|
| 말풍선 | 타원(가로 반지름 ≥ 세로 반지름 × 1.6) 하나 + 말하는 대상(그 말을 하는 쪽) 쪽으로 부드럽게 휜 꼬리 하나. 꼬리 밑동 두 점 중 하나에서 시작해 타원을 돌고, 다른 밑동에서 `Q` 곡선 두 개로 뾰족하게 모였다 돌아온다. 꼬리 길이는 세로 반지름의 0.5~0.8배. 외곽선과 꼬리는 한 획 |
| 생각 구름 | 타원 위 이음점 6~9개를 바깥으로 볼록한 호(반지름 = 이음점 거리 ÷ 2 × 1.05)로 이은 한 획. 혹 수는 6 또는 8(짝수)이다. 이음점 간격은 1.3과 0.8을 번갈아 둔 값에 ±10% 흔들림을 곱한 뒤 합이 타원 둘레가 되게 모두 같은 비율로 늘이거나 줄여 정한다. 이렇게 하면 시작점을 넘어가는 이웃까지 혹 크기가 큰 쪽 기준 20% 이상 다르다. 같은 크기 혹을 줄지어 붙이지 않는다. 끝은 시작점에서 닫는다. 꼬리는 생각하는 대상 쪽으로 작아지는 원 3개(반지름 12, 8, 5px, 중심 간격 24px)를 하위 경로 셋인 `<path>` 하나로 그린다 |
| 막대 인물 | 머리 = 빈 원(반지름 28~36px, 얼굴 없음), 몸통 = 선 하나(길이 머리 지름 × 1.8~2.2), 팔·다리 = 선 하나씩. 손·발·옷을 그리지 않는다 |
| 상자 사물 | 손그림 사각형(폭·높이 80~160px) 안에 FILL 채움 + 점 + 위에 작은 손잡이·안테나 하나. 기계·장치·저장소를 뜻한다. 채움은 외곽선보다 앞(아래)에 둔 `<rect>`이고 외곽선 마지막 획이 끝날 때 `data-show` |
| 함수 상자 | 손그림 사각형(폭 120~360px, 높이 80~200px) 안에 짧은 글씨 하나, 양옆에 작은 반원 귀(들어가고 나오는 자리). 입력 → 처리 → 출력 흐름에 쓴다 |
| 밑줄 | 제목(선택) 아래 PEN 6px 선 하나. 길이 = Pillow `ImageFont.truetype(<Gaegu-Bold.ttf>, 크기).getlength(제목)` + 양쪽 10px |

- 실제 제품 로고·알려진 캐릭터를 그리지 않는다. 사물은 위 도형과 선만으로 만든다.

### 글씨

| 대상 | 글꼴 | 크기 |
|---|---|---|
| 제목 | `'Gaegu', cursive` 700 | 52~60px, PEN, 밑줄 |
| 수식·값·이름 | `'Gaegu', cursive` 700 | 36~48px, PEN 또는 색 글씨 |
| 위첨자·작은 주석 | `'Gaegu', cursive` 700 | 22~28px |

- 위첨자는 따로 `<text>`(22~28px, 기준선을 앞 글씨보다 18px 위)로 두고 앞 글씨 다음 빌드로 쓴다. 써지기(`data-write`)를 쓰는 글씨에는 `tspan`을 쓰지 않는다.
- 문장을 길게 쓰지 않는다. 한 글씨 묶음은 영어 6단어, 한국어 14글자 이하(공백 제외).

### 모션

보드에 손 하나가 쓰는 속도다. spec의 `drawings_per_second`는 `fps`와 같게 한다(예: 30, 30).

| 움직임 | 방식 | 길이 |
|---|---|---|
| 선·도형 그리기 | `data-draw`. 사람이 긋는 방향: 선은 흐름의 시작에서 끝으로, 원은 맨 위에서 시작해 반시계, 구름·사각형은 왼쪽 위(구름은 맨 위)에서 시작해 시계 방향, 말풍선은 도형 표대로 | 선 길이(px) ÷ 600초를 0.05초 단위로 올림, 최소 0.25초 |
| 글씨 쓰기 | `data-write` | 글자 수(공백 포함, 렌더러가 세는 방식) ÷ 5초를 0.05초 단위로 올림, 최소 0.3초 |
| 사물 채움·점 | `data-show`. 외곽선이 다 그려진 뒤 | 즉시 |
| 획 사이 쉼 | 앞 빌드 끝과 다음 빌드 시작 사이 | 0.1~0.2초 |
| 보드 지우기 | 아무것도 없는 포즈로 교체(하드 컷) | 즉시 |

- **한 번에 한 획**: 빌드(`data-draw`·`data-write`)는 겹치지 않는다. 앞 빌드가 끝난 뒤 다음 빌드가 시작한다. 손은 하나다.
- 생각 구름·말풍선의 외곽선을 먼저 그리고, 안의 글씨를 그다음에 쓴다. 구름 꼬리는 외곽선 바로 뒤에 그린다.
- 글씨 색이 바뀌는 지점은 `<text>`를 나눠 이어서 쓴다.
- 마지막 빌드는 장면 끝 1.0초 전에 끝낸다. 대본 마지막 단어에 묶인 요소 때문에 지킬 수 없으면 0.5초 전까지 허용한다. 장면 하나는 25초 이하다.
- 카메라는 쓰지 않는다. 같은 보드에 이어 쓰는 장면은 앞 장면 그림을 처음부터 보이게(시간 속성 없이) 두고 새 획만 그린다.
- 시각은 대본의 신호 단어에 묶는다. 신호 단어는 그 요소의 이름이나 그 변화를 말하는 첫 단어다. 앞 빌드가 신호 단어보다 늦게 끝나면 앞 빌드 끝 + 0.1초에 시작한다. 이렇게 밀려서 신호 단어보다 1.0초 넘게 늦어지는 요소는 장면 표에 "늦음"으로 표시하고, 그 앞 문장 끝에 쉼을 넣어 읽자고 대본 수정안을 함께 적는다. 이 skill의 수치가 링크한 다른 skill과 다르면 이 skill을 따른다. 음절 세는 법과 녹음 후 다시 맞추는 법은 [code-window-lilac의 녹음 전후 시각 맞추기](../akbun-draw-code-window-lilac/SKILL.md#녹음-전후-시각-맞추기)를 따른다.

## 작업 흐름

`<doodle>`은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md) 디렉터리다. 출력 폴더는 사용자가 정한 곳, 없으면 `scribble-black-output/<작업명>/`.

1. **장면 표**: 장면마다 id, 길이, 그릴 획 순서(도형·글씨), 색 글씨, 획별 신호 단어와 시작·끝 시각을 적는다. 획이 겹치지 않는지 표에서 확인한다.
2. **SVG 포즈**: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H">`로 시작하고 `width`·`height`·배경 사각형·`filter`·`<image>`를 넣지 않는다. 손그림 흔들림(제어점 비킴, 원 끝 겹침, 구름 혹 크기)은 작은 생성 스크립트(출력 폴더)에서 고정 시드 난수로 한 번 정한다.
3. **spec.json**: `"background": "#0E0E10"`, `"grain": 0.01`, `fps`와 `drawings_per_second`는 놓을 타임라인 fps(정수). 23.976·29.97처럼 정수가 아니면 렌더하지 말고 사용자에게 알린다.
4. **렌더**: 기본은 `uv run --python 3.12 <doodle>/scripts/render_doodle.py <출력>/spec.json <출력>/out.mp4 --stills <출력>/stills`. 배경을 따로 작업한다는 신호가 있으면 렌더 전에 [motion-doodle의 출력 형식](../akbun-draw-motion-doodle/SKILL.md#2-출력-형식)대로 "MOV(투명 배경)"와 "MP4(보드 배경)" 두 선택지로 묻고, MOV를 고르면 `out.mov`로 렌더한다.
5. **검수**: 아래 숫자 검사를 먼저 하고, 스틸을 한 장으로 붙여 한 번만 본다.

예시: [references/example/](references/example/)는 해시 함수가 한 방향뿐임을 위→아래 흐름과 생각하는 막대 인물로 설명한 한 장면이다. 스타일 확인용이며 배치·문구를 그대로 쓰지 않는다.

### 검수

SVG에 색 표 밖의 색이 없는지 보는 명령이다. 아무것도 출력하지 않아야 한다.

```bash
grep -ohiE '#[0-9a-f]{6}' <출력>/*.svg | tr a-f A-F | sort -u | grep -vE '^#(0E0E10|F2F2EE|8A93A6|6EC6F0|F8823A|FFD54A|FF5A5A|24486B)$'
```

- 렌더 프레임 수 = 장면 길이 합 × fps.
- `--fonts "Gaegu"`가 `ok`. `missing`이면 렌더하지 말고 설치를 묻는다(Google Fonts의 Gaegu).
- 빌드 구간이 서로 겹치지 않는가(앞 끝 ≤ 다음 시작). 마지막 빌드가 장면 끝 1.0초(예외 0.5초) 전에 끝나는가.
- 선 길이·글자 수로 계산한 빌드 길이와 SVG의 시간 속성이 0.05초 안에서 같은가.
- 포즈마다 색 글씨 종류 ≤ 3, YELLOW ≤ 1개인가.
- 시트에서: 글씨가 도형 밖으로 넘치지 않는가, 말풍선·구름이 자연스러운 한 덩어리로 보이는가(같은 크기 혹이 줄지어 있지 않은가), 막대 인물 머리가 빈 원인가, 손·얼굴·실제 로고·알려진 캐릭터와 닮은 그림이 없는가.

## 완료 보고

출력 경로, 출력 형식(MP4·MOV)과 고른 이유, 장면 표(획 순서·신호 단어·녹음 전 시각·녹음 후 시각), 렌더 프레임 수, 글꼴 검사, 색 검사 출력, 검수 결과를 적는다. 확인하지 않은 항목은 "확인하지 않음"으로 적는다. Resolve에 놓아 달라고 하면 [motion-doodle의 Resolve 배치](../akbun-draw-motion-doodle/SKILL.md#resolve-배치)를 따른다.

## 하지 말 것

- 배치는 장면이 설명하는 관계로 고른다: 순서·흐름(방향은 위→아래, 아래→위, 오른쪽→왼쪽, 대각선 모두 된다), 가운데와 둘레(하나가 여럿과 이어짐), 안과 밖(포함·겹침), 나란히 견주기(둘 비교), 하나만 크게(한 값·한 대상). 흐름을 기본으로 왼쪽→오른쪽에 두지 않고, 이어지는 두 장면이 같은 배치였으면 다음 장면은 다른 배치를 고른다.
- 빌드를 겹치게 두지 않는다. 동시에 두 곳이 그려지면 손으로 쓰는 느낌이 깨진다.
- 밝은 배경, 검은 선, 그리는 손, 사람 얼굴, 실사 사진, 실제 로고를 넣지 않는다. 그라데이션·그림자·질감 필터도 쓰지 않는다.
