# akbun-draw-animation-garnet

## 목적

아무 소재·주제를 garnet 스타일의 짧은 가로 애니메이션으로 만든다. 애니메이션은 그림체, 스토리보드(무엇을 어떤 순서·크기로 보여 주나), 연출(리듬·전환·긴장), 사운드가 함께 맞아야 하므로 이 skill은 넷을 모두 고정한다. 무엇이 일어나는지(이야기·장소·배역·행동)는 입력에 맞춰 정한다. 대사와 자막은 없다.

산출물은 배역 캐릭터 시트, 컷별 열쇠 그림(1–3장), 임시 사운드 `sound.wav`, 사운드가 든 1920×1080 MP4, 소리 없는 미리보기 GIF, 큐 시트 `cues.txt`, 시트 `sheet.jpg`다.

모델은 프롬프트 문장도, 소리도 직접 만들지 않는다. 이야기 spec만 쓰고, 그림 문장은 스크립트가 라이브러리에서 가져오고 소리는 스크립트가 spec의 박자·energy·sfx로 합성한다. 그래서 몇 편을 만들어도 같은 그림체·같은 연출 문법이 나온다.

## 무엇을 정할 때 어느 파일

| 정할 것 | 파일 | 고르는 법 |
|---|---|---|
| 그림체(선·음영·빛·배경·인물·색·연기) | [references/style.jsonl](references/style.jsonl) | 고르지 않는다. 스크립트가 전부 넣는다. 장면이 이 규칙과 어긋나지 않게만 한다 |
| 연출 규칙 | [references/direction.jsonl](references/direction.jsonl) | 고르지 않는다. 채점이 줄마다 확인한다. 이야기를 컷으로 나누기 전에 전부 읽는다 |
| 소리(energy·sfx) | [references/sound.jsonl](references/sound.jsonl) | 컷마다 energy 0–3 하나와 sfx 0–2개를 `ko`의 쓰임에 맞춰 고른다 |
| 색 | [references/palettes.jsonl](references/palettes.jsonl) | 막마다 `use`가 그 막의 감정과 맞는 `id`. 팔레트는 `light`로 시간대도 정하므로, 둘 이상 맞으면 `light`가 이야기 시간대와 맞는 쪽. 시간대가 맞는 팔레트가 없으면 감정이 맞는 쪽을 고르고 `setting`을 그 `light`의 시간대로 쓴 뒤 결과 보고에 적는다 |
| 카메라 | [references/cameras.jsonl](references/cameras.jsonl) | 컷마다 그 순간이 가장 세게 읽히는 `id` 하나. 두 사람이 닿거나 주고받는 순간은 `chars`가 2 이상인 카메라. `drift`는 렌더 때 컷 끝까지 밀어 들어가는 비율. style·cameras 문장 속 %·각도는 이미지 모델에 주는 목표이고 채점하지 않는다 |
| 배역 특징 | [references/traits.jsonl](references/traits.jsonl) | 배역마다 특징 7개(성별·나이·키·체격·얼굴형·피부·옷 주색)를 `options`의 키로 고른다 |
| 참고 배역 | [references/characters.jsonl](references/characters.jsonl) | 형식 예시 4명. 그대로 쓰지 않는다. 새 배역은 성별·나이·키·체격·얼굴형·피부 6개 중 2개 이상이 모든 참고 배역과 달라야 한다 |
| spec·결과 예시 | [references/example/](references/example/) | `story.json`·`cues.txt`·`sheet.jpg`로 형식과 결과만 본다. 소재·배역을 그대로 쓰지 않는다 |

라이브러리에 없는 팔레트·카메라·특징·효과음이 필요하면 spec에 지어내지 말고, jsonl에 한 줄을 더하는 변경으로 사용자에게 제안한다.

## 작업 흐름

### 1. 스토리보드 짜기

길이가 없으면 12초로 본다. 길이는 6–40초(경계 포함)이고 40초를 넘으면 여러 편으로 나눈다. 글만 있으면 이야기를 지어내고, 지어낸 것임을 결과에 밝힌다.

1. 템포 `bpm`(90–140 정수)을 이야기의 속도로 고른다. 느긋하면 90–105, 보통 106–120, 급하면 121–140.
2. 이야기를 막(act) 1–3개로 나눈다. 막은 같은 장소·같은 시간대의 한 덩어리이고, 막이 바뀌면 색 세계(팔레트)가 바뀐다. 컷이 6개 이상이면 2막 이상이다.
3. 컷은 모두 4–20개(경계 포함), 막마다 2개 이상이다. 컷 길이는 박(beats) 1–8(경계 포함), 0.5박 단위다. 컷 하나는 장면의 뜻 하나만 담는다.
4. direction.jsonl을 지키도록 배치한다: 시작(조각 또는 넓은 컷), 절정(energy 3 + hit, 시작 시각이 전체의 40% 이상), 몰아치기(절정과 앞 2컷의 평균 박 수 < 전체 평균), 막의 시작(모든 막 첫 컷 3박 이상, 2막부터는 energy를 앞 컷보다 작게 또는 0), 여운(마지막 컷 박 수 ≥ 앞 3컷 최댓값, energy 0–1). 예시 spec으로 계산을 확인한다.
5. 박 수 합 × 60 ÷ bpm이 길이와 0.5초 이내(경계 포함)가 되게 맞춘다.

### 2. 배역 짜기

이야기에 나오는 사람마다 배역을 하나 만든다(1–3명). 배경의 이름 없는 사람은 배역이 아니며 그리지 않는다.

| 키 | 값 |
|---|---|
| `id` | `p-` + 영어 소문자 역할 이름, 하이픈 가능(예: `p-clerk`, `p-night-nurse`) |
| `gender`, `age`, `height`, `build`, `face`, `skin`, `color` | traits.jsonl의 `options` 키. 배역끼리는 실루엣이 구분되게 키·체격 중 하나 이상을 다르게 한다 |
| `hair` | 머리 모양·색과 안경·모자 같은 얼굴 둘레 특징, 영어 2–12단어. 붉은색(red·crimson·scarlet) 금지 |
| `outfit` | 옷차림과 늘 지니는 물건, 영어 3–14단어. 색 이름(red·navy·charcoal·khaki·cream 같은 일반 색과 traits의 color 이름)은 하나도 쓰지 않는다(색은 `color`가 정함). 무늬(striped)와 소재(denim·wool)는 써도 된다. 색 이름 금지는 `outfit`에만 적용된다 |

### 3. spec 쓰기

출력 폴더는 사용자가 정한 곳, 없으면 작업 디렉터리 아래 `garnet-output/<작업명>/`(영어 소문자·하이픈 짧은 이름). 미리 만들고 그 안에 `story.json`을 쓴다. 키는 `{"title": 한국어 제목, "length": 초, "bpm": 정수, "cast": [배역, ...], "shots": [컷, ...]}`이고 컷은 아래 키를 가진다.

| 키 | 값 |
|---|---|
| `id` | 영어 소문자·숫자·하이픈 짧은 이름, 컷끼리 중복 없이 |
| `act` | 막 번호 1–3. 첫 컷은 1, 다음 컷은 같거나 1 큼 |
| `palette`, `camera` | jsonl의 `id`. 한 막 안 팔레트는 2개 이하 |
| `beats` | 컷 길이(박), 1–8, 0.5 단위. 초 = 박 × 60 ÷ bpm |
| `energy` | 음악 세기 0–3(sound.jsonl의 `energy-N`) |
| `sfx` | sound.jsonl의 sfx id 0–2개, 중복 없이. 없으면 `[]` |
| `scene` | 무슨 일이 일어나는지 영어 6–40단어(공백으로 나눈 수, 경계 포함). 인물은 역할로 부른다(a courier, the old guard) |
| `setting` | 어디인지 영어 2–16단어. 팔레트의 `light`와 시간대가 어긋나지 않게 |
| `characters` | `[{"id": 배역 id, "action": 영어 3단어 이상}]`, 카메라의 `chars` 범위(경계 포함) 안. 생김새·옷은 늘 붙으므로 되풀이하지 않는다. `silhouette-frame`은 목록 첫 인물이 카메라 앞 실루엣이므로 지켜보는 쪽을 먼저, 주인공을 둘째로 쓴다. `hand-insert`는 손의 주인 하나이고 소매까지만 보인다 |
| `props` | 장면의 사물 영어 구절 1–8개, 한 컷 안에서 중복 없이. 여러 컷에 이어지는 사물은 컷마다 단수·복수까지 같은 구절로 쓴다. 글자 자체가 주인 사물(간판·라벨·포스터·메뉴·신문)은 쓰지 않는다. 화면·휴대폰·정류장·가게처럼 글자가 붙기 쉬운 사물은 써도 되고, 프롬프트가 글자 없이 그리게 한다 |
| `poses` | 첫 장 다음에 바꿔 넣을 자세 목록(선택), 각 영어 3–40단어(경계 포함). 3박 이하(3박 포함) 컷은 0–1개, 그보다 긴 컷은 0–2개. 자세 하나 = 몸의 위치나 팔다리 방향이 바뀐 동작 단계 하나. 표정만 바뀌거나 가만히 있으면 0개. 편집 모델은 이 문장만 받으므로 인물을 생김새와 옷 주색으로 부른다(the tall man in the cream work shirt). `hand-insert`는 손·물건의 변화만 쓴다 |

영어 칸(`scene`·`setting`·`action`·`props`·`poses`)에는 배역 id와 참고 배역 이름을 쓰지 않는다. 그림 모델은 id를 모른다. 그림 수는 배역 수 + 컷 수 + 자세 수다.

### 4. 채점과 프롬프트

`<skill>`은 이 `SKILL.md`가 있는 디렉터리다. 채점이 100점이 아니면 프롬프트를 쓰지 않고 FAIL 항목을 보여 준다. 고쳐서 다시 돌린다. 채점은 위 표의 수치, direction.jsonl의 규칙 전부, 배역이 모두 한 컷 이상 나오는지, 참고 배역과 2개 이상 다른지, 영어 칸의 ASCII·id·글자 소품, 금지 화풍 낱말(watercolor·gouache·painterly·oil paint·3d·realistic·pixel art·chibi·anime·neon)을 본다. 이야기가 입력의 뜻을 담는지, 팔레트·카메라·소리가 감정에 맞는지, 이어지는 소품 구절이 컷마다 같은지는 채점이 못 보므로 직접 확인한다.

spec을 채점하고 spec 옆에 배역 시트 `cast_<id>.txt`, 컷 첫 장 `NN_<id>.txt`, 자세 `NN_<id>_<k>.txt`(k = 2부터), 생성 스크립트 `codex.sh`, 큐 시트 `cues.txt`를 쓰는 명령이다.

```bash
uv run --python 3.12 --with pillow --with numpy python -I <skill>/scripts/garnet.py prompts garnet-output/<작업명>/story.json
```

채점표만 보려면 `prompts` 대신 `check`를 쓴다. 스크립트나 jsonl을 고쳤으면 `--selftest`가 `selftest ok`를 내는지 먼저 본다.

### 5. 그림 생성

`codex.sh`는 codex CLI의 내장 이미지 생성으로 세 단계를 차례로 돌린다. 단계 안의 그림은 동시에 만든다. 모델은 사용자 설정의 기본값을 쓴다.

1. 배역 시트: 배역마다 밝은 회색 바탕 전신 정면 한 장(세로 2:3).
2. 컷 첫 장: 그 컷에 나오는 배역의 시트를 참조 이미지로 붙인다(가로 16:9).
3. 자세: 그 컷 첫 장과 배역 시트를 붙여 첫 장을 편집한다. 배경과 카메라는 첫 장 그대로이고 자세만 바뀐다.

생성 스크립트를 돌리는 명령이다. 이미 있는 PNG는 건너뛰고, 끝에 빠진 그림이 있으면 이름과 로그 파일을 알려 주며 종료 코드 1로 끝난다.

```bash
bash garnet-output/<작업명>/codex.sh
```

codex를 쓰지 않으면 같은 순서로 다른 이미지 생성 도구에 프롬프트 파일 전문과 참조 이미지를 넣는다. 움직임은 열쇠 그림을 박자에 맞춰 바꾸는 렌더가 만들므로, 이미지 도구에 GIF·영상을 만들게 하지 않는다.

### 6. 렌더와 확인

렌더 전에 ffmpeg가 설치돼 있어야 한다. 없으면 스크립트가 멈추고, 설치할지 사용자에게 먼저 묻는다.

spec 옆에 `sound.wav`, `garnet.mp4`, `garnet.gif`, `sheet.jpg`를 만드는 명령이다.

```bash
uv run --python 3.12 --with pillow --with numpy python -I <skill>/scripts/garnet.py render garnet-output/<작업명>/story.json
```

판형은 스크립트가 고정한다: H.264 + AAC MP4, 1920×1080, 24fps, 48kHz 스테레오. GIF는 640px 폭 12fps이고 소리가 없다. 컷 경계 프레임은 누적 박 수 × 60 ÷ bpm × 24를 반올림(0.5는 올림)한 값이라 컷이 박자에서 밀리지 않는다. 그림은 1920×1080에 맞춰 가운데를 채워 자르고, 컷 안에서는 카메라 `drift`만큼 밀어 들어가며 열쇠 그림을 섞지 않고 같은 간격으로 바꾼다. 막의 첫 컷은 첫 8프레임 검정(무음), 다음 6프레임 동안 밝아진다. 쓴 프레임 수가 박 수 합 기준과 다르면 종료 코드 1로 끝난다.

`sound.wav`는 연출 타이밍을 듣기 위한 임시 사운드다: 팔레트 화음의 지속음, energy가 올라갈수록 더해지는 박자(1 맥박, 2 킥·하이햇, 3 스네어·베이스), sfx, 마지막 0.5초 페이드아웃. 진짜 음악·효과음으로 바꿀 때는 `cues.txt`의 타임코드(mm:ss:ff)와 bpm에 맞춰 편집기에서 갈아 끼운다.

`sheet.jpg`(열쇠 그림마다 한 칸)와 배역 시트를 한 장으로 붙여 한 번만 보고 아래를 확인한다. 어긋난 그림은 그 PNG를 지우고 `codex.sh`를 다시 돌리되 그림마다 2번까지만 하고, 그 그림에서 만든 그림도 함께 지운다(컷 첫 장이면 그 컷의 `_2`–`_3`, 배역 시트면 그 배역이 나오는 컷 그림 전부). 그래도 어긋나면 그 항목을 결과 보고에 적는다. 알려진 영화·만화·게임 캐릭터와 닮았으면 그 배역의 특징을 2개 이상 바꾸고, 그 배역의 시트와 나오는 컷 그림을 지운 뒤 prompts부터 다시 한다.

- 인물·소품에 얇고 굵기가 고른 짙은 선이 있고, 붓결·종이 질감이 없다.
- 면마다 바탕색과 경계가 딱 떨어지는 그림자색 하나뿐이다.
- 그림자가 순검정이 아니라 팔레트 색이고, 빛기둥·비네트·바둑판·바큇살 빛줄기가 없다.
- 컷마다 팔레트의 한 색 계열이 화면 대부분을 덮는다.
- 얼굴 표정이 절제돼 있고(크게 뜬 눈·소리 지르는 입 없음) 감정이 자세로 읽힌다.
- 같은 배역이 모든 컷에서 시트와 같은 체형·머리·옷 색이다.
- 한 컷의 열쇠 그림끼리 배경·카메라가 같고 자세만 다르다.
- 그림 안에 글자가 없다.
