# akbun-draw-juno

## 목적

아무 장소를 juno 스타일 여행 스냅으로 담는 16:9 영어 이미지 생성 프롬프트를 만든다. 이 skill이 고정하는 것은 실제 카메라 스냅의 색 보정·입자·빛·관찰자 시점과 얼굴 없는 인물 처리이고, 어디서 무엇을 찍을지는 입력에 맞춰 정한다.

모델은 프롬프트 문장을 직접 쓰지 않는다. spec만 쓰고, 스타일 문장은 스크립트가 라이브러리에서 가져온다. 그래서 몇 장을 만들어도 같은 사진체가 나온다.

## 무엇을 정할 때 어느 파일

| 정할 것 | 파일 | 고르는 법 |
|---|---|---|
| 사진체(색 보정·질감·관찰자 시점·빛·인물 처리·움직임) | [references/style.jsonl](references/style.jsonl) | 고르지 않는다. 스크립트가 전부 넣는다. 읽고 장면이 이 규칙과 어긋나지 않게만 한다 |
| 색 보정 | [references/palettes.jsonl](references/palettes.jsonl) | 기본 `overcast-beige`. 장면의 시간·장소가 다른 줄의 `use`와 맞을 때만 그 `id`. 두 줄이 다 맞으면 화면 대부분을 비추는 빛(실내 전구인지 바깥 가로등·하늘인지)으로 고른다 |
| spec 형식 예시 | [references/example/](references/example/) | 형식만 본다. 소재를 그대로 쓰지 않는다 |

라이브러리에 없는 팔레트가 필요하면 spec에 지어내지 말고, jsonl에 한 줄을 더하는 변경으로 사용자에게 제안한다.

## 작업 흐름

### 1. 장면 정하기

입력에서 장면 하나를 정한다(여러 장이면 장면마다). 글만 있으면 가장 일상적인 한 순간을 고르고, 지어낸 장면임을 결과에 밝힌다. 장면마다 `<id>`(영어 소문자·하이픈 짧은 이름, 예: `closed-bakery`)를 붙인다.

### 2. spec 쓰기

출력 폴더는 사용자가 정한 곳, 없으면 작업 디렉터리 아래 `matte-output/<작업명>/`이고, build 전에 폴더를 먼저 만든다. 사람은 `scene`·`props`가 아니라 `figures`에만 쓴다.

| 키 | 값 |
|---|---|
| `palette` | palettes.jsonl의 `id` |
| `scene` | 어떤 순간인지 영어 6~40단어(공백으로 나눈 수, 경계 포함) |
| `setting` | 어디인지 영어 한 구절, 빈칸 불가 |
| `props` | 화면에서 알아봐야 할 사물 영어 구절 1~6개(경계 포함), 중복 없이 |
| `figures` | 그 장소에 사람이 없으면 어색할 때(시장·역·번화가)만 영어 한 구절, 아니면 `""`(키를 빼도 같다). `behind`·`back`·`silhouette`·`blurred` 중 하나를 꼭 담는다(예: `two travelers seen from behind at the railing`) |
| `motion` | 영상까지 만들 때만. 고정 카메라 화면 안에서 움직이거나 바뀌는 것 하나(간판 하나의 깜빡임도 된다)와 그 움직임을 영어 4~30단어(공백으로 나눈 수, 경계 포함)로. pan·zoom·dolly·tracking·handheld·orbit·tilt 금지. 정지 사진이면 키를 뺀다 |

### 3. 프롬프트 조립

`<skill>`은 이 `SKILL.md`가 있는 디렉터리다. 채점이 100점이 아니면 프롬프트를 쓰지 않고 FAIL 항목을 보여 준다. 고쳐서 다시 돌린다.

spec을 채점하고 프롬프트 파일을 쓰는 명령이다.

```bash
uv run --python 3.12 python -I <skill>/scripts/matte_prompt.py build matte-output/<작업명>/01_<id>.json -o matte-output/<작업명>/01_<id>.txt
```

`motion`이 있으면 같은 장면을 2×2 칸 4장으로 그리는 스프라이트 시트 프롬프트가 나온다. 채점표만 보려면 `build` 대신 `check`를 쓴다. 채점은 위 표의 수치 외에 모델이 쓴 글이 영어(ASCII)인지, 금지 낱말(face·facial·portrait·selfie·smile·eyes·looking at camera·close-up, 3d·cgi·render·illustration·cartoon·anime·vector·neon·hdr·4k·8k·ultra·sharp·cinematic·cyberpunk)이 없는지 본다. 낱말은 대소문자를 가리지 않고 단어 경계로 센다.

스크립트나 jsonl을 고쳤으면 자체 검사가 `selftest ok`를 내는지 먼저 본다. 예시 spec을 고쳤으면 예시 txt도 `build`로 다시 쓴다.

```bash
uv run --python 3.12 python -I <skill>/scripts/matte_prompt.py --selftest
```

### 4. 이미지 생성과 확인

사용자가 이미지까지 요청했을 때만 프롬프트 파일 전문을 그대로 넣어 만든다.

사용자가 쓰는 이미지 생성 도구와 기본 모델로 `matte-output/<작업명>/01_<id>.txt`를 16:9 가로로 만들어 같은 폴더에 `01_<id>.png`로 저장한다. 여러 장은 장마다 따로, 동시에 만들어도 된다.

`motion`이 있는 spec이면 시트 PNG를 칸 4개로 잘라 반복 영상으로 잇는다. 이미지 도구는 PNG만 돌려주므로 움직이는 gif도 이 스크립트로 만든다. 칸마다 `--hold`(기본 1.0)초에 `--fade`(기본 0.6)초를 더한 만큼 머물고 다음 칸으로 겹쳐 넘어가며, 끝 장면이 첫 장면으로 돌아온다. 길이는 4 × (hold + fade) + fade초로 기본 7.0초다. 큰 이동은 겹쳐 보이므로 느리게 하려면 `--hold`를 늘린다. `-o`를 `.gif`로 주면 10fps·무한 반복·폭 640px gif(기본값 기준 약 3MB)가 나온다.

시트를 mp4로 잇는 명령이다. `ffmpeg`·`ffprobe`가 PATH에 있어야 한다. gif는 `-o`의 확장자만 `.gif`로 바꾼다.

```bash
uv run --python 3.12 python -I <skill>/scripts/sheet_to_video.py matte-output/<작업명>/01_<id>.png -o matte-output/<작업명>/01_<id>.mp4
```

여러 장이면 결과를 한 장으로 붙여 한 번만 보고 아래를 확인한다. 영상이면 시트 PNG를 본다. 어긋난 장은 같은 프롬프트로 다시 생성한다.

- 검정이 팔레트의 가장 어두운 색까지만 내려가 무광이고(낮은 들뜸, 밤은 하늘만 깊은 검정), 하이라이트가 베이지, 그림자가 올리브·청록 쪽이며 채도가 낮다.
- 디지털처럼 매끈하지 않고 고운 입자·약한 비네팅이 보인다.
- 얼굴이 보이거나 초점 맞은 인물이 없고, 레터박스 검은 띠가 없다.
- 그림 안에 읽히는 글자·로고·워터마크가 없다.
- 시트면 칸 4개의 배경·빛·카메라 위치가 같고 `motion`의 대상만 칸마다 한 단계씩 바뀌며(위치든 불빛이든), 칸 사이 틈·테두리·번호가 없다. 배경이 칸마다 다르면 다시 생성한다.
- 알려진 영화·사진·앨범 표지 장면과 닮지 않았다. 닮았으면 setting·props를 바꿔 build부터 다시 한다.

## 결과 보고

장면마다 spec 파일, 프롬프트 파일, 채점 점수, 고른 팔레트를 적는다. 이미지·영상을 만들었으면 경로(영상은 길이 초 포함)와 위 확인 결과를, 만들지 않았으면 "이미지 생성하지 않음"을 적는다. 프롬프트는 한 개의 `text` 코드블록으로도 보여 준다.

## 하지 말 것

- 프롬프트 문장을 손으로 고치거나 라이브러리 밖 스타일 문구를 덧붙이는 것. 바꿀 것이 있으면 jsonl을 고친다.
- 얼굴이 보이는 인물·포즈 잡은 인물 사진을 만드는 것, 알려진 사진·영상 장면을 따라 하는 것.
- 그림 안에 글자(제목·자막·간판 문구)를 넣는 것.
