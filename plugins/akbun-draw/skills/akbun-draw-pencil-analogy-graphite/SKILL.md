# akbun-draw-pencil-analogy-graphite

## 언제 쓰나

레이아웃은 고정하지 않는다. 상황에 맞는 부품을 고르고, 부품의 모양·색·글꼴·모션만 아래 "스타일"대로 지킨다.

| 상황 | 화면에 나오는 것 |
|---|---|
| 기술 개념을 일상 물건·행동에 빗댄다 | 막대 인물 하나 + 색 소품 하나(비유의 대상) + 지면선 |
| "원래 있던 정보가 사라진다"를 보여 준다 | 소품에 붙은 꼬리표 1~3개가 포즈 교체로 떨어진다 |
| 규칙·재료·단계 목록을 짚는다 | 테이프 메모 한 장(손글씨 2~4줄) + 인물이 가리키거나 바라봄 |
| 인물이 모르는 것·헷갈리는 것 | 인물 머리 위 손글씨 물음표 1~3개, 표정 포즈 교체 |
| 전후 비교 | 같은 인물·소품을 화면 좌우에 두 번. 바뀐 부분만 색·꼬리표가 다름 |

- 비유는 한 장면에 하나다. 인물·소품·메모가 모두 같은 비유 안에 있다.
- 실제 코드·화면은 이 스킬로 그리지 않는다. 코드는 [akbun-draw-code-window-lilac](../akbun-draw-code-window-lilac/SKILL.md), 실제 화면은 akbun-editvideo의 편집 스킬이다.

## 녹음 전후 시각 맞추기

작업 흐름은 대본 → 영상 → 녹음 → 영상 수정이다. 시간 속성·카메라 키·장면 길이는 모두 대본의 "신호 단어"에 묶는다. 시각은 장면 시작 기준 초이고, 장면의 0초는 그 장면 첫 문장의 시작이다.

- **녹음 전**: 대본을 초당 6.5음절로 읽는다고 보고 시각을 잡는다. 한글 한 글자 = 1음절, 영어 단어 = 모음 글자 묶음 수(a·e·i·o·u, 단어 끝이 아닌 y 포함, 붙어 있는 모음은 한 묶음, 최소 1, camelCase·snake_case는 단어로 나눠 센다), 숫자·기호 = 한국어로 읽는 소리 수(`4초` → 사초, 2음절). 띄어쓰기는 시간을 더하지 않고, 쉼표는 0.2초, 문장 끝은 0.4초를 더한다.
- 요소는 신호 단어 시작 0.1초 전에 시작한다. 0보다 작으면 0이다. 내림할 때는 계산 오차 때문에 0.000001을 더한 뒤 내린다(4.30이 4.29가 되지 않게). 시각은 소수 둘째 자리에서 내림한다.
- 장면 길이는 녹음 전에는 그 장면 마지막 음절이 끝나는 시각 + 0.4초(문장 끝 쉼 0.4초를 한 번만 더한다), 녹음 후에는 다음 장면 첫 문장 시작까지다. 프레임 단위로 반올림한다. 느린 흐름 카메라 키의 마지막 `at`은 장면 길이와 같게 옮긴다.
- **녹음 후**: 단어 시각(Resolve 전사, SRT, Whisper 단어 타임스탬프 중 있는 것)에서 신호 단어의 시작 시각을 찾아 등장 시점과 카메라 키를 다시 맞추고 다시 렌더한다. 빌드 길이는 그대로 두고 시작 시각만 옮긴다.
- SRT처럼 문장 단위 시각만 있으면 문장 시작~끝을 음절 수 비율로 나눠 단어 시각을 추정하고 장면 표에 "추정"으로 표시한다. 신호 단어를 못 찾으면 시각을 추측하지 말고 목록으로 보고한다.
- **우선순위**: 신호 단어 시각 > 모션 표의 길이 > 그 밖의 간격 규칙(동시 빌드 수, "마지막 빌드는 장면 끝 1.0초 전"). 마지막 단어에 묶인 요소 때문에 끝 여유가 1.0초보다 줄면 0.5초까지는 그대로 둔다. 신호 단어에 맞추면 다른 규칙이 깨질 때는 빌드 길이를 모션 표의 최소값까지 줄이고, 그래도 안 되면 그 요소를 가장 가까운 다른 신호 단어(앞이든 뒤든)로 옮기고 장면 표에 이유를 적는다. 시간 규칙 때문에 대본·글자를 바꾸지 않는다.
- 장면 표에는 요소마다 신호 단어, 녹음 전 시각, 녹음 후 시각 열을 둔다. 녹음 전이면 녹음 후 열은 "녹음 후 갱신"으로 둔다.

## 스타일

1920×1080 기준이다. 다른 해상도는 세로 비율로 늘이거나 줄인다.

### 종이와 선

| 이름 | 값 | 쓰임 |
|---|---|---|
| PAPER | `#EDE8D5` | 배경. spec `background` + `"grain": 0.035`. SVG에 배경 사각형을 그리지 않는다 |
| GRAPHITE | `#3F3B36` | 외곽선 3.5px, 세부 2px, 손글씨, 지면선 2.5px |
| HATCH | `#8C8579` | 빗금 그늘 1.5px |
| CARD | `#FBF8EE` | 메모 종이 |
| RULE | `#D9D2BE` | 메모 줄선 1.5px |
| TAPE | `#E8A867` | 테이프, `opacity="0.75"` |
| TAG | `#F1D27B` | 꼬리표 |

- 선은 연필로 그은 듯 자로 잰 직선을 피한다. 긴 선은 `Q`·`C` 곡선으로 2~5px 휘고, 사각형도 네 변을 살짝 휜 `<path>`로 그린다. `stroke-linecap`·`stroke-linejoin`은 `round`.
- 그늘은 HATCH 45° 평행 빗금, 선과 선 사이 수직 거리 7px. 그늘 면(물체의 오른쪽 또는 아래 35~45%)의 모양으로 `clipPath`를 만들어 빗금을 그 안에만 둔다. 채움 그라데이션·흐림은 쓰지 않는다.
- 그리는 순서는 물체마다(뒤 물체부터) 채움 → 빗금 → 외곽선이다.

### 색 소품

| 이름 | 값 | 그늘 |
|---|---|---|
| BRICK | `#B65A42` | 위에 HATCH 대신 `#7A3A2A` 빗금 |
| OCHRE | `#D4A043` | `#93702C` 빗금 |
| SAGE | `#7F9C78` | `#55704F` 빗금 |
| SLATE | `#5E7D9F` | `#3E566F` 빗금 |

- 한 장면의 색 소품은 1~2개, 각 소품은 위 4색 중 하나로 평면 채움 + 같은 계열 빗금 그늘 + GRAPHITE 외곽선이다.
- **세는 법**: 위 4색 중 하나로 칠한 면이 있는 물건을 1개로 센다. 테이프 조각, 꼬리표, 메모 종이, 지면선은 세지 않는다. 같은 소품이 여러 장면에 나오면 장면마다 1개로 센다.
- **큰 면 색의 위치**: 막대 인물에는 색을 칠하지 않는다(외곽선과 HATCH 빗금만). 위 4색으로 칠한 면 중 가장 큰 것은 비유의 대상인 소품이다. 메모 종이·꼬리표는 이 비교에 넣지 않는다.

### 막대 인물

인물은 영상마다 새로 정한다. 모델마다 한 모양으로 몰리지 않도록 아래 표에서 열마다 한 칸씩 골라 장면 표에 적는다. 같은 영상에 인물이 둘이면 세 열 중 두 열 이상을 다르게 고른다.

| 머리 | 머리 위 | 몸통 |
|---|---|---|
| 원(반지름 30~36) | 없음 | 선 하나 |
| 세로 달걀형 | 짧은 앞머리 곡선 3~4개 | 좁은 사다리꼴 + 빗금 |
| 둥근 사각형 | 작은 모자(반원 + 챙 선) | 세로 타원 + 빗금 |
| 가로 타원 | 정수리 묶은 머리(작은 원) | 직사각형 + 가로 줄무늬 2줄 |

- 키는 머리 위 끝(머리카락·모자 제외)부터 발끝까지 300~380px. 팔다리는 GRAPHITE 3.5px 선 하나씩, 손·발은 짧은 선 끝으로 끝낸다.
- 한 영상 안에서는 같은 인물을 계속 쓴다.
- 얼굴은 점 눈 둘(반지름 4)과 짧은 선 입(2px). 표정은 [motion-doodle 표정 표](../akbun-draw-motion-doodle/SKILL.md#캐릭터-설계-규칙)의 눈·입 모양을 고르되, 선 굵기는 2px, 색은 GRAPHITE, 흰 원은 CARD로 채운다. 기본 표정에도 입을 그린다.
- 물건을 쥔 팔 끝은 물건 외곽선에 닿는다.

### 메모와 꼬리표

- **테이프 메모**: CARD 사각형(살짝 휜 변, GRAPHITE 2px 외곽선, 폭 260~380px), RULE 줄선, 손글씨 2~4줄(한 줄 한 `<text>`, 위 줄부터 차례로 써짐). 위 가장자리에 TAPE 띠 하나(80×26px, -8~-14° 회전, 살짝 휜 `<path>`, 외곽선 없음)를 걸친다. 한 화면 메모는 2장까지.
- **꼬리표**: TAG 채움 + GRAPHITE 2.5px(구멍 원은 PAPER 채움), 한쪽 끝을 자른 가로로 긴 오각형(높이 56~70px), 구멍 원 하나, 대상까지 GRAPHITE 2px 끈. 글자는 손글씨 34~40px 또는 코드 토큰이면 D2Coding 28~32px, 꼬리표 하나에 8자 이하이고 꼬리표와 함께 바로 보인다(써지기 아님). 꼬리표 폭은 글자 폭 + 70px(구멍 쪽 여백 포함). 한 화면 꼬리표는 3개까지.
- **꼬리표가 떨어짐**: 포즈 세 장으로 한다. ① 붙음 ② 끈이 끊기고 30~60px 아래, 매달린 각도에서 15~30° 더 기욺 ③ 지면선 위에 납작하게 누움(회전 -12~12°, 아래 변이 지면선에 닿음). ②는 그 요소의 시각(신호 단어 0.1초 전)을 그림 격자(1 ÷ drawings_per_second의 배수)로 내림한 값, ③은 ② + 2 ÷ drawings_per_second다(12장/초면 0.1667초, 15장/초면 0.1333초를 더한 뒤 소수 둘째 자리로 적는다). 떨어지는 동안 위치를 보간하지 않는다. 이 포즈들은 "포즈당 0.5초" 규칙의 예외다.

### 손글씨

- `font-family`는 `'Gaegu', 'Nanum Pen', 'Nanum Pen Script', sans-serif`. 렌더 전에 `uv run --python 3.12 <doodle>/scripts/render_doodle.py --fonts "Gaegu"`가 `ok`인지 본다(D2Coding 꼬리표를 쓰면 `"Gaegu,D2Coding"`). `missing`이면 렌더하지 말고 설치할지 사용자에게 묻는다(Google Fonts 공식 배포처).
- 메모 38~46px, 라벨 34~40px, 물음표 50~70px. 화면에서 손글씨는 카메라 zoom 1 기준 34px보다 작게 쓰지 않는다. 글자는 GRAPHITE. 강조할 단어 하나만 BRICK으로, 같은 `<text>` 안 `<tspan fill>`로 칠한다(써지기는 tspan 글자까지 이어진다).
- 글자마다 `rotate`(-3~3도)를 다르게 준다. 값 개수는 공백을 포함한 글자 수와 같다. `dy`는 쓰지 않는다.

### 화면 배치

- 바탕은 빈 종이다. 지면선 하나(y 820~900, 화면 가로 6~94%를 가로지르는 살짝 물결진 선)만 예외로 그린다.
- 주인공 묶음(인물 + 비유 소품, 손잡이 같은 소품 부분 포함, 꼬리표·끈·메모 제외)의 경계 상자 중심은 가로·세로 모두 화면 가운데 60% 안(x 384~1536, y 216~864)에 둔다.
- 작은 낙서(별·소용돌이·작은 새 같은 GRAPHITE 선 그림, 40px 이하)는 빈 곳에 2개까지 둘 수 있다(선택).
- 요소끼리 60px 이상 띄운다(끈, 쥔 물건과 팔 끝, 받침 위에 놓인 물건, 지면선에 닿는 발·다리·떨어진 꼬리표는 예외).

### 모션

| 움직임 | 방식 | 길이 |
|---|---|---|
| 인물·소품 등장 (기본) | `data-show` | 즉시(한 그림) |
| 화살표·끈 | `data-draw` | 선 길이 ÷ 700초, 최소 0.3초. 빗금은 그 물체와 함께 바로 보인다. 꼬리표는 끈이 다 그려진 시각에 `data-show` |
| 손글씨 | `data-write` | 글자 수(공백 포함) ÷ 8초 |
| 메모·꼬리표 등장 | `data-show` | 즉시 |
| 인물 동작·표정 | 포즈 교체(눈·입·팔 각도 중 1~2개만 다름) | 인물 포즈당 0.5초 이상 |
| 사라짐 | 그 요소가 없는 포즈로 교체 | 즉시 |

- `drawings_per_second`: fps 24·48·60이면 12, fps 30이면 15.
- 빌드·간격 규칙은 이 표와 아래 문단이 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md)보다 우선한다(motion-doodle의 0.3초 쉼과 "초당 12장 고정"은 쓰지 않는다). 카메라 이동은 빌드가 아니라 마감 뒤에도 이어져도 된다. 시작 시각은 소수 둘째 자리에서 내림, 끝 시각은 올림한다.
- **빌드**는 시간이 걸리는 등장(`data-draw`, `data-write`, `data-fade`)이다. `data-show`와 포즈 교체는 빌드가 아니다. 동시에 진행 중인 빌드는 둘까지다. 마지막 빌드는 장면 끝 1.0초 전까지 끝낸다. 그 뒤로는 빌드·포즈 교체가 없다(카메라 흐름은 이어진다).
- **느린 흐름(항상)**: 모든 장면에 카메라 키를 둔다. 장면 시작부터 끝까지 `"ease": "linear"`로 zoom을 장면 전체에서 0.03~0.06 늘리거나, zoom 1.05 이상에서 x·y를 30~80px 옮긴다. 카메라가 멈춘 구간을 두지 않는다.
- **핵심 순간 확대**: 선택이며 장면당 한 번까지. 0.8~1.0초 ease-in-out으로 zoom을 그 시점의 흐름 값보다 0.15~0.35 더(최대 1.4) 올린다. 확대 뒤에도 같은 기울기의 linear 흐름을 장면 끝까지 이어 간다(마지막 키 zoom = 확대 값 + 남은 시간만큼의 흐름). 확대 중심은 그 순간의 꼬리표·메모·소품 중심이다.
- **화면 밖 금지**: 카메라 키마다 보이는 영역(x ± 960/zoom, y ± 540/zoom)이 캔버스(0~1920, 0~1080) 안에 있어야 한다. 대상이 가장자리에 가까우면 중심을 안쪽으로 옮긴다(x는 960/zoom ~ 1920 − 960/zoom, y는 540/zoom ~ 1080 − 540/zoom).
- 장면 전환은 하드 컷이다. 장면 하나는 25초를 넘기지 않는다.

## 작업 흐름

`<doodle>`은 [akbun-draw-motion-doodle](../akbun-draw-motion-doodle/SKILL.md) 디렉터리다.

1. **장면 표**: 장면마다 id, "언제 쓰나"에서 고른 행, 비유(무엇을 무엇에 빗대는지 한 줄), 고른 인물 칸, 색 소품과 색, 요소별 신호 단어와 시각을 적는다. 출력 폴더는 사용자가 정한 곳, 없으면 `pencil-output/<작업명>/`.
2. **SVG 포즈**: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1920 1080">`로 시작하고 `width`·`height`·배경 사각형·`filter`·`<image>`를 넣지 않는다. 그리는 순서는 지면선 → 물체마다(뒤 물체부터) 채움 → 빗금 → 외곽선 → 메모·꼬리표 → 글자. 포즈가 여러 장이면 공통 부분을 한 번만 정의하는 작은 생성 스크립트(출력 폴더)로 만들고, 바뀌지 않는 좌표는 포즈 사이에 똑같이 둔다.
3. **spec.json**: 아래 예시처럼 쓴다. `fps`는 놓을 타임라인 fps와 같게 한다.
   예시: [references/example/](references/example/)(캐시를 컵·유통기한 꼬리표로 빗댄 두 장면, `sheet.jpg`는 포즈별 마지막 그림). 스타일 확인용이며 인물·소품·문구를 그대로 쓰지 않는다.
4. **렌더**와 **검수**, **완료 보고**는 아래를 따른다.

인물이 소품을 보는 9초 장면 하나에 느린 흐름과 핵심 순간 확대를 둔 spec 예시다.

```json
{
  "size": [1920, 1080], "fps": 24, "drawings_per_second": 12,
  "background": "#EDE8D5", "grain": 0.035,
  "scenes": [
    {"id": "label_drop", "duration": 9.0,
     "poses": [{"svg": "drop_1.svg", "at": 0}, {"svg": "drop_2.svg", "at": 5.0}, {"svg": "drop_3.svg", "at": 5.17}],
     "camera": [{"at": 0, "zoom": 1.0}, {"at": 4.2, "zoom": 1.03, "ease": "linear"},
                {"at": 5.1, "zoom": 1.3, "x": 1120, "y": 620}, {"at": 9.0, "zoom": 1.33, "ease": "linear"}]}
  ]
}
```

spec을 MP4로 렌더하고 포즈별 스틸을 남기는 명령이다.

```bash
uv run --python 3.12 <doodle>/scripts/render_doodle.py pencil-output/<작업명>/spec.json pencil-output/<작업명>/out.mp4 --stills pencil-output/<작업명>/stills
```

스틸을 한 장으로 붙이는 명령이다. `tile=열x행`은 스틸 수로 정한다: 1장 `1x1`, 2장 `2x1`, 3장 `3x1`, 4장 `2x2`, 5~6장 `3x2`, 7~8장 `4x2`, 9장 `3x3`, 10~12장 `4x3`, 13~16장 `4x4`.

```bash
ffmpeg -v error -y -pattern_type glob -i 'pencil-output/<작업명>/stills/*.png' -vf "scale=640:-1,tile=3x1:color=0xEDE8D5" -frames:v 1 pencil-output/<작업명>/sheet.jpg
```

### 검수

숫자로 먼저 확인한다.

- 렌더 프레임 수 = 장면 길이 합 × fps.
- 글꼴 검사가 `ok`.
- SVG 색 값이 위 두 표(종이와 선, 색 소품)와 그늘 빗금 색 안에 있는가. 색 소품 수(세는 법대로) 1~2개인가.
- 모든 장면에 카메라 키가 있고, 첫 키 `at`이 0, 마지막 키 `at`이 장면 길이와 같은가. zoom 최대값 ≤ 1.4이고 키마다 보이는 영역이 캔버스 안인가.
- 동시에 진행 중인 빌드가 둘 이하이고, 마지막 빌드가 장면 끝 1.0초 전에 끝나는가.
- 주인공 묶음 경계 상자 중심이 x 384~1536, y 216~864 안인가.
- 꼬리표가 떨어지는 ②→③ 포즈가 렌더된 그림 번호로 2장 차이인가(`at × drawings_per_second`를 내림한 값의 차이).
- 글꼴 검사 출력 JSON의 값이 모두 `"ok"`인가.

시트를 한 번 보고 확인한다.

- 인물에 색이 칠해져 있지 않고, 가장 큰 색 면이 비유 소품인가.
- 선이 자로 그은 듯 반듯하지 않은가. 빗금이 그늘 면 밖으로 나가지 않는가.
- 인물·소품이 이미 알려진 캐릭터·장면과 닮아 보이지 않는가. 닮았으면 인물 표에서 두 칸 이상 바꾼다.

### 완료 보고

출력 경로, 장면 표(비유·인물 칸·신호 단어·녹음 전/후 시각), 렌더 프레임 수, 글꼴 검사, 검수 결과를 적는다. 확인하지 않은 항목은 "확인하지 않음"으로 적는다. Resolve에 놓아 달라고 하면 [motion-doodle의 Resolve 배치](../akbun-draw-motion-doodle/SKILL.md#resolve-배치)를 따른다.

## 하지 말 것

- 인물·소품을 사진·3D·그라데이션으로 그리지 않는다. `filter`(특히 `feTurbulence`)로 종이 결을 만들지 않는다. 종이 결은 spec `grain`이다.
- 카메라를 멈춘 채 두지 않는다. 흔들기(wiggle)·회전은 하지 않는다.
- 실제 브랜드 로고·제품 모양을 그리지 않는다.
