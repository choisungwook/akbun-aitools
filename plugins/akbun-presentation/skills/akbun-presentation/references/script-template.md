# 발표 대본 작성 가이드

발표 대본(`.md`)은 슬라이드 요약본이 아니다. **이 분야를 처음 접한 발표자가 대본을 순서대로 읽으면
개념·문제·방법·결과를 이해하고, 화면을 가리키며 설명할 수 있는 완성 원고**다.

원본 자료를 번역하거나 슬라이드 문장을 그대로 옮겨 적으면 실패다. 발표자가 내용을 실제로 이해하고
말하는 것처럼 쓴다.

## 슬라이드별 항목

슬라이드마다 아래 11개 항목 중 **그 슬라이드에 필요한 것만** 쓴다. 전부 기계적으로 채우면 대본이
읽을 수 없게 길어진다. 전환 슬라이드는 2·11번만 있으면 충분하고, Figure 슬라이드는 3·4·5가
핵심이다.

1. 먼저 알아야 할 배경지식
2. 실제로 읽을 수 있는 자연스러운 발표 대본
3. 화면에서 먼저 가리킬 부분
4. Figure·Chart를 가리키는 순서
5. 축·범례·색상·화살표·박스의 의미
6. 수식에 등장하는 기호의 뜻
7. 수식이 만들어지는 단계별 과정
8. Algorithm·프로세스의 입력·반복 과정·조건·출력
9. 헷갈리기 쉬운 점
10. 이 내용이나 결과가 중요한 이유
11. 다음 슬라이드로 넘어가는 연결 문장

## 분량

한국어 발표는 분당 300~330자다. 목표 발표 시간 × 320자를 대본 본문(2번 항목) 총합의 기준으로 잡는다.

- 중요한 Figure·수식·Algorithm 슬라이드에 분량을 더 준다.
- 전환·요약 슬라이드는 두세 문장으로 짧게 쓴다.
- 배경지식·기호 설명 같은 나머지 항목은 발표자가 읽고 이해하는 용도라 글자 수 계산에서 뺀다.

## 파일 형식

파일명은 `<덱이름>-script.md`. 슬라이드 번호는 pptx와 정확히 일치시킨다.

```markdown
# <발표 제목> 발표 대본

- 발표 시간: 10분 / 슬라이드 14장
- 청중: 배경지식이 부족한 소프트웨어 엔지니어
- 대본 본문 총 3,180자 (약 9분 55초)

## Slide 1 — Cache Stampede and How We Survived It (표지)

**대본**
안녕하세요, ...

**다음 슬라이드로**
오늘 다룰 순서를 먼저 보겠습니다.

## Slide 5 — Normal Cache Read Path (내용)

**먼저 알아야 할 배경지식**
캐시는 ... / TTL(Time To Live)은 캐시에 저장한 값이 살아 있는 시간이다.

**화면에서 먼저 가리킬 부분**
왼쪽 코드 패널의 `GET key` 한 줄.

**Figure를 가리키는 순서**
① 애플리케이션 → ② Redis 조회 → ③ 미스면 DB 조회 후 캐시에 저장.
연노랑 박스가 워크로드, 연초록이 인프라 리소스입니다.

**대본**
먼저 정상 상황부터 보겠습니다. ...

**헷갈리기 쉬운 점**
③에서 DB를 읽는 건 실패가 아니라 정상 경로다. 문제는 이게 동시에 몰릴 때만 생긴다.

**다음 슬라이드로**
그런데 이 정상 경로가 한꺼번에 일어나면 어떻게 될까요?
```

## 수식이 있는 슬라이드

수식은 결과만 읽어주면 아무도 이해하지 못한다. 아래 순서로 쓴다.

1. 이 수식이 무엇을 계산하거나 표현하는지
2. 각 기호가 무엇을 의미하는지
3. 앞 항과 뒤 항이 각각 어떤 의미인지
4. 어떤 기본식이나 가정에서 출발했는지
5. 값을 하나씩 대입해 최종식이 나오는 과정
6. 가능하면 숫자를 넣은 간단한 예시
7. 이 수식이 Figure·결과·설계 결정과 어떻게 연결되는지

## Algorithm·절차가 있는 슬라이드

의사코드를 그대로 읽지 않는다. 아래 순서로 쓴다.

1. 이 알고리즘·절차가 필요한 이유
2. 입력값이나 시작 조건의 의미
3. 각 단계·반복문이 처리하는 대상
4. 조건식·의사결정 기준이 필요한 이유
5. 후보나 결과를 평가하는 기준
6. 최종 출력값이나 도달 상태
7. 가능하면 실제 숫자나 작은 사례로 한 바퀴 돌려보기
8. 관련 Figure·시스템 구조·실제 결과와 연결

수식이나 Algorithm이 없는 자료에서는 같은 원칙을 프로세스·의사결정 구조·분석 방법·업무 흐름
설명에 적용한다. 원본에 수식·Algorithm이 없으면 억지로 만들지 않는다.

## 주의점 표시

원본 자료에서 불확실하거나 해석이 갈리는 부분, 특정 조건에서만 성립하는 결과는 대본에
`> 주의:` 로 표시해 발표자가 단정하지 않도록 한다. 외부 자료를 가져온 슬라이드는 대본에도 출처를
남긴다.
