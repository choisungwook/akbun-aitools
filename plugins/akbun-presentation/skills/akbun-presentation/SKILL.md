# akbun 다크 발표자료 생성

주제·글·논문·코드·장애 경험을 핵심 메시지가 한 개씩 있는 발표 덱과 읽고 말할 수 있는 대본으로 만든다.
제공된 스타일은 발표 슬라이드의 가독성·편집 가능성·페이지 전개에 맞춰 적용한다.
영상 편집 도구의 조작, 초 단위 타이밍, 프레임 효과는 제작 지침으로 옮기지 않는다.
이 파일이 디자인의 단일 기준이다. 기존 제작 방식은
[akbun-presentation-paper](../akbun-presentation-paper/SKILL.md)으로 이름을 옮겼다.
paper의 디자인·pptxgenjs 키트와 akbun-presentation-visual의 기존 이미지 스타일은 이 덱에 적용하지 않는다.

## 설정과 제작 순서

- 미지정 값은 발표 10분, 12~15장, 배경지식이 부족한 소프트웨어 엔지니어 청중,
  슬라이드·대본 한국어로 정한다. 사용자가 지정한 시간·장수·청중·언어를 우선한다.
- 원본 자료를 읽고 슬라이드별 유형·제목·핵심 메시지·출처를 표로 제시한 뒤 제작한다.
  문제·질문 → 필요한 배경 → 과정·근거 → 답·결론으로 연결하되 원본 논리를 유지한다.
- 슬라이드별 대본을 먼저 쓴다. 대본 형식과 분량은
  [발표 대본 가이드](../akbun-presentation-paper/references/script-template.md)의 항목·분량 규칙을
  재사용한다. 그 문서의 예시 색·코드 패널 배치는 적용하지 않는다.
- 편집 가능한 텍스트·도형으로 `.pptx`를 만든다. 사용할 수 있는 제작 도구를 선택하고 아래 스펙을
  구현한다. 이미지에 슬라이드 전체를 굽지 않는다.
- 원본의 관계·수치·단위·조건을 유지한다. 없는 장애나 인과를 만들지 않는다. 예시는 `가정`으로 표시한다.
  원본 도식을 재구성하면 `adapted from ...` 캡션과 출처를 대본에 남긴다.
- 실제 렌더링으로 글자 잘림·겹침·폰트 대체·색과 좌표를 확인하고 수정한다.
  렌더러가 없으면 미검증 항목을 밝히고, 확인하지 않은 결과를 검수 완료로 표시하지 않는다.

## 캔버스와 단위

- 실제 PPT 페이지는 16:9 와이드(13⅓×7.5in)다. 1920×1080px은 배치·크기 비율을 설명하는
  디자인 기준 좌표이며 영상 출력 해상도를 지정하는 것이 아니다.
- 전 슬라이드 배경은 단색 `#252525`다. 그라디언트·텍스처·사진 배경을 넣지 않는다.
- PPT를 13⅓×7.5in으로 만들면 좌표·길이는 `px / 144` in, 글자·선 두께는 `px / 2` pt로 변환한다.
  예: 56px 헤더 = 28pt, 최소 24px = 12pt, 2px 선 = 1pt. CSS의 96dpi 환산과 혼용하지 않는다.
- 페이지 번호·목차·장식 푸터를 자동으로 추가하지 않는다. 필요한 출처는 아래 각주 영역에 둔다.

## 색상

기본 5색과 노랑 내부 글자용 검정 1색, 총 6색만 사용한다.

| 역할 | 색 |
|---|---|
| 배경 | `#252525` |
| 본문 | `#EBEBEB` |
| 선·테두리·표지 제목·질문 | `#FFFFFF` |
| 주인공 박스·핵심 강조·정상 단계 마커 | `#FFC000` |
| 문제 경로·✕·장애 캡션·문제 단계 마커 | `#FF0000` |
| 노랑 박스·정상 단계 마커 내부 글자 | `#000000` |

슬라이드당 핵심 강조는 1~2개, 노랑 채움 하이라이트는 최대 1개다. 주인공 박스·강조 셀·텍스트
하이라이트는 이 한 자리를 공유한다. 순서를 나타내는 작은 단계 마커는 하이라이트 개수에서 제외한다.
기술 로고는 제공되거나 확보한 원본을 경계 박스 좌상단에 직접 삽입한다. 로고 고유색은 보존하되
도형 팔레트로 확장하지 않는다. 로고를 확보하지 못하면 꾸며 만들지 않고 텍스트 라벨을 쓴다.

## 폰트와 글자 크기

Gmarket Sans 단일 서체를 쓴다. 사용할 수 없으면 덱 전체를 Pretendard로 대체한다.
기본 Medium(500), 라벨·강조 Bold(700)다. PPT 글자는 최소 12pt(기준 24px)로 두고,
투사 환경에서 작게 보이면 키우고 내용을 나눈다. 아래 표의 pt 값을 PPT에 적용한다.

| 요소 | 기준 px | PPT pt | 지정 |
|---|---|---|---|
| 표지 제목 | 104px | 52pt | Bold, 흰색 |
| 표지 부제 | 40px | 20pt | 본문색 |
| 질문·전환 문장 | 72px | 36pt | 흰색, 가운데 정렬, 줄간격 1.4 |
| 파트 라벨 | 32px | 16pt | 노랑, 예: PART 1 · Cache 동작 |
| 슬라이드 헤더 | 56px | 28pt | 본문색 |
| 메시지 한 줄 | 34px | 17pt | `• `로 시작 |
| 다이어그램 라벨 | 28px | 14pt | Bold, 보조 줄 12~13pt(24~26px) |
| 각주·캡션 | 24px | 12pt | 본문색, 장애 캡션은 빨강 |

## 고정 위치

좌표는 요소 텍스트 상자의 좌상단 기준이다. 글자 잘림을 막는 상자 높이를 확보한다.

| 요소 | 위치 |
|---|---|
| 헤더 | x 66, y 56 |
| 메시지 한 줄 | x 108, y 166 |
| 다이어그램 | y 280~940 |
| 각주 | x 66~300, y 960~990 |
| 질문·전환 | 파트 라벨과 질문을 묶어 화면 정중앙에 배치, 두 요소 사이 간격 44px |

다이어그램 영역에는 경계 라벨·화살촉·범위 괄호의 아래 라벨까지 포함한다. 각주의 x 범위는 시작점
선택 범위이며 너비 제한이 아니다. 긴 출처는 짧은 표시명과 링크로 두고 전체 URL은 대본에 남긴다.

## 다이어그램

| 요소 | 규칙 |
|---|---|
| 컴포넌트 박스 | 채움 없음, 흰색 2px 실선, 직각 모서리, 라벨 가운데 정렬 |
| 주인공 박스 | 노랑 채움, 검정 Bold 글자, 테두리 없음 |
| 논리 경계(site·VPC 등) | 흰색 2px 점선, 라벨은 박스 위 46px·좌측에서 안쪽 12px, 28px |
| 데이터 흐름 | 흰색 3px 실선, 삼각형 화살촉 20×20px |
| 주의·문제 흐름 | 빨강 3px 점선, 빨간 삼각형 화살촉 |
| 문제 표시 | 빨간 ✕ 52~60px Bold + 빨간 캡션 |
| 단계 마커 | 지름 48~56px 원, 숫자 24~28px Bold |
| 정상 단계 | 노랑 원 + 검정 숫자 |
| 문제 단계 | 빨강 원 + 흰 숫자 |
| 범위 괄호 | 흰색 2px 선, 윗변 없는 ㄷ자(위로 열린 U형), 높이 22~24px, 라벨은 아래 |
| 표 | 흰색 2px 격자, 배경 #252525, 행 높이 92px, 강조 셀은 최대 1개 노랑 채움 |

- 읽는 방향은 왼쪽 → 오른쪽, 요청 → 응답이다.
- 슬라이드당 다이어그램은 1개, 컴포넌트 박스는 최대 7개다. 내용이 적으면 5개를 채우지 않는다.
- 화살표가 라벨·박스·마커를 가로지르지 않게 배치한다. 응답 경로는 별도 높이로 돌아오게 한다.
- 그림자·블러·반투명 효과·그라디언트·둥근 카드·이모지·아이콘 세트를 쓰지 않는다.
  채움 없음은 반투명 효과와 구분한다. 코드에도 별도 구문 강조 팔레트를 추가하지 않는다.

## 단계별 연속 슬라이드

과정 설명은 슬라이드를 복제해 한 단계씩 보여준다. 각 페이지는 애니메이션 없이도 의미가 완결되어
PDF로 내보내거나 정지 화면으로 보아도 이해할 수 있어야 한다.

- 기존 도형·라벨의 배치와 크기를 고정하고 다음 슬라이드에 필요한 요소·화살표·마커만 추가한다.
- ① → ①② → ①②③처럼 현재까지의 흐름을 유지한다. 새 요소의 공간은 첫 슬라이드부터 확보한다.
- 화살표는 해당 단계의 슬라이드에서 완성된 선과 화살촉으로 표시한다.
- 문제 → 해결은 같은 구도를 유지하되 해결된 문제의 빨간 경로·✕·캡션을 갱신한다.
  더 이상 유효하지 않은 문제 표식을 누적하지 않는다.
- 강조는 슬라이드마다 대상 하나로 옮기고, 이전 대상은 기본 흰 테두리로 돌린다.
  한 페이지의 노랑 채움 제한을 유지한다.
- 슬라이드 전환 효과와 자동 재생을 기본으로 넣지 않는다. 발표자가 페이지를 넘기며 설명한다.
- 단계별 페이지도 목표 장수에 포함한다. 대본은 각 페이지에서 새로 드러난 변화만 설명하고,
  반복 도형 전체를 매번 다시 읽지 않는다.

## 말투

- 슬라이드 글은 평어체 단정문으로 쓴다: `~이다`, `~한다`.
- 질문·전환은 해요체로 쓴다: `~일까요?`.
- 결론은 청유형으로 닫는다: `~하자`.
- 영문 기술 용어는 번역하지 않는다: SA, rekey, TGW, ESP. 설명이 필요하면 대본에서 뜻을 풀되
  화면의 용어 표기는 유지한다. 다른 언어를 지정받으면 해당 언어의 자연스러운 문장으로 쓴다.

## 예시

입력: `메시지 큐의 재시도와 중복 처리를 10분 발표자료로 만들어줘.`

| 슬라이드 | 메시지·화면 |
|---|---|
| 표지 | 메시지 재시도와 중복 처리 — 흰색 52pt 제목 |
| 질문 | PART 1 · Retry / 같은 메시지가 두 번 오면 어떻게 될까요? |
| 정상 | Producer → Queue → Consumer, Consumer 한 곳 노랑 채움 |
| 문제 | 같은 배치에서 중복 전달 경로만 빨간 점선·✕·캡션으로 표시 |
| 해결 | 같은 배치에 중복 확인 단계를 추가, 근거 있는 처리 순서만 표시 |
| 결론 | 재시도를 고려해 중복 처리를 설계하자 |

이 예시는 구성 방식만 보여준다. 입력에 없는 제품 동작·수치·장애 사실을 덧붙이지 않는다.

## 완료 전 확인과 출력

- 1920×1080 기준 좌표, 글자 최소 24px, 팔레트, 선 두께, 강조 개수가 맞는가?
- 질문 화면의 중앙 정렬·44px 간격·줄간격 1.4와 각주의 가독성을 렌더링으로 확인했는가?
- 다이어그램·캡션이 영역 안에 있고 연속 슬라이드의 기존 요소 위치가 유지되는가?
- 애니메이션 없이 각 페이지의 단계·문제·해결을 이해할 수 있고 이전 강조가 남지 않았는가?
- 단계별 페이지를 포함한 모든 슬라이드 번호에 대응하는 대본과 필요한 출처가 있는가?
- 최종 답변은 `.pptx`·대본 `.md` 링크, 장수·예상 발표 시간, 검수 결과만 짧게 적는다.
