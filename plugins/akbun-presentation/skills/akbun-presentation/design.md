# akbun 발표자료 디자인 가이드

akbun 발표자료의 스타일을 재현하기 위한 자기완결적 스펙이다. 색·타이포·레이아웃·그림 언어·말투·
스크린샷 규칙을 담는다. 특정 도구(pptxgenjs 등)에 의존하지 않으므로, 다른 프롬프트·문서·디자인
도구에 그대로 복붙해 스타일을 재현할 수 있다.

기본 형식은 **라이트 샌드위치**다. 다크 표지·섹션 슬라이드가 흰 내용 슬라이드를 감싸고, 목차·
실습자료 안내·페이지 번호·링크 푸터까지 갖춘 정식 발표 형식이다. 전 슬라이드를 다크로 가는
**다크 스텝** 변형은 문서 마지막 절에 있다.

## 원칙

- **캔버스**: 16:9 와이드(13.33 × 7.5 in).
- **스토리는 "질문 → 여정 → 답"이다.** 정답을 먼저 말하지 않고, 질문/전환 슬라이드로 궁금증을
  만든 뒤 스텝을 밟아 답에 도착한다.
- **전환 슬라이드가 발표의 리듬이다.** 섹션 사이, 실습 직전, 반전 지점에 글자만 있는 전환
  슬라이드를 끼워 청중의 호흡을 조절한다.
- **순서는 숫자 마커로 밟는다.** 다이어그램의 흐름은 ①②③ 서클 숫자로 표시하고, 청중은 마커
  순서대로 그림을 읽는다.
- **강조 색 문법**: 노랑(`#FFC000`)은 포인트(섹션 바·표지 키워드·주인공), 빨강(`#FF0000`)은
  문제·에러·주목할 흐름. 한 슬라이드에 강조는 1~2개면 충분하다.
- **실습은 재현 가능해야 한다.** 실습 슬라이드에는 `github 링크: URL`, 데모 영상이 있으면
  `유투브 데모링크: URL`을 하단에 단다.
- **출처를 밝힌다.** 가져온 이미지·자료 아래 `[ 출처: ... ]` 캡션을 달고, 원본 자료가 있으면
  슬라이드 하단에 페이지·Figure 번호를 작게 남긴다.
- **같은 다이어그램을 반복하며 장면을 진행한다.** 슬라이드마다 새 그림을 그리지 말고, 같은
  구도에서 마커·강조·설명만 바꿔 이야기가 진행되는 효과를 낸다.
- **레이아웃은 내용이 정한다.** 페이지마다 같은 장식 구성을 반복하지 않는다. Figure 중심, 수식
  중심, 과정 설명, 비교 — 네 가지 배치를 내용에 맞게 골라 쓴다.
- 영어 기술 용어(pod, iptables, TTL 등)는 번역하지 않고 그대로 쓴다.

## 말투

말투 규칙은 **한국어로 쓰는 쪽**(보통 발표 대본, 슬라이드 언어가 한국어면 슬라이드도)에 적용한다.

- **내용은 평어체 단정문·명사형**으로 짧게 쓴다: "~이다", "~한다", "설정방법", "통신순서".
- **전환·질문은 청중에게 말을 건다.** 해요체·합쇼체를 허용한다:
  "왜 통신이 안될까요?", "직접 디버깅해봐요!", "자! 이제 ~를 다뤄봅시다".
- **시나리오로 구체화한다**: "시나리오: pod 1개가 분당 처리할 수 있는 요청 수 1,000".
- 질문에 답할 때는 **"정답: ~"** 또는 **"첫 번째 포인트: ~"** 로 시작한다.
- **꼬리지식 패턴**: 정의가 와닿지 않으면 배경지식으로 파고들었다가 "다시 돌아와서 ~란?"으로 복귀한다.
- **솔직하게 수준을 밝힌다**: "전문 분야가 아니라 겉핥기 수준으로 정리" 같은 고백을 아끼지 않는다.
- 결론은 **청유형**으로 닫는다: "~하자", "~까지 설계하자".
- 이모지는 덱 전체에서 0~1회.

슬라이드를 영어로 쓸 때는 짧은 명사구·질문문만 쓴다. 헤더는 Title Case, 불릿은 문장부호 없는
명사구, 전환 슬라이드는 질문문 한 줄: `What happens when 10,000 keys expire at once?`
한국어 말투를 영어로 직역하지 않는다. 대본은 위 말투 규칙 그대로 한국어로 쓴다.

## 색

| 역할 | 색 | 쓰는 곳 |
|---|---|---|
| 다크 배경 | `#212022` | 표지·섹션 표지 |
| 라이트 배경 | `#FFFFFF` | 내용·전환·목차 등 나머지 전부 |
| 본문 | `#000000` | 라이트 슬라이드의 텍스트·도형선 |
| 포인트 | `#FFC000` | 섹션 표지 세로 바, 표지 제목의 핵심 키워드 |
| 문제/강조 | `#FF0000` | 빨간 화살표·박스·X·경고 텍스트 |
| 워크로드 채움 | `#FFF2CC` | 다이어그램의 pod·앱 등 워크로드 박스 |
| 리소스 채움 | `#E2EFDA` | service 등 쿠버네티스/인프라 리소스 박스 |
| 그룹 채움 | `#F2F2F2` | Endpoints 같은 묶음 영역 |
| 캡션 회색 | `#7F7F7F` | 출처 캡션 |
| 코드 패널 | 배경 `#1E1E1E`, 기본 `#D4D4D4`, 키 `#569CD6`, 문자열 `#CE9178` | VS Code Dark+ 스타일 코드/YAML |

원본 Figure를 다시 그릴 때는 원본의 의미 구분에 필요한 색만 추가로 쓴다. 장식 목적의 색·
그라데이션은 쓰지 않는다.

## 타이포그래피

본문은 **나눔바른고딕**(없으면 맑은 고딕), 코드는 **Consolas**. bold는 헤더·섹션 제목·라벨에 쓴다.

| 요소 | 크기 |
|---|---|
| 표지 제목 | 40pt bold (핵심 키워드만 노랑, 나머지 흰색) |
| 섹션 표지 제목 | 40pt bold 흰색 |
| 전환/질문 멘트 | 32pt bold 검정, 중앙, 2~4줄 스택 |
| 수식 | 20~28pt (화면에서 바로 읽혀야 한다) |
| 내용 헤더 | 18pt bold, `N. 섹션명` 형식 |
| ■ 메인 불릿 | 14pt |
| - 서브 불릿·본문 | 12pt |
| 다이어그램 라벨·표 글자 | 10~11pt (10pt가 하한) |
| 코드 패널 | 10pt Consolas |
| 푸터 링크·출처 캡션 | 9~10pt |
| 페이지 번호 | 11pt, 오른쪽 아래 (표지 제외 모든 슬라이드) |

글자를 줄여 내용을 더 밀어 넣지 않는다. 표가 10pt로 안 들어가면 표를 나누거나 핵심 행·열만 남긴다.

## 덱 구성 (스토리 순서)

1. **표지** (다크) — 제목 중앙(핵심 키워드 노랑). 발표자 정보는 넣지 않는다
2. **목차** (라이트) — 번호 목록으로 섹션 나열
3. **실습자료 안내** (라이트) — 예제 github repo, 실습 환경(vagrant 등), 출처. 실습이 없는 발표면 생략
4. **섹션 반복** ×N — 섹션마다 아래 리듬을 반복한다
   - 섹션 표지 (다크 + 노란 세로 바)
   - 개념 설명 (■ 불릿 + 다이어그램)
   - 전환 질문 ("왜 ~일까요?")
   - 원리/정답 (①②③ 스텝 다이어그램)
   - 실습 (코드 패널 + 링크 푸터), 디버깅 확인 (스크린샷)
5. **마치며** (섹션 표지 후 라이트) — 내용 요약 → 다음 공부 → 감사 인사
6. **참고자료** (라이트) — 번호 목록 링크

## 레이아웃 상세

좌표 단위는 inch, 원점은 슬라이드 왼쪽 위.

- **표지**: 제목 (0.9, 2.9) 폭 11.5 중앙 정렬. 부제가 있으면 제목 아래 20pt 회색 한 줄.
- **섹션 표지**: 노란 세로 바 (0.42, 세로 중앙, 0.18 × 1.0). 제목은 바 오른쪽 (0.95)에서 시작.
  부제는 제목 아래 `- 부제` 20pt 흰색.
- **내용**: 헤더 (0.42, 0.2). 불릿 블록 (0.79, 0.96)에서 시작, ■ → `-` → ①②③ 들여쓰기 계층.
  불릿은 2~4줄까지만 쓰고 나머지는 다이어그램·코드가 말하게 한다.
  본문 영역 y 1.7~6.9에 다이어그램 하나(+코드 패널 하나) 배치.
- **Figure 중심**: Figure를 본문 영역 폭 60~80%로 크게 두고, 옆이나 아래에 "무엇을 봐야 하는지"
  한 줄. 축·범례·단위가 잘리지 않게 crop을 최소화한다.
- **수식 중심**: 수식을 중앙 상단에 20pt 이상으로 두고, 아래에 기호 뜻을 `기호 = 의미` 목록으로 나열.
- **과정 설명**: 왼쪽→오른쪽 스텝 박스 + ①②③ 마커. 스텝은 5개 이하.
- **비교**: 세로 분할 2열, 각 열 위에 라벨. 다른 점 한 곳만 강조색으로.
- **실습/코드**: 코드 패널을 왼쪽(폭 3.5~4.5), 다이어그램을 오른쪽에 두고 사이에 굵은 검정
  화살표(➡)를 넣는 배치가 기본. 코드가 주인공이면 중앙 배치.
- **전환/질문**: 빈 흰 화면 중앙에 멘트만. 줄을 짧게 끊어 2~4줄로 쌓는다.
- **푸터**: 링크·출처는 왼쪽 아래 (0.3, 7.12), 페이지 번호는 오른쪽 아래 (12.6, 7.05).

## 그림 언어 (라이트 다이어그램)

- **컴퍼넌트 박스**: 흰 채움 + 검정 0.75pt 테두리 + 검정 라벨. 필요하면 살짝 둥근 모서리.
- **워크로드/리소스 구분 채움**: pod·앱 등 워크로드는 연노랑(`#FFF2CC`), service 같은
  쿠버네티스·인프라 리소스는 연초록(`#E2EFDA`), 묶음 영역은 연회색(`#F2F2F2`).
- **논리 경계**: 노드·클러스터·호스트는 둥근 모서리 얇은 검정 테두리 박스. 라벨은 경계 안쪽
  왼쪽 위. 공식 로고(kubernetes 등)는 경계 왼쪽 위 모서리에 걸쳐 배치.
- **화살표**: 데이터 흐름은 검정 실선 + 삼각 화살촉. 설정·관리 흐름이나 주목할 경로는
  **빨간 점선 화살표**. 문제 지점은 빨간 X·빨간 박스.
- **순서 마커**: ①②③ 서클 숫자 문자를 라벨 앞이나 흐름 위에 단다.
- **텍스트 강조**: 본문 키워드는 노란 형광펜(하이라이트) 또는 빨간 글씨. 한 슬라이드 한 곳.
- **밀도**: 슬라이드당 다이어그램 하나, 박스 5~7개 이하, 여백 넉넉히.
- **읽는 방향**: 왼쪽 → 오른쪽, 요청 → 응답.
- **다시 그린 도식**: 원본 Figure를 재구성했으면 캡션에 `adapted from ...` 또는
  `simplified view`를 달아 원본과 구분한다.

## 스크린샷 규칙

- 터미널·콘솔 캡처는 **다크 테마 그대로**, 필요한 부분만 잘라 넣는다. 창 프레임은 잘라낸다.
- 봐야 할 줄에 **빨간 화살표, 빨간 밑줄, 빨간 박스 중 하나**를 딱 한 곳 단다.
- 캡처 아래 `[ 설명 ]` 형식의 짧은 캡션을 달 수 있다.
- 기술 로고나 원본 Figure를 슬라이드에 실제 이미지로 넣을지, 도형+라벨로 다시 그릴지는 그때
  쓸 수 있는 도구에 맞춰 판단한다. 이미지를 못 넣는 상황이면 도형+라벨로 대체하고 자리를 남긴다.

## 변형: 다크 스텝

전 슬라이드를 다크로 가는 미니멀 변형이다. 라이트니스가 안 맞는 자리(라이트닝 토크, 밤 행사,
참고 PPT가 다크)에 쓴다. 위 스펙에서 아래만 바뀌고 나머지(스토리·마커·색 문법·스크린샷 규칙)는
그대로다.

- **배경**: 전 슬라이드 `#252525` 단색. 색은 5개로 제한 — 배경 `#252525`, 본문 `#EBEBEB`,
  도형선 `#FFFFFF`, 포인트 `#FFC000`, 문제 `#FF0000`.
- **폰트**: G마켓 산스 Medium 하나만(없으면 Pretendard).
- **크기**: 표지 제목 48~54pt, 훅·섹션 36~44pt 중앙, 슬라이드 헤더 28pt (0.46, 0.39) 고정,
  메시지 한 줄 16pt 불릿 (0.75, 1.0), 다이어그램 라벨 11~14pt, 캡션 10pt.
- **슬라이드당 메시지는 한 줄.** 목차·페이지 번호·푸터를 쓰지 않는다. 헤더는 덱 주제를 같은
  자리·같은 문구로 반복한다.
- **그림 언어**: 컴퍼넌트 박스는 채움 없음 + 흰 1pt 테두리 + `#EBEBEB` 라벨. 주인공 박스 하나만
  노랑 채움 + 검정 bold 라벨. 논리 경계는 점선 흰 사각형(라벨은 경계선 바로 위 왼쪽). 화살표는
  흰 실선 1.5pt. 숫자 마커는 지름 0.3in 채움 원 — 정상은 노랑 원+검정 숫자, 문제는 빨강 원+흰 숫자.
- **아이콘 팔레트 슬라이드**를 덱 마지막에 둔다. 자주 쓰는 도형 견본과 기술 로고를 모아두는
  작업용 슬라이드로, 발표 때는 숨긴다.
