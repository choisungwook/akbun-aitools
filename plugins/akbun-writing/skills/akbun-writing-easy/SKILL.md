# akbun 기초 레이어 글쓰기

이 skill은 원본 자료를 **처음 보는 사람이 전체 그림을 잡는 글**로 바꾼다. 목적은 하나다. **공부의 큰 흐름을 먼저 세우는 것.**

처음부터 세부를 파고들지 않는다. 디폴트 값의 근거, 설계 문서의 의도, 예외 케이스는 이 글의 몫이 아니다. 이 글의 몫은 **이게 뭐고, 왜 필요하고, 어떤 순서로 동작하는지**를 한 번에 이해시키는 것이다. 그 위에 심화 레이어를 올리는 것은 `akbun-writing`이 한다.

기초 레이어라고 해서 얕은 글이 아니다. 얕은 글은 전체 그림 없이 조각만 나열한 글이고, 기초 레이어는 조각을 다 걷어내고 **뼈대만 정확하게 남긴** 글이다. 독자가 이 글을 읽고 나면 원본 자료를 직접 읽을 수 있어야 한다. 그게 성공 기준이다.

`akbun-writing`과 다른 점은 세 가지다. 요점이 원리가 아니라 **흐름**이고, 독자가 실무자가 아니라 **이 주제를 처음 보는 엔지니어**이며, 줄글이 아니라 **개조식**으로 쓴다. 나머지 akbun 스타일 규칙(존댓말, 지어내지 않기, 추임새 금지)은 그대로 지킨다.

## 독자: 다른 분야 엔지니어

독자는 개발 경험은 있지만 **이 주제는 처음 보는 엔지니어**다. 학생도 완전 비전공자도 아니다.

- 프로그래밍 상식은 설명하지 않는다. 변수·함수·HTTP·git이 무엇인지 깔지 않는다.
- **주제 고유 용어는 전부 푼다.** 이 주제를 아는 사람만 아는 약어·구성 요소·기본 개념은 하나도 건너뛰지 않는다.
- 독자는 "이걸 왜 알아야 하는가"부터 모른다. 필요성이 먼저 오고 동작이 나중에 온다.
- 독자가 헷갈리는 지점은 대개 **이름이 비슷한 두 개념**이다. 그 자리에서 표로 구분한다.

`akbun-writing`의 tokenops 규칙(엔지니어 상식은 쓰지 않는다)은 여기서 **프로그래밍 일반 상식에만** 적용한다. 주제 고유 개념에는 적용하지 않는다.

## 입력: 원본 자료를 확인한 것만 쓴다

입력은 보통 넷 중 하나다. 어떤 자료든 규칙은 같다. **원본에 있는 것만 쓰고, 없는 것은 지어내지 않는다.**

| 원본 자료 | 변환할 때 주의할 점 |
|---|---|
| 공식 문서·데이터시트 | 목차 순서를 그대로 따라가지 않는다. 독자가 이해하는 순서로 다시 배열한다. |
| 영상·강의 스크립트 | 말한 순서에는 중복과 곁가지가 섞여 있다. 같은 이야기를 한 자리에 모은다. |
| 실습 노트·삽질 기록 | 시행착오 과정을 그대로 옮기지 않는다. 결과로 확인된 흐름만 남긴다. |
| 책·아티클 요약 | 저자의 주장과 사실을 구분한다. 주장은 누구의 주장인지 밝힌다. |

- 인터뷰하지 않는다. 동기·실패담·날짜·사람·감정은 입력에 있을 때만 쓴다.
- 원본이 애매하게 넘어간 부분을 매끄럽게 메우지 않는다. `확인 필요`로 남긴다.
- 쉽게 쓰려다 틀리면 최악이다. **정확도를 깎아서 쉬움을 사지 않는다.** 정확히 쓸 수 없으면 그 항목은 빼고 `더 공부할 것`으로 옮긴다.

## 구조: 용어 표 → 서론 → 흐름 → 다음에 파볼 것

네 부분이다. 순서대로 만들되, 실제로 쓸 때는 본론의 흐름을 먼저 잡고 서론과 용어 표를 나중에 채운다.

### 용어 표를 글 앞머리에 둔다

본문에 들어가기 전에 이 글에서 쓸 용어를 표로 정리한다. 진입 장벽을 한 번에 낮추는 장치다.

- 표 형식: `| 용어 | 뜻 |` 두 칸. 뜻은 한 줄로 끝낸다.
- 이 글을 읽는 데 필요한 용어만 넣는다. 5~10개면 충분하고, 표가 20줄이 되면 글을 나눈다.
- 표에 넣었다고 본문에서 안 풀지 않는다. **처음 나오는 자리에서 괄호로 한 번 더 푼다.**
- 약어는 원문 그대로 적고 풀어 쓴 형태를 같이 준다.

### 서론은 세 문장이면 끝난다

서론의 임무는 하나다. **이 글이 어느 레이어의 글인지 알리고 곧바로 본론으로 넘기는 것.**

- 첫 문장으로 무엇에 관한 글인지 답한다. 30자 안팎, 평서문.
- 이 글이 기초 레이어라는 것을 숨기지 않는다. 어디까지 다루고 어디부터는 안 다루는지 서론에서 선을 긋는다.
- 이 글을 읽으면 무엇을 할 수 있게 되는지 약속한다. 약속은 "원본 문서를 직접 읽을 수 있다" 수준이면 충분하다.
- 배경 설명을 길게 깔지 않는다. 서론이 다섯 문장을 넘으면 줄인다.

### 본론의 요점은 원리가 아니라 흐름이다

본론은 **전체 그림 → 구성 요소 → 동작 순서 → 헷갈리는 지점** 으로 전개한다.

- **전체 그림**: 이게 무엇이고 어떤 문제를 풀려고 나왔는지. 문제가 먼저 오고 해결책이 나중에 온다.
- **구성 요소**: 등장하는 것들의 이름과 역할. 각각 한 줄로 끊고, 관계는 표나 목록으로 보여준다.
- **동작 순서**: 요청이 들어와서 나갈 때까지 무슨 일이 순서대로 일어나는지. 번호 목록으로 쓴다.
- **헷갈리는 지점**: 이름이 비슷하거나 역할이 겹쳐 보이는 것들을 비교 표로 구분한다.

깊이는 여기서 멈춘다.

- 원리는 **한 줄씩만** 짚는다. "왜 그렇게 동작하는가"는 한 문장으로 답하고 더 파지 않는다.
- 수치·디폴트 값·설계 문서 근거는 흐름을 이해하는 데 꼭 필요할 때만 넣는다. 나머지는 `다음에 파볼 것`으로 내린다.
- 예외 케이스는 다루지 않는다. 예외를 먼저 배우면 원칙이 흐려진다.
- 한 글에 개념 하나. 개념이 둘 이상이면 글을 나눈다.

### 결론은 다음에 파볼 것 목록이다

기초 레이어 글은 요약으로 닫지 않는다. **심화로 넘어가는 목록**으로 닫는다.

- 제목은 `다음에 파볼 것`으로 둔다.
- 각 항목은 이번 글에서 일부러 넘긴 지점이다. 무엇을 넘겼는지와 왜 궁금한지를 한 줄로 쓴다.
- 3~5개가 적당하다. 목록이 길어지면 이번 글이 잡아야 할 흐름을 놓친 것이다.
- 확인하지 못한 것은 `확인 필요`로 여기에 함께 남긴다.
- 목록 앞뒤로 요약을 덧붙이지 않는다. 앞에서 한 말을 되풀이하지 않는다.

## 개조식으로 쓴다

이 글은 줄글이 아니라 개조식이다. 처음 보는 독자는 문단을 읽지 않고 훑는다.

- **불릿은 명사형으로 끊는다.** `~ 방식으로 동작`, `~ 역할을 담당`처럼 명사·어근으로 끝낸다.
- **불릿에 딸린 설명 문장은 존댓말(`~합니다`)로 쓴다.** 개조식 뼈대에 존댓말 설명이 붙는 형태가 이 글의 기본 리듬이다.
- 한 불릿은 한 줄. 두 줄을 넘으면 불릿을 쪼개거나 설명 문장으로 내린다.
- 나열은 hyphen bullet, 순서가 있으면 번호 목록, 비교는 표. 세 가지를 섞어 같은 정보를 반복하지 않는다.
- 불릿만 20줄 이어지지 않게 한다. 묶음마다 존댓말 설명 한두 문장으로 숨을 준다.
- 분량은 2000자 안팎. 흐름을 잡는 글이라 심화 글보다 짧다.

## 코드 블록은 개념 확인용만

- 개념을 눈으로 확인시키는 최소한의 예시만 넣는다. 실습 절차·전체 명령어 세트는 심화 글로 미룬다.
- 코드 블록 앞에 이게 무엇인지 설명을 먼저 쓰고, 언어 태그를 붙인다.
- 초보자가 걸릴 줄에는 주석을 단다.
- 확인하지 않은 명령어·코드는 넣지 않는다.

## 쓰지 않는 것

- 입력에 없는 동기·실패담·사람·날짜·감정
- `결과적으로`·`결론적으로`·`즉`·`정리하면`·`다시 말해`·`결국` 같은 추임새
- 정확도를 깎은 단순화. 틀린 설명은 쉬운 설명이 아니다.
- 근거 없는 비유. 비유를 쓸 거면 어디까지가 같고 어디부터 다른지 한 줄로 밝힌다.
- 원리·예외·튜닝 값을 파고드는 문단. 그건 심화 글의 몫이다.
- 격려·응원 문장(`어렵지 않아요`, `천천히 따라오세요`), 이모지, 과장 수식
- 특정인·특정 회사·고객 정보

## 포맷

- H1로 시작하고 H2, H3 순서로 내려간다. 레벨을 건너뛰지 않는다.
- 본문은 한국어로 쓴다. 기술 용어·명령어·서비스명·URL은 실무 영어 표기를 유지한다.
- 발행용 글은 마지막에 `참고자료`를 둔다. 원본 자료의 출처를 여기 남긴다.

## 자기 검토

- 이 글만 읽고 원본 자료를 직접 열어 읽을 수 있는가?
- 요점이 흐름인가, 원리로 새지 않았는가?
- 주제 고유 용어 중 안 푼 것이 있는가? 프로그래밍 상식을 다시 설명하지 않았는가?
- 불릿이 명사형으로 끊기고, 설명 문장은 존댓말로 끝나는가?
- 쉽게 쓰려다 사실을 비튼 문장이 있는가?
- `다음에 파볼 것`이 3~5개로 닫혀 있는가? 요약으로 되풀이하지 않았는가?
- 입력에 없는 내용이 들어가지 않았는가?
