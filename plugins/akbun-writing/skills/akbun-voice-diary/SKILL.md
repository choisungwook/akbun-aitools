# 음성 일기

사용자가 말로 하루를 풀어놓으면 그 말을 일기로 남기는 skill이다. 사용자는 정리하지 않고 말한다. 정리는 이 skill이 한다. 듣는 동안은 부담을 주지 않고, 끝나면 일기를 쓰고 저장하고, 말 속에 섞인 "나중에 공부해야지"를 주말 일정으로 만든다.

## 진행 순서

1. 듣기: 사용자가 말을 마칠 때까지 짧게 반응한다.
2. 쓰기: 고정 규격으로 일기를 만든다.
3. 저장: 파일로 저장하고, 지정된 곳이 있으면 그곳에도 보낸다.
4. 일정: 공부하면 좋은 것을 이번 주 주말 Apple Calendar에 등록한다.
5. 응답: 저장 위치와 등록한 일정을 짧게 알린다.

## 1. 듣기

음성 채팅이므로 답은 소리로 읽힌다. 길게 말하지 않는다.

- 사용자가 말하는 동안 답은 한 문장 이하다. "응, 그래서?", "계속해." 정도로 받는다.
- 중간에 요약하거나 정리해서 되묻지 않는다. 사용자의 흐름을 끊지 않는다.
- 사용자가 멈췄는데 아래 세 가지 중 비어 있는 것이 있으면 딱 하나만 짧게 묻는다. 없으면 묻지 않는다.
  - 오늘 있었던 일
  - 오늘 힘들었던 것
  - 나중에 공부하면 좋은 것
- 사용자가 "끝", "저장해", "오늘은 여기까지", "일기 써 줘"라고 하면 듣기를 끝낸다. 명시적 신호가 없어도 "그게 다야" 같은 마무리 표현이면 "정리할게" 한 마디 하고 넘어간다.
- 사용자가 skill 호출과 함께 한 번에 다 말했으면 듣기 단계를 건너뛰고 바로 쓴다.

## 2. 쓰기

아래 규격을 그대로 쓴다. 헤더 이름과 순서를 바꾸지 않는다. 내용이 없는 섹션은 `- 없음`으로 둔다. `내일`은 사용자가 말했을 때만 넣는다.

```markdown
# 2026-09-08 (월)

## 한 줄
오늘을 한 문장으로.

## 오늘 있었던 일
- 시간 순서대로 한 일과 있었던 일
- ...

## 힘들었던 것
- 무엇이 힘들었고 왜
- ...

## 나중에 공부하면 좋은 것
| 주제 | 왜 | 볼 것 | 언제 |
|---|---|---|---|
| Helm hooks | 배포 순서 문제로 두 시간 씀 | Helm 공식 문서 Chart Hooks | 9/12(토) 10:00 |

## 내일
- 사용자가 말한 경우만
```

작성 원칙:

- **사용자의 말을 쓴다.** 1인칭, 사용자가 쓴 표현과 어미를 유지한다. 문어체로 고쳐 쓰지 않는다. "음", "그러니까" 같은 군말과 반복만 뺀다.
- **없는 말을 만들지 않는다.** 사용자가 말하지 않은 사실, 감정, 평가를 넣지 않는다. 위로나 조언을 일기 본문에 쓰지 않는다.
- **음성 인식 오류**는 문맥으로 확실한 것만 고친다. 확실하지 않으면 들린 대로 두고 뒤에 `(?)`를 붙인다.
- **한 줄**은 사용자가 가장 길게, 또는 가장 감정을 담아 말한 것에서 뽑는다.
- **오늘 있었던 일**은 말한 순서가 아니라 하루 시간 순서로 정렬한다. 순서를 알 수 없으면 말한 순서다.
- **힘들었던 것**은 사건과 이유를 한 줄에 쓴다. 해결됐으면 어떻게 해결했는지 같은 줄에 붙인다.
- **나중에 공부하면 좋은 것**은 3단계에서 채운다. 아래 「공부 주제 알아차리기」를 따른다.
- 사람 이름은 사용자가 말한 대로 쓴다. 회사 기밀로 보이는 숫자·고객명은 사용자가 말했더라도 `XXX`로 가린다.

### 공부 주제 알아차리기

사용자가 "공부해야겠다"고 직접 말한 것뿐 아니라, 말 속에서 드러나는 것도 잡는다.

- 직접 신호: "이거 공부해야겠다", "나중에 봐야지", "모르겠더라", "찾아봐야겠다".
- 간접 신호: 같은 문제로 오래 헤맴, 남이 알려줘서 해결함, 용어를 모른 채 넘어감, 다음에 또 마주칠 것이 분명한 것.
- 주제는 한 주에 최대 3개. 넘으면 오늘 가장 힘들었던 것과 직접 이어지는 순서로 고르고, 나머지는 표에만 `언제`를 `보류`로 두고 남긴다.
- 각 주제에 `왜`는 일기에서 나온 상황 한 줄로 쓴다. 일반론("중요하니까")을 쓰지 않는다.
- `볼 것`은 공식 문서를 먼저 둔다. 웹 검색이 가능하면 실제 문서 제목과 URL을 확인해 쓰고, 불가능하면 `검색어: ...` 형태로 쓴다. 확인하지 않은 URL을 만들지 않는다.

## 3. 저장

파일명은 `YYYY-MM-DD.md`이고 날짜는 로컬 시간 기준 오늘이다. 사용자에게 어디에 저장할지 묻지 않는다.

1. **md 파일(항상)**: 사용자가 경로를 지정했으면 그 경로, 없으면 `~/Downloads/YYYY-MM-DD.md`. 같은 날 파일이 이미 있으면 덮어쓰지 않고 파일 끝에 `## 추가 (HH:MM)` 섹션으로 이어 붙인다.
2. **Apple Notes(지정 시)**: md 파일을 만든 뒤 실행한다. 폴더는 `일기`.

   ```bash
   python3 <skill-dir>/scripts/create_apple_note.py "YYYY-MM-DD 일기" ~/Downloads/YYYY-MM-DD.md --folder "일기"
   ```

3. **Google Docs(지정 시)**: Google Docs/Drive MCP로 `YYYY-MM-DD 일기` 문서를 만든다. MCP가 없으면 md 파일만 남기고 그 사실을 알린다.

Apple Notes는 macOS에서만 된다. 스크립트가 exit 2면 md 파일만 남기고 알린다.

## 4. 일정 등록

`나중에 공부하면 좋은 것`의 주제마다 Apple Calendar 이벤트를 하나씩 만든다. `보류`는 만들지 않는다.

날짜는 이번 주 주말이다.

| 오늘 | 등록 날짜 |
|---|---|
| 월~금 | 이번 주 토요일 |
| 토 | 이번 주 일요일 |
| 일 | 다음 주 토요일 |

시간은 10:00부터 주제당 60분씩 이어 붙인다(10:00, 11:00, 12:00). 사용자가 다른 날짜·시간·캘린더 이름을 말했으면 그것을 쓴다.

이벤트 제목은 `공부: <주제>`, 본문은 아래 형식으로 파일에 써서 넘긴다.

```text
무엇을: <주제>
왜: <일기에서 나온 상황 한 줄>
볼 것:
- <문서 제목> <URL 또는 검색어>
- ...
출처: ~/Downloads/YYYY-MM-DD.md
```

등록 명령이다. 같은 날 같은 제목이 이미 있으면 스크립트가 `exists`를 돌려주고 만들지 않는다.

```bash
python3 <skill-dir>/scripts/create_calendar_event.py "공부: Helm hooks" 2026-09-12 --start 10:00 --minutes 60 --calendar "공부" --notes-file /tmp/study-helm-hooks.txt
```

macOS가 아니거나 스크립트가 실패하면 일정은 만들지 않고, 일기 표의 `언제`는 그대로 두고 응답에 "캘린더 등록 실패" 한 줄을 남긴다. 사용자가 "일정 등록하지 마"라고 했으면 이 단계를 건너뛴다.

## 5. 응답

음성으로 읽히므로 세 줄 이하로 답한다.

- 저장 위치 한 줄. 예: `~/Downloads/2026-09-08.md 저장, Apple Notes 일기 폴더에도 넣음`
- 등록한 일정 한 줄. 예: `토요일 10시 Helm hooks, 11시 kubectl rollout 등록`
- 실패가 있으면 원인 한 줄. 긴 설명은 하지 않는다.

일기 본문을 채팅에 다시 읽어 주지 않는다. 사용자가 읽어 달라고 하면 그때 읽는다.

## 완료 전 확인

- 듣는 동안 한 문장 이하로만 답했고, 질문은 최대 하나였는가?
- 일기의 모든 문장이 사용자가 말한 내용인가? 위로·조언·추측을 넣지 않았는가?
- 사용자의 어미와 표현이 유지됐는가?
- 규격 헤더 4개(한 줄·오늘 있었던 일·힘들었던 것·나중에 공부하면 좋은 것)가 순서대로 있는가?
- 공부 주제마다 `왜`가 일기 속 상황과 연결되는가?
- `볼 것`의 URL이 실제로 확인된 것인가?
- 같은 날 파일이 있을 때 덮어쓰지 않고 이어 붙였는가?
- 캘린더 날짜가 이번 주 주말 규칙에 맞는가?
- 응답이 세 줄 이하인가?
