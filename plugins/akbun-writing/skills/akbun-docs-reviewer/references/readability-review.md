# 잘 읽히는 글을 위한 Don't/Do 예시

SKILL.md의 `서론과 결론`, `정보 구조`, `문장과 문단`을 적용할 때 참고한다. 규칙 자체는 SKILL.md에 있고, 이 문서는 예시만 모았다. Do 문장은 차분한 존댓말(`합니다`체)로 적었으며, 리뷰 대상 글의 문체를 다른 문체로 바꾸지 않는다.

## 서론과 결론

Don't — 본문 목차를 옮겨 적었을 뿐이라 읽고 싶어지지 않는다.

```text
이 문서는 TypeScript의 유틸리티 타입을 소개합니다. Partial, Pick, Omit을 사용할 수 있습니다.
```

Do — 본문이 무엇을 다루는지 알려주면서 읽을 이유를 준다.

```text
같은 타입을 조금씩 바꿔가며 여러 번 선언한 경험이 있다면, 그 반복은 유틸리티 타입으로 줄일 수 있습니다. Partial, Pick, Omit으로 기존 객체 타입을 변형하는 방법을 정리했습니다.
```

Don't — 본문에 없는 상황과 감정을 지어내 억지스럽고, 15초 분량을 넘는다.

```text
개발을 하다 보면 누구나 한 번쯤 타입 때문에 밤을 새워본 적이 있을 겁니다. 저도 신입 시절 타입 선언만 하루 종일 붙잡고 있다가 선배에게 혼난 기억이 있습니다. 그때는 몰랐지만 지금 돌아보면 방법이 없었던 게 아니라 도구를 몰랐던 것이었습니다. 그래서 오늘은 그 도구에 대해 이야기해보려고 합니다.
```

Don't — 본문을 요약해 되풀이하기만 하는 결론이다.

```text
지금까지 Partial, Pick, Omit에 대해 알아보았습니다. Partial은 모든 속성을 선택적으로 만들고, Pick은 일부 속성만 고르고, Omit은 일부 속성을 제외합니다. 이 글이 도움이 되었으면 좋겠습니다.
```

Do — 본문을 읽은 사람에게 남길 것 하나로 짧게 닫는다.

```text
세 타입 모두 원본 타입을 건드리지 않고 새 타입을 만듭니다. 그래서 공용 타입을 고칠지 말지 고민될 때는, 고치는 대신 유틸리티 타입으로 파생시키는 쪽이 대체로 안전합니다.
```

## 정보 구조

한 목표 집중 — Don't는 "React 사용법"이라는 넓은 주제에 개념이 뒤섞여 위계가 H5까지 깊어지고, Do는 하나의 목표로 좁혀 평탄하다.

```text
Don't
# React 사용법
## 컴포넌트 생성
### 컴포넌트 기본 구조
#### JSX 사용법
##### JSX 문법 세부사항

Do
# React 컴포넌트 생성하기
## 컴포넌트 기본 구조
## 상태 관리
## 라이프사이클 메서드
```

예측 가능한 구조 — Don't는 기본 사용법보다 응용이 먼저 나오고, Do는 기본 개념부터 점진적으로 확장한다.

```text
Don't
# React에서 useEffect 사용하기
## 비동기 데이터 요청하기
## 기본적인 사용법
## 클린업 함수 활용하기

Do
# React에서 useEffect 사용하기
## 기본적인 사용법
## 비동기 데이터 요청하기
## 클린업 함수 활용하기
```

가치 먼저 — 배경 역사나 설정 옵션이 아니라 적용했을 때 얻는 변화를 먼저 준다.

```text
Don't: 리버스 프록시 설정은 2019년에 도입되었고, 많은 수정이 있었습니다.
Do:    리버스 프록시를 설정하면 네트워크 지연 문제를 줄일 수 있습니다.

Don't: 이 스니펫은 다양한 설정 옵션을 제공합니다. 먼저 connection_timeout, retry_attempts, max_pool_size를 수정하세요.
Do:    이 스니펫을 사용하면 PostgreSQL 연결 속도가 50% 빨라집니다.
```

효과적인 제목 — 물음표로 끝내는 대신 구체적 키워드를 넣는다.

```text
Don't: # 에러를 해결하는 방법은?
Do:    # NOT_FOUND_USER 에러를 해결하는 방법
```

자세히 설명 — 새 개념은 처음 등장할 때 정의한다.

```text
Don't: 이 서비스는 이벤트 소싱 방식으로 상태를 관리합니다.
Do:    이 서비스는 이벤트 소싱(Event Sourcing) 방식으로 상태를 관리합니다. 이벤트 소싱은 상태의 최종 결과만 저장하는 대신, 상태를 바꾼 모든 이벤트를 기록하는 방식입니다.
```

## 문장 다듬기

메타 담화 최소화 — '말에 대한 말'을 지우고 핵심만 남긴다.

```text
Don't: 앞에서 설명했지만, 결론은 이 설정을 변경하는 것이 가장 효과적이라는 겁니다.
Do:    이 설정을 변경하는 것이 가장 효과적입니다.
```

구체적으로 쓰기 — 모호한 표현을 사실·수치로 바꾸고, 빠진 주어를 채운다. 코드를 그대로 옮긴 표현(`Exception을 던집니다`)보다 실제 동작(`예외를 일으킵니다`)을 드러낸다.

```text
Don't: 데이터가 많을 때는 성능이 저하될 수 있습니다.
Do:    데이터가 10,000건을 넘으면 응답 시간이 1초 이상 걸립니다.

Don't: 파일을 업로드하면 자동으로 저장됩니다.
Do:    사용자가 파일을 업로드하면 서버에 자동으로 저장됩니다.
```

자연스러운 한국어 — 불필요한 한자어와 영어식 명사형 번역체를 고친다.

```text
Don't: 로그 파일을 삭제하는 작업을 수행합니다.
Do:    로그 파일을 삭제합니다.

Don't: API 키를 이용한 사용자 인증 처리가 완료된 후, 데이터베이스 접속 설정 진행이 가능합니다.
Do:    API 키로 사용자를 인증한 후, 데이터베이스에 접속하도록 설정할 수 있습니다.
```

일관되게 쓰기 — 약어는 처음 등장할 때 풀어 쓰고, 같은 개념을 여러 단어(`추가`/`첨부`/`넣다`)로 바꿔 쓰지 않는다.

```text
Don't: 이 기능은 SSR을 지원합니다.
Do:    이 기능은 SSR(Server-Side Rendering)을 지원합니다.
```
