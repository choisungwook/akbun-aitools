# 한국어 글의 공통 자연화 규칙

이 문서는 단어를 찾아 일괄 치환하는 금칙어 목록이 아니다. 표현 하나가 아니라 문장 안에서 맡는 역할, 주변 문장과의 관계, 글쓴이가 이미 만든 말투를 보고 수정 여부를 판단한다. 같은 표현도 정보나 태도를 정확히 전달하면 남긴다.

## 적용 원칙

1. 먼저 코드, 인용문, URL, 고유명사, 수치와 사실 관계를 보호한다.
2. 글쓴이의 어휘, 높임말, 1인칭 경험, 확신의 정도를 기준 목소리로 삼는다.
3. 아래 징후가 실제로 뜻을 흐리거나 글쓴이의 목소리를 덮는 구간만 고친다.
4. 문장 하나를 고칠 수 있으면 문단 전체를 다시 쓰지 않는다. Markdown의 전체 논지와 구조도 유지한다.
5. 고친 뒤 사실, 수치, 부정, 조건, 인과, 시제, 주체, 가능성과 의무의 강도가 원문과 같은지 대조한다.

## 번역한 듯한 문장

### 번역투 문맥 판단

- 주어와 목적어보다 명사 덩어리가 앞서서 동작의 주체가 보이지 않는가
- 수동 표현과 명사형 서술이 겹쳐 한국어 어순으로 한 번에 읽히지 않는가
- 외국어 문장 구조를 따라 수식어가 멀리 떨어진 명사를 꾸미는가
- 조사와 서술어의 호응은 맞지만 실제 한국어 화자가 잘 쓰지 않는 결합인가

### 번역투 보존 예외

- 행위자를 알 수 없거나 일부러 드러내지 않아야 하는 문장
- 법률, 규정, 계약처럼 행위보다 상태와 적용 범위가 중요한 문장
- 분야에서 뜻이 굳어진 전문 용어와 공식 번역

### 번역투 수정 방향

- 실제로 행동하는 주체와 동사를 가까이 둔다.
- 뜻 없는 명사형 표현은 동사로 풀고, 여러 겹의 수동 표현은 필요한 한 겹만 남긴다.
- 수식어를 꾸미는 말 가까이 옮기되 강조 순서는 원문을 따른다.

```text
전: 장애의 발생에 대한 원인 분석이 운영팀에 의해 진행되었습니다.
후: 운영팀이 장애 원인을 분석했습니다.
```

## 내용 없는 안내와 상투적인 마무리

### 안내·마무리 문맥 판단

- 다음 내용을 예고하지만 독자에게 새 정보나 필요한 길잡이를 주지 않는가
- 본문에서 이미 말한 내용을 결론에서 표현만 바꿔 다시 늘어놓는가
- 글의 목적과 무관한 인사, 기대, 다짐으로 문단을 채우는가
- 글 자체를 설명하는 문장이 실제 주제보다 앞에 나서는가

### 안내·마무리 보존 예외

- 긴 글에서 현재 위치나 읽는 순서를 알려주는 안내
- 앞 절과 뒤 절의 논리 관계를 밝혀야 이해되는 전환
- 글쓴이가 평소 독자에게 건네는 인사나 마무리 방식

### 안내·마무리 수정 방향

- 안내가 없어도 흐름이 이어지면 안내 표현만 지운다. 안내 문장에 중요도·찬반·의도 같은 독립적인 판단이 함께 있으면 직접 서술로 분리해 남긴다.
- 전환이 필요하면 앞으로 다룰 내용을 소개하지 말고 두 내용의 관계를 바로 쓴다.
- 결론의 상투적인 표지어는 덜어내되 문장에 담긴 주장·판단·조건은 남긴다.
- 반복 요약을 합칠 때도 다른 문장에 없는 사실이나 글쓴이의 판단을 삭제하지 않는다. 원문에 없는 판단이나 다음 행동을 새로 만들지 않는다.

```text
전: 이제 캐시 만료 시간을 어떻게 정해야 하는지 자세히 살펴보겠습니다. 캐시 만료 시간은 데이터가 바뀌는 주기에 맞춰 정합니다.
후: 캐시 만료 시간은 데이터가 바뀌는 주기에 맞춰 정합니다.
```

```text
전: 이 글에서는 매우 중요한 장애 복구 순서를 살펴보겠습니다.
후: 장애 복구 순서는 매우 중요합니다.
```

```text
전: 결론적으로, 이번 장애는 배포 전 검증이 중요하다는 점을 보여줍니다.
후: 이번 장애를 보면 배포 전 검증이 중요합니다.
```

## 기계적으로 맞춘 구조

### 기계적 구조 문맥 판단

- 모든 절이 같은 길이와 같은 순서로 반복되어 내용보다 틀이 두드러지는가
- 한두 문장마다 소제목을 붙여 생각의 흐름이 자주 끊기는가
- 서로 같은 층위가 아닌 항목을 숫자나 목록 개수를 맞추려고 나란히 놓았는가
- 하나의 생각을 서론, 목록, 정리에서 세 번 반복하는가

### 기계적 구조 보존 예외

- 작업 절차, 점검표, API 명세처럼 순서와 병렬 구조가 정보인 글
- 비교 대상의 조건을 동일하게 맞춰야 하는 분석
- 원문 전체에서 의도적으로 반복되는 장치

### 기계적 구조 수정 방향

- 내용 없는 소제목은 지우고 인접 문단에 합친다.
- 같은 역할의 항목만 목록으로 묶고, 문장으로 충분한 짧은 목록은 문장으로 되돌린다.
- 순서가 중요한 항목만 번호를 유지한다.
- 전체 Markdown 뼈대는 유지하고 문제가 생긴 국소 구조만 다듬는다.

```text
전: 장점은 세 가지입니다. 첫째 설정 절차가 단순합니다. 둘째 바로 적용할 수 있습니다. 셋째 처리 시간이 줄어듭니다.
후: 설정 절차가 단순합니다. 바로 적용할 수 있고, 처리 시간도 줄어듭니다.
```

## 일정하게 반복되는 리듬과 어조

### 리듬·어조 문맥 판단

- 가까운 문장이 같은 길이, 같은 어순, 같은 종결형으로만 이어지는가
- 글쓴이의 평소 어조와 다르게 갑자기 과장되거나 지나치게 격식적인 문장이 나타나는가
- 답이 이미 정해진 질문이나 독자에 대한 호명이 습관적으로 반복되는가
- 모든 문장이 같은 세기로 단정되어 근거의 확실성 차이가 사라지는가

### 리듬·어조 보존 예외

- 명령문이 반복되는 절차서와 규칙 문서
- 발표문, 연설문, 문학적 산문에서 의도한 반복과 운율
- 원문에서 일관되게 쓰인 글쓴이 고유의 종결 방식

### 리듬·어조 수정 방향

- 짧게 말할 내용은 짧게 쓰고, 근거가 필요한 문장은 충분히 설명한다.
- 질문이 흐름을 만들지 못하면 핵심 진술로 바꾼다.
- 확정, 추정, 제안의 차이를 원문 근거에 맞춰 복원한다.
- 어조를 새로 입히지 말고 주변의 자연스러운 문장에서 종결 방식과 말의 세기를 가져온다.

```text
전: 설정 파일은 짧습니다. 적용 과정도 단순합니다. 서버를 재시작할 필요도 없습니다.
후: 설정 파일이 짧고 적용 과정도 단순합니다. 서버를 재시작할 필요도 없습니다.
```

## 반복 설명과 막연한 추상화

### 반복·추상화 문맥 판단

- 새 정보 없이 같은 주장을 동의어로 바꿔 되풀이하는가
- 구체적인 행위나 대상 대신 넓은 개념어만 이어져 무엇이 달라지는지 알 수 없는가
- 근거가 없는 중요성, 효과, 가치 판단이 설명을 대신하는가
- 문단 끝에서 앞 문장의 의미를 한 번 더 포장하는가

### 반복·추상화 보존 예외

- 처음 배우는 독자를 위해 정의와 사례를 다른 방식으로 설명하는 경우
- 앞선 조건을 환기해야 오해를 막을 수 있는 경우
- 기술적으로 정확한 추상화가 여러 구현을 함께 가리키는 경우

### 반복·추상화 수정 방향

- 반복 중 정보가 가장 선명한 문장을 남기고 나머지를 합친다.
- 원문에 있는 주체, 행동, 조건, 결과를 앞으로 가져온다.
- 원문에 없는 사례나 수치를 지어내 구체적인 척하지 않는다.
- 추상어가 기술적 범위를 나타내면 지우지 말고 그 범위를 이해할 단서를 가까이 둔다.

```text
전: 로그 관리는 시스템 운영의 안정성 측면에서 매우 중요합니다. 장애가 난 시점의 요청과 오류를 확인하는 데 활용할 수 있습니다.
후: 로그 관리는 시스템 운영 안정성에 매우 중요하며, 장애가 난 시점의 요청과 오류를 확인하는 데 활용할 수 있습니다.
```

## 과한 완곡 표현, 접속어, 형식 명사

### 완곡 표현·접속어·형식 명사 문맥 판단

- 책임이나 판단을 피하려는 완곡 표현이 겹쳐 결론을 알 수 없는가
- 문장마다 접속어가 붙지만 앞뒤 관계는 이미 분명한가
- `부분`, `측면`, `과정`, `경우`, `것` 같은 넓은 말이 구체적인 대상을 대신하는가
- 가능성 표현이 근거의 불확실성을 나타내는지, 단지 단정을 피하려고 붙었는지 구분되는가

### 완곡 표현·접속어·형식 명사 보존 예외

- 실제로 불확실하거나 조건에 따라 결과가 달라지는 설명
- 정중함이 필요한 요청, 공지, 고객 응대
- 법적 책임과 적용 범위를 정확히 제한하는 표현
- 형식 명사를 빼면 가리키는 대상이나 논리 관계가 달라지는 문장

### 완곡 표현·접속어·형식 명사 수정 방향

- 완곡 표현을 걷어내되 원문의 확신 수준을 높이지 않는다.
- 접속어를 지워도 관계가 분명하면 지우고, 관계가 모호하면 원인, 대조, 조건을 정확히 드러낸다.
- 넓은 형식 명사는 실제 대상이나 행동으로 바꾼다.

```text
전: 트래픽이 예상치를 넘는 상황에는 설정을 재검토할 필요가 있을 수도 있을 것으로 보입니다.
후: 트래픽이 예상치를 넘을 때는 설정 재검토가 필요할 수 있습니다.
```

## 의미 없이 더한 시각 장식

### 시각 장식 문맥 판단

- 굵은 글씨, 이모지, 인용문, 구분선이 강조할 정보 없이 반복되는가
- 거의 모든 문장이 강조되어 정보의 우선순위를 구분할 수 없는가
- 본문과 같은 내용을 장식된 요약 상자나 목록으로 다시 보여주는가
- 장식 때문에 원래 Markdown의 계층이나 읽는 순서가 흐려지는가

### 시각 장식 보존 예외

- 경고, 보안 주의사항, 호환성 제한처럼 놓치면 안 되는 정보
- 문서 전체에서 일관된 의미를 가진 표식
- 글쓴이가 의도한 시각적 리듬과 출판 매체가 요구하는 형식
- 인용임을 밝혀 출처와 화자를 구분하는 블록

### 시각 장식 수정 방향

- 의미가 겹치는 장식만 줄이고 원래 Markdown 구조는 유지한다.
- 강조는 실제 핵심어에만 남기며, 장식을 없애려고 문장 내용을 바꾸지 않는다.
- 인용, 경고, 코드와 일반 본문의 경계는 보존한다.

```text
전: **핵심:** **반드시** 설정값을 **확인하세요.**
후: 핵심 설정값을 확인하세요.
```

## 판단이 서지 않을 때

문장이 어색해 보여도 글쓴이의 의도나 의미를 보존하면서 고칠 방법이 분명하지 않으면 원문을 유지한다. 무엇이 불확실한지만 결과 파일 밖에서 `확인 필요`로 알린다.
