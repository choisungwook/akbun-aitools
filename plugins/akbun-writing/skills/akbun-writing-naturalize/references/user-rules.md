# 사용자 규칙

사용자가 글에서 반복해서 발견한 AI스러운 표현과 사람답게 바꾸는 방향을 합의한 커스텀 규칙으로 누적한다. 보편적인 AI 판별 기준이 아니며, AI가 새 규칙을 추측해 추가하거나 기존 규칙을 자동으로 바꾸지 않는다.

## 운영 원칙

- 규칙을 추가하거나 바꾸기 전에 사용자와 조건, 예외, 의미 변화 가능성을 의논한다.
- 새 규칙이 기존 규칙과 충돌하면 어느 쪽이 더 적절한지 예시로 비교하고, 합의한 뒤 반영한다.
- 이 문서에는 현재 유효한 규칙만 남긴다. 폐기한 규칙과 변경 이력은 쌓지 않는다.
- 이 규칙은 금칙어, 삭제 목록, 일괄 치환표가 아니다.
- 표현이 현재 문맥에서도 AI스럽게 쓰였는지 확인한 뒤, 해당할 때만 사용자가 선호하는 사람다운 문장으로 다시 쓴다.
- 보존 예외에 해당하거나 원문의 자연스러운 목소리로 쓰인 표현은 그대로 둔다.
- 코드, 인용문, URL, 고유명사, 사실과 원문의 의미 보존은 모든 사용자 규칙보다 우선한다.

## 규칙 항목 형식

각 항목은 다음 정보를 담는다.

- 표현 또는 문장형
- AI처럼 느껴지는 조건
- 보존해야 하는 예외
- 사람다운 수정 방향
- 사용자 전후 예시(선택)

## 사용자 커스텀 규칙

각 표현은 AI스러움을 확인하는 단서다. 합의한 조건과 예외를 현재 문맥에 대조한 뒤, 조건이 맞으면 글쓴이의 목소리와 의미를 보존하면서 사용자가 선호하는 방향으로 다시 쓴다.

### `함정`

- 표현 또는 문장형: `함정`, `~의 함정`
- AI처럼 느껴지는 조건: 주의점, 한계, 실수 가능성을 구체적으로 설명하지 않고 `함정`이라는 비유로 과장하거나, 제목과 본문에서 같은 비유를 반복한다.
- 보존해야 하는 예외: 실제 함정, 게임·보안 분야의 함정이나 허니팟, 인용문, 고유명사, 글쓴이가 의도적으로 이어 가는 비유에는 적용하지 않는다.
- 사람다운 수정 방향: 원문에 드러난 위험, 오류, 한계를 직접 적는다. 무엇을 가리키는지 확정할 수 없으면 원문을 유지하고 `확인 필요`로 보고한다.

### `실제`

- 표현 또는 문장형: `실제`, `실제로`
- AI처럼 느껴지는 조건: 가상과 현실, 예상과 관찰, 테스트와 운영 환경을 구분하지 않으면서 강조어나 문장 연결어로만 쓴다.
- 보존해야 하는 예외: 실제와 가상, 예상과 관찰, 테스트와 운영 환경의 차이가 논지에 필요하거나 인용문·고유명사에 포함된 경우에는 유지한다.
- 사람다운 수정 방향: 없어도 의미가 같으면 덜어낸다. 대비가 필요하면 원문에 있는 대상과 상황을 직접 밝혀 쓴다.

### 여러 대상을 연결하는 `다리`

- 표현 또는 문장형: `A와 B를 잇는 다리`, `연결하는 다리`처럼 여러 개념이나 대상을 연결하는 역할을 `다리`로 표현한 문장
- AI처럼 느껴지는 조건: 관계나 역할을 구체적으로 설명할 수 있는데도 추상적인 연결 비유로 대신한다.
- 보존해야 하는 예외: 실제 다리, 네트워크의 브리지처럼 정식 기술 용어인 경우, 인용문, 고유명사, 글쓴이가 의도적으로 이어 가는 비유에는 적용하지 않는다.
- 사람다운 수정 방향: 원문이 밝힌 관계에 맞춰 `연결한다`, `전달한다`, `변환한다`, `중개한다`처럼 구체적인 역할을 적는다. 관계를 확정할 수 없으면 원문을 유지하고 `확인 필요`로 보고한다.

### `~하는 것`

- 표현 또는 문장형: `~하는 것`, `~하는 것이`, `~하는 것입니다`
- AI처럼 느껴지는 조건: 동작을 불필요하게 명사화해 문장을 늘이거나, 같은 문장형을 가까운 문단에서 반복한다.
- 보존해야 하는 예외: `것`이 실제 대상·내용·사건을 가리키거나, 대조와 초점에 필요하거나, 글쓴이의 자연스러운 말투·인용문·고유명사에 속하면 유지한다.
- 사람다운 수정 방향: 주어와 동사를 직접 연결하되 원문의 강조, 조건, 가능성, 의무 강도는 바꾸지 않는다. 단순히 `것`을 기계적으로 삭제하지 않는다.

### `의미를 잃습니다.`로 끝나는 문장

- 표현 또는 문장형: `의미를 잃습니다.`라는 문장 끝
- AI처럼 느껴지는 조건: 무엇이 왜 무효가 되는지 설명하지 않은 채 추상적인 결론이나 문단 마무리로 쓴다.
- 보존해야 하는 예외: 번역, 인코딩, 용어 해석처럼 의미 자체가 사라진다는 사실이 논지이거나, 인용문·고유명사에 포함된 경우에는 유지한다.
- 사람다운 수정 방향: 원문에 이미 제시된 기준, 기능, 효과의 손실을 구체적으로 적는다. 구체적인 결과를 원문에서 확인할 수 없으면 문장을 유지하고 `확인 필요`로 보고한다.

### `나옵니다`로 끝나는 문장

- 표현 또는 문장형: `나옵니다`로 끝나는 문장
- AI처럼 느껴지는 조건: `결과가 나옵니다`, `차이가 나옵니다`, `문제가 나옵니다`처럼 더 정확한 동사를 쓸 수 있는데도 포괄적인 서술어로 반복해서 마무리한다.
- 보존해야 하는 예외: 대상이 실제로 나오거나 나타나는 상황, 글쓴이의 자연스러운 구어체, 인용문, 고유명사에는 적용하지 않는다.
- 사람다운 수정 방향: 원문이 가리키는 사건에 맞춰 `표시됩니다`, `발생합니다`, `확인됩니다`, `계산됩니다`처럼 구체적인 동사로 바꾼다. 사건을 확정할 수 없으면 원문을 유지하고 `확인 필요`로 보고한다.

### `쓰는가`

- 표현 또는 문장형: 기술 설명의 질문이나 제목에서 문장 끝에 쓰인 `쓰는가`
- AI처럼 느껴지는 조건: 어떤 자원이나 구성 요소가 필요한지 묻는 내용을 `무엇이 자원을 쓰는가`처럼 딱딱한 설명문형 질문으로 표현한다.
- 보존해야 하는 예외: `어떤 API를 쓰는가에 따라`처럼 문장 안에서 선택 조건을 나타내거나, 인용문, 고유명사, 글쓴이가 의도한 격식체에는 적용하지 않는다.
- 사람다운 수정 방향: 질문의 초점을 먼저 확인하고 `~할까?` 문장으로 다시 쓴다. 필요한 구성 요소를 묻는 문맥이면 그 대상을 직접 묻고, 자원 소비 주체를 묻는 문맥이면 소비 관계를 유지한다.
- 의미 보존형 적용 예시:
  - 전: `weight 말고 무엇이 VRAM을 쓰는가`
  - 후: `weight 말고 무엇이 VRAM을 더 쓸까?`
- 사용자 선호 예시(원문의 질문 초점이 VRAM에 필요한 구성 요소로 확인된 경우):
  - 전: `weight 말고 무엇이 VRAM을 쓰는가`
  - 후: `VRAM에 weight 말고 무엇이 더 필요할까?`

### 문장 끝의 `-는가/-인가`

- 표현 또는 문장형: 직접 질문이나 질문형 제목을 끝내는 `-는가`, `-인가` 계열의 종결어미
- AI처럼 느껴지는 조건: 독자에게 직접 던지는 질문을 논문이나 보고서처럼 딱딱하게 끝낸다.
- 보존해야 하는 예외: 간접의문문, 인용문, 고유명사, 글 전체가 의도적으로 격식 있는 문답체를 유지하는 경우에는 적용하지 않는다. 조사 `가`에는 적용하지 않으며, 문장 끝의 `쓰는가`는 위 전용 규칙만 적용한다.
- 사람다운 수정 방향: 원문의 행위와 질문 초점을 유지하면서 글쓴이의 구어체에 맞는 `~할까?`, `~일까?` 형태로 문장 전체를 자연스럽게 다시 쓴다.
- 의미 보존형 적용 예시:
  - 전: `optimization을 무엇을 기준으로 고르는가`
  - 후: `어떤 기준으로 optimization을 고를까?`
- 사용자 선호 예시(문맥상 optimization의 선택과 수행을 구분하지 않는 경우):
  - 전: `optimization을 무엇을 기준으로 고르는가`
  - 후: `어떤 기준으로 optimization을 할까?`
