# 기술 문서 교정

## 목표

원문의 내용, 문체, 레이아웃을 유지하면서 명백한 언어 오류와 표기 불일치만 바로잡는다.

Markdown처럼 사람이 읽는 텍스트 문서를 대상으로 한다. 코드, 설정 파일, 번역, 요약, 새 글 작성, 문서 구조 변경은 대상이 아니다.

## 교정 범위

- 맞춤법, 띄어쓰기, 조사, 어미, 호응 등 문법 오류
- 오타와 명백히 잘못 쓰인 표현
- 같은 제품명과 기술 용어의 대소문자 및 표기 불일치
- 같은 의미로 사용된 용어의 문서 내 표기 불일치
- 공식 표기가 분명한 제품명, 프로젝트명, 프로토콜명, 약어

표기를 통일할 때는 문서 안에서 가장 많이 쓰인 표현보다 공식 표기와 해당 기술 분야의 일반적인 관례를 우선한다.

## 보존 범위

- 헤더 순서, 문단 순서, 목록, 이미지, 코드 블록 등 레이아웃을 바꾸지 않는다
- 문체, 말투, 글쓴이의 경험과 주장, 설명의 깊이를 바꾸지 않는다
- 틀리지 않은 문장을 더 매끄럽거나 간결하게 만들기 위해 다시 쓰지 않는다
- 코드 블록, 인라인 코드, 명령어, 설정값, 파일 경로는 수정하지 않는다
- 기술적 사실, 수치, 예제의 동작은 수정하지 않는다

교정 때문에 문장 의미가 달라질 가능성이 있으면 원문을 유지하고 별도 보고한다.

## 결과

원문 파일에 교정을 직접 반영한다. 레이아웃과 내용은 그대로 두고 교정한 부분만 바꾼다.

확실한 기술적 오류를 발견하면 원문을 수정하지 않고 다음 형식으로 별도 보고한다. 확실하지 않은 내용은 오류로 단정하지 않는다.

```text
기술적 오류
- 위치: 오류 내용과 판단 근거
```
