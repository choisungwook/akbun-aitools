# 여행블로그 글쓰기

다녀온 곳의 메모·동선·사진 목록을 여행블로그 글로 바꾼다. 독자가 방문 경험을 따라 읽고, 필요한 방문 정보를 바로 찾게 한다. **본문은 경험과 장면**, **정보 상자는 찾아갈 때 쓰는 사실**이다.

## 입력 다루기

입력에 있는 것만 쓴다. 빠진 정보 때문에 인터뷰를 시작하지 않는다.

- 본 것, 들은 것, 먹은 것, 느낀 것은 입력에 있을 때만 쓴다. 냄새·소리·날씨·사람의 자세·감정·구매 행동을 보충하지 않는다. 차를 마셨다는 메모만으로 손이 따뜻해졌다고 쓰지 않는다.
- 역사·유래·연도·인물은 입력에 있거나 근거를 확인한 것만 쓴다. 전해 오는 이야기에도 출처가 필요하다. `~라고 해요`는 미확인 사실을 허용하는 표현이 아니다.
- 가격·시간·주소는 입력 값과 적용 조건을 보존한다. 누락은 무료·상시 운영·예약 불필요를 뜻하지 않는다.
- 직접 방문, 가 보지 않은 추천, 다른 사람에게 들은 정보를 구분한다. 추천이나 예정만 주어졌으면 방문 후기처럼 쓰지 않고 소개·계획임을 밝힌다.
- 동선은 입력 순서를 따른다. 순서가 없으면 확인된 위치 관계로만 제안하고 제안임을 표시한다. 위치 관계도 없으면 입력의 나열 순서로 소개하며 실제 이동 순서는 `확인 필요`로 보고한다.
- 사진 목록이 있으면 해당 파일 이름을 주석에 쓴다. 맞는 사진이 없으면 필요한 장면을 적되 파일을 만들어내지 않는다.
- 방문일과 정보 확인일을 구분한다. 날짜가 없으면 현재 날짜를 방문일로 대체하지 않는다.

## 글의 뼈대

글 하나는 여행지 하나 또는 입력에 있는 연결 코스를 다룬다. 여러 장소는 보통 2~4개 구간으로 묶되, 장소가 하나면 구간을 늘리지 않는다.

| 순서 | 블록 | 내용 |
|---|---|---|
| 1 | 제목(H1) | 여행지 이름과 입력에 있는 특징 하나. 검색어·동의어를 줄줄이 붙이지 않음 |
| 2 | 썸네일 자리 | `[썸네일]` 1개. 대표 장면과 짧은 제목을 설명 |
| 3 | 도입 | 2~4문장. 방문 계기·시점·둘러본 범위를 입력에서 선택. 교통·소요 시간을 채우려고 추정하지 않음 |
| 4 | 코스 미리보기 | 여러 구간일 때만 번호 목록. 실제 H2와 같은 순서·이름 |
| 5 | 약도 자리 | 이동 코스가 있을 때 `[약도]`. 한 장소 안의 이동이 없으면 생략 |
| 6 | 본문(H2) | `1. 장소 이름 · 핵심 장면`처럼 번호+장소+짧은 설명. 구간 안에 여러 장소가 있을 때만 H3 사용 |
| 7 | 맺음 | 입력의 마지막 장면이나 감상 1~2문장. 정보가 없으면 마지막 관찰에서 끝냄 |
| 8 | 안내 | 방문일·정보 기준일, 입력에 있는 준비물·예약·경사 안내 |

장소 안에서는 **도착 → 눈앞의 모습 → 그곳의 이야기 → 다음 이동 또는 감상** 순서로 연결한다. 이것은 문장의 흐름이지 네 문단을 채우라는 뜻이 아니다. 역사·유래나 감상이 없으면 해당 박자를 생략한다.

## 화면에서 읽는 호흡

- 한 문단은 **1~3문장, 보통 40~120자**로 쓴다. 숫자를 맞추기보다 한 장면·한 정보 묶음인지 확인한다. 긴 문단은 관찰이나 행동이 바뀌는 곳에서 나눈다.
- 문단 사이에는 빈 줄 하나를 둔다. 문장 중간을 15자·20자 같은 고정 폭으로 자르거나, 여백을 만들려고 빈 줄을 여러 개 넣지 않는다.
- 문장별 줄바꿈이 필요할 때만 Markdown의 두 칸 줄바꿈을 쓴다. 낱말·주소·가격·시간 범위는 중간에서 끊지 않는다. 기본 정렬은 발행 편집기에 맡기고 가운데 정렬 태그를 강제하지 않는다.
- 사진 한 장 또는 같은 장면의 묶음에 설명 1~2문단을 붙인다. 장소당 `[현장]` 1~3개를 기본으로 삼되 사진과 사실이 적으면 줄인다. 전체 사진 개수를 맞추려고 장면을 늘리지 않는다.
- 사진과 설명의 앞뒤 순서는 맥락에 맞춘다. 길 안내는 설명 뒤에 사진, 시각적 관찰은 사진 뒤에 설명을 둘 수 있다. 어느 사진의 설명인지 사이에 다른 장면을 끼우지 않는다.
- 같은 장면의 전경·세부 사진만 연달아 둘 수 있다. 최대 2개 주석을 묶고 앞이나 뒤에 설명 문단을 둔다. 다른 장소 사진 사이에는 본문을 둔다.
- 소제목만 읽어도 장소와 순서가 보이게 한다. 긴 글은 구간 제목을 코스 미리보기로 쓰고, 짧은 단일 장소 글에 목차·H3를 억지로 만들지 않는다.
- 강조는 방문 판단에 필요한 조건이나 장소 이름 한 구절에 쓴다. 문단 전체를 굵게 만들지 않는다.

## 문체: 다녀온 경험을 이야기한다

기본은 **정중한 말투의 과거형**이다. 방문 경험은 `걸었습니다`, `보였습니다`, `들어갔습니다`로 서술하고, 장소 소개나 확인된 설명에는 `~입니다`, `~습니다`를 쓴다. 중간중간 감상이나 짧은 덧붙임에 `~했어요`, `~더라고요` 같은 해요체를 섞어 대화하듯 자연스럽게 풀어 준다. 사용자에게 다른 말투 요청이 있으면 그 요청을 따른다.

말투와 시제는 따로 판단한다. `~입니다`는 소개·설명의 정중한 종결이며, 지난 방문 당시의 상태를 지금도 같은 사실인 것처럼 바꾸지 않는다. `~했었습니다`, `~였었습니다`는 이전 경험을 돌아보거나 당시와 지금을 구분할 때 쓴다. 단순한 방문 기록은 `~했습니다`, `~였습니다`로 충분하며 모든 과거형을 `~했었습니다`로 늘이지 않는다.

| 문장 종류 | 종결 예 | 기준 |
|---|---|---|
| 이동 | `~으로 걸었습니다`, `~에 들어갔습니다` | 입력에 있는 이동 순서 |
| 관찰·감각 | `~이 보였습니다`, `~이 들렸습니다` | 직접 경험한 입력만 |
| 발견·감상 | `~라는 생각이 들었습니다`, `~더라고요`, `~했어요` | 정중형을 기본으로 하되 입력에 있는 감상·덧붙임에서 해요체를 간간이 사용 |
| 역사·전언 | `안내판에는 ~라고 적혀 있었습니다` | 출처를 남기고 내용의 시제 보존 |
| 소개·현재 정보 | `~을 소개하는 곳입니다`, `확인일 기준 ~입니다` | 입력이나 확인된 근거가 있는 설명. 변동 정보는 정보 상자로 분리 |
| 이전 경험 회상 | `이전 방문 때는 ~했었습니다` | 입력에 이전 방문이나 시점 대비가 있을 때만 |

운용 규칙:

- 정중형이 글의 중심이 되게 한다. 해요체는 감상을 가볍게 덧붙이는 지점 등에 넣되, 비율을 맞추거나 문장마다 두 말투를 번갈아 쓰지 않는다. 짧은 글이나 감상이 없는 입력에는 해요체를 억지로 넣지 않는다.
- 한 문장에 한 동작이나 관찰을 담는다. `~는데요`, `~더라고요`, `~답니다`만 연달아 반복하지 않는다.
- `저는`은 화자를 구분할 때 쓴다. 문단마다 붙이지 않는다. 개인 경험과 다른 사람의 말을 구분하는 데 필요하면 생략하지 않는다.
- 감상은 입력에 있을 때 문단 끝에 한 문장 이하. 비유도 한 문단에 하나 이하이며 새로운 감각을 만들어내는 데 쓰지 않는다.
- 사람은 입력에 있는 동작만 쓴다. `고양이가 있었음`을 `고양이가 앉아 있었음`으로 구체화하지 않는다.
- 직접 인용은 입력에 실제 발언이 있을 때만 큰따옴표로 옮긴다. 요약된 전언은 간접화법으로 쓴다. 속말을 새로 만들지 않는다.
- 음식은 입력의 맛 표현과 먹은 행동으로 설명한다. 주문·재주문·완식 여부를 추정하지 않는다.
- 작품·이름의 유래는 입력이나 확인된 근거가 있을 때 한두 문장으로 짚는다. 알려진 정보로 개인 감상을 대신 채우지 않는다.
- 가게·건물·길 이름은 첫 등장에 작은따옴표, 작품 제목은 낫표(`「 」`)로 묶는다.
- 해요체를 쓰기 위해 `ㅎㅎ`, 물결표, 과한 느낌표·이모지를 덧붙이지 않는다.

## 어휘

말로 이야기해도 자연스러운 단어를 고른다. 아래 표현은 입력의 의미가 맞을 때만 쓰며, 분위기를 만들려고 보충하지 않는다.

| 쓰임 | 표현 예 |
|---|---|
| 이동 | 걸어갔습니다, 올라갔습니다, 내려왔습니다, 골목으로 들어갔습니다 |
| 풍경 | 보였습니다, 이어져 있었습니다, 내려다보였습니다 |
| 분위기 | 한적했습니다, 아담했습니다, 조용했습니다 |
| 감각 | 바람이 불었습니다, 소리가 들렸습니다 |
| 마음 | 마음이 편해졌습니다, 오래 보고 싶었습니다. 가벼운 덧붙임에는 편해졌어요, 보고 싶더라고요 |
| 연결 | 길을 따라, 모퉁이를 지나, 잠시 뒤, 돌아오는 길에 |

`정취`, `세월을 품은`, `발걸음을 옮기다` 같은 문어체를 반복하지 않는다. `인생샷`, `존맛`, `찐`, `강추`, `미쳤다`, `안 가면 후회` 같은 과장과 검색어의 기계적 반복도 피한다.

## 사진삽입 주석

두 skill이 함께 읽는 계약이다. 종류는 `[썸네일]`, `[약도]`, `[현장]`으로 유지하며 형식을 바꿀 때는 `akbun-draw-travel-blog`도 함께 고친다.

주석 형식은 다음과 같다.

```markdown
<!-- 사진삽입: [종류] 사진에 무엇이 보여야 하는지 | 캡션: 사진 아래에 넣을 한 문장 -->
```

| 종류 | 자리 | 개수 | 채우는 방법 |
|---|---|---|---|
| `[썸네일]` | 제목 아래 | 1 | 일러스트 프롬프트 또는 사용자가 고른 대표 사진 |
| `[약도]` | 코스 미리보기 아래 | 코스가 있으면 1, 필요할 때 구간별 분할 | 일러스트 프롬프트. 순서·방향의 확인 범위를 설명에 적음 |
| `[현장]` | 해당 장면 설명 앞이나 뒤 | 장소당 보통 1~3 | 직접 찍은 사진. 없으면 자리만 남김 |

- 파일이 있으면 설명 앞에 `파일: 이름`을 적는다. 한 주석은 사진 한 장을 가리킨다.
- 입구·표지판·음식·전경 등 사진에서 확인할 대상을 적는다. 과거 이야기만으로 현재 모습을 요구하지 않는다.
- 캡션은 30자 안팎의 한 문장 또는 명사구. 본문을 그대로 반복하지 않고 사진 속 대상이나 볼 지점을 적는다. 입력에 없는 방문 요령은 넣지 않는다.
- 대표 이미지의 문구는 글 제목을 통째로 복사하지 말고 장소 이름과 특징 하나로 줄인다. 그림 속 글자가 필요 없으면 주석에 `무문자`라고 적는다.
- `[현장]`은 사진이 없다는 이유만으로 자동 생성 대상이 되지 않는다. 사용자가 장면 삽화를 요청하면 설명이나 캡션에 `장면 삽화`를 표시한다.
- 약도 방향이 없으면 `방향 미확인, 방문 순서만 표시`를 설명에 적고 캡션에도 `방문 순서도 · 실제 방향·거리와 다름`을 밝힌다.

## 정보 상자

장소가 하나면 도입 뒤에 한 번, 여러 구간이면 해당 구간 끝에 둔다. 독자가 찾을 주소·시간·가격을 항목 이름으로 구분한다. 같은 정보를 앞뒤에서 복제하지 않는다.

형식 예는 다음과 같다. `<...>` 항목은 입력이 있을 때만 채우고 없으면 행을 생략한다.

```markdown
> **방문 정보 · <장소 이름>**
>
> - 주소: <도로명과 건물·층 정보>
> - 운영 시간: <요일별 HH:MM~HH:MM>
> - 휴무: <정기 휴무와 임시 휴무>
> - 입장 마감: <HH:MM>
> - 요금: <대상·메뉴·단위별 금액>
> - 주차·예약: <입력에 있는 조건>
> - 정보 기준: <사용자가 제공한 기준일 또는 실제 확인일>
```

- `운영 종료`, `입장 마감`, `주문 마감`은 서로 다른 항목이다. 근거 없이 같은 시간으로 채우지 않는다.
- 금액은 `5,000원/잔`, `성인 1인 7,000원`, `주차 10분당 500원`처럼 입력에 있는 대상·단위를 보존한다. 범위·할인 조건·연령 제한을 생략하지 않는다.
- 입력이 무료라고 명시하면 `입장료: 무료`로 쓴다. 모르는 요금은 무료로 바꾸지 않는다.
- 주소와 층·출구 번호는 그대로 보존한다. 알려지지 않은 도로명·층·교통편을 추가하지 않는다.
- 날짜가 없으면 기준 행은 생략하고 `확인 필요`에 정보 기준일을 적는다. 직접 확인하지 않은 입력 값을 `최신`, `확인 완료`로 표시하지 않는다.
- 미방문 추천은 `미방문 · 추천 정보`로 구분한다. 경험 문단에 섞지 않는다.

## 쓰지 않는 것

- 겪지 않은 장면·감정, 확인하지 않은 유래, 지어낸 숫자·지리.
- 마지막의 반복 요약, 교훈, 별점, `총평`.
- 인사, 구독·공감 요청, 다음 글 예고, 과장된 방문 명령.
- 참고 자료의 문장·소제목·코너 이름·장면과 출처 식별 정보.

## 예시

다음은 설명을 위해 만든 가상 장소의 입력이다.

```text
솔내항 언덕마을. 2026년 9월 방문. 버스 종점에서 내려 등대길 계단으로 감.
계단 많음. 중간에 파란 대문 앞 고양이. 등대 안내판에 1962년 건립이라고 적혀 있었음.
등대에서 바람 많이 불었음. 항구에 배 들어오는 것 봄.
등대 옆 솔내다방에서 쌍화차 마심. 한 잔 5,000원. 주인이 40년 했다고 말함.
사진: IMG_0412(계단), IMG_0420(등대), IMG_0431(쌍화차).
주소·운영 시간·정확한 방향은 모름.
```

출력 예는 구간 하나를 발췌한 것이다.

```markdown
## 1. 등대길 · 계단 위에서 본 항구

버스 종점에서 등대로 올라가는 '등대길'입니다. 종점에서 내려 계단으로 올라갔습니다. 중간에는 파란 대문 앞에 고양이가 있었어요.

<!-- 사진삽입: [현장] 파일: IMG_0412 등대길의 계단 | 캡션: 버스 종점에서 등대로 가는 길 -->

### 등대에서 내려다본 항구

계단이 많은 길을 올라 등대에 도착하니 바람이 많이 불었습니다. 항구로 배가 들어오는 모습도 봤습니다.

<!-- 사진삽입: [현장] 파일: IMG_0420 등대의 모습 | 캡션: 등대길 끝의 등대 -->

안내판에는 이 등대가 1962년에 세워졌다고 적혀 있었습니다.

### 솔내다방에서 마신 쌍화차

등대 옆 '솔내다방'에서 쌍화차를 마셨습니다. 주인은 40년 동안 다방을 운영했다고 말했습니다.

<!-- 사진삽입: [현장] 파일: IMG_0431 쌍화차 | 캡션: 솔내다방에서 마신 차 -->

> **방문 정보 · 솔내다방**
>
> - 메뉴: 쌍화차 5,000원/잔
> - 정보 기준: 2026년 9월 방문 당시 제공된 메모
```

입력에 없는 손의 온기·고양이 자세·가게 주소를 쓰지 않았다. 연도와 전언은 출처를 남겼고, 가격은 정보 상자로 분리했다. 정중형으로 소개와 방문 경험을 이어 가되 고양이를 본 짧은 덧붙임에만 해요체를 썼다. 입력이 부족한 항목은 글 밖의 `확인 필요`로 보고한다.

## 마무리

다 쓴 뒤 `akbun-writing-naturalize`의 규칙 파일과 처리 절차를 호출 모드로 적용하고 산출물 파일에 덮어쓴다. 보호 영역은 정중한 과거형 중심에 해요체를 간간이 섞는 말투, 정보의 시제·출처·조건, `사진삽입` 주석, 정보 상자, 고유명사·수치, 작은따옴표와 낫표다.

산출물은 Markdown 파일 하나다. 채팅에는 파일 경로, 주석 종류별 개수, `확인 필요` 목록만 보고한다.

## 자기 검토

- 방문 경험이 정중한 과거형 중심이며 해요체는 자연스러운 덧붙임에만 쓰였는가? 말투를 교대로 쓰거나 `~했었습니다`를 반복하지 않았는가?
- 소개의 `~입니다`와 방문 당시의 과거형을 구분하고, 방문일·확인일과 정보의 시제를 보존했는가?
- 문단이 한 장면에 집중하고 사진 설명이 해당 사진과 붙어 있는가?
- 이야기·감각·감정이 없는 입력을 분량 때문에 채워 넣지 않았는가?
- 소제목과 미리보기의 장소·순서가 일치하며 단일 장소에 구간을 만들지 않았는가?
- 주석 형식, 파일명, 종류별 개수가 맞고 `[현장]`을 자동 생성으로 넘기지 않았는가?
- 방향이 없는 약도를 방문 순서도로 표시했는가?
- 주소·시간·금액의 대상과 단위·조건이 보존되었는가? 무료와 미확인을 구분했는가?
- 마지막 경험 문단이 요약을 반복하지 않으며 참고 자료의 식별 정보·문장·장면이 없는가?
