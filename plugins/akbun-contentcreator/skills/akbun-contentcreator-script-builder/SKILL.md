# akbun-contentcreator-script-builder

옵시디언 공부 노트를 얼굴 없이 화면 녹화와 목소리로 설명하는 영상 대본으로 바꾼다. 노트는 공부한 순서로 적혀 있지만 대본은 시청자가 가진 문제에서 시작한다. 결과는 마크다운 대본 하나와 훅 3개다.

## 채널 전제

아래는 모든 콘텐츠가 따르는 채널 전제다. 충돌하면 전제가 이긴다.

```yaml
channel:
  name: 악분일상
  url: https://www.youtube.com/@Akbun
  blog: https://malwareanalysis.tistory.com/
  faceless: true                       # 얼굴 노출을 전제로 한 연출·조언을 넣지 않는다
  strength: 공식 문서와 직접 실험으로 확인하는 것
  structure: [문제, 예상, 실험, 결과]   # 모든 콘텐츠의 기본 뼈대
  never:
    - 노트에 없는 실험·실패·경험을 만들어 넣는다
    - 수치를 지어낸다. 노트에 없으면 "노트에 없음"으로 두고 사용자에게 묻는다
    - 회사 도메인·계정 ID·토큰·실제 로그의 개인정보를 대본에 옮긴다
```

## 언제 쓰는가

- 공부 노트 하나가 끝났고 이것을 본편 영상으로 만들려 할 때
- 이미 쓴 대본이 원리 설명부터 시작해서 문제부터 시작하게 뒤집고 싶을 때

## 입력

아래는 시작 전에 확인할 입력이다. 노트가 없으면 만들지 않고 먼저 달라고 한다.

```yaml
inputs:
  - id: note
    description: 옵시디언 공부 노트 원문(마크다운). 링크면 열어서 읽는다
    when_missing: ask                   # "옵시디언 원본 노트 링크(또는 내용)를 주세요". 추측해서 채우지 않는다
  - id: audience
    description: 누구를 위한 영상인가(예. EKS를 운영해 본 인프라 엔지니어)
    when_missing: 노트의 전제 지식 수준에서 추정하고 대본 맨 위에 "가정"으로 표시한다
  - id: target_length
    description: 목표 길이(분)
    when_missing: 6~9분. 억지로 맞추지 않는다
  - id: blog_url
    description: 같은 주제의 티스토리 글 주소
    when_missing: 마무리에 "블로그 링크 자리"로 비워 둔다
```

## 노트 읽는 법

옵시디언 노트는 frontmatter, `[[위키링크]]`, 코드블록, 캡처 이미지, 공식 문서 인용으로 이뤄진다. 아래 표로 노트의 요소를 대본의 재료로 분류한다.

```yaml
note_mapping:
  frontmatter.tags: 주제 범위. 대본에 쓰지 않는다
  "[[위키링크]]": 전제 지식. 대본에서는 한 문장 설명으로 풀거나 "이전 영상" 안내로 바꾼다
  코드블록·명령: 실험 재료. 영상에는 핵심 줄만, 전체는 블로그로 보낸다
  캡처·결과 출력: 결과 재료. 가장 놀라운 것 하나가 첫 15초 후보다
  공식 문서 인용·URL: 검증 장면 재료. "문서에는 이렇게 적혀 있다"로 쓴다
  "처음엔 ~인 줄 알았다" 류 문장: 예상 재료. 생각이 바뀐 순간이므로 반드시 살린다
  TODO·물음표·미확인: 대본에 넣지 않고 "확인 필요" 목록으로 뺀다
```

## 단계

아래는 대본을 만드는 순서다.

```yaml
steps:
  - step: 1
    name: 질문 하나 고르기
    do:
      - 노트에서 시청자가 실제로 막힐 질문 후보를 3개 뽑는다
      - 노트 안에 실험 증거(명령·출력·캡처)가 있는 질문만 남긴다
      - 하나를 고르고 나머지는 "다음 영상 후보"로 적는다
  - step: 2
    name: 네 칸 채우기
    do:
      - 문제. 시청자가 겪는 상황을 한 문장으로. 기술명은 그대로 둔다
      - 예상. 노트를 쓰기 전 사용자가 믿었던 것. 노트에 없으면 사용자에게 묻는다
      - 실험. 한 장면에 질문 하나. 바꾼 것과 관측한 것을 쌍으로 적는다. 2~3개
      - 결과. 관측에서 나온 결론과 조건. 공식 문서 근거를 한 줄 붙인다
  - step: 3
    name: 시간 배치
    do:
      - 0~15초는 결과 또는 실패 화면. 원리 설명이 먼저 오지 않게 한다
      - 15~35초는 대상과 도착점 약속. 자기소개·복귀 인사는 뒤로 보낸다
      - 본론은 실험 순서대로. 설치 대기·반복 타이핑은 "블로그 참고"로 접는다
      - 중간에 "처음엔 이렇게 생각했는데 문서를 보니"를 한 번 넣는다. 노트에 그 순간이 있을 때만
      - 마지막은 세 줄 요약, 주제에 맞는 질문 하나, 이어지는 영상 하나
  - step: 4
    name: 훅 3개
    do:
      - 결과형. 실험 결과 화면을 먼저 보여 주며 시작
      - 질문형. 시청자가 겪는 문제를 질문으로 시작
      - 오해형. 흔한 예상이 왜 틀리는지로 시작. 노트에 그 오해가 있을 때만
      - 각 훅은 15초 안에 말할 길이(한국어 70자 안팎)로 쓴다
  - step: 5
    name: 검수 목록 분리
    do:
      - 버전·명령·숫자·공식 문서 날짜는 대본에 [검수] 표시를 남긴다
      - 노트에 없어서 비워 둔 곳은 [노트에 없음]으로 남기고 질문 목록을 만든다
```

## 출력 형식

아래는 대본 파일의 형식이다. 출력 폴더에 `script-{주제-슬러그}.md`로 저장하고 대화에는 훅 3개와 질문 목록만 보여 준다.

```markdown
# {영상 가제}

- 대상: {audience} (가정 여부)
- 목표 길이: {분}
- 원본 노트: {노트 제목 또는 링크}
- 블로그: {blog_url 또는 "블로그 링크 자리"}

## 훅 후보

1. 결과형: ...
2. 질문형: ...
3. 오해형: ...

## 대본

| 시간 | 화면 | 말 |
|---|---|---|
| 0:00~0:15 | {결과 화면 설명} | {훅 본문} |
| 0:15~0:35 | {대상·도착점 카드} | ... |
| ... | ... | ... |

## 문제 → 예상 → 실험 → 결과

- 문제: ...
- 예상: ...
- 실험 1: 바꾼 것 / 관측한 것
- 실험 2: ...
- 결과: ... (근거: 공식 문서 URL)

## 다음 영상 후보

- ...

## 확인 필요

- [검수] ...
- [노트에 없음] ...
```

## 체크리스트

아래를 모두 만족해야 끝난다.

```yaml
done_when:
  - 첫 15초가 결과·실패·질문 중 하나로 시작하고 원리 설명이 아니다
  - 네 칸(문제·예상·실험·결과)이 모두 있고 실험마다 바꾼 것과 관측한 것이 쌍이다
  - 대본의 모든 명령·출력·수치가 노트에 있다. 없는 것은 [노트에 없음]이다
  - 얼굴·표정·출연을 전제로 한 지시문이 없다
  - 훅 3개가 서로 다른 유형이고 각각 70자 안팎이다
  - 블로그 링크 자리가 마무리에 있다
  - 회사·고객·계정 식별 정보가 없다
```
