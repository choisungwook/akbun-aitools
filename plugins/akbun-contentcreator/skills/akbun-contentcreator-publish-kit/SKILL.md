# akbun-contentcreator-publish-kit

대본이 실제로 답하는 것만 제목·글·쇼츠로 옮긴다. 입력은 대본 하나, 출력은 고른 파생물이다. 기본은 셋 다 만든다.

## 채널 전제

아래는 모든 파생물이 따르는 전제다. 충돌하면 전제가 이긴다.

```yaml
channel:
  name: 악분일상
  blog: https://malwareanalysis.tistory.com/
  faceless: true                       # 얼굴·표정 썸네일, 출연 컷을 제안하지 않는다
  structure: [문제, 예상, 실험, 결과]
  roles:
    video: 가장 중요한 질문 하나와 실험
    blog: 재현 가능한 전체 기록. 코드·버전·명령·참고 링크
    shorts: 예고편이 아니라 질문 하나에 대한 작은 답변
  never:
    - 대본·노트에 없는 결과·명령·수치를 쓴다. 없으면 [노트 필요]로 남긴다
    - 완벽·무손실·N배·절대 같은 대본 밖 약속을 한다
    - 키워드 반복·해시태그 도배를 한다
    - 회사 도메인·계정 ID·토큰·실제 로그의 개인정보를 옮긴다
```

## 언제 쓰는가

- 대본이 확정돼 업로드 전 제목·썸네일·글·쇼츠를 준비할 때
- 셋 중 하나만 필요할 때. 예. 이미 올린 영상의 제목만 다시 뽑기, 글만 쓰기

## 입력

아래는 시작 전에 확인할 입력이다.

```yaml
inputs:
  - id: script
    description: 영상 대본(akbun-contentcreator-script-builder 출력이면 가장 좋다)
    when_missing: ask
  - id: outputs
    description: 만들 것. titles | blog | shorts 중 하나 이상
    when_missing: 셋 다
  - id: note
    description: 원본 옵시디언 노트. 영상에서 "블로그 참고"로 접은 전체 명령·출력의 출처
    when_missing: blog를 만들 때 접힌 부분을 [노트 필요]로 표시한다
  - id: video_url
    description: 영상 주소
    when_missing: "{영상 링크}" 자리표시자. 업로드 후 바꾸라고 적는다
  - id: existing_post
    description: 같은 주제의 기존 티스토리 글 URL
    when_missing: 새 글로 쓴다. 있으면 새 글 대신 기존 글 상단에 넣을 영상 링크 문단만 만든다
  - id: previous_title
    description: 기존 영상이면 현재 제목·썸네일 문구
    when_missing: 새 영상으로 본다. 있으면 이전 제목·썸네일·변경일 기록 줄을 함께 낸다
  - id: ctr_data
    description: 비슷한 주제의 내 영상 노출 클릭률
    when_missing: 쓰지 않는다. "CTR 데이터가 있으면 주세요"라고만 적고 숫자를 추정하지 않는다
  - id: speech_rate
    description: 말 속도(초당 글자 수)
    when_missing: 한국어 초당 4.5자로 가늠하고 "가정"으로 표시한다
```

## 단계

아래는 공통 준비와 파생물별 순서다. titles를 만들 때는 `references/title-examples.md`를 먼저 읽는다.

```yaml
common:
  - 대본의 문제·결과 칸에서 "시청자가 영상을 보고 알게 되는 것"을 한 문장으로 적는다
  - 대본에 있는 기술명·버전·수치·명령을 목록으로 뽑는다. 모든 파생물은 이 목록 밖의 것을 쓰지 않는다

titles:
  - 제목 5개. 검색형 3개(기술명 + 시청자 질문 또는 얻는 것), 호기심형 2개(예상이 틀리는 지점·비교)
  - 회차 번호·"스터디"·"정리"·"이론과 실습"은 빼고 필요하면 끝이나 재생목록으로 보낸다
  - 60자 안쪽. 앞 30자만 보여도 뜻이 통하게 한다
  - 썸네일 문구 3개. 역할은 결과·비교·질문 하나씩, 제목 단어를 반복하지 않고 공백 포함 15자 안쪽. 함께 넣을 그림을 한 줄로 적는다
  - 터미널 전체 화면·긴 CVE 번호·작은 글자 구조도는 그림 후보에서 뺀다
  - 필터. 대본 밖 약속, 대본 밖 수치, 공포·분노만 자극(충격·경악·큰일), 제목과 썸네일이 다른 영상을 약속, 기술명 없음, 얼굴 전제. 걸리면 고치거나 버리고 이유를 적는다
  - 제목 하나와 문구 하나를 추천하고 이유 한 줄. CTR 데이터가 없으면 "패턴 기준, 데이터 검증 전"이라고 적는다

blog:
  - 대본에서 훅·화면 지시·말투를 지우고, "블로그 참고"로 접은 것을 노트에서 찾아 전체 명령·출력으로 채운다
  - 제목은 영상과 같은 기술명에 검색되는 오류 문구·설정 이름을 자연스럽게 넣는다
  - 첫 문단은 영상 링크와 역할 안내 한 줄. "영상으로 핵심 확인 / 글로 코드·버전·명령 확인"
  - 문제·예상·실험·결과 H2 절. 코드블록마다 위에 설명 한 줄과 언어 표시. 결과에 공식 문서 근거 링크
  - 마지막 절은 참고 링크. 영상 설명란 첫 줄용 문장을 따로 낸다. "전체 명령과 버전은 블로그에 있습니다. {블로그 링크}"
  - 버전·날짜·숫자는 [검수], 노트에도 없으면 [노트 필요]. 가린 정보는 샘플 값으로 바꿨다고 적는다
  - 문체는 akbun-writing이 설치돼 있으면 그 규칙, 없으면 존댓말(-습니다)에 짧은 문장

shorts:
  - 후보는 실험 결과 장면, 예상이 틀린 순간, 결과 절의 조건 한 줄. 본편 앞 내용 없이 질문 → 답이 되는 것만 남기고 같은 질문은 합친다
  - 구조. 0~3초 질문 자막(기술명 포함), 3~10초 답 한 줄, 10~45초 그림 또는 화면 하나로 이유, 45~55초 조건·주의, 마지막 3~5초 본편 안내. 구독 요청은 넣지 않는다
  - 길이는 말할 글자 수 ÷ 초당 글자 수로 계산해 적는다. 60초를 넘으면 10~45초 구간을 줄인다
  - 9:16에서 한 컷에 요소 하나. 터미널 전체 화면 대신 핵심 줄만 키운다
  - 쇼츠 제목은 질문 그대로 40자 안쪽. 첫 자막은 제목과 다른 말로 답의 방향을 보여 준다
  - 2~3개. 혼자 서는 순간이 2개뿐이면 2개. 뽑지 않은 후보와 이유를 적는다
```

## 출력 형식

아래는 결과의 형식이다. titles는 대화에 바로 보여 주고, blog는 `post-{주제-슬러그}.md`, shorts는 `shorts-{주제-슬러그}.md`로 출력 폴더에 저장한 뒤 대화에는 설명란 문장·검수 목록·쇼츠 제목만 보여 준다.

````markdown
# 업로드 준비: {영상 가제}

영상이 답하는 것: ...
대본에 있는 기술명·수치: ...

## 제목 5개

| # | 유형 | 제목 | 글자 수 |
|---|---|---|---|

## 썸네일 문구 3개

| # | 역할 | 문구 | 함께 넣을 그림 |
|---|---|---|---|

## 걸러 낸 표현

| 후보 | 걸린 기준 | 처리 |
|---|---|---|

## 추천

- 제목 N + 문구 M. 이유: ... CTR 데이터: {있음/없음}

## 블로그 글 (post-{슬러그}.md)

이 내용은 영상으로도 정리했습니다. 영상은 핵심 질문과 실험 결과를, 이 글은 전체 명령과 버전을 다룹니다. {영상 링크}

### 문제 / 예상 / 실험 / 결과 / 참고

아래는 ...을 확인하는 명령입니다.

```bash
...
```

<!-- 영상 설명란 첫 줄: 전체 명령과 버전은 블로그에 있습니다. {블로그 링크} -->
<!-- 검수: [검수] ..., [노트 필요] ... -->

## 쇼츠 (shorts-{슬러그}.md)

### 쇼츠 1: {질문 제목} — 예상 48초 (말 215자, 초당 4.5자 가정)

| 시간 | 화면(9:16) | 자막 | 말 |
|---|---|---|---|

### 뽑지 않은 후보

- ...: 앞 내용 없이는 질문이 서지 않음
````

## 체크리스트

아래를 모두 만족해야 끝난다. 만들지 않은 파생물의 항목은 건너뛴다.

```yaml
done_when:
  common:
    - 모든 결과·명령·수치가 대본 또는 노트에 있다. 없는 것은 [노트 필요]다
    - 얼굴·표정·출연을 전제로 한 제안이 없다
    - 회사·계정 식별 정보가 없다
  titles:
    - 제목 5개 모두 기술명이 있고 대본이 답하는 것만 약속한다
    - 썸네일 문구 3개의 역할이 다르고 제목 단어를 반복하지 않는다
    - 걸러 낸 표현 표에 기준과 처리가 있다. 없으면 "없음"
  blog:
    - 첫 문단에 영상 링크와 역할 안내, 설명란용 블로그 링크 문장이 있다
    - 문제·예상·실험·결과 절이 있고 코드블록마다 설명과 언어 표시가 있다
    - 기존 글이 있으면 새 글이 아니라 상단 문단만 만들었다
  shorts:
    - 쇼츠마다 질문 하나·답 하나이고 본편 없이 뜻이 통한다
    - 계산한 길이가 60초 이하이고 글자 수와 속도 가정이 적혀 있다
    - 본편 안내가 마지막 한 줄이고 구독 요청이 없다
```
