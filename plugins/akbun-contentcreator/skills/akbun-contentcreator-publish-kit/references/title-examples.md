# 제목 개선 예시

"악분일상 채널 분석 및 4주 코칭 (2026-11)" 문서의 제목 개선 5개를 옮겼다. 패턴을 보는 기준이지 그대로 쓰는 제목은 아니다.

## 원본 → 개선

| 원본 제목 | 개선 제목 | 썸네일 문구 | 바뀐 점 |
|---|---|---|---|
| Site-to-Site VPN, 구축보다 중요한건, 접근 제어와 운영 | AWS Site-to-Site VPN, 연결 뒤 꼭 확인할 접근 제어·운영 4가지 | 연결보다 접근 범위 | 대상(AWS)과 시점(연결 뒤)을 넣고 개수로 범위를 보여 줌 |
| 요즘 공부할때 사용하는AI 도구 | AI 답변을 믿기 전에: 공식 문서로 검증하는 나의 공부법 | AI 답 → 원문 확인 | 도구 나열을 시청자의 행동(믿기 전에)으로 바꿈 |
| 쿠버네티스에서 GPU를 사용하는 원리와 설정방법 | 쿠버네티스 Pod에서 GPU를 쓰려면? OS·K8s 설정 한 번에 이해하기 | OS 설정 + K8s 설정 | 시청자의 질문을 앞에 두고 영상이 그 질문에 답하게 함 |
| AWS RDS 복원기능 - PITR | AWS RDS PITR: 원하는 시점으로 복원하는 방법 | 이 시점으로 복원 | 기능 이름 뒤에 시청자가 얻는 것을 붙임. 무손실·완벽 복구는 약속하지 않음 |
| Argo CD 이해하기 5편: phase | Argo CD 배포 전·후 작업은 어떻게? PreSync·PostSync 실습 | 배포 전 / 배포 후 | 회차 번호를 빼고 질문과 실습 대상을 넣음 |

## 문서가 정한 기본 규칙

- 검색할 기술명은 남기고 시청자의 질문 하나를 앞쪽에 둔다.
- 공부기록형(기술명·이론·실습·스터디·회차)을 "대상 + 문제 + 해결/판단"으로 바꾼다.
- 썸네일은 제목을 반복하지 않고 결과·비교·핵심 질문 하나만 크게 쓴다.
- 작은 터미널 전체 화면과 긴 CVE 번호만으로 의미를 전달하지 않는다.
- 원본 내용에 없는 성과·시간 절약·장애 사례를 약속하지 않는다.
- 모바일 크기로 줄여 읽히는지 확인한다.
