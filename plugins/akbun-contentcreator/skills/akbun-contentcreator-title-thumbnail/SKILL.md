# akbun-contentcreator-title-thumbnail

대본이 실제로 답하는 것만 제목으로 약속한다. 제목은 검색형과 호기심형을 섞어 5개, 썸네일 문구는 제목을 반복하지 않는 짧은 문구 3개다. 걸러 낸 표현은 이유와 함께 남긴다.

## 채널 전제

아래는 모든 콘텐츠가 따르는 채널 전제다. 충돌하면 전제가 이긴다.

```yaml
channel:
  name: 악분일상
  faceless: true                       # 얼굴·표정 썸네일을 제안하지 않는다
  strength: 공식 문서와 직접 실험으로 확인하는 것
  title_rule: 검색할 기술명은 남기고 시청자의 질문 하나를 앞에 둔다
  never:
    - 대본에 없는 성과·시간 절약·장애 사례·무손실·완벽을 약속한다
    - 수치를 지어낸다. 대본에 있는 수치만 쓴다
    - 다른 채널의 제목·썸네일을 그대로 가져온다
```

## 언제 쓰는가

- 대본이 끝나서 업로드용 제목·썸네일을 정할 때
- 기존 영상 하나의 제목·썸네일을 바꿔 보려 할 때. 이때는 이전 제목·썸네일·변경일을 함께 기록하게 한다

## 입력

아래는 시작 전에 확인할 입력이다.

```yaml
inputs:
  - id: script
    description: 영상 대본(akbun-contentcreator-script-builder 출력이면 가장 좋다)
    when_missing: ask
  - id: audience
    description: 누구를 위한 영상인가
    when_missing: 대본 머리의 대상을 쓴다. 없으면 대본에서 추정하고 표시한다
  - id: previous_title
    description: 기존 영상이면 현재 제목·썸네일 문구
    when_missing: 새 영상으로 본다
  - id: ctr_data
    description: 비슷한 주제의 내 영상 노출 클릭률
    when_missing: 쓰지 않는다. "CTR 데이터가 있으면 주세요"라고만 적고 숫자를 추정하지 않는다
```

## 단계

아래는 제목·썸네일을 만드는 순서다. `references/title-examples.md`를 먼저 읽는다.

```yaml
steps:
  - step: 1
    name: 대본이 답하는 것 적기
    do:
      - 대본의 문제·결과 칸에서 "시청자가 영상을 보고 알게 되는 것"을 한 문장으로 적는다
      - 대본에 있는 기술명·버전·수치를 목록으로 뽑는다. 제목에는 이 목록 밖의 것을 쓰지 않는다
  - step: 2
    name: 제목 5개
    do:
      - 검색형 3개. 기술명 + 시청자 질문 또는 얻는 것. 예시 표의 "쿠버네티스 Pod에서 GPU를 쓰려면?" 패턴
      - 호기심형 2개. 예상이 틀리는 지점이나 비교. 예시 표의 "AI 답변을 믿기 전에" 패턴
      - 회차 번호·"스터디"·"정리"·"이론과 실습"은 빼고 필요하면 제목 끝이나 재생목록으로 보낸다
      - 60자 안쪽으로 쓴다. 모바일에서 앞 30자만 보여도 뜻이 통하게 한다
  - step: 3
    name: 썸네일 문구 3개
    do:
      - 제목의 단어를 반복하지 않는다. 결과 하나, 비교 하나, 질문 하나
      - 각 문구는 공백 포함 15자 안쪽. 함께 넣을 그림을 한 줄로 적는다(단순 구조도·화살표·두 층 비교 등)
      - 터미널 전체 화면·긴 CVE 번호·작은 글자 구조도는 그림 후보에서 뺀다
  - step: 4
    name: 걸러 내기
    filter:                              # 하나라도 걸리면 그 후보를 고치거나 버리고 이유를 적는다
      - 대본에 없는 결과를 약속한다(완벽·무손실·N배·절대·반드시)
      - 수치가 대본 밖에서 왔다
      - 공포·분노만 자극하고 영상이 답하지 않는다(충격·경악·큰일)
      - 제목과 썸네일이 서로 다른 영상을 약속한다
      - 기술명이 빠져 검색으로 찾을 수 없다
      - 얼굴·표정을 전제로 한다
  - step: 5
    name: 추천 한 쌍
    do:
      - 제목 하나와 썸네일 문구 하나를 추천하고 이유를 한 줄 적는다
      - CTR 데이터가 없으면 "추천은 패턴 기준이고 데이터 검증 전"이라고 적는다
```

## 출력 형식

아래는 결과의 형식이다. 대화에 바로 보여 주고 사용자가 원하면 `title-{주제-슬러그}.md`로 저장한다.

```markdown
# 제목·썸네일 후보: {영상 가제}

영상이 답하는 것: ...
대본에 있는 기술명·수치: ...

## 제목 5개

| # | 유형 | 제목 | 글자 수 |
|---|---|---|---|
| 1 | 검색형 | ... | 38 |
| ... | | | |

## 썸네일 문구 3개

| # | 역할 | 문구 | 함께 넣을 그림 |
|---|---|---|---|
| 1 | 결과 | ... | ... |
| 2 | 비교 | ... | ... |
| 3 | 질문 | ... | ... |

## 걸러 낸 표현

| 후보 | 걸린 기준 | 처리 |
|---|---|---|
| ... | 대본에 없는 약속 | "완벽"을 빼고 조건을 붙임 |

## 추천

- 제목 N + 썸네일 M. 이유: ...
- CTR 데이터: {있음/없음. 없으면 요청 문장}
```

## 체크리스트

아래를 모두 만족해야 끝난다.

```yaml
done_when:
  - 제목 5개 모두에 검색할 기술명이 있다
  - 제목 5개 모두 대본이 실제로 답하는 것만 약속한다
  - 썸네일 문구 3개가 제목 단어를 반복하지 않고 역할(결과·비교·질문)이 다르다
  - 걸러 낸 표현 표에 기준과 처리가 있다. 걸린 것이 없으면 "없음"이라고 적었다
  - 수치는 전부 대본에서 왔다
  - 얼굴·표정 전제 제안이 없다
  - 기존 영상이면 이전 제목·썸네일·변경일 기록 줄이 있다
```
