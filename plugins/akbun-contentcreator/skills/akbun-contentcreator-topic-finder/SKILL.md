# akbun-contentcreator-topic-finder

영상 하나는 질문 하나와 실험 하나다. 소스 세 곳을 훑어 그 모양으로 만들 수 있는 후보만 남긴다. 결과는 후보 5개 표 하나다.

## 채널 전제

아래는 후보를 고를 때 지키는 전제다.

```yaml
channel:
  name: 악분일상
  blog: https://malwareanalysis.tistory.com/
  faceless: true                       # 리뷰·브이로그·출연형 후보는 내지 않는다
  strength: 공식 문서와 직접 실험으로 확인하는 것
  axes:                                 # 코칭 문서의 콘텐츠 축. 후보 5개 배분은 검색형 2, 운영 판단 2, AI 공부법 1
    검색형_문제_해결: Pod GPU 인식, RDS PITR, Argo CD 배포 전·후, Kubernetes probe 류
    운영_판단_오해_검증: VPN 접근 범위, Scale out 한계, AI Gateway 토큰 집계 차이 류
    AI로_공부한_과정: AI에 질문 → 공식 문서 검증 → 작은 실험 → 블로그 정리
  never:
    - 실험할 수 없는 주제(소식 전달·의견·비교 리뷰)를 후보로 낸다
    - 수요·조회수를 숫자로 예측한다
    - 승인되지 않은 대상에 대한 공격 실습을 설계한다. 보안 주제는 격리 실습 환경과 방어 점검 중심이다
```

## 언제 쓰는가

- 다음 본편 주제를 정할 때
- 4주 계획의 빈 주차를 채울 때
- 블로그에 이미 있는 글 중 영상으로 옮길 것을 고를 때

## 입력

아래는 시작 전에 확인할 입력이다.

```yaml
inputs:
  - id: scope
    description: 이번에 다룰 기술 범위(예. EKS, AWS 네트워크, LLM 운영)
    when_missing: 블로그 최근 글의 범위를 쓴다
  - id: sources
    description: 훑을 소스. 공식 문서 변경 로그·릴리스 노트, 보안 뉴스·CVE 공지, 블로그 인기 글
    when_missing: 세 종류 모두 훑는다. 접근할 수 없는 소스는 "확인 못 함"으로 적는다
  - id: blog_popular
    description: 티스토리 관리 화면의 인기 글·검색 유입 순위
    when_missing: 공개 목록만 보고 "인기 글 데이터 없음"으로 표시한다. 추정하지 않는다
  - id: environment
    description: 실험 가능한 환경(계정·클러스터·GPU 유무)
    when_missing: 후보마다 필요한 환경을 적고 사용자가 거른다
  - id: recent_videos
    description: 최근 올린 영상 제목
    when_missing: 채널 공개 목록을 본다
```

## 단계

아래는 후보를 뽑는 순서다.

```yaml
steps:
  - step: 1
    name: 소스 훑기
    do:
      - 공식 문서. 범위 안 서비스의 최근 변경·새 기능·동작이 바뀐 항목
      - 보안 뉴스. 범위 안 기술의 취약점·설정 실수 공지. 재현은 격리 환경에서 방어 확인이 가능한 것만
      - 블로그. 인기 글·검색 유입 글. 질문 → 응답 → 비교 구조로 쓰인 글이 1순위
      - 소스마다 "문제가 될 수 있는 것"을 10개 안팎 메모한다
  - step: 2
    name: 질문 하나로 좁히기
    do:
      - 메모마다 "시청자가 막히는 질문 한 문장"으로 바꾼다. 못 바꾸면 버린다
      - 그 질문에 답하는 실험을 설계할 수 있는지 본다. 바꿀 것 하나와 관측할 것 하나가 있어야 한다
      - 최근 영상과 같은 질문은 버리거나 후속편으로 표시한다
  - step: 3
    name: 5개 고르기
    do:
      - 축 배분을 따른다. 검색형 2, 운영 판단 2, AI 공부법 1. 범위에 맞지 않으면 배분을 적고 조정한다
      - 후보마다 예상(흔한 믿음), 실험(바꾸는 것 → 보는 것), 필요한 환경, 연결할 블로그 글(있으면 URL)을 적는다
      - 소스 근거 URL을 붙인다. 근거 없는 후보는 내지 않는다
  - step: 4
    name: 순서 제안
    do:
      - 실험 환경이 이미 있고 블로그 글이 있는 후보를 먼저 둔다
      - 수요는 "가설"로 적는다. 숫자로 예측하지 않는다
```

## 출력 형식

아래는 결과의 형식이다. 대화에 보여 주고 사용자가 원하면 `topics-{YYYYMMDD}.md`로 저장한다.

```markdown
# 영상 후보 5개 ({YYYY-MM-DD}, 범위: ...)

| # | 축 | 시청자 질문 | 예상(흔한 믿음) | 실험(바꾸는 것 → 보는 것) | 필요한 환경 | 블로그 연결 | 근거 |
|---|---|---|---|---|---|---|---|
| 1 | 검색형 | ... | ... | ... | ... | URL 또는 "새 글 필요" | URL |
| ... | | | | | | | |

## 제안 순서

1. 후보 N. 이유: 환경·글이 이미 있음
2. ...

## 확인 못 한 소스

- ...

## 버린 후보와 이유

- ...: 실험으로 답할 수 없음
```

## 체크리스트

아래를 모두 만족해야 끝난다.

```yaml
done_when:
  - 후보 5개 모두 질문 한 문장과 실험(바꾸는 것 → 보는 것) 한 쌍이 있다
  - 후보 5개 모두 소스 근거 URL이 있다
  - 축 배분을 적었고 배분과 다르면 이유가 있다
  - 수요·조회수를 숫자로 예측한 문장이 없다
  - 출연·리뷰·소식 전달형 후보가 없다
  - 보안 후보는 격리 환경과 방어 점검 중심이다
  - 확인 못 한 소스와 버린 후보를 적었다
```
