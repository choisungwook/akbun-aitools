# akbun-contentcreator-performance-review

숫자에서 영상이 막힌 곳(노출·클릭·시청) 하나를 찾고, 다음 영상에서 바꿀 것 3가지를 정한다. 관찰과 가설을 구분하고 데이터에 없는 숫자는 만들지 않는다. 결과는 마크다운 보고서 하나다.

## 채널 전제

아래는 성과를 읽을 때 지키는 전제다.

```yaml
channel:
  name: 악분일상
  faceless: true                       # 얼굴 노출·출연을 개선점으로 내지 않는다
  structure: [문제, 예상, 실험, 결과]   # 개선점은 이 구조 안에서 낸다
  compare_with: 내 채널의 비슷한 영상. 다른 채널 숫자와 비교하지 않는다
  never:
    - 없는 데이터를 추정해 채운다. "데이터 없음"으로 두고 달라고 한다
    - 고정된 정답 CTR이나 "몇 분이면 성공" 기준을 적용한다
    - 조회수·구독자 증가를 약속한다
    - 공개 조회수 하나로 원인을 확정한다
```

## 언제 쓰는가

- 영상을 올리고 7일(또는 28일)이 지나 스튜디오 숫자를 볼 때
- 4주 계획의 한 주를 마치고 다음 주 영상에서 바꿀 것을 정할 때

## 입력

아래는 시작 전에 확인할 입력이다. 화면 캡처나 내보낸 파일의 숫자를 사용자가 붙여 넣는다. 로그인 정보는 받지 않는다.

```yaml
inputs:
  - id: video
    description: 영상 제목, 게시일, 길이
    when_missing: ask
  - id: period
    description: 숫자의 기간(게시 후 7일, 28일 등)
    when_missing: ask                   # 기간이 다른 영상끼리 비교하지 않기 위해 필요하다
  - id: impressions
    description: 노출수
    when_missing: "노출수를 주세요"라고 적고 노출 진단은 비운다
  - id: ctr
    description: 노출 클릭률(%)
    when_missing: "노출 클릭률을 주세요"라고 적고 클릭 진단은 비운다
  - id: views
    description: 조회수
    when_missing: ask
  - id: avd
    description: 평균 시청 지속 시간과 평균 조회율(%)
    when_missing: 시청 진단은 비운다
  - id: retention
    description: 시청 지속 그래프. 첫 30초 유지율과 큰 하락 지점의 시각
    when_missing: 첫 30초 진단은 비운다
  - id: traffic_sources
    description: 유입 경로 비율(검색·탐색·추천·외부)
    when_missing: CTR 비교에 "유입 경로 확인 필요"를 붙인다
  - id: baseline
    description: 비슷한 주제·길이·기간의 내 영상 2개 이상의 같은 숫자
    when_missing: "비교할 내 영상 숫자를 주세요"라고 적고 비교 없이 절대값만 읽는다
  - id: packaging
    description: 제목·썸네일 문구·첫 15초에서 한 약속
    when_missing: 제목에서 추정하고 "확인 필요"로 표시한다
```

## 단계

아래는 숫자를 읽는 순서다. 지표의 뜻은 YouTube 공식 문서를 따른다(노출·클릭률 <https://support.google.com/youtube/answer/16767369>, 시청 지속 <https://support.google.com/youtube/answer/9314415>).

```yaml
steps:
  - step: 1
    name: 표로 옮기기
    do:
      - 받은 숫자를 영상 한 줄, 비교 영상 한 줄씩 표로 적는다. 없는 칸은 "데이터 없음"
      - 기간이 다른 영상이 섞이면 같은 줄에서 비교하지 않고 표시한다
  - step: 2
    name: 막힌 곳 하나 고르기
    diagnose:
      노출: 노출수가 비교 영상보다 작다. 주제의 시청자 풀·검색 수요를 본다. 실패로 단정하지 않는다
      클릭: 노출은 비슷한데 CTR이 낮다. 제목·썸네일의 약속을 본다. 검색·탐색·추천 CTR은 섞지 않는다
      시청_초반: 클릭은 되는데 첫 30초 유지가 낮다. 제목의 약속과 첫 장면이 같은지 본다
      시청_중반: 초반은 유지되는데 중간에 큰 하락. 그 시각이 설치 대기·반복 설명·주제 전환인지 본다
      쇼츠만_큼: 쇼츠 조회수만 크다. 본편 연결 유입·재방문을 따로 본다
    do:
      - 위 다섯 중 가장 약한 곳 하나를 고르고 근거 숫자를 적는다
      - 데이터가 없어 판단할 수 없으면 "판단 불가"와 필요한 데이터를 적는다
  - step: 3
    name: 관찰과 가설 나누기
    do:
      - 관찰. 숫자에 실제로 있는 것만
      - 가설. 왜 그런지. 확인할 다음 영상과 볼 지표를 붙인다
  - step: 4
    name: 개선점 3가지
    do:
      - 막힌 곳에 맞는 변경 1개를 첫 번째로. 변수는 하나(제목 형식·썸네일·첫 15초·중간 압축·주제 중 하나)
      - 문제→예상→실험→결과 구조 안에서 바꾼다. 예. 결과 화면을 0초로, 설치 장면을 블로그로
      - 각 개선점에 다음 영상에서 볼 지표와 "어떤 숫자면 가설을 버릴지"를 적는다
      - 얼굴 출연·음악 추가·AI 캐릭터는 개선점에 넣지 않는다
  - step: 5
    name: 다음 분석에 필요한 데이터
    do:
      - 이번에 없어서 비운 칸을 목록으로 적고 스튜디오의 위치를 한 줄씩 안내한다
```

## 출력 형식

아래는 보고서의 형식이다. 대화에 보여 주고 사용자가 원하면 `review-{영상-슬러그}-{YYYYMMDD}.md`로 저장한다.

```markdown
# 성과 리뷰: {영상 제목}

기간: {게시 후 N일} · 게시일: ... · 길이: ...

## 숫자

| 영상 | 노출수 | CTR | 조회수 | 평균 시청 | 평균 조회율 | 첫 30초 유지 | 주 유입 |
|---|---|---|---|---|---|---|---|
| 이번 영상 | ... | ... | ... | ... | ... | ... | ... |
| 비교 A | ... | 데이터 없음 | ... | ... | ... | ... | ... |

## 막힌 곳

- {노출 | 클릭 | 시청 초반 | 시청 중반 | 쇼츠만 큼 | 판단 불가}. 근거: ...

## 관찰

- ...

## 가설

- ... → 확인: 다음 영상 N개에서 {지표}

## 다음 영상 개선점 3가지

1. {바꿀 것 하나}. 볼 지표: ... 버리는 기준: ...
2. ...
3. ...

## 다음 분석에 필요한 데이터

- {항목}: 스튜디오 → 분석 → ... 에서 내보내기
```

## 체크리스트

아래를 모두 만족해야 끝난다.

```yaml
done_when:
  - 표의 모든 숫자가 사용자가 준 것이다. 없는 칸은 "데이터 없음"이다
  - 기간이 다른 영상을 같은 줄에서 비교하지 않았다
  - 막힌 곳이 하나이고 근거 숫자가 있다. 못 고르면 "판단 불가"와 필요한 데이터가 있다
  - 관찰과 가설이 섞이지 않았다
  - 개선점이 정확히 3개이고 각각 바꾸는 변수 하나, 볼 지표, 버리는 기준이 있다
  - CTR을 말할 때 노출수와 유입 경로를 함께 적었다
  - 얼굴 출연을 개선점으로 내지 않았다
  - 다른 채널 숫자와 비교하지 않았다
```
