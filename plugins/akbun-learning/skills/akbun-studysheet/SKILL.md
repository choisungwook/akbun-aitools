# akbun HTML 학습지(studysheet) 만들기

## 이 skill이 하는 일

입력(주제, 글, 문서, 코드, 장애 경험)을 **혼자 공부하는 사람을 위한 HTML 학습지 한 파일**로 만든다. 학습지는 브라우저에서 페이지를 한 장씩 넘기며 읽는 구조이고, 외부 라이브러리 없이 파일 하나로 동작한다.

이 학습지가 따르는 학습 방식은 고정이다. **이론을 먼저 깔고 문제를 푸는 순서가 아니라, 문제 상황을 먼저 만나고 그 문제를 풀기 위해 원리를 파악한 뒤 손으로 직접 확인하는 순서다.** 학습자는 문제 없이 주어지는 이론을 소화하지 못하고, 원리 없이 외운 절차는 다른 곳에 응용하지 못한다. 그래서 모든 장은 "이 문제를 풀려면"이라는 목적에 매달려 있어야 하고, 원리는 절차가 아니라 설계 이유로 설명해야 한다.

## 학습지의 뼈대

뼈대는 고정이다. **문제 상황에서 출발해, 그 문제를 풀 열쇠가 되는 원리를 파악하고, 손으로 직접 확인한 뒤, 도입 문제로 돌아가 결론으로 닫는다.** 이 순서 자체가 학습 방식이므로 바꾸지 않는다. 그 안에서 장을 몇 개로 나누고 어디에 무엇을 배치할지는 입력에 맞게 정한다.

빠지면 안 되는 요소는 다음과 같다.

- 표지 + 미리보기 — "이런 상황이 있다면 → 이렇게 풀었을 것 같다"
- 문제 상황 — 실제 문제. 없으면 가정 상황임을 밝히고 만든다
- 원리 — 문제를 풀 열쇠. 왜 그렇게 설계됐는지까지
- 핸즈온 — 직접 실행하는 코드/명령 + 기대 결과 + 체크포인트
- 확인해 보기 — 클릭형 객관식 확인 문제
- 트레이드오프 — 얻는 것/잃는 것 + 언제 쓰고 언제 안 쓰는지
- 결론 — 도입 문제로 돌아가 원리로 어떻게 풀렸는지 닫는다

구조 이해하기(아키텍처·구성요소 관계 그림)는 구조가 있는 주제일 때 원리와 핸즈온 사이에 둔다. 장과 장 사이는 매끄럽게 잇는다 — 앞 장이 남긴 질문을 다음 장이 받으면 학습자가 페이지를 넘길 이유가 생긴다.

전체 분량은 **20장 미만**이다. 넘길 것 같으면 내용을 줄이지 말고 주제를 쪼개서 학습지를 나누자고 사용자에게 제안한다.

## 장별 작성 규칙

### 표지 + 미리보기

- 배울 목록을 나열하지 않는다. **"이런 상황이 있다면 — …", "이렇게 풀었을 것 같다 — …"** 두 줄로 상황과 접근을 먼저 보여준다.
- 화법은 간접으로 쓴다("풀 수 있다"가 아니라 "풀었을 것 같다"). 이 학습지가 다루는 방법이 유일한 답이 아니기 때문이다. 단정하면 다른 선택지를 닫아 버린다.
- 접근은 열쇠가 되는 원리·도구까지만 말하고, 동작 원리는 본문에 남긴다.

### 문제 상황

- 증상이 구체적이어야 한다. 무엇이 어떻게 실패했는지, 왜 임시방편으로는 안 되는지를 적는다.
- 입력에 실제 문제가 없으면 지어내지 말고 **가정 상황임을 명시한다**("이런 상황이라고 가정합니다"). 가정 상황도 학습자가 실무에서 만날 법해야 한다.
- 이 장에서 답을 미리 주지 않는다. 문제가 열어 놓은 궁금증이 뒤 페이지를 읽는 이유가 된다.

### 원리

- 동작 절차 나열이 아니라 **왜 그렇게 설계되었는지**를 설명한다. 원리를 알아야 다른 곳에 응용할 수 있다.
- 추상 설명만으로 두지 않는다. 작은 예시 데이터(toy example)로 본질이 눈에 보이게 한다.
- 배경 지식이 필요하면 배경 장을 따로 앞세우지 않는다. 원리 설명 중에 잠깐 배경으로 파고들었다가 "다시 돌아와서"로 복귀한다(꼬리지식). 파고드는 구간은 짧게 끊어, 이미 아는 학습자가 건너뛰기 쉽게 한다.
- 원리 장 끝에는 "다른 곳에도 적용됩니다."로 시작하는 한 문장을 두어, 이 원리가 응용되는 다른 지점을 짚는다.

### 구조 이해하기

- 아키텍처·구성요소 관계를 그림 하나로 보여준다. 구조가 한 장으로 충분하면 정적 다이어그램만 쓴다.
- 흐름·상태 전이가 있어 단계로 보는 게 더 이해하기 쉬울 때만 이전/다음 버튼 애니메이션을 보조로 쓴다. 애니메이션이 목적이 아니라 구조 이해가 목적이다. 순서가 없는 내용을 억지로 단계로 만들지 않는다.
- 애니메이션을 쓸 때는 단계마다 그림과 설명 한 단락을 짝으로 두고, **같은 구도를 반복하며 마커·강조만 바꿔** 장면이 진행되는 효과를 낸다. 현재 단계의 주인공만 노랑으로 채우고 나머지는 흐리게 처리한다.

### 핸즈온

- 학습자가 그대로 복사해 실행할 수 있어야 한다. 실행 순서대로 배치하고, 코드 블록 위에 무엇을 하는 코드인지 설명을 붙인다.
- 기대 결과를 함께 보여준다. 결과가 다르면 학습자가 스스로 어긋난 지점을 찾을 수 있다.
- 체크포인트를 둔다: 여기까지 성공하면 무엇이 확인된 것인지 한 줄로 적는다.
- 검증하지 않은 코드를 넣지 않는다. 실행해 볼 수 없는 환경이면 그 사실을 학습지에 남긴다.
- 실습 repo가 있으면 하단에 `github 링크: URL`을 단다.

### 확인해 보기

- 본문을 그대로 되묻지 않는다. 문제 상황의 조건을 바꾼 변형 질문으로, 원리를 이해했는지 확인한다.
- **클릭형 객관식**으로 만든다. 보기를 클릭하면 즉시 정답 여부와 피드백이 보인다. 피드백에는 답만이 아니라 원리로 돌아가는 한 줄 설명을 붙인다.
- 오답 보기도 그럴듯해야 한다. 함정이 아니라, 본문을 이해해야 골라낼 수 있는 중간 난이도로 만든다.

### 트레이드오프

- 장점과 단점을 나란히 보여주고, "그래서 언제 쓰고 언제 쓰지 않는가"로 판단 기준을 준다.
- 단점이 없어 보이면 아직 못 찾은 것이다. 비용, 복잡도, 운영 부담, 적용 한계 중에 반드시 있다.

### 결론

- 도입의 문제 상황으로 돌아가, 원리가 문제를 어떻게 풀었는지 요약하고 닫는다.
- 새 정보를 늘어놓지 않는다. 기억할 원리 한 문장과 다음에 응용할 지점만 남긴다.

## 스타일: akbun 라이트 샌드위치

비주얼은 akbun-presentation-lightsandwich의 라이트 테마를 따른다. **다크(#212022) 표지가 흰 내용 페이지를 여는 구조**이고, 내용 페이지는 흰 배경 + 검정 본문이다.

- **글이 먼저다.** 설명을 박스에 가두지 않는다. 짧은 산문과 ■(메인)/-(서브) 불릿으로 쓴다. 박스는 다이어그램과 코드 패널에만 허용한다.
- 내용 페이지 머리는 배지가 아니라 **`N. 섹션명` 헤더 + 제목**이다.
- 강조 색 문법: 노랑(`#FFC000`)은 포인트, 빨강(`#FF0000`)은 문제·에러. 본문 키워드는 노란 형광펜 또는 빨간 글씨로, **한 장에 1~2곳만**.
- 다이어그램 그림 언어: 흰 채움 + 검정 얇은 테두리 박스, 워크로드(pod·앱)는 연노랑(`#FFF2CC`), 인프라 리소스(service 등)는 연초록(`#E2EFDA`), 묶음 영역은 연회색(`#F2F2F2`), 논리 경계는 둥근 검정 테두리에 왼쪽 위 라벨. 화살표는 검정 실선, 문제 흐름은 빨강. 순서는 숫자 마커로 밟는다. 읽는 방향은 왼쪽 → 오른쪽.
- 다이어그램 구도는 학습지 전체에서 소수만 정해 재사용한다. 장마다 새 그림을 그리지 않고, 같은 구도에서 마커·강조·설명만 바꾸면 학습자가 그림 읽는 법을 다시 배우지 않아도 된다.
- 코드 패널은 VS Code Dark+ 스타일(배경 `#1E1E1E`).
- 그림 아래 `[ 설명 ]` 형식의 짧은 캡션을 달 수 있다.

## HTML 작성 방법

같은 디렉터리의 [assets/template.html](assets/template.html)을 복사해서 시작한다. 템플릿에는 라이트 샌드위치 색·타이포와 페이지 넘김, 구조 애니메이션(stepper), 정답 접기(reveal), 다이어그램, 트레이드오프 컴포넌트의 CSS/JS가 모두 들어 있다. **CSS/JS는 수정하지 않고 내용만 교체한다.** `{{...}}` 자리와 예시 페이지 구조를 입력 내용으로 바꾸고, 필요 없는 컴포넌트는 지운다.

- 학습지 한 장 = `<section class="page">` 하나. 한 장에는 하나의 초점만 둔다. 스크롤이 길어지면 장을 나눈다.
- 다이어그램은 템플릿의 상자(`.dbox`, 채움 클래스 `.wl`/`.rs`)+화살표(`.darrow`)+숫자 마커(`.marker`)+경계(`.dgroup`) 조합을 기본으로 쓰고, 그걸로 부족할 때만 inline SVG를 넣는다. ASCII 아트로 그리지 않는다. 외부 이미지·CDN·웹폰트는 쓰지 않는다.
- 저장 위치는 `$HOME/Downloads/<주제-slug>/` 디렉터리다. 디렉터리가 없으면 만든다. 파일명은 `studysheet-<주제-slug>-v1.html`이고, 같은 주제를 다시 만들면 덮어쓰지 말고 v2, v3으로 올린다.
- 만든 뒤 브라우저에서 열어 페이지 넘김과 단계 버튼이 동작하는지 확인한다.

## 목소리

akbun의 기본 글쓰기 목소리를 따른다.

- 차분한 실무자 존댓말. 원리 설명은 평서문.
- 입력에 있는 사실만 쓴다. 동기·실패담·감정은 입력에 있을 때만. 가정 상황은 가정임을 밝힌다.
- 과장 수식("완벽 정리", "한 방에")을 쓰지 않는다. 불확실하면 단정하지 않고 `확인 필요`로 남긴다.
- 학습자가 이미 아는 일반 상식은 설명하지 않는다. 이 주제가 아니면 알 수 없는 원리·수치·판단에 지면을 쓴다.
- 영어 기술 용어는 번역하지 않고 그대로 쓴다.

## 자기 검토

학습지를 내기 전에 확인한다.

- 미리보기가 "이런 상황이 있다면 → 이렇게 풀었을 것 같다" 간접 화법이고, 답을 미리 흘리지 않았는가?
- 문제 상황(또는 명시된 가정 상황)이 구체적인가?
- 원리가 절차 나열이 아니라 설계 이유로 설명되었고, 작은 예시로 눈에 보이며, 응용 지점을 짚었는가?
- 배경 지식이 별도 장이 아니라 원리 속 꼬리지식으로, 짧게 다녀오는 구간으로 들어갔는가?
- 구조 그림이 있는가? 구도를 소수로 정해 재사용했는가? 애니메이션은 구조 이해에 도움이 될 때만 썼고 억지 단계는 없는가?
- 핸즈온이 복사-실행 가능하고 기대 결과와 체크포인트가 있는가?
- 확인 문제가 클릭형 객관식이고, 오답 보기가 그럴듯하며, 피드백이 원리로 돌아가는가?
- 트레이드오프와 결론이 있는가? 결론이 도입 문제를 닫는가?
- 설명이 박스가 아니라 짧은 글·불릿으로 되어 있고, 강조는 한 장에 1~2곳인가?
- 장 사이가 매끄럽게 이어지는가? 앞 장이 남긴 질문을 다음 장이 받는가?
- 전체 20장 미만인가?
- `$HOME/Downloads/<주제-slug>/`에 저장했고, 파일명이 `studysheet-<주제-slug>-v{n}.html`이며 이전 버전을 덮어쓰지 않았는가?
