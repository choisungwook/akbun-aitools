# 설계 판단

이 skill을 이렇게 만든 이유다. 구조를 바꾸려면 여기의 이유가 여전히 맞는지 먼저 본다.

## 판단과 이유

| 판단 | 이유 |
|---|---|
| 단일 원본은 `storyboard.json`(spec). 모델은 spec만 쓰고, 스크립트가 검사·프롬프트 조립·pptx·대본을 만든다 | 컷 수·속도·길이 같은 숫자는 모델이 대충 맞추기 쉽고 스크립트는 정확히 센다. 같은 spec에서 pptx와 대본이 어긋날 수 없다. spec 한 곳만 고치면 둘 다 다시 만들어진다 |
| 틀은 스크립트가, 스케치만 이미지 생성 모델이 그린다. 컷 번호·설명·의도·타임라인·표는 pptx의 도형과 글상자이고, 이미지 모델에는 글자 없는 16:9 스케치 한 장씩만 맡긴다 | 글자와 틀까지 이미지로 만들면 고칠 수 없고, 한글이 틀리고, 컷 하나만 다시 그릴 수 없다 |
| 형식은 pptx | 컷 순서 바꾸기, 글 고치기, 스케치 교체를 사용자가 직접 한다. 타임라인 블록도 개별 도형이라 끌어서 고친다 |
| 이미지 생성 도구·모델·CLI 명령·모델 옵션을 skill에 쓰지 않는다. 프롬프트에 폰트 이름을 쓰지 않는다 | 도구는 사용자 환경마다 다르고 바뀐다. 스케치에는 글자가 없어서 폰트가 필요 없다 |
| 사운드는 특정 음원 서비스에 묶지 않는다. 분위기·장르·BPM·악기·에너지 변화로 서술하고 검색어와 생성용 문장을 둘 다 적는다 | 음원 라이브러리에서 찾든 음악 생성으로 만들든 같은 서술에서 출발한다. 서비스가 바뀌어도 spec이 그대로 쓰인다 |
| 스케치가 없어도 pptx는 만들어진다(회색 자리표시). 스케치는 사용자가 이미지까지 요청했을 때만 생성 | 구성과 대본만 먼저 검토하고 싶을 때가 많고, 그림은 비용이 든다 |
| pptx 글꼴은 상업용으로 써도 되는 공개 라이선스 글꼴(Pretendard, SIL OFL 1.1) 하나만 쓴다 | 스토리보드에서 글자를 복사해 영상 자막·썸네일로 옮겨도 저작권 문제가 없어야 한다 |
| 시각을 spec에 쓰지 않고 `dur`만 쓴다 | 컷 하나의 길이를 바꾸면 뒤 시각이 전부 달라진다. 합은 스크립트가 센다 |
| 얼굴을 그리지 않는다 | 채널 주인은 얼굴을 드러내지 않는다. 손·뒷모습·1인칭·화면·사물로 대신한다 |

## 하지 않은 것

- 컷마다 별도 pptx 파일: 순서를 바꾸기 어렵다.
- 움직임과 샷을 자유 문장으로 쓰기: 스크립트가 연속 사용·종류 수를 셀 수 없다. 그래서 jsonl의 id로 고른다.
