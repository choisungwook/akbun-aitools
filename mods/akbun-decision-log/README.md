# akbun-decision-log

Claude의 답이 "A, B, C 중 어느 것으로 할까요?"처럼 선택지를 묻는 질문으로 끝나면, 현재 대화를 fork한 모델이 선택지마다 뜻·다음 단계·장단점과 추천을 정리해 `Decision` pane에 띄운다. 사용자가 고른 안은 버튼 한 번 또는 프롬프트 답변으로 `docs/adr/`에 결정 기록(ADR)과 색인 행으로 남는다. 버린 대안과 그 단점이 함께 기록된다.

## 해결하는 문제

- 결정의 순간은 Claude가 질문을 던질 때인데, 그 결론이 대화에만 남고 `docs/adr/`에는 기록되지 않는다.
- 나중에 적으면 버린 대안과 이유가 빠진다. 질문 시점에 선택지가 정리돼 있어야 그대로 ADR이 된다.
- 터미널에서 긴 선택지 글을 읽기 어렵다. pane에 상자로 나눠 보면 비교가 쉽다.

## 동작

매 턴이 끝나면 아래 순서로 돈다. 메인 대화의 정상 종료만 본다.

1. 정규식으로 답의 끝을 본다. 마지막 문단이 물음표로 끝나거나, 번호·글자 선택지가 2개 이상이고 "어느", "선택", "which" 같은 말이 있으면 질문으로 본다. 대부분의 턴은 여기서 끝나고 모델 호출이 없다.
2. `haiku`가 확인한다(`$.model.complete`). 작업을 이어가기 전에 사용자가 결정해야 하면 `YES`, "더 필요한 것 있나요?" 같은 인사면 `NO`.
3. `YES`면 현재 대화를 fork한다(`$.model.fork`). fork는 도구 없이 JSON으로만 답한다.

   fork가 돌려주는 JSON 형식이다.

   ```json
   {"title": "저장소 선택", "slug": "storage-choice", "scope": "akbun-md-to-notion",
    "question": "어느 저장 방식을 쓸까?", "context": "단일 사용자 CLI다.",
    "options": [{"label": "SQLite", "detail": "내장 DB 파일", "leadsTo": "스키마 작성", "pros": ["쿼리 가능"], "cons": ["드라이버 필요"]}],
    "recommendation": {"label": "SQLite", "why": "파일 하나로 끝나고 쿼리가 된다."}}
   ```

4. pane이 질문 상자와 선택지 상자를 그린다. 추천 안은 초록 굵은 테두리와 `★ 추천`, 각 상자에 `이 안으로 ADR 기록` 버튼, 마지막 상자는 직접 쓴 답을 넣는 입력란이다. 터미널이 144열보다 좁으면 pane이 자동으로 열리지 않고 toast가 뜬다. `/decision`으로 열면 폭과 무관하게 열린다.
5. 사용자가 프롬프트로 답하면(예: "SQLite로 가자") 그 턴이 끝날 때 `haiku`가 어느 선택지인지 고른다(`A`~`H`, `OTHER`, `NONE`). 고른 안은 pane에 `● 선택됨`으로 표시되고 띠에 `결정 감지: B SQLite  [ADR 기록] [열기] [무시]`가 뜬다. 파일은 `ADR 기록`을 눌러야 쓴다.
6. 기록 시 `docs/adr/NNNN-<slug>-<option>.md`를 쓴다. 번호는 기존 최대값 +1이다. `docs/adr/README.md`가 있으면 표 끝에 행을 추가한다. 고른 안이 Decision, 그 안의 pros와 추천 이유가 Reason, 나머지 선택지와 cons가 Rejected alternatives가 된다.

`AGENTS.md`의 결정 기록 조건(되돌리기 어렵고, 맥락 없이는 이상해 보이고, 트레이드오프가 있었다)은 이 mod가 판단하지 않는다. 기록 버튼을 누르는 사람이 판단한다.

## 사용법

Claude가 선택지를 묻는 답을 하면 pane이 열린다. 상자의 버튼을 누르면 그 안으로 기록된다.

```text
/decision
```

명령으로도 같은 일을 한다. `b`는 선택지 B로, `other`는 직접 쓴 답으로 기록한다.

```text
/decision b
/decision other DuckDB
```

정리된 질문이 없을 때 결정 한 줄을 주면 대화를 fork해 초안을 만들고 바로 기록한다. 첫 선택지가 고른 안이 된다.

```text
/decision Notion 동기화는 CLI 우선, MCP는 대체
```

기존 기록 목록을 본다.

```text
/decision list
```

`claude -p`에서는 pane이 없다. 판정과 fork를 기다리게 하려면 `AKBUN_DECISION_WAIT=1`을 준다.

B의 버튼을 누르면 `docs/adr/0007-storage-choice-sqlite.md`가 아래 내용으로 생긴다(`claude plugin test`가 쓴 파일 그대로).

```markdown
# 저장소 선택: SQLite

Scope: akbun-md-to-notion

## Decision

내장 DB 파일

스키마 작성

## Reason

- 쿼리 가능
- 파일 하나
- 파일 하나로 끝나고 쿼리가 된다.

## Rejected alternatives

- JSON 파일: 동시 쓰기 불가
- Redis: 서버가 필요

## Source

- 2025-10-09 Claude Code 세션 sess-1
- 질문: 어느 저장 방식을 쓸까?
```

`docs/adr/README.md` 표 끝에 행이 하나 붙고, pane 아래에 `기록됨: docs/adr/0007-storage-choice-sqlite.md`가 뜬다.

```markdown
| [0007](0007-storage-choice-sqlite.md) | akbun-md-to-notion | 저장소 선택: SQLite |
```

프롬프트로 "JSON 파일로 가자"라고 답한 뒤의 띠다.

```text
결정 감지: A JSON 파일  [ADR 기록] [열기] [무시]
```

## 한계

- 선택지 정리는 fork가 쓴 초안이다. 기록한 파일을 열어 다듬고, `AGENTS.md`의 결정 기록 조건에 맞지 않으면 지운다.
- 질문은 세션당 하나만 기억한다. 새 질문이 오면 이전 질문은 사라진다. 기록된 파일은 남는다.
- 선택지를 실제 세션 fork로 끝까지 시뮬레이션하는 탐색 기능은 없다. pros·cons와 `leadsTo`로 비교한다.
- `docs/adr/`가 없으면 만들어 쓴다. 색인 `README.md`는 있을 때만 갱신한다.
