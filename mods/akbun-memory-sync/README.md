# akbun-memory-sync

턴이 끝날 때마다 `haiku`가 "다음 세션에도 지켜야 할 규칙"이 나왔는지 판정하고, 나왔으면 현재 대화를 fork한 모델이 메모리 파일의 어느 섹션에 어떤 줄을 덧붙일지 정한다. 파일은 mod가 직접 쓴다. 메인 세션은 멈추지 않고, 프롬프트 위 띠와 `Memory` pane에 바뀐 파일과 줄 수가 뜬다.

메모리 파일은 `AGENTS.md`와 그 파일이 참조하는 문서다. `~/.claude/projects/*/memory/`나 별도 메모리 파일을 만들지 않는다.

## 해결하는 문제

- "앞으로 커밋 메시지는 한국어로", "다시는 README를 자동으로 고치지 마" 같은 지시가 세션이 끝나면 사라진다.
- 메인 에이전트가 작업과 메모리 갱신을 동시에 하면 둘 다 흐트러진다. 메모리 갱신은 옆에서 돌아야 한다.
- `CLAUDE.md`가 `AGENTS.md`를 가리키는 저장소에서 모델이 엉뚱한 파일에 규칙을 남긴다.

## 동작

매 턴이 끝나면 아래 순서로 돈다. 메인 대화의 정상 종료(`turn.complete`, reason `answer`)만 보고 서브에이전트 턴은 건너뛴다.

1. 메모리 파일을 찾는다. 작업 디렉터리에 `AGENTS.md`가 있으면 그 파일, 없으면 `CLAUDE.md`. 그 파일 본문에서 `` `docs/foo.md` ``나 `](docs/foo.md)`로 참조된 `.md` 중 실제로 있는 파일을 최대 10개까지 함께 쓴다.
2. `haiku`가 판정한다(`$.model.complete`). 입력은 마지막 사용자 프롬프트부터의 대화와 메모리 파일들의 제목 목록이고, 출력은 `SKIP` 또는 `UPDATE: <남길 것>` 한 줄이다. 대부분의 턴은 `SKIP`으로 끝난다.
3. `UPDATE`면 현재 대화를 fork한다(`$.model.fork`). fork는 세션의 대화를 프롬프트 캐시에서 그대로 이어받으므로 맥락을 다시 설명하지 않는다. fork에는 원본 파일 전문(16,000자까지)과 참조 문서의 제목 목록을 붙이고, 도구 없이 JSON으로만 답하게 한다.

   fork가 돌려주는 JSON 형식이다.

   ```json
   {"edits": [{"file": "AGENTS.md", "section": "## Pull Request 작성 규칙", "lines": ["- 커밋 메시지는 한국어로 쓴다."]}]}
   ```

4. mod가 파일을 쓴다(`$.fs.write`). 지정한 섹션의 끝, 즉 다음 같은 급 이상 제목 앞에 줄을 덧붙인다. 같은 줄이 그 섹션에 이미 있으면 건너뛴다. 메모리 파일 목록에 없는 파일이나 없는 섹션은 무시한다.
5. 띠에 `메모리: +1 · AGENTS.md`처럼 결과가 뜬다. `열기`는 pane, `되돌리기`는 반영 전 내용으로 복구, `숨기기`는 띠를 지운다.
6. 시스템 프롬프트(`prompt.compose`)에 인계 문단을 덧붙인다. 사용자가 "기억해"라고 하면 메인 에이전트는 파일을 고치지 않고 알겠다고만 답하고, 턴이 끝나면 이 mod가 반영한다.

## 사용법

규칙을 말하면 된다. 턴이 끝나고 몇 초 뒤 띠가 바뀐다.

```text
> 앞으로 이 저장소에서는 커밋 메시지를 한국어로 써줘. 기억해 둬.
```

판정과 반영 기록을 보려면 pane을 연다.

```text
/memory-sync
```

지금 턴을 바로 판정·반영하거나, 마지막 반영을 되돌린다.

```text
/memory-sync now
/memory-sync undo
```

`claude -p`처럼 턴이 끝나면 프로세스가 종료되는 환경에서는 반영이 끝날 때까지 기다리게 한다.

```bash
AKBUN_MEMORY_SYNC_WAIT=1 claude -p --plugin-dir mods/akbun-memory-sync "앞으로 커밋 메시지는 한국어로 써줘"
```

## 결과

위 프롬프트를 이 저장소 사본에서 `claude -p`로 실행한 결과다. fork가 `## Pull Request 작성 규칙` 섹션을 고르고 끝에 한 줄을 덧붙였다.

```diff
@@ -121,6 +121,7 @@
 - 왜 하는지와 의사결정은 기록용 Issue에 두고 PR에는 링크만 남긴다.
 - 각 섹션은 요약 한 줄과 필요한 경우 근거 목록 하나까지만 사용한다.
 - 쓰지 않는 것: 커밋 SHA 나열, 파일별 체크리스트, ...
+- 커밋 메시지는 한국어로 쓴다.
 
 ## 세션 중 원칙
```

반영 중과 반영 뒤의 띠다. 실패하면 빨간 글자로 이유가 나온다.

```text
메모리: 반영 중 (커밋 메시지를 한국어로 쓴다)  [열기] [숨기기]
메모리: +1 −0 · AGENTS.md  [열기] [되돌리기] [숨기기]
```

`Memory` pane에는 세션의 모든 판정이 시간순으로 쌓인다. `SKIP`은 마지막 것만 보인다.

```text
이 세션에서 메모리 파일 1개 변경 +1

04:21 커밋 메시지를 한국어로 쓴다
  ~ AGENTS.md  +1 −0

04:18 남길 규칙 없음
```

`/memory-sync now`의 응답이다.

```text
akbun-memory-sync: AGENTS.md +1 −0
```

## 한계

- 판정은 `haiku` 한 번이라 일회성 요청을 규칙으로 볼 수 있다. 띠의 `되돌리기`로 복구한다.
- fork는 섹션을 고르기만 하고 mod는 섹션 끝에만 덧붙인다. 기존 줄을 고치거나 지우지는 않는다. 틀린 규칙을 바꾸려면 사람이 고친다.
- 메인 에이전트의 `AGENTS.md` 쓰기를 막지 않는다. `akbun-reflect` 같은 skill이 같은 파일을 고치는 저장소이기 때문이다. 같은 턴에 둘이 같은 파일을 쓰면 나중 쓴 쪽이 남는다.
- 작업 디렉터리에 `AGENTS.md`도 `CLAUDE.md`도 없으면 아무것도 하지 않는다.
- 조직이 관리하는 Claude Code에서는 `prompt.compose` hook이 실행되지 않는다. 판정·반영·띠·pane은 동작한다.
