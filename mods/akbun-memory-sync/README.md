# akbun-memory-sync

턴이 끝날 때마다 사용자가 말한 내용에서 "앞으로도 지켜야 할 규칙"을 뽑아 메모리 파일에 반영하는 턴을 제안하거나 자동으로 실행한다. 메모리 파일은 `AGENTS.md`와 그 파일이 참조하는 문서다. 별도 메모리 파일을 만들지 않는다.

## 해결하는 문제

- "앞으로 커밋 메시지는 한국어로", "다시는 README를 자동으로 고치지 마" 같은 지시가 세션이 끝나면 사라진다.
- `CLAUDE.md`가 `AGENTS.md`를 가리키는 저장소에서 모델이 엉뚱한 파일에 규칙을 남긴다.

## 동작

1. `prompt.submit`에서 사용자 발화를 모은다. `/`로 시작하는 명령과 이 mod가 큐에 넣은 프롬프트는 뺀다.
2. 메인 대화의 턴이 정상 종료(`turn.complete`, reason `answer`)하면 모은 발화를 `haiku`에 보내 규칙 후보 JSON을 받는다. 후보가 없으면 아무 일도 하지 않는다.
3. 메모리 파일을 찾는다. 작업 디렉터리에 `AGENTS.md`가 있으면 그 파일, 없으면 `CLAUDE.md`. 그 파일 본문에서 `` `docs/foo.md` ``나 `](docs/foo.md)` 형태로 참조된 `.md` 중 실제로 있는 파일을 최대 10개까지 함께 쓴다.
4. 자동 반영이 꺼져 있으면(기본) 프롬프트 위 띠에 후보를 띄운다. `반영`을 누르면 메인 에이전트에 반영 프롬프트를 큐에 넣는다. 켜져 있으면 띠 없이 바로 큐에 넣고 toast로 알린다.
5. 시스템 프롬프트(`prompt.compose`)에 메모리 파일 위치를 한 문단 덧붙인다. 사용자가 "기억해"라고 하면 모델이 이 파일들에 쓴다.

## 사용법

턴이 끝난 뒤 띠가 뜨면 버튼을 고른다.

```text
메모리 후보 1개: 커밋 메시지는 한국어로 쓴다  [반영] [무시]
```

세션 전체를 다시 훑어 반영하려면 명령을 직접 부른다.

```text
/memory-sync
```

자동 반영을 켜거나 끄거나 상태를 본다. 설정은 세션이 바뀌어도 유지된다.

```text
/memory-sync auto on
/memory-sync auto off
/memory-sync status
```

## 결과

`반영`을 누르거나 자동 반영이 실행되면 메인 에이전트가 아래 형식의 프롬프트를 받아 한 턴을 돈다.

```text
[akbun-memory-sync] 이번 세션 사용자 지시에서 뽑은 규칙 후보다. 메모리 파일에 반영해라.
규칙:
- 규칙마다 아래 메모리 파일 중 가장 맞는 자리에 넣는다. 첫 파일이 원본이고 나머지는 그 파일이 참조하는 문서다.
- 같은 뜻의 규칙이 이미 있으면 추가하지 않고 "이미 있음"으로 보고한다.
- 기존 문체와 섹션 구조를 따르고, 새 파일이나 새 섹션은 만들지 않는다.
- 끝나면 고친 파일과 추가한 줄만 짧게 보고한다.

메모리 파일:
- AGENTS.md
- docs/guide_deploy_plugins.md

규칙 후보:
- 커밋 메시지는 한국어로 쓴다 (근거: "앞으로 커밋 메시지는 한국어로")
```

그 턴이 끝나면 `AGENTS.md`(또는 참조 문서)에 규칙 한 줄이 추가되고, 에이전트가 고친 파일과 줄을 보고한다. 같은 규칙이 이미 있으면 "이미 있음"만 보고하고 파일은 그대로다.

`/memory-sync status`의 출력 예시다.

```text
akbun-memory-sync: 자동 반영 꺼짐, 메모리 파일: AGENTS.md, docs/guide_deploy_plugins.md, docs/adr/README.md
```

## 한계

- 규칙 추출은 `haiku` 한 번이라 질문이나 일회성 요청을 규칙으로 잘못 뽑을 수 있다. 띠에서 `무시`로 거른다.
- 작업 디렉터리에 `AGENTS.md`도 `CLAUDE.md`도 없으면 아무것도 하지 않는다.
- 조직이 관리하는 Claude Code에서는 `prompt.compose` hook이 실행되지 않는다. 띠와 명령은 동작한다.
