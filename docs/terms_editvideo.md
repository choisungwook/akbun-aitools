# 영상 편집·DaVinci Resolve 용어사전

영상 기획·촬영·편집과 `akbun-editvideo` 스킬에서 자주 쓰는 용어를 쉽게 설명한다. Resolve 메뉴와 구체적인 실행 절차는 각 스킬의 `SKILL.md`를 따른다.

## 이야기와 촬영

| 용어 | 뜻 |
|---|---|
| 훅 (hook) | 도입부에서 시청자의 관심을 붙잡는 질문·상황·핵심 문장. 영상이 약속하는 내용을 빠르게 보여준다. |
| 약속 (plot promise) | 제목과 썸네일이 시청자에게 알리는 "이런 영상을 보게 된다"는 내용. 훅은 첫 5~7초 안에 이 약속을 화면과 글자로 확인해 준다. |
| 콜드 오픈 (cold open) | 제목 화면이나 설명 없이 가장 강한 장면으로 바로 시작하는 도입. 훅 스킬에서는 첫 5~7초, 1~3컷이다. |
| 인트로 (intro) | 콜드 오픈 뒤 본편 전까지의 20~30초. 최소한의 맥락, 궁금증, 이 영상만의 것, 예고를 담는다. 훅 전체는 45초 이내다. |
| 궁금증 고리 (curiosity gap, open loop) | 시청자가 아는 것과 알고 싶은 것 사이의 틈. 대비·질문·중단·예고로 열고 본편에서 닫는다. 닫히지 않는 고리는 열지 않는다. |
| 예고 (foreshadow) | 끝이나 중간에 무엇이 있는지 미리 알리는 컷이나 문구. 본편에 실제로 있는 것만 예고한다. |
| 로그라인 (logline) | 영상이 무엇에 관한 것인지 한 문장으로 설명한 이야기의 중심 문장. |
| 비트 (beat) | 이야기의 한 단계. 하나의 메시지나 변화가 있고, 말·장면·목표 길이를 연결할 수 있다. |
| 스토리 아크 (story arc) | 이야기의 변화 흐름. 개발자 diary에서는 맥락과 목표에서 시작해 사건·장애·선택·결과로 이어질 수 있다. |
| day-in-the-life | 하루 전체를 빠짐없이 기록하는 형식이 아니라, 하루 중 이야기의 변화를 보여주는 순간을 골라 담는 영상 형식. |
| 주차 diary | 특정 주차의 진행을 기록하는 형식. 할 일 목록보다 이번 주의 변화와 다음 질문에 초점을 둔다. |
| 스토리보드 (storyboard) | 비트가 어떤 화면과 순서로 보일지 프레임 단위로 계획한 문서. |
| 샷 스케치 (shot sketch) | 한 샷의 카메라 위치, 프레임, 동작, 빛을 촬영 전에 재현할 수 있게 그린 그림. |
| 샷 리스트 (shot list) | 촬영할 샷과 각 샷의 목적·준비 사항을 정리한 목록. |
| 셋업 (setup) | 카메라 위치와 조명·소품 배치를 포함해 한 장면을 찍기 위한 준비 상태. 같은 셋업을 여러 비트에서 재사용할 수 있다. |
| 커버리지 (coverage) | 장면의 이해에 필요한 서로 다른 화면 크기·각도·세부 화면의 묶음. 샷 수를 채우기보다 각 화면이 주는 정보가 달라야 한다. |
| A-roll | 일반적인 영상 용법에서 이야기의 주가 되는 화면이나 인터뷰·진행자 촬영분. 단순히 음성만을 뜻하지 않는다. |
| 주 음성·내레이션 (voice-over, VO) | 영상 위에 얹는 말소리. 촬영하면서 녹음하거나 나중에 따로 녹음할 수 있다. 이 저장소의 촬영·스토리보드에서는 모호함을 줄이려고 `A-roll` 대신 이 말을 쓴다. |
| B-roll | 주 음성이나 이야기 위에 보태는 보조 화면. 행동·장소·근거·분위기처럼 비트 이해에 필요한 정보를 제공한다. |
| 컷어웨이 (cutaway) | 말하거나 행동하는 주 화면에서 잠깐 벗어나 관련된 물건·행동·주변 화면을 보여주는 샷. B-roll의 한 쓰임이다. |
| 타임랩스 (time-lapse) | 긴 시간에 일어난 변화를 짧게 보여주는 촬영 방식. 시간 경과가 의미를 더할 때 사용한다. |
| 레퍼런스 (reference) | 촬영 전에 구도·빛·색의 방향을 논의하기 위해 참고하는 이미지나 영상. 그대로 복제할 대상이 아니라 의도를 공유하는 자료다. |

## DaVinci Resolve와 타임라인

| 용어 | 뜻 |
|---|---|
| 프로젝트 (project) | 미디어, 타임라인, 편집·색·오디오 설정을 담는 Resolve 작업 단위. |
| 미디어 풀 (Media Pool) | 프로젝트에 가져온 영상·음성·이미지 파일을 모아 관리하는 곳. |
| 클립 (clip) | 미디어 파일 전체 또는 타임라인에 놓인 일부 구간. 문맥에 따라 소스 클립과 편집 클립을 구분한다. |
| 타임라인 (timeline) | 영상·음성 클립과 효과가 시간순으로 배열된 편집 시퀀스. 원본을 보존해야 하는 workflow에서는 복제한 작업 타임라인을 사용한다. |
| 타임코드 (timecode, TC) | 영상의 위치를 시·분·초·프레임으로 표시하는 주소. 소스 타임코드는 원본 파일 위치, 타임라인 타임코드는 편집 시퀀스 안의 위치다. |
| 프레임레이트 (fps) | 1초에 표시되는 영상 프레임 수. 타임라인과 출력의 움직임·길이 계산에 영향을 준다. |
| 중첩 타임라인 (nested timeline) | 타임라인 하나를 다른 타임라인 안에 클립처럼 넣은 것. 안쪽 타임라인의 색·자막·오디오가 그대로 보이고, 안쪽을 고치면 바깥에도 반영된다. |
| 훅 타임라인 | 완성 타임라인을 복제하고 맨 앞에 훅 구간을 넣은 타임라인. 본편은 복제된 실제 클립이고 원본은 수정하지 않는다. 이름은 `<완성 타임라인>_hook_<일시>`이고 렌더는 이 타임라인으로 한다. |
| 훅 소스 | 완성 타임라인을 한 번 더 복제해 BGM 트랙을 끈 스냅숏. 이름은 `<훅 타임라인>_src`. 훅 구간이 이 타임라인의 일부를 중첩 클립으로 가져오므로 지우지 않는다. |
| ripple | 클립을 넣거나 지울 때 그 뒤의 클립이 함께 밀리거나 당겨지는 편집. 잠긴 트랙은 밀리지 않는다. |
| 트랙 잠금 (track lock) | 트랙의 클립이 편집으로 바뀌거나 밀리지 않게 막는 설정. 훅 스킬은 BGM 트랙을 잠가 음악을 제자리에 둔다. |
| 마커 (marker) | 타임라인이나 클립의 특정 위치에 남기는 메모·작업 표시. 챕터·그래픽 삽입 지점·확인할 문제 등을 가리킬 수 있다. |
| 노드 (node) | Color 페이지에서 색 변환·보정 등을 개별 단계로 처리하는 블록. 노드를 순서대로 연결해 이미지 처리를 구성한다. |
| Serial 노드 | 앞 노드의 결과를 받은 뒤 다음 처리를 이어 하는 노드. 이 플러그인의 색 스킬은 작업별로 새 라벨 Serial 노드를 사용한다. |
| 노드 라벨 | 노드의 목적을 알아보도록 붙이는 이름. 예: `EXPOSURE`, `WB`, `CST`, `CONTRAST`, `SAT`, `LOOK`. |
| 스틸 (still) | 타임라인의 한 순간을 이미지로 저장한 프레임. 전후 비교나 스코프 측정의 근거로 쓸 수 있다. |
| 키프레임 (keyframe) | 효과·위치·마스크 등의 값이 시간에 따라 변하도록 지정하는 기준점. |
| 마스크 (mask) | 이미지의 어느 부분에 효과를 적용할지 선택하는 모양이나 영역. |
| Power Window | Color 페이지에서 영상의 특정 영역을 선택해 보정하거나 추적하는 마스크 도구. |
| 안정화 (stabilization) | 카메라 흔들림을 줄여 화면이 더 안정적으로 보이도록 하는 처리. |
| 렌더·출력 (render/export) | 편집 타임라인을 재생 가능한 최종 영상 파일로 만드는 과정. |
| 화면비 (aspect ratio) | 가로와 세로 길이의 비율. 일반 영상은 가로형, Shorts는 세로형 비율을 사용한다. |

## 색과 밝기

| 용어 | 뜻 |
|---|---|
| 색보정 (color correction) | 촬영 조건 차이를 정리해 노출·화이트밸런스·색공간을 자연스럽고 일관되게 만드는 기술적 조정. |
| 룩 (look) | 영상의 분위기와 시각적 취향을 만드는 창의적 색 표현. 색보정으로 소스의 기본 상태를 정리한 뒤 적용하는 것이 이해하기 쉽지만, 실제 노드 순서는 색관리와 소스에 맞춘다. |
| 컬러 그레이딩 (color grading) | 색보정과 창의적 룩 작업을 통틀어 부르는 경우가 많다. 요청이 모호하면 기술 보정인지 스타일 변경인지 구분한다. |
| 노출 (exposure) | 영상 신호가 얼마나 밝거나 어둡게 기록·표현되는지를 말한다. 이 플러그인의 노출 스킬은 화이트밸런스나 채도를 바꾸지 않는다. |
| 스톱 (stop) | 노출량의 두 배 또는 절반을 나타내는 단위. +1스톱은 빛이 두 배, +2스톱은 네 배에 해당한다. 장면 선형 빛 기준의 배율이며, 감마·Log 신호값의 고정 차이는 스톱이 아니다. 화면에서 체감되는 밝기는 신호와 모니터 환경에 따라 달라질 수 있다. |
| 스코프 (scope) | Waveform·Vectorscope 같은 영상 신호 측정 도구. 비교 근거를 제공하지만 최종 화면이 시청 환경에서 적절하게 보이는지까지 대신 판단하지는 않는다. |
| Waveform | 화면의 밝기 신호가 어느 범위에 분포하는지 보여주는 스코프. 노출과 클리핑 확인에 쓴다. |
| Vectorscope | 색상 방향과 채도 분포를 보여주는 스코프. 색 균형을 살피는 데 도움을 준다. |
| IRE | 영상 밝기 신호의 단계 표현 단위. Rec.709 SDR Waveform에서 보통 0–100 IRE 범위를 읽는다. |
| 퍼센타일 (percentile, P10/P50/P95) | 밝기 픽셀을 어두운 순서로 정렬했을 때 각각 10·50·95% 위치의 값. 한 픽셀에 좌우되지 않는 밝기 분포 비교에 쓴다. |
| 유효 영상 영역 | 레터박스·자막·UI를 제외한 실제 영상 영역. Look의 밝기 통계는 이 영역 전체에서 계산한다. |
| ROI (관심 영역) | 수목·벽돌 등 측정할 물체를 지정한 영역. 색 군집 반경은 같은 ROI의 픽셀 반경 중앙값으로 비교한다. |
| 고휘도 비율 | 유효 영역에서 Y′가 99 IRE 이상인 픽셀 비율. 채널 클리핑이나 디테일 소실의 증거와 같지 않다. |
| 밝기 근사 스케일 | 기존 노출 스크립트의 8비트 JPEG 회색값 × 4(0–1020). Rec.709 IRE나 스톱으로 직접 환산하지 않는다. |
| 노드 순서 / 조정 순서 | 신호가 통과하는 연결 순서와 사람이 컨트롤을 만지는 순서. 노출→WB→대비로 연결해도 대비부터 조정할 수 있다. |
| 앵커 프레임 (anchor frame) | 색 스타일의 방향과 스코프 목표를 먼저 정할 대표 장면의 프레임. 다른 컷을 같은 분포로 강제하는 기준은 아니다. |
| 허용 오차 (tolerance) | 목표 측정값에서 어느 정도 벗어남을 허용할지 정한 범위. 스타일별로 다르며 보기 좋은 화면보다 우선하지 않는다. |
| 퍼센트포인트 (%p) | 두 백분율 값 사이의 절대 차이. 예를 들어 vectorscope 반경 40%와 목표 32%의 차이는 8%p다. |
| 클리핑 (clipping) | 밝거나 어두운 신호가 표현 범위 끝에 닿아 세부 정보가 사라지는 현상. |
| 화이트밸런스 (white balance, WB) | 광원의 색을 고려해 흰색·회색이 불필요하게 파랗거나 노랗게 치우치지 않도록 색 균형을 맞추는 것. |
| 중립 픽셀 (neutral pixel) | 화면에서 거의 무채색으로 간주할 수 있는 픽셀. 이 플러그인의 화이트밸런스 스킬은 이를 기준점으로 RGB 차이를 살핀다. |
| 색온도 (color temperature) | 빛이 파랗거나 노랗게 느껴지는 경향. 일반적으로 숫자가 높을수록 더 푸른 빛, 낮을수록 더 따뜻한 빛으로 표시된다. |
| 틴트 (tint) | 색 균형의 초록·자홍 방향 조정. 색온도의 파랑·노랑 축과 구분된다. |
| Log | 넓은 밝기 범위를 담기 위해 영상 신호를 압축해 기록하는 감마 표현. 일반 보기용 영상처럼 바로 보이지 않을 수 있다. |
| Rec.709 | HD 영상과 일반 디스플레이에서 널리 쓰이는 SDR 색공간·감마 기준. Log 소스를 보기 좋은 신호로 변환할 때 목표가 될 수 있다. |
| LUT | 입력 색을 다른 색으로 변환하는 표. 기술 변환용과 분위기를 만드는 창의적 룩용이 있으며 목적을 혼동하지 않는다. |
| CST (Color Space Transform) | 입력 색공간·감마를 출력 색공간·감마로 변환하는 처리. LUT와 목적이 겹칠 수 있지만 설정 방식이 다르다. |
| 대비 (contrast) | 밝은 영역과 어두운 영역 사이의 차이. 대비를 높이면 화면이 또렷해질 수 있지만 세부가 날아갈 수도 있다. |
| Pivot | 대비 조정이 중심으로 작용하는 밝기 기준점. 대비 양과 함께 조정하면 중간톤을 기준으로 밝고 어두운 영역이 어떻게 벌어질지 바꾼다. |
| 채도 (saturation) | 색이 얼마나 선명하거나 무채색에 가까운지 나타내는 정도. |
| DCTL | Resolve Color 페이지에서 실행할 수 있는 색 처리 프로그램 형식. 이 플러그인에서는 API 지원이 제한된 선택 보정에 쓰일 수 있다. |

## 음향·자막·그래픽

| 용어 | 뜻 |
|---|---|
| 현장음 (production sound) | 촬영 장소에서 함께 녹음된 말소리와 주변 소리. 편집에서 실제 공간감을 전달한다. |
| 앰비언스 (ambience) | 장소의 지속적인 배경 소리. 실내의 공기 소리나 야외의 바람·도시 소음 등이 예다. |
| 효과음 (sound effect, SFX) | 동작·공간·전환·강조를 만드는 소리. 짧은 악센트뿐 아니라 긴 환경음·질감도 포함할 수 있다. |
| 배경음악 (background music, BGM) | 영상 아래에서 분위기와 흐름을 보태는 음악. 말소리와 현장음을 가리지 않도록 섞는다. |
| LUFS | 사람의 청감 특성을 고려한 음량 측정 단위. 평균 음량과 최종 출력 레벨을 맞출 때 쓴다. |
| 덕킹 (ducking) | 말소리가 나올 때 음악이나 배경 소리를 낮춰 음성을 잘 들리게 하는 조정. |
| 사운드 디자인 (sound design) | 어떤 소리가 언제·어디서·어떤 감정으로 들릴지 구성하는 작업. 소스 선택·레이어·편집·공간·음악의 흐름을 함께 다룬다. |
| 믹싱 (mixing) | 여러 소리의 레벨·대역·위치·시간별 변화를 조절해 함께 들리게 하는 작업. 설계와 겹치지만 최종 파일 출력·계측과는 구분한다. |
| 큐 / 큐시트 (cue / cue sheet) | 소리가 들어갈 한 구간과 그 목록. 이 저장소에서는 ID·TC·장면 앵커·의도·자산·처리·검토 상태를 연결한다. |
| 룸톤 (room tone) | 같은 녹음 공간의 조용한 바닥 소리. 대사 컷 사이를 자연스럽게 잇는 데 쓴다. 완전한 디지털 무음과 다르다. |
| 폴리 (Foley) | 화면 동작에 맞춰 발걸음·옷·물건 소리 등을 직접 녹음하는 작업. 모든 라이브러리 SFX의 동의어가 아니다. |
| 극중음 / 비극중음 (diegetic / non-diegetic) | 장면 세계 안에서 들리는 소리 / 관객을 위해 덧붙인 소리. 화면 밖 소리도 극중음일 수 있으며 BGM도 장면 속 라디오라면 극중음이다. |
| Tonal SFX / 비조성 SFX | 뚜렷한 음높이가 있어 음악과의 음정 관계를 확인하는 효과음 / 주로 소음·질감 중심인 효과음. 어느 쪽도 감정 표현에서 항상 우월하지 않다. |
| 패드 / 드론 (pad / drone) | 분위기·화성을 채우는 지속적인 음색 / 지속음·낮은 움직임으로 긴장이나 공간을 유지하는 소리. 레이어가 서로 겹치는 대역을 확인한다. |
| 라이저 / 스웰 / 히트 (riser / swell / hit) | 상승하는 기대감 / 부풀어 오르는 소리 / 순간적인 강세. 끝·최고점·attack을 장면 변화에 맞춘다. |
| 트랜지언트·어택 / 바디 / 테일 | 소리의 빠른 시작·타격 / 중심 질감 / 뒤에 남는 여운. 파일 시작과 실제 어택 위치는 다를 수 있다. |
| 스템 (stem) | 드럼·베이스·악기군 등으로 나눈 음악의 하위 믹스. 개별 악기 원본 트랙과 항상 같지는 않으며 full mix와 겹치면 중복 증폭될 수 있다. |
| Key / 코드 / phrase / 강박 | 곡의 조성 / 순간의 화음 / 음악적 구절 / 박자의 중심 강세. 같은 key여도 코드·멜로디·리듬이 충돌할 수 있다. 이야기 비트와 음악의 박은 구분한다. |
| J-cut / L-cut | 다음 화면의 소리가 화면보다 먼저 시작 / 이전 화면의 소리가 다음 화면까지 남는 연결. 장면의 공간과 흐름을 잇는다. |
| 크로스페이드 (crossfade) | 한 소리를 줄이면서 다른 소리를 키워 겹쳐 연결하는 것. 길이·곡선은 신호와 음악 구조에 맞추며 constant-power도 항상 음량이 일정하지는 않다. |
| 리버브·테일 (reverb / tail) | 공간의 반사로 이어지는 잔향 / 그 여운. 리버브를 걸었어도 처리·렌더 구간이 짧으면 tail이 잘릴 수 있다. |
| EQ / high-pass / low-pass | 주파수별 크기 조절 / 저역을 줄이고 고역을 통과 / 고역을 줄이고 저역을 통과시키는 필터. 말과 음악의 충돌 대역을 줄이는 데 쓴다. |
| 패닝 (panning) | 소리의 좌우 위치 조절. stereo를 넓히는 것과 실제 surround 채널 제작은 다르며 모노 재생도 확인한다. |
| 오토메이션 / sidechain | 시간에 따라 gain·pan·효과 값 변경 / 다른 신호를 검출 입력으로 쓰는 방식. 음성을 기준으로 음악을 낮추는 덕킹에 사용할 수 있다. |
| dBFS / dBTP / integrated LUFS | 디지털 샘플 피크 / 재구성 신호의 true peak 추정 / 프로그램 전체의 지각 음량. 페이더 dB 값만으로 이 측정값들을 알 수 없다. |
| AUDIO_REVIEW | 사운드 검토용 Sand 타임라인 마커. cue ID·정확한 TC·의도·적용 여부·들을 지점·상태를 남기며 AI 검청과 사용자 승인을 구분한다. |
| HOOK | 훅 타임라인의 훅 구간마다 찍는 Mint 타임라인 마커. 이름은 `HOOK <구간 이름>`, 길이는 구간 길이이고 노트에 완성 타임라인의 원래 타임코드가 있다. |
| HOOK_BGM | 훅을 넣은 뒤 음악 길이 보정이 필요한 BGM 클립의 끝에 찍는 Mint 타임라인 마커. 노트에 몇 프레임을 어떻게 고칠지 있다. |
| HOOK_TEXT 트랙 | 훅의 화면 텍스트만 놓는 비디오 트랙. 하나만 쓴다. 화면 텍스트마다 일반 Text+ 클립 하나를 놓으므로 클립을 선택해 Inspector에서 문구를 바로 고친다. |
| HOOK_TEXT_TEMPLATE | 미디어 풀의 같은 이름 bin에 두는 Fusion Title 항목. 이것을 `HOOK_TEXT` 트랙에 놓아 화면 텍스트 클립을, `SUBTITLE` 트랙에 놓아 자막 클립을 만든다. 프로젝트마다 Resolve 화면에서 한 번 만든다. |
| HOOK 오디오 트랙 | 훅 구간의 소리만 놓는 새 오디오 트랙. 본편의 현장음·효과음·BGM 트랙과 섞지 않아 훅의 소리만 따로 고칠 수 있다. |
| Workflow Integration / MCP | Resolve 안에서 여는 플러그인 경로 / AI가 연결 서비스의 도구를 사용하는 프로토콜. Epidemic 검색·다운로드와 Resolve 타임라인 조작은 서로 다른 역할이다. |
| 대사 자막 (subtitle/caption) | 말한 내용을 글자로 보여주는 자막. 전사와 대조해 실제 발화와 맞춘다. |
| Text+ | DaVinci Resolve의 Fusion 기반 텍스트 도구. 키워드·제목·장면 코멘트 등을 화면에 얹을 때 쓴다. |
| SUBTITLE 트랙 | 자막·챕터 제목·키워드 Text+만 놓는 비디오 트랙. 번호가 아니라 이름으로 찾는다. Text+를 타임라인 중간에 바로 삽입하면 V1에 끼어들어 모든 트랙과 마커를 밀기 때문에, 미디어 풀의 `HOOK_TEXT_TEMPLATE`을 이 트랙에 놓아 자막마다 일반 Text+ 클립 하나를 만든다. |
| 기사 발췌 오버레이 (article excerpt overlay) | 블로그·뉴스·논문의 제목·출처·일부 본문을 패널로 본편 위에 겹치는 편집. 원문 캡처와 Text+ 재조판을 구분하며 인용·요약 여부를 표시한다. |
| ARTICLE_OVERLAY 트랙 | 본문 발췌를 본편보다 위에 겹쳐 놓는 비디오 트랙의 역할 이름. 기존 상위 오버레이 트랙의 빈 구간을 재사용하거나 새 트랙을 만들며, 본편 트랙에는 넣지 않는다. |
| 밑줄 / 원 표시 / 형광 강조 | 글자 아래의 선(underline) / 단어를 둘러싼 원·타원(circle callout) / 글자 뒤 색 띠(highlight). 선택한 부분을 강조하며 패널과 같은 좌표계로 움직인다. |
| 수정 가능한 오버레이 | 패널 전체 위치와 밑줄·원의 위치·크기·색·표시를 Fusion Inspector에서 따로 고칠 수 있게 남긴 구성. 전체 이동용 ARTICLE_LAYOUT과 애니메이션용 ARTICLE_MOTION을 분리하며, 강조를 원문 이미지에 굽지 않는다. |
| Write-on | 선이나 획이 시간에 따라 그려지는 효과. 밑줄·원 표시의 시작과 완성을 효과음에 맞출 수 있다. |
| REVEAL / FADE 노드 | 강조가 그려지기 전 시작점을 숨기거나 전체 그래픽의 등장·퇴장 불투명도를 애니메이션하는 합성 노드의 역할 이름. 사용자가 고정값으로 조절할 LAYOUT·COLOR·개별 MERGE와 분리한다. |
| Whoosh / Paper rustle / Page turn | 빠른 이동을 표현하는 바람 소리 / 종이 바스락거림 / 페이지 넘김 소리. 패널 등장·교체의 선택적 효과음 검색 용어다. |
| Marker stroke / Scribble | 마커의 한 획 / 연속해서 긋는 필기 소리. `marker on paper stroke`, `marker writing circle`, `highlighter drag` 등으로 검색하고 강조 획과 동기화한다. 특정 자산명이나 필터를 뜻하지 않는다. |
| 미삽입 큐시트 | 효과음을 넣지 못했을 때 채팅에 남기는 경과 분·초, 길이, 검색어, 동기화 기준, 대상 트랙과 실패 사유. 타임라인이 있으면 실제 Resolve TC·fps·시작 TC도 병기한다. |
| 모션그래픽 (motion graphics) | 글자·도형·도표·아이콘 등이 움직이며 개념이나 정보를 보여주는 그래픽. 필요한 이유를 먼저 정하고 제작 도구는 별도로 선택한다. |
| GFX | 그래픽을 놓을 위치를 표시하는 타임라인 마커 이름으로 이 플러그인에서 사용한다. |
| 챕터 (chapter) | 영상의 주제를 나누는 구간 제목. 타임라인 마커와 게시 플랫폼의 챕터 정보로 만들 수 있다. |

## 브이로그 사운드 검색 용어

Epidemic Sound에서 효과음·BGM 후보를 찾을 때 사용할 **영문 검색 표현**이다. 실제 곡명이나 공식 카테고리·필터 이름을 보장하는 목록은 아니다. 아래 조합을 그대로 넣어 결과가 적으면 핵심 단어부터 검색하고 하나씩 좁힌다. 장면에 적용하는 방법은 [매뉴얼의 사운드 효과 시나리오](manual_editvideo.md#장면별-사운드-효과-시나리오)를 참고한다.

### 환경음과 일상 동작 검색

| 검색 용어 | 뜻·찾는 소리 | 조합 예시와 확인점 |
|---|---|---|
| `ambience`, `ambient sound`, `background` | 장소를 채우는 지속적인 배경 소리 | `city ambience distant`. 음악 검색의 `ambient`와 구분하려 효과음 영역에서 검색 |
| `room tone`, `room ambience` | 조용한 실내의 바닥 소리 | `room tone quiet`, `small room ambience`. 음성 녹음 공간과 어울리는지 확인 |
| `city`, `traffic`, `street` | 도시·차량·거리 소리 | `traffic distant`, `quiet street`. 차가 많은 도로와 조용한 골목을 구분 |
| `cafe`, `crowd`, `chatter` | 카페·군중·웅성거림 | `cafe ambience`, `crowd murmur`. 또렷한 타인의 대사가 내레이션을 방해하지 않는지 확인 |
| `wind`, `leaves`, `birds` | 바람·나뭇잎·새소리 | `wind trees gentle`, `leaves rustle`. 실제 계절·장소와 맞는지 확인 |
| `rain`, `water`, `ocean waves` | 비·물·파도 | `rain window`, `water stream`, `ocean waves gentle`. 소리의 크기와 촬영 거리를 비교 |
| `footsteps`, `walking` | 걷는 발소리 | `footsteps pavement`, `footsteps gravel`, `footsteps wood`. 신발·바닥 재질과 걸음 싱크 확인 |
| `keyboard`, `typing`, `mouse click` | 키보드·마우스 동작음 | `keyboard typing soft`, `mouse click single`. 실제 동작보다 크거나 빠르지 않게 선택 |
| `coffee pour`, `cup`, `kettle` | 커피·컵·주전자 소리 | `coffee pour`, `cup ceramic`, `kettle boil`. 준비·따르기·내려놓기를 나눠 검색 |
| `page turn`, `pen`, `cloth`, `zipper`, `door` | 책·필기·옷·가방·문 등 생활 동작 | `page turn slow`, `pen writing`, `cloth rustle`, `zipper bag`, `door close soft` |
| `train interior`, `subway`, `car interior` | 이동 수단 안의 환경음 | `train interior steady`, `car interior rain`. 실내/외부 시점이 다른 소리를 구분 |

### 전환·강조·음악적 효과음 검색

| 검색 용어 | 뜻·잘 맞는 역할 | 조합 예시와 확인점 |
|---|---|---|
| `whoosh`, `swoosh`, `swish` | 공기나 물체가 스치는 움직임 | `soft whoosh`, `short swish`. 이름은 겹쳐 쓰이므로 실제 소리를 비교 |
| `click`, `tick`, `tap` | 작은 클릭·딱 소리·두드림 | `soft click`, `wood tap`. UI 변화나 작은 동작에 사용 |
| `pop`, `bubble` | 가볍게 튀는 소리 | `soft pop`, `bubble pop`. 카드·키워드 등장에 쓰되 반복 피로 확인 |
| `ding`, `chime`, `bell` | 짧은 음높이가 있는 울림 | `notification chime`, `soft bell`. 결과 강조에 쓰며 BGM과 음정 충돌 확인 |
| `hit`, `impact`, `thump`, `boom` | 순간적인 타격·무게감 | `soft impact`, `low thump`. 일상 영상에서는 거대한 충격음보다 작은 후보부터 비교 |
| `riser`, `build up` | 점차 높아지거나 강해져 변화를 예고하는 소리 | `short riser`, `subtle riser`. 도착점을 화면 변화·음악 강박과 비교 |
| `swell`, `reverse`, `suckback` | 부풀거나 역방향으로 빨려 들어가는 인상 | `gentle swell`, `reverse cymbal`, `short suckback`. `reverse`는 재생 방향/가공 방식이며 항상 음악적 소리는 아님 |
| `downlifter`, `fall`, `decay` | 고조 이후 내려앉거나 사라지는 소리 | `soft downlifter`, `long decay`. `decay`는 감쇠 특성으로도 쓰이므로 다른 명사와 조합 |
| `glitch`, `digital`, `static` | 디지털 끊김·전자적 잡음 | `short digital glitch`, `soft static`. 버그·화면 변화를 과장할 때의 선택지이며 개발자 영상의 필수 효과는 아님 |
| `stinger`, `sting` | 짧게 마침표를 찍는 음악적 악센트 | `short stinger`, `soft musical sting`. 말·결과 화면보다 앞서 주목을 빼앗지 않는지 확인 |
| `tonal hit`, `tonal riser`, `texture` | 음높이가 있는 타격·고조 또는 소리의 질감 | `soft tonal hit`, `airy texture`. `texture`만으로 음높이 유무를 단정하지 않음 |
| `pad`, `drone`, `pulse` | 지속적인 화성·지속음·반복 맥동 | `warm pad`, `subtle drone`, `soft pulse`. 곡 사이 여백·집중·긴장에 사용하며 tonal 여부와 반복 리듬 확인 |

### BGM의 분위기·스타일·악기 검색

| 검색 용어 | 의미·어울리는 출발 상황 | 검색 조합 예시 |
|---|---|---|
| `warm`, `cozy`, `gentle` | 따뜻하고 편안한 인상. 아침·책상·일상 | `warm acoustic`, `gentle piano` |
| `calm`, `relaxed`, `laid back`, `mellow` | 차분하고 여유로운 흐름. 산책·작업 과정 | `laid back electronic`, `mellow instrumental` |
| `reflective`, `introspective`, `nostalgic` | 되돌아봄·내면적 분위기·그리움. 회고·주차 diary | `reflective piano`, `nostalgic acoustic` |
| `dreamy`, `atmospheric`, `ambient` | 몽환적·공간감 중심의 분위기. 풍경·여백 | `dreamy ambient`, `atmospheric instrumental` |
| `curious`, `playful`, `quirky` | 호기심·장난기·독특함. 발견·작은 시행착오 | `curious pizzicato`, `playful light percussion`. pizzicato는 현을 손가락으로 뜯는 주법 |
| `tension`, `suspense`, `dark` | 긴장·기다림·어두운 인상. 막힘·다음 결과의 예고 | `minimal tension`, `subtle suspense`. 같은 태그라도 공포·액션처럼 과할 수 있음 |
| `hopeful`, `uplifting`, `optimistic` | 기대·고양감·긍정적 변화. 해결·다음 계획 | `gentle uplifting`, `hopeful instrumental` |
| `lo-fi`, `lofi`, `chillhop`, `downtempo` | 거친 녹음 질감을 활용한 스타일·느긋한 힙합 계열·느린 전자음악 계열 | `lofi instrumental`, `chillhop mellow`, `downtempo minimal`. 말 없는 곡이라는 보장은 없음 |
| `acoustic`, `indie folk`, `piano`, `felt piano` | 어쿠스틱 악기·포크 계열·피아노·펠트로 부드럽게 만든 피아노 음색 | `acoustic guitar gentle`, `felt piano sparse` |
| `electronic`, `synth`, `light percussion` | 전자음악·신시사이저·가벼운 타악기 | `minimal synth`, `light percussion steady`. 기술 영상이라고 강한 전자음을 강제하지 않음 |
| `cinematic`, `underscore` | 영화적인 전개·대사나 장면을 받치는 음악 | `minimal cinematic underscore`. `cinematic`만 검색하면 큰 오케스트라·트레일러 곡도 나오므로 의도로 좁힘 |
| `instrumental`, `no vocals`, `sparse`, `minimal` | 보컬 없는 곡·성긴 편성·적은 요소를 원하는 표현 | `reflective piano instrumental`, `ambient sparse`. 합창·보컬 질감이나 강한 멜로디가 남는지 미리듣기 |

분위기 단어는 감정을 강제로 지정하는 정답이 아니다. 같은 `uplifting`도 조용한 기대부터 큰 축하까지 다르므로 실제 말·화면과 비교한다. `instrumental`은 음성 간섭을 줄이는 출발점이며 반주가 성기다는 뜻은 아니다.

### 검색을 좁히는 수식어와 방법

| 표현 | 뜻·선택 목적 | 예시 |
|---|---|---|
| `soft`, `subtle`, `gentle` / `hard`, `heavy` | 부드러운·눈에 덜 띄는 / 강한·무거운 인상 | `soft impact`와 `heavy impact`를 대비해서 듣기 |
| `close`, `distant` / `interior`, `exterior` | 가까운·먼 거리 / 실내·실외 관점 | `distant traffic`, `train interior` |
| `dry`, `reverberant`, `airy`, `warm` | 잔향이 적은·울리는·공기감 있는·따뜻한 음색 | `dry click`, `airy whoosh`. warm은 음량·음정의 수치가 아님 |
| `short`, `long`, `single`, `loop` | 길이·한 번의 사건·반복 가능한 구간을 원하는 표현 | `single click`, `rain loop`. loop라는 이름이어도 실제 접합부 검청 |
| `slow`, `fast`, `steady`, `pulsing` | 속도·일정함·맥동하는 흐름 | `footsteps slow`, `steady pulse` |
| `wood`, `metal`, `glass`, `ceramic`, `gravel` | 나무·금속·유리·도자기·자갈 재질 | `wood tap`, `metal click`, `footsteps gravel` |

1. **효과음:** 소리의 명사부터 찾고 재질·동작·거리 중 필요한 조건을 더한다. `footsteps` → `footsteps gravel` → `footsteps gravel slow`. 결과가 없으면 마지막 조건을 빼거나 동의어를 바꾼다.
2. **BGM:** 감정 + 스타일/악기부터 찾고 보컬 유무·밀도·길이·BPM을 조정한다. 예: `reflective piano`를 듣고 보컬이 있으면 instrumental 후보로 좁힌다. 느린 BPM도 편성이 빽빽할 수 있으므로 템포만으로 말 가림을 판단하지 않는다.
3. **음악 연결:** `stem`은 악기군별 하위 믹스, `key`는 조성, `BPM`은 분당 박 수, `build`·`breakdown`은 고조·편성 축소 구간을 찾을 때의 표현이다. 곡 설명·제공 스템을 확인하고 실제 phrase와 코드를 들어 연결한다. `stem`을 검색했다고 스템 파일을 얻는 것은 아니다.
4. **AI 요청:** “내레이션 아래에서 멜로디가 적고 따뜻한 피아노, 중간에 드럼을 뺄 수 있는 후보”처럼 목적을 먼저 설명해도 된다. 키워드는 대안을 찾는 수단이다.

위 문자열은 검색 표현이며 따옴표 검색·제외 연산자 같은 특수 문법을 전제하지 않는다. UI나 MCP에 지원되는 필터가 있으면 그 필드로 조건을 전달한다. Epidemic Sound의 공식 MCP는 음악의 분위기·악기·BPM·보컬 등과 SFX의 검색어·길이·태그를 지원하며, 정확한 필드는 현재 연결의 도구 스키마를 확인한다. [공식 MCP 검색 문서](https://developers.epidemicsound.com/docs/mcp/)

## 용어를 읽을 때 참고

- 사람마다 `look`, `color grading`, `color correction`을 넓거나 좁은 뜻으로 쓸 수 있다. 요청이 모호하면 기술적 균형 조정과 창의적 스타일 변경 중 무엇을 원하는지 먼저 구분한다.
- 스코프 목표는 비교와 반복을 돕는 기준이다. 실제 밝기·색 판단은 원본, 모니터링 환경, 장면 의도와 함께 확인한다.
- A-roll은 업계에서 보통 주요 촬영 화면을 뜻하며, 음성만을 가리키지 않는다. 이 저장소의 촬영 스킬은 혼동을 피하려 `주 음성(내레이션)`과 B-roll 화면을 구분해 쓴다.
