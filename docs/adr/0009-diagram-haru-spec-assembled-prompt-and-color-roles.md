# diagram-haru는 관계에 맞는 배치를 고르고, 색은 역할 라벨 칩에만 쓴다

Scope: akbun-draw / akbun-draw-diagram-haru

## Decision

- 모델은 다이어그램 spec(JSON)만 쓰고, 영어 프롬프트는 `scripts/haru_prompt.py`가 `references/*.jsonl`(style·palettes·layouts·shapes·edges·groups) 문장으로 조립하고 채점한다. 배치 라우팅(`pick`·`key`·`values`·`title`·`same`·`sequence`)은 `layouts.jsonl` 필드에 둔다.
- spec을 쓰기 전에 독자가 확인할 관계를 정하고, 관계에 맞는 배치를 고른다. 같은 참여자가 시간순으로 메시지를 주고받으면 `sequence`(생명선, 시간순 가로 화살표, `wait` 여백, `spans` 대괄호)를 쓴다.
- 맞는 도형·팔레트가 라이브러리에 없으면 부족한 점을 밝히고 작업 폴더의 `shapes.jsonl`·`palettes.jsonl`에 새 `id`로 정의한다. 스크립트는 기존 `id`를 덮지 않고 더하기만 한다. 배치는 스크립트 지원이 필요해 `layouts.jsonl`에 더하는 변경으로 제안한다.
- 선·화살표·번호·글자는 모두 잉크(검정)다. 색은 구별해야 할 역할이 있는 화살표 라벨 뒤 칩(`chip`)에만 쓰고, 같은 역할은 같은 칩이다. 도형 채움 강조(`focus`)와 강조색 화살표 팔레트는 없앴다.
- 화살표는 직선이고, 직선이 다른 도형을 가로지를 때만 한 번 휜다. 실패 경로는 `sync`를 빌리지 않고 `blocked`를 쓴다.

## Reason

모델이 프롬프트 문장을 직접 쓰면 장마다 그림체가 달라져 문장을 라이브러리로 고정했다. 강조색을 화살표·라벨에 쓰던 때는 팔레트에 따라 글자가 파랑·검정으로 바뀌었고, 노랑 채움 두 색은 한 그림 안에서 농도가 달라 보였다. 사용자가 고친 SSE 시퀀스 그림은 흰 바탕·잉크 선 위에 요청·헤더·이벤트를 라벨 칩 색으로만 구별했고, 기존 배치로는 시간순 메시지를 표현할 수 없었다.

버린 대안: 강조색 화살표 유지(역할이 아닌 장식 색이 되고 글자 색이 흔들림), `focus` 노랑 채움 유지(색이 라벨이 아닌 도형에 퍼짐), 시퀀스를 `column`으로 흉내(참여자·생명선·대기·응답 범위를 못 보임), 라이브러리에 없는 도형을 spec에 지어내기(채점·조립이 깨짐).

트레이드오프: 강조 도형을 색으로 표시할 수 없어 위치·제목으로만 보인다. 작업 폴더 정의는 그 작업에만 있어, 여러 번 쓰이면 라이브러리로 옮기는 변경이 따로 필요하다.
